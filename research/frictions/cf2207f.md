# cf2207f — Hanabi

## `LazySegTree<Bounds<D>, T>` cannot be instantiated or ranged over `Bounds<D>`
- **Where:** `cf2207f.cp`, lines 38–42:
  ```cp
  domain Pos = 0..=n
  var seg = LazySegTree<Pos, Int>(AddMax, [Pos] _ => 0)
  for r in Rank:
      let v = seg.all + Int(not must_rank[r])
      seg.set(Pos(r.to_idx + 1), v)
      for lo in by_right[r]: seg.apply(..=Pos(lo.to_idx), 1)
  ```
- **What felt wrong:** The DP state lives naturally on the `n + 1` boundaries `Rank.bounds` (`r.r` after rank `r`, and prefix `..=lo.l` before rank `lo`). Trying `LazySegTree<Bounds<Rank>, Int>(AddMax, [Bounds<Rank>] _ => 0)` fails with two errors:
  - `E0302: expected ?[Int]Int, found [Rank.bounds]Int` (`Bounds<Rank>` collapses to `Int` in the generic type parameter `D`).
  - `..=lo.l` is rejected with `E0301: ..= ends at a position; a range up to the boundary ... is written ..`, and `..lo.r` is typed as `Range<Rank>` rather than `Range<Rank.bounds>`.
  Because of this, we had to declare a parallel `domain Pos = 0..=n` and write two manual `.to_idx` domain crossings (`Pos(r.to_idx + 1)` and `Pos(lo.to_idx)`), losing type-level protection against off-by-one boundary shifts.
- **Goal it hurts:** hard-to-get-wrong, express, coherence.
- **Ideal code:**
  ```cp
  var seg = LazySegTree<Bounds<Rank>, Int>(AddMax, fill: 0)
  for r in Rank:
      seg.set(r.r, seg.all + Int(not must_rank[r]))
      for lo in by_right[r]: seg.apply(..=lo.l, 1)
  ```
- **General fix:** Treat `Bounds<D>` as a first-class `Index` domain in generic parameters (`LazySegTree<Bounds<D>, T>`, `SegTree<Bounds<D>, T>`, `Fenwick<Bounds<D>>`) and allow `Range<Bounds<D>>` when the expected type is a range of boundaries (distinguishing position-ranges of `D` delimited by boundaries from ranges over `Bounds<D>` itself). Helps every prefix/cut DP over a domain (`0..=n` cuts beside `1..=n` items).
- **Severity:** high.
- **Status:** fixed: `D.bounds` is now a first-class index domain in `SegTree`, `LazySegTree`, and `Fenwick` (`df094364`), and `cf2207f.cp` migrated to `LazySegTree<Rank.bounds, Int>` (`4dfa63e3`, 373 -> 361 tokens, no shadow `Pos` domain or `.to_idx` casts).

## Boundary-delimited `for j in hi.r..r.l:` yields `Rank.bounds` instead of `Rank`
- **Where:** `cf2207f.cp`, lines 22–23 and 33–34:
  ```cp
  if let next = hi + 1:
      for j in next..r: must_rank[j] = true
  ```
  and:
  ```cp
  if let next = hi + 1:
      for j in next..: must_rank[j] = true
  ```
- **What felt wrong:** Iterating the ranks strictly between `hi` and `r` (or strictly after `hi`) should be `for j in hi.r..r.l:` and `for j in hi.r..:`. Instead, `for j in hi.r..r.l: must_rank[j] = true` fails with `E0301: this is indexed by Rank, but the index is a Rank.bounds` — even though `..r.r` in a `SegTree`/`LazySegTree` call is typed as `Range<Rank>`! That inconsistency forces an `if let next = hi + 1:` guard every time an open-left interval `(hi, r)` or `(hi, end]` is iterated over a nominal domain.
- **Goal it hurts:** express, coherence.
- **Ideal code:**
  ```cp
  for j in hi.r..r.l: must_rank[j] = true
  // ...
  for j in hi.r..: must_rank[j] = true
  ```
- **General fix:** Make boundary-bounded ranges `b1..b2` / `b1..` / `..b2` consistently yield elements of `D` (positions between the two boundaries), matching the `V.bounds` design and `SegTree`/`LazySegTree` range semantics. Helps every problem iterating open intervals `(a, b)` or suffixes `(a, end]` over a nominal domain without `a + 1` optional unwrapping.
- **Severity:** high.

## Initializing a `LazySegTree<D, Int>(AddMax, ...)` to a constant requires allocating a temporary array
- **Where:** `cf2207f.cp`, line 39:
  ```cp
  var seg = LazySegTree<Pos, Int>(AddMax, [Pos] _ => 0)
  ```
- **What felt wrong:** Omitting the initial array fills leaves with `AddMax.over.id` (`Int.MIN`), which is rarely what a nonnegative DP wants. Initializing all leaves to `0` forces allocating and filling a throwaway `[Pos]Int` array just to pass into `LazySegTree.new`.
- **Goal it hurts:** express, performance.
- **Ideal code:**
  ```cp
  var seg = LazySegTree<Pos, Int>(AddMax, fill: 0)
  ```
- **General fix:** Add an optional `fill: ?T = none` parameter (or `.filled(act, val)`) to `LazySegTree` and `SegTree` constructors so constant-initialized trees skip the extra O(n) allocation. Helps every `AddMax`/`AddMin` DP segment tree.
- **Severity:** low.
- **Status:** fixed: `LazySegTree`, `SegTree`, and `DualSegTree` accept `fill: ?T = none` (`385b851b`), and `proto/ports/ecnerwala/cf2207f.cp` uses `LazySegTree<Pos, Int>(AddMax, fill: 0)` (`147d73cd`).
