- **Tokens (contestant-written):** `671` (CP Lang) vs `697` (dream, **0.96x**) vs `1067` (C++ `main()`, **0.63x**; `1078` total)
- **Max-input runtime** (`n = 200_000, q = 200_000`, 500 spaced large barrels + 199,500 random barrels, 3-run median): `7994.0 ms` (CP Lang) vs `1307.8 ms` (C++ `g++ -O2 -std=c++20`) — **6.11x** (exceeds both the 1.5x goal and the 4s problem TL)
- **Peak RSS (max input):** `70252 KB` (CP Lang) vs `22272 KB` (C++) — **3.15x**
- **Emitted C++ size:** `25293 bytes` (limit 65,536 bytes)

## Algorithm

A multiset of barrels can merge to one iff no threshold `k >= 1` has `sum(barrels < k) < k`, at least two barrels `>= k`, and every adjacent gap `< k` occurring strictly below `k`. Split at `B = 1000 = sqrt(10^6)`:
- Large `k > B`: walk downward from the largest barrel in `bag`, stopping as soon as the minimum gap drops to `<= B` or a duplicate is hit (at most `B` steps).
- Small `k <= B`: maintain `gaps[d]` for every adjacent gap `d in 0..=B` and `small_cnt[v]` for `v in 0..=B`, then sweep `k = 1..=B` in `O(B)`.

## Frictions (port vs dream)

### 1. `SortedBag<K>` lacks O(1) ordered iteration/cursors, turning O(q sqrt(M)) into O(q sqrt(M) log n) — 6.11x slower (`dream/cf2066e.cp:48-56`)
- **Severity:** high
- **Goal it hurts:** performance and control
- **Where:** `while let nxt = bag.last_lt(cur):` calls both `bag.last_lt(cur)` and `bag.count(nxt)` on every step — two `O(log n)` treap traversals per element instead of one `O(1)` amortized iterator decrement (`++it` on `std::set::rbegin()`). Neighbor lookup in `add_barrel`/`remove_barrel` likewise performs four separate `O(log n)` traversals instead of one `insert`/`find` + `O(1)` `prev`/`next`. On `n = q = 200_000`, this pushes runtime to `7994 ms` vs `1308 ms` (`6.11x`, TLE on 4s).
- **Dream (`dream/cf2066e.cp:51-56`):**
  ```cp
  for nxt in bag.cursor(cur).prevs():
      rem -= nxt
      min_gap = min(min_gap, cur - nxt, nxt)
      if rem < min_gap: return false
      if min_gap <= B or bag.count(nxt) >= 2: break
      cur = nxt
  ```
- **General fix:** Back `Set<T>` / `SortedBag<T>` with a balanced tree (or `std::set`/`std::map` in C++ codegen) exposing `O(1)` amortized reverse iteration and cursors.

### 2. `SortedBag<K>` leaks removed treap nodes and uses 6 parallel `Int`/`?Int` lists — 3.15x RSS (`dream/cf2066e.cp:10-12`)
- **Severity:** high
- **Goal it hurts:** performance and control
- **Where:** `stdlib/bag.cp` pushes onto 6 parallel `List`s (`key`, `pri`, `cnt`, `sub`, `left`, `right`) and `remove` never recycles freed indices (`70252 KB` vs `22272 KB`, `3.15x` RSS).
- **Dream:** `proto/ports/ecnerwala/dream/cf2066e.cp` lines 10-12.
- **General fix:** Recycle freed indices via a free list (or lower to `std::set`/`std::map` / B-tree) and narrow child indices to 32-bit with `-1` niche.

### 3. No stateful struct methods (`struct Barrels`) or tuple `if let (p, x) = (prv, nxt)` (`dream/cf2066e.cp:9-45,70-75`)
- **Severity:** low
- **Goal it hurts:** express and revise
- **Where:** Top-level mutable globals (`bag`, `gaps`, `last_gap_at`, `small_cnt`, `total`) with free functions `add_barrel`/`remove_barrel`/`can_merge`, nested `if let p = prv: if let x = nxt:`, and manual `last_gap_at` cache because `gaps[d].last` traverses the treap root-to-leaf in `O(log n)` instead of `O(1)`.
- **Dream:** `proto/ports/ecnerwala/dream/cf2066e.cp` lines 9-45, 70-75.
- **General fix:** Support stateful structs with `mut self` methods and `O(1)` `.last` caching on `SortedBag`, plus tuple optional binding (`if let (p, x) = (prv, nxt)`).

### Closed since previous wave
- `SortedBag.add()` / `.remove()` no longer require `let _ =` discards; all five discards were removed from `cf2066e.cp`.
