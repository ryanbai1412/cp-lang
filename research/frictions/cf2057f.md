# cf2057f — Formation

The editorial: raising pupil `i` to `X` lifts the `l` pupils `s = i−l+1 ..= i`
to `⌈X / 2^j⌉`, and `l` is the right count exactly when `X` lies in
`(a_s·2^(l−1), a_{s−1}·2^l]` (the first lifted pupil is below its target, the
one before already meets it). For fixed `l` the cost `Σ ⌈X / 2^j⌉ − Σ window`
rises with `X`, so keep the window with the largest sum on every stretch of
`X` (paint windows in increasing sum), then sweep the stretches from high to
low, answering the queries by decreasing `k` with a binary search inside the
stretch. `l <= 31` because `X <= 2·10^9`.

## Painting runs costs bound plumbing
- **Where:** `cf2057f.cp`, lines 23–26:
  ```cp
  var saved = IntervalMap<cuts.D, ?Int>.new(none)
  for s in (0..=n - l).sorted(by: s => window.sum(s..s + l)):
      let end = if s > 0: cuts.at(2 * a[s - 1]).l else: cuts.D.last.r
      saved.assign(cuts.at(a[s]).l..end, window.sum(s..s + l))
  ```
- **What felt wrong:** "paint `[a_s, 2a_{s−1})` with the window sum" needs
  `.l` on both ends to turn compressed indices into cuts, and "to the end"
  is `cuts.D.last.r`, which names the last element to get past it. The
  window sum is written twice because `prefix` has no indexing by range.
  `IntervalMap` needs an explicit `use std.interval` (the error names it).
- **Goal it hurts:** express; hard to get wrong (cut vs element is the
  off-by-one the `.l`/`.r` pair is there to prevent, but it is spelled per use).
- **Ideal code:** `saved[cuts.at(a[s]) ..< (cuts.at(2 * a[s - 1]) if s > 0 else cuts.end)] = window[s..s + l]`.
- **General fix (ranges/containers):** a range from an element to an
  element (`x ..< y`) or to the domain's end (`D.end`), index assignment on
  `IntervalMap`, and `Prefix1[r]` for `sum(r)`.
- **Dream:** `dream/cf2057f.cp` lines 10, 19–21.
- **Severity:** medium.
- **Area:** ranges

## Walking the runs backwards, with their next cut
- **Where:** `cf2057f.cp`, lines 28–32:
  ```cp
  for (r, best) in [run for run in saved.each()].reversed():
      if let best = best:
          let (_, j) = r.ends
          let lo = (cuts[r.first!] << (l - 1)) + 1
          let hi = if j < cuts.len: min(cap, cuts[cuts.D.nth(j)] << (l - 1)) else: cap
  ```
- **What felt wrong:** `each()` is a generator, so iterating it backwards
  materialises a list first. A run is never empty, yet `r.first` is `?D`.
  The value after the run (the stretch's upper end) is reached through raw
  offsets (`r.ends`, `cuts.D.nth(j)`, `j < cuts.len`). The painted/unpainted
  split is an `if let` one level down instead of a pattern in the `for`.
- **Goal it hurts:** express.
- **Ideal code:** `for (r, some best) in saved.runs.reversed():` and
  `(cuts[r.first] << (l − 1)) <..= min(cap, (cuts.get(r.end) ?? cap) << (l − 1))`.
- **General fix (containers/core):** `IntervalMap.runs` as a reversible
  view; non-empty runs typed so `first` is `D`; `cuts.get(bound)` for the
  element at a cut (`none` past the end); refutable patterns in `for`.
- **Dream:** `dream/cf2057f.cp` lines 23–24.
- **Severity:** medium.
- **Area:** containers

## Answering the satisfied queries is a manual pop loop
- **Where:** `cf2057f.cp`, lines 35–37:
  ```cp
  while let x = waiting.last, ks[x] + best >= floor:
      ans[x] max= bsearch_last(lo..=hi, h => raise(l, h) <= ks[x] + best)!
      waiting.pop()
  ```
- **What felt wrong:** as in cf2057e2, peek-test-act-pop on a stack; the
  search over a non-empty range whose first point is known to pass still
  returns `?Int`, so it needs `!`, and it is a free function where every
  other search on a sequence is a method.
- **Goal it hurts:** express.
- **Ideal code:** `for x in waiting.pop_while(x => ...): ans[x] max= xs.last(h => ...)`.
- **General fix (seq):** `pop_while` (proposed in cf2057e2), and
  `bsearch_first`/`bsearch_last` as `Range` methods.
- **Dream:** `dream/cf2057f.cp` lines 25–26.
- **Severity:** low.
- **Area:** seq

## `++` is accepted and means `+ +`
- **Where:** first draft of line 12, `compress([x for x in a] ++ [2 * x for x in a])`.
- **What felt wrong:** `++` (list concatenation in Haskell, Scala and the
  dream sketches) type-checks as `a + (+b)`: unary plus on a list is
  accepted, and only `cpl fmt` revealed it by printing `+ +`. It happened
  to mean concatenation, but a silent parse of an unknown operator is
  unsafe. Arrays also have no `map`, so `2 *` over `a` is a comprehension.
- **Goal it hurts:** hard to get wrong (unguessable parse); express.
- **Ideal code:** `compress(a + a.map(2 *))`.
- **General fix (core):** reject unary `+` on non-numbers (or `++`
  outright with "did you mean `+`?"); `map` on arrays as on lists.
- **Dream:** `dream/cf2057f.cp` line 11.
- **Severity:** medium.
- **Area:** core

## An upper-case lambda parameter is "not in scope"
- **Where:** first draft of line 36, `X => raise(l, X) <= ...`.
- **What felt wrong:** the editorial's `X` as a parameter name gives
  `E0201 no X in scope`, with the help "declare it first: `let X = ...`";
  the real rule (upper-case names are types or domains) is not said.
- **Goal it hurts:** doubt to evidence (errors name the rule).
- **Ideal code:** `h => raise(l, h)` (as written), with an error naming the rule.
- **General fix (diagnostics):** when a lambda parameter is upper-case,
  say so: "parameters are lower-case; `X` reads as a type".
- **Dream:** none (naming).
- **Severity:** low.
- **Area:** diagnostics

## The closed form of the cost needs bit plumbing
- **Where:** `cf2057f.cp`, lines 17–19.
- **What felt wrong:** `popcount(y & ((1 << (l - 1)) - 1))` builds the mask
  for "the low `l − 1` bits"; `popcount` is a free function while the
  neighbouring integer operations are methods.
- **Goal it hurts:** express.
- **Ideal code:** `(y % (1 << (l - 1))).popcount`, or `y.low(l - 1).popcount`.
- **General fix (math):** `Int.popcount` and `Int.low(k)` as methods.
- **Dream:** `dream/cf2057f.cp` line 15.
- **Severity:** low.
- **Area:** math
