# cf2147f — Exchange Queries

## `Action` and `Monoid` lower to `std::function` closures, causing 2.97x slowdown in `LazySegTree` (and force boilerplate over `+` / `with`)
- **Where:** `cf2147f.cp`, lines 13–26 (`dream/cf2147f.cp`, lines 15–21):
  ```cp
  fn merge(a: ?Low, b: ?Low) -> ?Low:
      ...
  let act = Action<?Low, Int>(
      id: 0,
      compose: (f, g) => f + g,
      apply: (f, x, _) => if let l = x: Low(l.cover + f, l.first, l.last, l.gaps) else: none,
      over: Monoid(id: none, op: merge),
  )
  var low = LazySegTree<Cut, ?Low>(act, [Cut] c => Low(0, c, c, 0))
  ```
- **What felt wrong:** Every `pull`, `put`, and `push` in `LazySegTree` calls `act.over.op`, `act.apply`, and `act.compose` through `std::function` fields in the emitted C++, blocking GCC from inlining them in the O(q log n) hot loop. On `n = 100_000, q = 100_000`, the `?Low` port takes 416.9 ms vs 140.3 ms for the original C++ (2.97x). Expressively, defining `+` on `Low` should let `LazySegTree` infer the semigroup combine without a manual `Monoid`/`Action` wrapper or fake `?Low` identity, and `l with cover: l.cover + d` should avoid rebuilding all 4 fields of `Low`.
- **Goal it hurts:** performance, express.
- **Ideal code (`dream/cf2147f.cp`, lines 15–21):**
  ```cp
  fn (a: Low) + (b: Low) -> Low = match cmp(a.cover, b.cover):
      less => a
      greater => b
      equal => Low(a.cover, a.first, b.last, a.gaps + b.gaps + choose2(b.first - a.last))

  var low = LazySegTree<Cut>([Cut] c => Low(0, c, c, 0),
                             apply: (d: Int, l: Low) => l with cover: l.cover + d)
  ```
- **General fix:** Monomorphize `LazySegTree` operations statically (no `std::function`), allow `LazySegTree` to pick up `+` directly without a fake `?T` identity when `apply` only touches non-empty ranges, and add `with` record update syntax.
- **Severity:** high.

## `?Low` is not niche-packed inside `LazySegTree`, nearly doubling runtime (232.6 ms -> 416.9 ms)
- **Where:** `cf2147f.cp`, lines 9, 13–18, 26 (`dream/cf2147f.cp`, lines 13–21):
  ```cp
  struct Low(cover: Int, first: Cut, last: Cut, gaps: Int)
  ...
  var low = LazySegTree<Cut, ?Low>(act, [Cut] c => Low(0, c, c, 0))
  ```
- **What felt wrong:** Using `?Low` instead of a magic `INF` sentinel lowers to `std::optional<Low>` (adding an 8-byte alignment-padded tag to every node and extra branches) rather than exploiting the `INT64_MIN` niche in `Low.cover: Int`. Switching from `INF`-sentinel to `?Low` increased max-input runtime from 232.6 ms (33.3 MB RSS) to 416.9 ms (39.0 MB RSS).
- **Goal it hurts:** performance, hard-to-get-wrong.
- **Ideal code (`dream/cf2147f.cp`, lines 13–21):**
  ```cp
  // Either `LazySegTree` needs no `?Low` identity, or `?Low` niche-packs on `cover: Int`.
  ```
- **General fix:** Propagate niche values from `Int` / domain fields up to enclosing structs so `?Struct` uses an existing field's niche with zero size overhead.
- **Severity:** high.
