## Algorithm summary

Maintain a permutation `x` of `1..=n` and an expression tree `ops` whose leaves `0..n` correspond to variables $x_1, \dots, x_n$ and whose internal nodes store `(l, r, is_max, ch: ?(Int, Int))`. Querying `1, 2, ..., n` and `n, ..., 1` determines whether the root operator is `max` or `min` and yields the winning index `m`. Recursively, `solve(l, r, is_max, known_m)` keeps `x[l..r]` monotone (ascending for `is_max`, descending for `not is_max`), isolates `l..m` by rotating `x[l..=m]` left by 1, isolates `m+1..r` by reversing `x[m..r]` (flipping `is_max`), and merges the resulting left and right chains around leaf `m` by reversing the spanning subrange `x[ll..rr]` and querying which side wins. Once the binary expression tree is built, print `!` and evaluate Bowser's online queries recursively over `ops`.

## Frictions

### 1. `std.seq.reverse` and `std.seq.rotate_left` do not operate on mutable slices

- **Severity:** medium
- **Goal it hurts:** express
- **Area:** seq

**What happened:**
The divide-and-conquer step repeatedly reverses and rotates subranges of `x` (`x[l..=m]`, `x[m..r]`, `x[ll..rr]`). In `std.seq`, `reverse(mut a: List<T>)` and `rotate_left(mut a: List<T>, k: Int)` only accept a whole `List<T>`, not a mutable slice `mut x[l..r]`. This forced 16 lines of hand-written index-swapping helpers (`rev_range`, `rot_left`, `rot_right`).

**Current code:**
```cp
fn rev_range(mut a: List<Int>, l: Int, r: Int):
    var (i, j) = (l, r - 1)
    while i < j:
        swap(mut a[i], mut a[j])
        i += 1
        j -= 1

fn rot_left(mut a: List<Int>, l: Int, r: Int):
    let first = a[l]
    for i in l..r - 1: a[i] = a[i + 1]
    a[r - 1] = first

fn rot_right(mut a: List<Int>, l: Int, r: Int):
    let last = a[r - 1]
    for i in (l + 1..r).rev: a[i] = a[i - 1]
    a[l] = last
```

**Ideal code:**
```cp
reverse(mut x[m..r])
rotate_left(mut x[l..=m], 1)
rotate_right(mut x[l..=m], 1)
```

**General fix:**
Support mutable slice lending `mut a[l..r]` (or `mut a[l..=r]`) and type in-place `std.seq` algorithms (`reverse`, `rotate_left`, `rotate_right`, `sort`, `next_permutation`) over mutable slices instead of whole `List<T>`s only.

### 2. No `rotate_right` (or signed `rotate`) in `std.seq`

- **Severity:** low
- **Goal it hurts:** express
- **Area:** seq

**What happened:**
`std.seq` provides `rotate_left(mut a, k)` but no `rotate_right` (or signed shift), so undoing a 1-element left rotation required writing a separate `rot_right` function.

**Ideal code:**
```cp
rotate_left(mut x[l..=m], 1)
var l_ch = solve(l, m, is_max, none)
rotate_right(mut x[l..=m], 1)
```

**General fix:**
Provide `rotate_right` alongside `rotate_left` (or a single `rotate(mut s, shift)` accepting positive/negative offsets) in `std.seq`.

---

### 3. Cannot `read()` directly into a subrange of an array (`vals[1..n]`)

- **Severity:** low
- **Goal it hurts:** express
- **Area:** seq

**What happened:**
Each online verification query starts with either `0` (end of test case) or the first variable `x_1`, followed by `n - 1` more integers. After peeking `first`, reading the remaining `n - 1` integers into `vals` requires a manual loop `for i in 1..n: vals[i] = read()` (the same subrange-read friction seen in `cf2207e2`).

**Current code:**
```cp
var vals: [0..n]Int = 0
vals[0] = first
for i in 1..n: vals[i] = read()
```

**Ideal code:**
```cp
var vals: [0..n]Int = 0
vals[0] = first
read_into(mut vals[1..n])
```

**General fix:**
Provide `read_into(mut slice)` (paired with mutable slice lending from Friction 1) so partial-array and sentinel-padded reads don't need explicit loops or second allocations.

## What worked well

- `@!interactive` handled flushing automatically on `print("?", x)` and `print("!")`, and `print("?", x)` printed the `List<Int>` space-separated directly without manual string concatenation.
- `x.find(resp)!` replaced `std::find(...) - X.begin()` in one expression.
- `ch: ?(Int, Int)` on `struct Node` eliminated the `-1` sentinel children from C++, and `while let li = l_ch.last, let ri = r_ch.last:` eliminated empty-check-then-unwrap boilerplate.
- Nested recursive `fn eval(cur: Int) -> Int` captured `ops` and `vals` naturally without C++23's `this auto&& self` lambda syntax.
