# cf1146h — Satanic Panic

Dream program: `proto/ports/ecnerwala/dream/cf1146h.cp`.

The port matches the dream token-for-token (`222` vs `222`, **1.00x**); `std.geometry.{Pt, turn}`, `V.after(i)`, and `Bitset<V>` worked directly. The frictions below are performance and API gaps found on the max-size run.

## `Bitset<V>` heap-allocates on every `&` in `(a & b & c).len` instead of using bounded-size storage or fused popcount
- **Area:** `containers` (`plan/STDLIB.md` 4.8) / codegen
- **Where:** `proto/ports/ecnerwala/cf1146h.cp` line 21:
  ```cp
  let inside = (left[i, j] & left[j, k] & left[k, i]).len
  ```
- **What felt wrong:** `Bitset<V>` stores its words in a heap-allocated `std::vector<uint64_t>` even though `n: 5..=300` bounds `V` to 5 `uint64_t` words, so each `a & b & c` in the `O(n^3)` loop allocates and frees two temporary `std::vector<uint64_t>` buffers (~9 million heap allocations at `n = 300`). On `n = 300`, the port takes `393.9 ms` vs `148.3 ms` for C++ `std::bitset<310>` (`2.66x`, though still well under the 4s TL).
- **Goal it hurts:** performance.
- **Ideal code (`dream/cf1146h.cp:21`):**
  ```cp
  let inside = (left[i, j] & left[j, k] & left[k, i]).len
  ```
- **General fix:** Use fixed-size inline word storage (`std::array<uint64_t, (MAX_N + 63) / 64>`) when `V`'s upper bound is small (e.g., `<= 4096`), and/or fuse `(a & b & ...).len` into a zero-allocation word-wise popcount loop.
- **Severity:** high.

## `Bitset<V>.from` does not accept a generator of `V` directly
- **Area:** `containers` (`plan/STDLIB.md` 4.8)
- **Where:** `proto/ports/ecnerwala/cf1146h.cp` lines 12–14:
  ```cp
  let left: [V, V]Bitset<V> = [V, V] (i, j) => Bitset<V>.from(
      [V] k => turn(pts[i], pts[j], pts[k]) > 0
  )
  ```
- **What felt wrong:** `Bitset<V>.from(k for k in V if ...)` is rejected with `E0302` because `.from` only accepts `[V]Bool`, forcing a temporary `[V]Bool` array allocation for every `(i, j)` pair (`O(n^2)` temporary arrays).
- **Goal it hurts:** express, performance.
- **Ideal code:** `Bitset<V>.from(k for k in V if turn(pts[i], pts[j], pts[k]) > 0)` (or `[V] k => ...` fused into direct bit-setting without materializing `[V]Bool`).
- **General fix:** Allow `Bitset<D>.from` to construct from an iterator/generator of `D` (or fuse `[D] k => pred` directly into bit words).
- **Severity:** low.
