# Friction report: cf1284e (New Year and Castle Construction)


Ported `cf1284e` (`n <= 2500` points, no three collinear; count 5-subsets with one point strictly inside the 4-hull) using `std.geometry.{Pt, arg, cross}` with float-free polar sorting (`arg(d)`) and a circular half-plane sweep around each center.

- Gate: `proto/ports/ecnerwala/gate.sh cf1284e 50` passed (`PASS cf1284e (3 samples, 50 random cases)`).
- Tokens: port `226` vs dream `142` (`1.59x`), original `1,616` (`0.14x`).
- Max-input runtime (`n = 2500`): `691.5 ms` CP Lang vs `383.4 ms` C++ (`1.80x`), exact output agreement. Emitted C++: `11,365 B`.

## `List.sorted(by:)` / `List.sort(by:)` allocates temporary key/index vectors and indirect-sorts

- **Severity:** medium
- **Status:** fixed (`cpl-codegen` lowers `sort(by: key)` with a cheap pure key expression to in-place `std::stable_sort` with an inlined comparator instead of `cpl::sort_by`'s three auxiliary vectors; `cf1284e` max input dropped from `1.63x` to `1.14x` matched C++ and emitted C++ shrank by 709 B).
- **Goal it hurts:** performance
- **Area:** containers (`plan/STDLIB.md`) + codegen
- **Dream lines:** `proto/ports/ecnerwala/dream/cf1284e.cp:12`
- **What happened:** Sorting `2500` lists of `2499` `Pt` vectors with `.sorted(by: d => ByAngle(d))` takes `691.5 ms` vs `383.4 ms` in C++ (`1.80x`) because `sort(by:)` emits Schwartzian-transform key and index vectors plus `std::stable_sort` and an indirect permutation copy, rather than an in-place comparator sort. Also, passing a type constructor directly (`by: ByAngle`) is not supported; it requires a lambda `d => ByAngle(d)`.
- **General fix:** Lower `sort(by:)` with a cheap/stateless key (such as `ByAngle`) to direct in-place sorting without allocating parallel key/index buffers, and allow type constructors as first-class functions.

## No two-pointer reach over a sequence

- **Severity:** medium
- **Status:** accepted as `xs.reach(while: p, cyclic: false) -> List<Int>` (decisions §95); owned by the sequence lane
- **Goal it hurts:** express
- **Area:** seq (`plan/STDLIB.md`)
- **Dream lines:** `proto/ports/ecnerwala/dream/cf1284e.cp:19`
- **What happened:** Counting the rays strictly within the half-turn after each ray takes a hand-written two-pointer loop with `j % m` wraparound and an `if j < i + 1: j = i + 1` clamp. A binary search per ray (`bsearch_last(1..m, k => cross(rays[i], rays[(i + k) % m]) > 0)`) states it without the loop but runs 2.6x slower than the port and adds 3 KB of emitted C++.
- **General fix:** `xs.reach(while: p, cyclic:)`: for each `i`, the largest `k` with `p(xs[i], xs[i + j])` for every `1 <= j <= k` (indices mod `len` when cyclic, `k < len`). Two pointers, O(n) calls of `p` when reach never drops by more than one step from `i` to `i + 1`, which holds whenever `p(a, ·)` is a true-then-false prefix along a sorted order. Covers angular sweeps, circular arcs, and "longest stretch after i within d" windows.

## No exact `std.math.choose` or anonymous-sized `[n]Pt` array reading

- **Severity:** low
- **Goal it hurts:** express
- **Area:** number theory (`plan/STDLIB.md`) + core language
- **Dream lines:** `proto/ports/ecnerwala/dream/cf1284e.cp:6, 9, 14, 16`
- **What happened:** The port hand-writes `choose3(k)` and `total_quads = (n - 1) * (n - 2) * (n - 3) * (n - 4) / 24`, and declares a `domain V = 0..n` solely to read `pts: [V]Pt` and iterate over it.
- **General fix:** Add exact `std.math.choose(n: Int, k: Int) -> Int`, and support `[n]T = read()` when elements are iterated by value rather than indexed.

## A list's tuple fields typed `0..n` stay 64-bit

- **Severity:** medium
- **Status:** worked around (the port names the element `struct Seg(d: Pt, a: 0..2500, b: 0..2500)`, whose fields narrow to `int`; that drops the tuned `perf.cp`)
- **Goal it hurts:** performance
- **Area:** codegen
- **Owner:** Perf A
- **What happened:** `[(d: p[j] - p[i], a: i, b: j) for i in 0..n for j in i + 1..n]` emits `std::vector<std::tuple<m1_Pt, ll, ll>>` even when written `List<(d: Pt, a: 0..n, b: 0..n)>`, since `n` is a runtime bound. The 3.1M 32-byte elements made the max input 1.20x C++ time; the 24-byte `Seg` takes it to 1.04x time and 0.58x RSS.
- **General fix:** Narrow a list element's range-typed tuple fields to the width their `// Bounds:` cap allows, as struct fields already do.

## `for Seg(_, a, b) in segs` is refused

- **Severity:** low
- **Goal it hurts:** express
- **Area:** core language
- **Owner:** Core
- **What happened:** A struct pattern in a `for` head gives E0501 ("can't handle this pattern outside a `match` yet"), so the loop reads `s.a`, `s.b` where the tuple form destructured.
- **General fix:** Lower irrefutable struct patterns in `for` and `let` heads like tuple patterns.
