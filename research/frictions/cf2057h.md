# cf2057h — Coffee Break

The editorial: turning off machine `j` sends `⌊a_j/2⌋` students each way,
and the operations commute, so the best for machine `i` is `a_i` plus
what flows in from each side separately with `i` never turned off.
Pushing a prefix toward `i` leaves it all 1s except a stack of 0
positions: each student sent in moves the nearest 0 one step toward `i`,
and a 0 that reaches `i` is consumed. Once the stack is empty the
students wrap around in whole laps of `i + 1`. The stack of 0s is the
whole state, amortised O(n). The algorithm is imperative, so both the
port and the dream keep the loop.

## The answer is per position, but the sweep is a list builder
- **Where:** `cf2057h.cp`, lines 5, 8, 27–28, 32:
  `fn inflow(a: List<Int>) -> List<Int>`, `var into = [0]`,
  `into.push(carried)`, `[a[i] + left[i] + right[n - 1 - i] for i in 0..n]`.
- **What felt wrong:** `inflow` produces one value per position of `a`,
  but it can only return a `List` built by pushes, so the right side is
  re-indexed by hand as `right[n - 1 - i]` (`inflow(a.rev)` is not
  reversible back into `a`'s positions). `a + b` on arrays is
  concatenation (`[1, 2, 3] + [1, 2, 3]` prints `1 2 3 1 2 3`), so the
  elementwise sum is a comprehension over raw indices.
- **Goal it hurts:** hard to get wrong (off-by-one in `n - 1 - i`);
  express.
- **Ideal code:** `a.positions.map(i => ...)` returning `[_]Int` over
  `a`'s positions, and `zip(a, inflow(a), inflow(a.rev).rev).map(sum)`.
- **General fix (seq):** `.rev` on an array result that keeps the
  position mapping, and `map` on arrays returning arrays over the same
  domain (also cf2057f).
- **Dream:** `dream/cf2057h.cp` lines 8, 11, 31, 33.
- **Severity:** medium.
- **Area:** seq

## No `divmod`, and the lap count needs two divisions
- **Where:** `cf2057h.cp`, lines 15–16:
  `carried += i * (sent / (i + 1))` and `sent %= i + 1`.
- **What felt wrong:** "whole laps, then the remainder" is one operation;
  the divisor is repeated, and mixing `/` and `%=` on the same variable is
  order-sensitive.
- **Goal it hurts:** express; revise.
- **Ideal code:** `let (laps, rest) = sent.divmod(i + 1)`.
- **General fix (math):** `divmod` on `Int` (also cf2035f).
- **Dream:** `dream/cf2057h.cp` line 19.
- **Severity:** low.
- **Area:** math

## The stack's top is `last!` and `[len - 1]`
- **Where:** `cf2057h.cp`, lines 14, 18, 24:
  `if zeros.is_empty:`, `let d = i - zeros.last!`,
  `zeros[zeros.len - 1] += sent`.
- **What felt wrong:** the three cases are "no zero left", "the nearest
  zero is reached" and "the nearest zero moves"; that is a `match` on the
  top. Reading the top is `last!` after an emptiness test the compiler
  can't connect to it, and writing it is a raw index.
- **Goal it hurts:** express; hard to get wrong.
- **Ideal code:** `match zeros.top: none: ..., z if sent >= i - z: ..., _: zeros.top! += sent`.
- **General fix (core, seq):** guarded `match` arms on optionals, and an
  assignable `last` (`xs.last! += d`).
- **Dream:** `dream/cf2057h.cp` lines 17–30.
- **Severity:** medium.
- **Area:** core

## The empty-stack case pushes a sentinel `-1`
- **Where:** `cf2057h.cp`, line 17: `zeros.push(-1)`.
- **What felt wrong:** after whole laps, the remainder behaves as if a 0
  sat just before position 0, so `-1` is pushed as a position that isn't
  one. Positions are `Int`, not a domain, because `-1` must be allowed.
- **Goal it hurts:** hard to get wrong (sentinels).
- **Ideal code:** kept in the dream (line 22); a cut domain
  (`a.bounds`) would make `-1` a real position.
- **General fix:** none proposed; recorded as a sentinel case.
- **Dream:** `dream/cf2057h.cp` line 22.
- **Severity:** low.
- **Area:** none

## The port runs 1.6x the original and uses 4x the memory
- **Where:** `cf2057h.cp`, lines 5–32.
- **What felt wrong:** on the max input (n = 10^6) the port takes 0.22 s
  and 82 MB against the original's 0.14 s and 19 MB. The port keeps
  `a`, `a.rev`, two result lists and the final printed list, all 64-bit,
  where the original updates one array in place. The pure form (two sweeps,
  then a sum) costs three extra n-sized copies.
- **Goal it hurts:** performance (max at most 1.5x); costs are visible.
- **Ideal code:** `zip(a, inflow(a), inflow(a.rev).rev).map(sum)` as a
  fused, non-copying pipeline.
- **General fix (seq, codegen):** `.rev` as a view; `zip`/`map` fused into
  the print.
- **Dream:** `dream/cf2057h.cp` line 33.
- **Severity:** medium.
- **Area:** codegen
