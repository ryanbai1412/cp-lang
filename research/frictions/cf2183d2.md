# cf2183d2 friction report

## `V.group(by: t.depth)` comes back in hash order
- **Where:** `port.cp` line 17, `let layers = t.bfs.runs(by: t.depth).collect()`; the dream's `let by_depth = V.group(by: t.depth)` (dream line 19).
- **What felt wrong:** `group(by:)` returns a `HashMap`, so `by_depth.items.rev` does not walk depths deepest first and the bottom-up fill traps on `Slot.find(...)!`. The port leans on `t.bfs` being depth-ordered and cuts it into runs, which is a fact about `Rooted`'s layout, not the idea "the layers by depth".
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** `let by_depth = V.group(by: t.depth)` walking keys in order when the key is ordered, or `t.layers` as a list of vertex lists indexed by depth.
- **General fix:** a key-ordered grouping (`group(by:)` returning a `SortedMap`-ordered walk for `Ord` keys, or `buckets(by:)` for `Int` keys in a known range), so every "bucket by depth/value, then sweep in order" port drops its hand ordering.
- **Severity:** medium

## `t.order.runs(by:).collect()` reads freed memory in the C++
- **Where:** `port.cp` line 17 written with the getter, `t.order.runs(by: t.depth).collect()`.
- **What felt wrong:** the getter returns a temporary `List<V>`; the emitted C++ stores the run views into it (`t34 = runs(Rooted_order(t), ...)`) and the temporary dies at the end of the statement. `cpl run` is right; `cpl test` crashes (RE), `--checked` reports heap-use-after-free, and `--checks none` happens to pass. The port reads the field `t.bfs` instead.
- **Goal it hurts:** hard-to-get-wrong, submission.
- **Ideal code:** `let layers = t.order.runs(by: t.depth).collect()`.
- **General fix:** extend `lend::pin_owners` to a view stored through `collect()` (and any store of views into an owned list) of a temporary, or reject it at check time (R05).
- **Severity:** high
