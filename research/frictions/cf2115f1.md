# cf2115f1 — Gellyfish and Lycoris Radiata

## No reversible implicit treap (`Rope`) with non-pushing path queries (`ranges`)
- **Where:** `proto/ports/ecnerwala/cf2115f1.cp` lines 13, 51–127 vs `proto/ports/ecnerwala/dream/cf2115f1.cp` lines 14–16, 27–30.
  ```cp
  struct TreapNode(l: ?Int, r: ?Int, pri: U64, own: ?Int, lazy: ?Int, sz: Int, flip: Bool)
  // ... 75 lines of split_treap, merge_treap, flip_treap, push_down, query_treap
  ```
- **What felt wrong:** `std.lazy.LazyTreap` lacks prefix/range reversal and non-pushing root-to-node path queries (`query_path`, where querying a position must not push heavy tags down). Running `cpl check` on `dream/cf2115f1.cp` fails with:
  `error[E0201]: no Rope in scope` (`dream/cf2115f1.cp:14:12`).
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** (`dream/cf2115f1.cp` lines 14–16, 27–30)
  ```cp
  var rope = Rope<Pos, MergeSeg<Query>>(merge: (a, b) => a.merge(b))
  rope.apply(..=decode_pos(b), MergeSeg.singleton(q))
  rope.reverse(..=decode_pos(b))
  let ans = rope.query_path(decode_pos(c), seg => seg.first_alive(id => alive[id]))
  ```
- **General fix:** Add a reversible implicit treap (`Rope<D, Tag>`) in `std.lazy` / `std.range` supporting `reverse(range)`, `apply(range, tag)`, and `query_path(pos, visitor)` (walking root-to-node pushing only reversals).
- **Severity:** medium.
- **Status (2026-11-23):** `std.lazy.Rope<D, T>` now has `apply`, `reverse` and `get`, but no
  non-pushing path query: `Rope<0..4, Int>(fill: 0).query_path(2, x => x)` is E0203 "has no field
  or method `query_path`". A port on `Rope<Pos, Ids>(merge: (tag, s) => tag.union(s))` reading
  `sets.get(p)` agreed on 120 generated inputs but took 18.7-24.8 s on the two max inputs, where
  the treap port took 7.4 s (orig 5.3-6.1 s): `get` and `apply`'s splits push every tag down as a
  set union, about 46% of the profile. So the port keeps its own treap.

## No mergeable binary segment tree (`MergeSeg<D>`) in stdlib (`ranges`)
- **Where:** `proto/ports/ecnerwala/cf2115f1.cp` lines 11, 20–49 vs `proto/ports/ecnerwala/dream/cf2115f1.cp` lines 14, 27, 30.
  ```cp
  struct SegNode(l: ?Int, r: ?Int)
  fn build_seg(q: Int, lo: Int, hi: Int) -> Int: ...
  fn concat_seg(x: ?Int, y: ?Int, lo: Int, hi: Int) -> ?Int: ...
  fn query_seg(s: ?Int, lo: Int, hi: Int) -> (?Int, ?Query): ...
  ```
- **What felt wrong:** Maintaining sets of domain elements under O(log q) tree-union (`merge`) and amortized dead-leaf pruning (`first_alive`) requires a hand-rolled arena of binary segment tree nodes. Running `cpl check` on `dream/cf2115f1.cp` fails with:
  `error[E0204]: no type or domain named MergeSeg, and not in the stdlib (yet)` (`dream/cf2115f1.cp:14:22`).
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** (`dream/cf2115f1.cp` lines 27, 30)
  ```cp
  rope.apply(..=decode_pos(b), MergeSeg.singleton(q))
  let ans = rope.query_path(decode_pos(c), seg => seg.first_alive(id => alive[id]))
  ```
- **General fix:** Provide a persistent/mergeable dynamic segment tree (`MergeSeg<D>`) over a domain with `singleton`, `merge`, and pruning `first_matching(pred)`.
- **Severity:** medium.
- **Status (2026-11-23):** `std.segtree.MergeSeg<D>` exists with `singleton`, `merge` and
  `first_alive`, but it is a heap per instance and `merge` copies the other heap's values
  (`std/GAPS.md`), so a tag pushed into both children copies the whole set twice instead of
  sharing nodes. The port keeps its own trie, now in an `Arena<SegNode>` with `Id` handles.

## `?Id<T>` is not niche-packed, so the arena trie keeps an `empty` node (`perf`)
- **Where:** `corpus/problems/cf2115f1/port.cp`, `struct SegNode(l: Id<SegNode>, r: Id<SegNode>)`
  and `let empty = new_seg(Id(0), Id(0))`.
- **What felt wrong:** an absent child is `None`, but `struct S(l: ?Id<S>)` emits
  `std::optional<Id_S0_4> l;` (8 bytes) though `Id(raw: 0..=2_000_000_000)` has spare values
  (R03.2.2). With `?Id` children the max input took 8.5 s and 4.2 GB (176M nodes, 16 B each);
  with the `empty` node 5.2-7.3 s and 2.1 GB, as orig's `int` children. Repro:
  `use std.marks.{Arena, Id}` / `struct S(l: ?Id<S>)` / `var a = Arena<S>.new()` /
  `let x = a.alloc(S(None))` / `let y = a.alloc(S(x))` / `print(yes(a[y].l == Some(x)))`.
- **Goal it hurts:** hard to get wrong (a sentinel stands for absent), performance.
- **Ideal code:** `struct SegNode(l: ?Id<SegNode>, r: ?Id<SegNode>)` and `x ?? return y`.
- **General fix:** give `Id<T>` its range's niche, as R03.2.2 says for a struct's first field.
- **Severity:** medium.

## A field of an arena node can't be assigned (`compiler`)
- **Where:** `query_seg` writes `seg[u] = SegNode(l, seg[u].r)`; the treap stays a
  `List<TreapNode>` with `?Int` links because its push-downs write single fields.
- **What felt wrong:** `arena[id] = x` works, but `arena[id].f = x` is E0305 "a `Arena<S>` can't
  be indexed". Repro: `use std.marks.{Arena, Id}` / `struct S:` / `    var l: Int` /
  `var a = Arena<S>.new()` / `let x = a.alloc(S(1))` / `a[x].l = 2`.
- **Goal it hurts:** express (one handle type for every node pool).
- **Ideal code:** `tr[t].flip = not tr[t].flip` on an `Arena<TreapNode>`, as on a `List`.
- **General fix:** a field place through a user `get`/`set` index reads, updates and writes back.
- **Severity:** low.

## An enum with only domain payloads reads its tag wrong (`compiler`, already filed from noi02p1)
- **Where:** `enum Op` keeps `Delete(id: 1..=q_cnt)` and converts with `Query(id)`.
- **What felt wrong:** with `Delete(id: Query)` both engines misread the sample. Repro:
  `let (n, q_cnt): (1..=9, 1..=5) = read()` / `domain Pos = 1..=n` / `domain Query = 1..=q_cnt` /
  `enum Op:` / `    @tag(1) Add(r: Pos)` / `    @tag(3) Del(id: Query)` / `for _ in Query:` /
  `    let (op, p): (Op, Pos) = read()`, printing each, on `9 3` / `1 4 7` / `3 2 5` / `1 1 1`
  prints `add 1 3`, `add 7 2`, `add 2 4` (`.ord`s); with
  `Del(id: 1..=q_cnt)` it prints `add 3 6`, `del 2 4`, `add 0 0`.
- **Ideal code:** `@tag(3) Delete(id: Query)` and `alive[decode(id)] = false`.
- **Severity:** high (silent misread).
