# cf2255e2 friction

Every version appends each position's value to that position's history, and the answer
is the best subarray of one position's history. A range tag is therefore a function on
(value, history summary). Negate and clamp-to-zero only look at the sign of the value
and scale with its magnitude, so until an assignment a tag is, for each sign, a new sign
plus the history it records per unit of |value|; after an assignment the value is a
constant and the recorded history is fixed. Tags compose in O(1), so one `DualSegTree`
over positions answers everything, with a "record" tag applied to the whole range after
each version. Using `std.lazy.DualSegTree` and `std.algebra.MaxSub` removed the fake
monoid, the `blank: Cell` binding, and the hand-rolled Kadane struct (945 -> 793 tokens,
51.5 KB -> 32.6 KB emitted C++, 4.20 s -> 3.17 s on max input).

## The idiomatic program is 3.3x slower than the original
- **Where:** the whole port. Max input (n = q = 500000): original 0.95 s, port 3.17 s
  (down from 4.20 s after switching from `LazySegTree` to `DualSegTree`, still above the
  3 s limit).
- **What felt wrong:** the algorithm and the call counts match the original; the cost is
  representation. Records go into `then`/`run` by value, `DualSegTree`'s `compose`/`apply`
  closures are called through `std::function` so nothing inlines, and a fixed-size
  `[-1..=1]Path` array inside `Tag` lowers to a heap `std::vector` per tag (6.0 s, 296 MB),
  forcing three named fields plus a `path(f, s)` selector.
- **Goal it hurts:** performance (max 1.5x of C++), and "the obvious way is the fast way".
- **Ideal code:** the port as written, at original speed.
- **General fix:** pass records by `const&` when the callee does not move them; lower
  arrays over a constant-size domain to `std::array`; monomorphise `DualSegTree` /
  `LazySegTree` operations instead of `std::function`; give `?T` of a record a niche or
  flag layout without `std::optional`'s copy cost.
- **Dream:** `dream/cf2255e2.cp` lines 13-20, 34 (the same tag code; the fix is in the lowering).
- **Severity:** high.

## An enum cannot index an array, so a three-way case is a range type and an if-chain
- **Where:** `cf2255e2.cp` lines 9-17 (`type Sign = -1..=1`, `fn sign(v)`, and
  `fn path(f: Tag, s: Sign) -> Path = if s < 0: f.neg elif s == 0: f.zero else: f.pos`).
- **What felt wrong:** the tag is a table indexed by "negative, zero, positive". `enum Sign: neg = -1, zero = 0, pos = 1` cannot index `[Sign]Path`, so each entry is named three times (field, constructor, selector).
- **Goal it hurts:** express, coherence (enums are the natural index space for a case split).
- **Ideal code:**
  ```cp
  enum Sign: neg = -1, zero = 0, pos = 1
  struct Tag(path: [Sign]Path, set: ?Cell)
  let p = f.path[sign(c.val)]
  ```
- **General fix:** a payload-free enum is a domain (`[E]T`, `for e in E`, `E.len`),
  stored as a fixed array.
- **Dream:** `dream/cf2255e2.cp` lines 7, 11, 14, 20 and 23.
- **Severity:** medium.

## No operator `+` / `*` on `MaxSub` or `st[p]` indexing on `DualSegTree`
- **Where:** `cf2255e2.cp` lines 24-25, 29, 53 (`MaxSub.join(c.hist, p.seen.scale(abs(c.val)))`, `st.get(at(read()))`).
- **What felt wrong:** `MaxSub` uses method calls `MaxSub.join` and `.scale` rather than `+` and `*`, and `DualSegTree` uses `st.get(p)` rather than `st[p]`. Also passing function items directly (`compose: then, apply: run`) currently wraps in lambdas.
- **Goal it hurts:** express, coherence.
- **Ideal code (`dream/cf2255e2.cp` lines 15-16, 20, 34, 40):** `c.hist + p.seen * abs(c.val)`, `st[at(read())]`, `compose: then, apply: run`.
- **General fix:** implement `Add`/`Mul` on `MaxSub`, `Index` on `DualSegTree`, and bare function references as closure arguments.
- **Severity:** low.

## No `minmax`, `I.at`, or `U64.wrap`
- **Where:** `cf2255e2.cp` lines 49, 55, 62 (`I(Int((y ^ last) % U64(n)) + 1)`, `U64(ans)`, `min(l, r)..=max(l, r)`).
- **What felt wrong:** Ordering two endpoints repeats both names, indexing a 1-based domain by a 0-based offset needs `Int(...) + 1`, and wrapping a signed answer into `U64` uses a plain cast rather than an explicit wrapping conversion.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code (`dream/cf2255e2.cp` lines 36, 42, 44):** `I.at((y ^ last) % n)`, `U64.wrap(ans)`, `let (l, r) = minmax(at(read()), at(read()))`.
- **General fix:** Add `minmax(a, b)` to the prelude, `D.at(offset)` on domains, and `U64.wrap(x)` for explicit two's-complement conversion.
- **Severity:** low.

## The interpreter cannot run the max input
- **Where:** `cpl run cf2255e2.cp < max.in` did not finish in 300 s.
- **What felt wrong:** the gate's random cases are small, so this does not block the port,
  but "is my program right on the big case?" needs the compiled path.
- **Goal it hurts:** evidence.
- **General fix:** interpreter speed on closure-heavy trees, or `cpl run --native`.
- **Dream:** `dream/cf2255e2.cp` the whole program, unchanged, under `cpl run`.
- **Severity:** low.
