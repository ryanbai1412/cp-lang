# cf2084g1 — Codeforces 2084 G1 (Wish Upon a Satellite, easy version)

Ported: `proto/ports/ecnerwala/cf2084g1.cp`. Place values in increasing
order; `dp[c]` is the best score with `c` of the `k` smallest values on even
positions, and value `k + 1` either must be odd, must be even (its fixed
position says so) or is free. O(n^2), the same DP as the original.

## "Absent or equal to" needs a list literal
- **Where:** `for z in [false, true] if c + Int(z) <= half and even[k + 1] in [none, some(z)]:`
- **What felt wrong:** the constraint "value k + 1 is free, or its parity is
  z" is a test on an optional, but the only spelling that reads well builds a
  two-element list of optionals and does membership. `even[k + 1] == none or
  even[k + 1] == z` repeats the place; `even[k + 1] ?? z == z` is a trick. The
  same shape came back in cf2084f (`c[i] not in [none, some(v)]`), so it is a
  pattern, not a one-off.
- **Goal it hurts:** express, coherence.
- **Ideal code:** `for z in [false, true] if c + Int(z) <= half and even[k + 1].allows(z):`
  (true when absent or equal), or a pattern guard `if even[k + 1] is none | z`.
- **General fix:** one optional combinator in the prelude, `?T.allows(x)` /
  `.is_none_or(pred)` (Rust's `is_none_or`), documented next to `??`, plus a
  lint that rewrites `x in [none, some(y)]`. Helps every port with partially
  given input (cf2084f, cf2084g2, cf2084e, all "-1 means unknown" problems).
- **Severity:** low.
- **Dream:** `proto/ports/ecnerwala/dream/cf2084g1.cp` lines 12

## A DP over "placed so far" carries a rolling array by hand
- **Where:** `var next: [0..=half]?Int = none` ... `dp = next`
- **What felt wrong:** the recurrence is `dp[k + 1][c']` from `dp[k][c]`; the
  rolling copy, the fresh `none` fill and the swap are three lines that state
  memory layout, not the idea. Adding a dimension (say, tracking a second
  parity) means editing the declaration, the fill and the swap together.
- **Goal it hurts:** express and revise.
- **Ideal code:**
  ```cp
  var dp: [0..=n, 0..=half]?Int = none @rolling(0)
  dp[0, 0] = 0
  for k in 0..n, c in 0..=min(k, half): ...  dp[k + 1, c + Int(z)] max= ...
  ```
- **General fix:** a rolling layout annotation on a multi-dimensional array
  (layout follows the type; the interpreter checks that only rows k and k + 1
  are touched). Helps every layered DP in the corpus.
- **Severity:** medium.
- **Dream:** `proto/ports/ecnerwala/dream/cf2084g1.cp` lines 9-14

## Position parity needs `.label`
- **Where:** `even[v] = i.label % 2 == 0`
- **What felt wrong:** "the statement's position i is even" is the natural
  fact; with `domain P = 1..=n` the contestant must remember that `i % 2` is
  not defined on a domain element and that `.label` (not `.ord`) is the
  1-based number. Picking `.ord` silently flips every parity, a wrong answer
  that passes the type checker.
- **Goal it hurts:** hard-to-get-wrong.
- **Ideal code:** `even[v] = i.label.even` with `.ord` parity rejected, or a
  diagnostic when `.ord % 2` is used on a 1-based domain.
- **General fix:** a lint on `.ord % k` / `.ord & 1` for domains whose labels
  differ from their ordinals, suggesting `.label`.
- **Severity:** medium.
- **Dream:** `proto/ports/ecnerwala/dream/cf2084g1.cp` lines 7

## Inverse of a partial injection
- **Goal it hurts:** express-and-revise.
- **Ideal code:** `let at = a.inverse()` on `a: [P]?(1..=n)` giving
  `[1..=n]?P`, where each fixed value sits.
- **Today:** `inverse` takes only a bijection `[I]V`, so the port fills
  `even[v]` in a hand loop over `P`.
- **General fix:** `inverse` on `[I]?V` returns `[V]?I`, trapping on a
  repeated value; the bijection form stays as is. Same name, since the
  partial map's inverse is the same idea.
- **Severity:** medium.
- **Dream:** `proto/ports/ecnerwala/dream/cf2084g1.cp` line 22
