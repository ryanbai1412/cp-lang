# cf2035f — Tree Operations

The editorial: with `t` operations node `v` owns `⌊t / n⌋ + [v <= t mod n]`
of them, and `t` works iff the need folded up from the leaves (`a_v` plus the
children's need minus what `v` owns; a surplus only cancels in pairs, so a
negative need settles to its parity) is 0 at the root. If `t` works, so does
`t + 2n`, so each residue modulo `2n` binary-searches its number of full
rounds, and the answer is the least `t` found.

## A bottom-up fold must spell the identity lift
- **Where:** `cf2035f.cp`, lines 15–19:
  ```cp
  let need = t.up(
      +,
      (c, _, _) => c,
      (s, v) => settle(s + a[v] - ops / n - Int(v.label <= ops % n)),
  )
  ```
- **What felt wrong:** the children's values go up unchanged, yet `up`
  takes `lift` positionally, so every plain subtree sum writes
  `(c, _, _) => c`. The formatter then spreads the call over five lines.
- **Goal it hurts:** express.
- **Ideal code:** `t.up(+, finish: (s, v) => settle(...))`.
- **General fix (trees):** default `lift` to the child's value and accept
  `finish:` by name, as `Monoid` folds already default their identity.
- **Dream:** `dream/cf2035f.cp` line 15.
- **Severity:** low.
- **Area:** trees

## Binary search on a range is a free function
- **Where:** `cf2035f.cp`, lines 24–28: `bsearch_first(rounds, k => works(k * cycle + r))`.
- **What felt wrong:** every other search on a sequence is a method
  (`xs.first(p)`, `D.sort(by:)`), so `rounds.bsearch_first(...)` is the
  guess; decisions §53.1 puts one-sequence operations on the receiver.
- **Goal it hurts:** express (one spelling per idea).
- **Ideal code:** `rounds.bsearch_first(k => works(k * cycle + r))`.
- **General fix (seq):** make `bsearch_first`/`bsearch_last` methods of
  `Range`, as the rest of `seq` is.
- **Dream:** `dream/cf2035f.cp` line 19.
- **What also hurt:** the formatter splits the one-line `print` of the
  minimum over residues into five lines because the free call is longer.
- **Severity:** low.
- **Area:** seq

## Quotient and remainder, and Bool as a count
- **Where:** `cf2035f.cp`, line 18: `ops / n - Int(v.label <= ops % n)`.
- **What felt wrong:** the editorial's `⌊t / n⌋` and `t mod n` are one
  division (`ops.divmod(n)` would name both once, outside the per-node
  closure); and the count `[v <= t mod n]` needs `Int(...)` around a `Bool`.
  `v.label` is needed because a vertex cannot be compared with an `Int`.
- **Goal it hurts:** express.
- **Ideal code:** `let (round, rest) = ops.divmod(V.count)` and
  `round + (v <= rest).int`.
- **General fix (core):** `Bool.int`, and comparing a domain element with
  an `Int` in its label space.
- **Dream:** `dream/cf2035f.cp` lines 14 and 15.
- **Severity:** low.
- **Area:** core
