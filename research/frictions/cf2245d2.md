# cf2245d2 friction report

## Missing stdlib: predicate-driven graph peeling (`peel` with custom readiness and update)
- **Where:** `proto/ports/ecnerwala/dream/cf2245d2.cp` lines 25–28 (`proto/ports/ecnerwala/cf2245d2.cp` lines 26–39).
- **What felt wrong:** `std.graph.peel` only supports Kahn's in-degree-zero peeling. Problems that peel vertices under a custom monotone readiness predicate (e.g., all remaining incident edges have the same kind, or `k`-core peeling with `deg(v) < k`, or bipartite/2-color peeling) must hand-roll the `order` queue, `queued: [V]Bool` array, and `while z < order.len` loop.
- **Goal it hurts:** express.
- **Ideal code:**
  ```cp
  let order = g.peel(
      ready: v => cnt[v, Kind(1)] == 0 or cnt[v, Kind(2)] == 0,
      on_remove: (v, a) => cnt[a.to, raw[a.e].kind] -= 1,
  )
  ```
- **General fix:** Generalize `peel` (or add `peel_by(g, ready:, on_remove:)` in `std.graph`) so callers supply a readiness predicate on `V` and an edge-removal callback when a vertex is peeled, deduplicating the queue + `queued` boilerplate across k-core, game-state, and constraint-peeling problems.
- **Severity:** medium.
