## Sentinel `n + 1` ("unreachable") in DP state tables vs `?Pos` optionals
- **Where:** `research/frictions/cf2229h.ideal.cp` lines 40-59:
  ```cp
  fn step_0(pos: Int) -> (even: Int, odd: Int):
      if pos > n: return (even: n + 1, odd: n + 1)
      let e = min(nxt_0[pos, 0], nxt_q[pos])
      ...
  var dp: [0..=n + 1, 0..=n + 1]M = M(0)
  ```
- **What felt wrong:** Subsequence-automaton DP naturally indexes states by `(earliest_even: ?Pos, earliest_odd: ?Pos)`, where `none` means unreachable and `min` on `?Pos` treats `none` as $+\infty$. Because `?Pos` cannot be used directly as an array index in `[?Pos, ?Pos]M`, the DP falls back to raw `Int` with sentinel `n + 1` and loses domain bounds checking on `nxt_0`, `nxt_q`, and `suff_1`.
- **Goal it hurts:** hard-to-get-wrong, express
- **Ideal code:**
  ```cp
  domain Pos = 0..=n
  var dp: [?Pos, ?Pos]M = M(0)
  dp[Pos(0), none] = M(1)
  ```
- **General fix:** Allow `?D` (optional of a finite domain `D`) as an array/grid index space (with `none` occupying the extra slot `D.len`), and define `min`/`max` or a `min_some` combinator on `?D`. Eliminates sentinel `n + 1` / `-1` indexing across automaton and DP problems.
- **Severity:** high
