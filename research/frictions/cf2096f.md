# cf2096f friction

## A min tree has no "absent" identity, so empty slots need a sentinel

- **Goal it hurts:** hard to get wrong
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2096f.cp:23,30,36,44`
  (`SegTree<V, ?V.bounds>(min, fill: none)`,
  `shortest.fold(lo..hi).is_none_or(e => e > hi)`)
- **Actual:** `proto/ports/ecnerwala/cf2096f.cp:22,29,35,43` stores
  `Int` right ends with `n + 1` as "no interval here", and compares against
  `hi.ord` instead of the cut itself.
- **General fix:** a `min`/`max` monoid over `?T` whose identity is `none`
  (absent elements ignored), plus `?T.is_none_or(p)`. Every "best live
  element per slot, maybe none" tree drops its sentinel.

## Sliding-window positions are `Int`, not a domain

- **Goal it hurts:** hard to get wrong
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2096f.cp:19,35,43,49-57`
  (`domain S = 1..=m`, `push(at: i, ...)`, `drop(at: i)`, `l = l.next!`)
- **Actual:** `proto/ports/ecnerwala/cf2096f.cp:18,34,42,47-59` indexes the
  statements by `0..m` and shifts the 1-based query by one; `MonoDeque.push`
  takes `at: Int` and only offers `drop_before(i + 1)` to retire the oldest
  entry.
- **General fix:** make `MonoDeque<T>` generic over its position type (any
  ordered domain), with `drop(at:)` for retiring exactly one position, so a
  window over a domain keeps its index space.

## Bug found on the way: `SortedBag` of a tuple overflows in C++

- **Goal it hurts:** dependable submission
- **Severity:** high
- **Area:** codegen
- **Status:** open
- **Actual:** a first draft kept the live intervals in one
  `SortedBag<(V, V)>` with `domain V = 1..=n`, n = 200,000. The interpreter
  was right, the emitted C++ was wrong on a max case: the tuple is packed into
  one key and the generated `make_node` takes it as `int`, which overflows
  once `|V|^2 > 2^31`. A 3,000-step random `add`/`remove`/`first_where`
  check against a list agrees in the interpreter and disagrees 2,972 times in
  C++. The port avoids the bag (a `MonoDeque` per start is also the better
  structure), so nothing here depends on the fix.
- **General fix:** size the packed key from the product of the component
  widths (or keep a struct key) and add the interpreter-vs-C++ check above as
  a regression test.

## Measurement
