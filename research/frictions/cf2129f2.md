# cf2129f2 — F2. Permutation (Hard Version)

The editorial idea: assign each value `1..=890` a 29-bit mask (each bit used `<= 60` times): 18 unique triples plus two copies of all 436 subsets of size `<= 2`. 29 type-2 queries recover every position's mask, narrowing each to a unique value or a colliding pair `(v0, v1)` with `v0 <= 454 < v1`; one randomized type-3 probe on one position per colliding pair resolves all pairs.

- **Where:** `proto/ports/ecnerwala/cf2129f2.cp` lines 17-20, 49-55:
  ```cp
  if by_sig.contains(s):
      by_sig[s].push(p)
  else:
      by_sig[s] = [p]
  ```
- **What felt wrong:** Grouping values by mask and positions by signature repeats the same 4-line `contains` / `push` / init boilerplate twice.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  let mask_vals = (1..=890).group(by: v => masks[v - 1])
  ...
  for (s, ps) in Pos.group(by: p => sig[p]):
  ```
- **General fix:** Add `group(by:)` (sequences area lane) and `Map.entry(k).or_default()` (containers area lane).
- **Dream:** `dream/cf2129f2.cp` lines 19, 36.
- **Severity:** medium
- **Status:** resolved: `group(by:)` landed in `std/seq.cp`; the port groups with `Val.group(by:)` and `order.group(by:)`.

## A domain value has no plain number

- **Goal it hurts:** express
- **Severity:** low
- **Area:** types
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2129f2.cp:44, 50-55`
- **Actual:** `proto/ports/ecnerwala/cf2129f2.cp:27, 37, 52, 58, 61`
- **General fix:** a 1-based domain value should print and convert as its own number (`Val(3)` prints `3`), so the answer table can be `[Pos]Val` and masks a `[Val]` table built straight from a list. The port writes `vs[0].ord + 1`, rebuilds `masks` with `[Val] v => all_masks[v.ord]`, and loops over `1..=n` then calls `Val(v)`. The rewrite also moved the hand LCG to `std.rand.Rng`, which with the `Map` grouping grows the emitted C++ from 15,203 to 19,748 bytes (see the `Rng` entry above); rebaselined.

## `Bitset<Q>` cannot be used as a `Map` key in C++ (`cpl::CpHash` missing `cpl::Row` overload)
- **Where:** `proto/ports/ecnerwala/cf2129f2.cp` lines 22-49 (`dream/cf2129f2.cp` lines 24-47).
- **What felt wrong:** `Map<Bitset<Q>, List<Val>>` passes `cpl check`, then fails `g++` because `cpl::CpHash` has no overload for `cpl::Row<unsigned long long, 1>` inside `Bitset<Q>`, forcing the port to keep raw `1 << q` `Int` masks.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:** `Bitset<Q>` masks with `Map<Bitset<Q>, List<Val>>` and `Map<Bitset<Q>, List<Pos>>`.
- **General fix:** Add a `cpl::CpHash` specialization for `cpl::Row<T, N>` (codegen / containers area lane).
- **Area:** containers
- **Severity:** medium

## `Subset<Q>` traps for a domain of 29 values

- **Where:** `corpus/problems/cf2129f2/port.cp` lines 20-24 (`mask`, `sig`): masks stay raw `Int`s built by `1 << q.ord`.
- **What felt wrong:** `Subset<Q>` is the one-word set the masks are, but `domain Q = 0..29` / `print(Subset<Q>.single(Q(28)).len)` traps R0001 "a `Subset` needs a domain of at most 25 values" in `cpl run` and the built C++, though `std/subset.cp` documents up to 64 members. Lowering always sizes the `Q.subsets` domain (2^29), used or not. `Bitset<Q>` hits the `CpHash` entry above.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:** `type Mask = Subset<Q>`, `sig[p] = sig[p].with(q)`, `Val.group(by: v => masks[v])`.
- **General fix:** size and cap `B.subsets` only when the program uses it as a domain (compiler lane, `MAX_SUBSET_BITS` in `crates/cpl-ir`).
- **Area:** compiler
- **Severity:** medium
