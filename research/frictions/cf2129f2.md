# cf2129f2 — F2. Top-K Tracker (Hard Version)

## No `Map.entry(k).or_default()` / `push`-into-map-bucket idiom
- **Where:** `proto/ports/ecnerwala/cf2129f2.cp` lines 13-16 and lines 51-55:
  ```cp
  if by_sig.contains(s):
      by_sig[s].push(p)
  else:
      by_sig[s] = [p]
  ```
- **What felt wrong:** Grouping items into a `Map<K, List<V>>` appears twice in this 80-line solution (`mask_vals` and `by_sig`) and each time needs a 4-line `if m.contains(k): m[k].push(x) else: m[k] = [x]` boilerplate with two hash/tree lookups.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  by_sig.get_or(s, []).push(p)
  // or: let by_sig = group_by(Pos, by: p => sig[p])
  ```
- **General fix:** Add a mutating `entry` / `get_or_insert_mut` method on `Map<K, V>` (and/or a `group_by` helper in `std.seq`) so building bucketed maps is a single expression with one lookup.
- **Severity:** medium

## No lightweight PRNG in stdlib for randomized / anti-adversarial algorithms
- **Where:** `proto/ports/ecnerwala/cf2129f2.cp` lines 29-32:
  ```cp
  var rng = 50
  fn next_bit() -> Int:
      rng = (rng * 1_103_515_245 + 12_345) % 2_147_483_648
      (rng / 65536) % 2
  ```
- **What felt wrong:** F2 requires flipping each colliding pair randomly with probability 1/2 so the number of larger values in the type-3 probe is $\mathrm{Binomial}(436, 1/2) \le 300$ against adversarial permutations (like sorted or reversed). Because stdlib has no `Rng` / `splitmix64` / `xorshift` (and 64-bit signed shifts can trap on overflow), the contestant has to hand-roll a 31-bit LCG and verify by hand that `rng * 1_103_515_245 + 12_345` stays under $2^{63} - 1$.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  var rng = Rng(seed: 50)
  if rng.bool(): swap(mut p0, mut p1)
  ```
- **General fix:** Add a deterministic `Rng` type (e.g. `SplitMix64` / `Xoshiro256**`, seeded explicitly or from a constant) to `std.rand` with `.int(lo..hi)`, `.bool()`, and `.shuffle(mut xs)` so randomized contest algorithms don't hand-roll overflow-prone LCGs.
- **Severity:** medium

## No `@!once` / shared precomputation with `@!multitest`
- **Where:** `proto/ports/ecnerwala/cf2129f2.cp` lines 34-36:
  ```cp
  let t: 1..=40 = read()
  for _ in 0..t:
  ```
- **What felt wrong:** Same as `cf2129f1` and `cf2135e2`: because the 890-mask lookup table (`masks`, `mask_vals`) is shared across all `t <= 40` test cases, `@!multitest` cannot be used and the test loop must be written manually.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  @!interactive
  @!multitest
  // with `@!once` for the shared 890-mask table
  ```
- **General fix:** Allow `@!once` (or a shared pre-test block) alongside `@!multitest` so per-test code stays unindented without recomputing tables per test case.
- **Severity:** low
