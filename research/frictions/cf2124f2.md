# Friction: `cf2124f2`

## Pure `first_ge` per (cut, wrap length) costs 1.38x (was: 64-bit `Mod<P>`)
- **Where:** `port.cp` `next_bad` (called from the `x0` loop, n^2 times).
- **What felt wrong:** `Mod<998_244_353>` is now `uint32_t` in the emitted C++, so the width half is fixed. The rest: the pure query `bads[d].first_ge(from)` is a binary search per `(c, x0)`, O(n^2 log n), where orig.cpp pops each diagonal's stack as the sweep passes (amortized O(1)). The review asked for the pure query; the stack form reads worse.
- **Measured:** max input (n = m = 5000, random cells), best of 5: orig.cpp 0.30 s, port 0.42 s (1.38x); previous port 0.46 s. n = 5000, m = 0: 0.29 vs 0.33 s.
- **Goal it hurts:** performance
- **General fix:** a monotone cursor over a sorted list (`xs.cursor().first_ge(x)`, advance-only, amortized O(1)) so a pure-looking query sweeps.
- **Severity:** low

## `c.shift(lo..=hi)` is specified but not implemented
- **Where:** `port.cp` overcount line: `j.after.take(j - c - 1).clip(..=wrap_limit(j))`.
- **Repro:** `domain Cut = 0..=5; for j in Cut(1).shift(2..=4): print(j)` gives E0203 "a `Cut` has no method `shift` that `cpl run` knows" (same for `Pos.cuts`), though spec/core/04-indices.md (R04.3) defines `c.shift(r)`.
- **Ideal code:** `overcount.add(j.shift(1..j - c).clip(..=wrap_limit(j)), dp[c])`.
- **Goal it hurts:** express
- **General fix:** implement `shift` on every domain position and cut, as the spec says.
- **Severity:** low

## L0537 fires on bucketing points by diagonal
- **Where:** `port.cp` `var bads: [Diag]List<Cut> = []` filled from read `(pos, val)` cells.
- **What felt wrong:** "adjacency list built one read edge at a time" (L0537) suggests `Graph.directed(es)`, but the buckets are forbidden cells per diagonal, not edges. Kept as a warning.
- **General fix:** fire only when both pushed endpoints are read as one vertex domain (key and value of the same type).
- **Severity:** low

## Emitted C++ grew 16,184 -> 19,621 B
- **Where:** `std.prefix.SweepAdd<Cut, Z>` and the `after.take(k).clip(r)` ranges.
- **What grew:** the generic `SweepAdd` struct with its `FillOrder.Reverse` branch, `m4_clip` and a lambda per `take` (30% of 64 KB, under the 48 KB warn line).
- **General fix (codegen):** drop the reverse branch when `order` is a constant `Forward`, and lower `take(k)` on a range inline.
- **Severity:** low

## Resolved
- `std.prefix.SweepAdd<D, T>` exists; the port uses it in place of a local difference array.
- `List.pop_while` exists; the pure `next_bad` no longer needs it.
