# cf2165f — Arctic Acquisition

For each right end `r`, the latest left end `best[r]` of a 21435 pattern
ending by `r`; the answer is `sum(best + 1)` after a prefix max. Exchange
arguments let "5" be the next greater element after "3", "4" the latest
earlier element valued between them, and "1" the next smaller element after
"2", so a `next_greater` pass and a monotonic-stack pass produce O(n) candidate triples and pairs,
and two max segment trees over values (latest position per value) join them.
Same algorithm as the original, with `SegTree<V, ?I>(max)` in place of its
hand-rolled in-order layout.

## An open-at-the-start value range needs `(v + 1)!`
- **Where:** `cf2165f.cp`, line 16:
  `if let i = next[j], let k = latest.fold((a[j] + 1)!..a[i]):`.
- **What felt wrong:** "a value strictly between `a[j]` and `a[i]`" is the
  range `(a[j], a[i])`. Domains offer `..v`, `..=v` and `v..`, but no
  exclusive start, so the port steps the domain value (`?V`) and unwraps it,
  an assertion the reader has to justify (`a[j] < a[i]`, so `a[j] + 1`
  exists). The bounds view (`v.r`) would express it exactly but `fold` takes a
  `Range<V>`, not a pair of bounds.
- **Goal it hurts:** express; hard to get wrong (off-by-one at the start).
- **Ideal code:** `if let k = latest.fold(a[j] <.. a[i]):` or
  `latest.fold(a[j].r .. a[i].l)` with bounds.
- **General fix:** let range structures accept a `Bounds<V>..Bounds<V>`
  interval (`design/spec/21-index-spaces.md` already models cuts between
  positions), which makes every open or closed end one spelling and removes
  the `!` unwraps.
- **Dream:** `dream/cf2165f.cp` line 15.
- **Severity:** medium.
- **Area:** ranges

## `SegTree<V, ?I>(max)` is 1.4x to 1.65x slower than the hand-rolled tree
- **Where:** `cf2165f.cp`, lines 13 and 20: `SegTree<V, ?I>(max)`, and its
  folds and sets on lines 16, 17, 24 and 27.
- **What felt wrong:** with matched algorithms the port takes 0.89 s against
  the original's 0.54 s on `n = 10^6` (best of three, `g++ -O2`); 0.71 s
  against 0.52 s after main's later codegen changes, which still emit both
  patterns below. The port
  cannot close the gap: `cpl profile --native` puts 58% of the time in the
  four tree lines, and the emitted tree already inlines `max`. Two
  codegen choices cost the rest, measured by editing only the emitted C++:
  - `p / 2` and `p % 2` on tree indices emit `cpl::divp`/`cpl::modp`
    (floor division with a sign fix-up and a zero check) although the
    indices are provably non-negative; emitting `p >> 1` and `p & 1` alone
    gives 0.64 s.
  - `max` on `?I` emits `has_value()` branches, although `?I` is a niche
    whose `none` (-1) already sorts first, so the raw `std::max` on the
    stored ints is the same function; that alone gives 0.70 s.
  - Both together: 0.54 s, 1.0x the original, same output.
- **Goal it hurts:** performance (abstractions cost what direct C++ costs).
- **Ideal code:** unchanged.
- **General fix (codegen lane):** lower `/` and `%` by a positive constant
  power of two to shifts and masks when the range analysis proves the
  dividend non-negative (index arithmetic in every tree, heap and Fenwick in
  the stdlib benefits); and lower `min`/`max`/comparisons on a niche
  optional whose `none` sorts first to the raw comparison.
- **Dream:** `dream/cf2165f.cp` lines 12 and 19 (same declarations as today; the fix is in what they compile to).
- **Severity:** high.
- **Area:** core

## Only one of the two monotonic stacks has a stdlib form
- **Where:** `cf2165f.cp`, lines 22–28: the second pass's
  `while let j = stack.last, a[i] < a[j]: stack.pop(); two.set(a[j], j)`.
- **What felt wrong:** the first pass is `a.next_greater()` (line 14), and the
  editorial's "1 is the next smaller after 2" is `a.next_smaller()`, but the
  second pass needs it the other way round: at position `i`, every `j` whose
  next smaller is `i`. The stdlib returns `[D]?D` with no inverse, so the
  pass keeps a hand-written stack, which is exactly where `<` and `>`
  silently swap; building the inverse by hand
  (`for j in I: if let s = ns[j]: freed[s].push(j)`) is as long.
- **Goal it hurts:** express; hard to get wrong.
- **Ideal code:**
  ```cp
  let freed = a.next_smaller().inverse   // freed[s]: the positions whose next smaller is s
  for i in I:
      for (v, r) in shapes[i]: best[r] max= two.fold(..v)
      for j in freed[i]: two[a[j]] = j
  ```
- **General fix (seq lane):** an `inverse` (or `group_by_value`) view on a
  `[D]?E` map that lists, for each `e`, the `d` mapped to it, in order and
  with O(n) total cost; it serves every "pop when it arrives" shape.
- **Dream:** `dream/cf2165f.cp` lines 13 and 21–24.
- **Severity:** low.
- **Area:** seq

## A `SegTree` cannot be assigned by index
- **Where:** `cf2165f.cp`, lines 17 and 27: `latest.set(a[j], j)`,
  `two.set(a[j], j)`.
- **What felt wrong:** a point update of a segment tree is "the value at
  `a[i]` is now `i`", which every array spells `latest[a[i]] = i`;
  `latest[v] = i` is rejected with `E0305` "can't be indexed", so the tree
  needs a second verb for the same act, and turning an array into a tree
  (the usual revision) rewrites every write.
- **Goal it hurts:** express and revise (an array becomes a tree as a local
  edit); guessable APIs.
- **Ideal code:** `latest[a[i]] = i`, and `latest[v]` reading the leaf.
- **General fix:** an index-assignment protocol (`[]=`) any library type can
  implement, with `SegTree`, `Fenwick` (as `+=`) and `LazySegTree` (point
  set) using it; the cost note stays `O(log n)` per write.
- **Dream:** `dream/cf2165f.cp` lines 16 and 24.
- **Severity:** low.
- **Area:** ranges

## A filtered comprehension has no `.sum()` form
- **Where:** `cf2165f.cp`, line 30:
  `print([l.to_idx + 1 for l in scan(best, max) if let l = l].sum())`.
- **What felt wrong:** the natural `sum(l.to_idx + 1 for l in ... if let l = l)`
  sums a lazy comprehension, but the spelling-drift ratchet makes `xs.sum()`
  canonical and counts every free `sum(...)` against it; a parenthesised
  comprehension cannot take a method (`E0103`), and `scan(...)` returns a
  `[I]?I` with no `map`, `flatten` or `present` to chain into `.sum()`. The
  only canonical spelling builds a list of `10^6` values just to add them, and
  the `if let l = l` re-binding is noise for "skip the absent ones".
- **Goal it hurts:** coherence (one spelling per idea); costs are visible
  (an allocation the idea does not need).
- **Ideal code:** `print(scan(best, max).present.map(l => l.label).sum())`
  or, if the free form stays, `sum(l.label for l in scan(best, max).present)`,
  where `l.label` is the 1-based position the domain already knows, instead of
  the raw `l.to_idx + 1`.
- **General fix (seq lane):** sequence adapters (`map`, `present` for
  optionals) on every indexed value, including the result of `scan`, so the
  method chain is always available; or make the free `sum(comprehension)`
  canonical, since comprehensions have no method form.
- **Dream:** `dream/cf2165f.cp` line 26.
- **Severity:** low.
- **Area:** seq
