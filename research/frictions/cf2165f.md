# cf2165f — Arctic Acquisition

For each right end `r`, the latest left end `best[r]` of a 21435 pattern
ending by `r`; the answer is `sum(best + 1)` after a prefix max. Exchange
arguments let "5" be the next greater element after "3", "4" the latest
earlier element valued between them, and "1" the next smaller element after
"2", so two monotonic-stack passes produce O(n) candidate triples and pairs,
and two max segment trees over values (latest position per value) join them.
Same algorithm as the original, with `SegTree<V, ?I>(max)` in place of its
hand-rolled in-order layout.

## An open-at-the-start value range needs `(v + 1)!`
- **Where:** `cf2165f.cp`, line 18:
  `if let k = latest.fold((a[j] + 1)!..a[i]):`.
- **What felt wrong:** "a value strictly between `a[j]` and `a[i]`" is the
  range `(a[j], a[i])`. Domains offer `..v`, `..=v` and `v..`, but no
  exclusive start, so the port steps the domain value (`?V`) and unwraps it,
  an assertion the reader has to justify (`a[j] < a[i]`, so `a[j] + 1`
  exists). The bounds view (`v.r`) would express it exactly but `fold` takes a
  `Range<V>`, not a pair of bounds.
- **Goal it hurts:** express; hard to get wrong (off-by-one at the start).
- **Ideal code:** `if let k = latest.fold(a[j] <.. a[i]):` or
  `latest.fold(a[j].r .. a[i].l)` with bounds.
- **General fix:** let range structures accept a `Bounds<V>..Bounds<V>`
  interval (`design/spec/21-index-spaces.md` already models cuts between
  positions), which makes every open or closed end one spelling and removes
  the `!` unwraps.
- **Dream:** `dream/cf2165f.cp` line 12.
- **Severity:** medium.

## `SegTree` with a monoid is 1.6x slower than the hand-rolled tree
- **Where:** `cf2165f.cp`, lines 13 and 26: `SegTree<V, ?I>(max)`.
- **What felt wrong:** with matched algorithms the port takes 0.92 s
  against the original's 0.56 s on `n = 10^6`. The emitted C++ stores the
  monoid's operation as `std::function<OptPos(OptPos, OptPos)>`, so every
  combine in every fold and set is an indirect call that the compiler cannot
  inline; the original's `max` is inlined into a two-line loop. Writing the
  tree by hand, as the original does, would give the speed back and lose the
  one-line declaration.
- **Goal it hurts:** performance (abstractions cost what direct C++ costs).
- **Ideal code:** unchanged.
- **General fix:** monomorphize monoids known at compile time (bare
  operators, `Monoid(id, op)` with a lambda literal) into a functor type
  parameter of the emitted tree, keeping `std::function` only for monoids
  chosen at run time.
- **Dream:** `dream/cf2165f.cp` lines 9 and 16 (same declarations as today; the fix is in what they compile to).
- **Severity:** high.

## Resetting a reused stack is a whole-variable reassignment
- **Where:** `cf2165f.cp`, lines 12 and 25: `var stack: List<I> = []` and
  later `stack = []`.
- **What felt wrong:** the two passes are the same "previous greater /
  previous smaller" scan with a different comparison, each written as an
  explicit stack loop; the second reuses and resets the first's stack. The
  standard monotonic-stack shapes (next greater, next smaller, with the popped
  elements) are not in the stdlib, so both are hand-written and the pop loop
  is where the comparisons (`<` versus `>`) can silently swap.
- **Goal it hurts:** express; hard to get wrong.
- **Ideal code:**
  ```cp
  for (j, i) in pops(a, by: (top, x) => top < x):   // j is popped when i arrives
      if let k = latest.fold(a[j] <.. a[i]): shapes[k].push((a[j], i))
  ```
- **General fix:** a stdlib monotonic-stack iterator that yields each
  `(popped, arriving)` pair in order, with the comparison as a named option,
  covering next/previous greater/smaller in one facility.
- **Dream:** `dream/cf2165f.cp` lines 11 and 19.
- **Severity:** low.
