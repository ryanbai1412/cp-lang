# Friction: `cf2245f`

## [Resolved] 64-bit `Mod<P>` storage and inner-loop modular division cause 8.6x slowdown in $O(n^3)$ loop

- **Severity:** high
- **Status:** closed
- **Goal it hurts:** performance
- **Measured:** `1782.29 ms` vs `206.16 ms` (`8.65x`) on `gen size=1000` initially; `749.48 ms` vs `102.20 ms` (`7.33x`) after 32-bit `Mod<P>` narrowing (`84ef265b`); `124.14 ms` vs `98.46 ms` (`1.26x`, RSS `4736 KB` vs `5248 KB` = `0.90x`) after switching `/ (right_idx[k] - i)` to `* comb.inv(right_idx[k] - i)`.
- **Resolution:** `84ef265b` narrowed `Mod<P>(v: 0..P)` to `uint32_t` storage when $P < 2^{31}$, and `cf2245f.cp` now multiplies by `comb.inv(right_idx[k] - i)` (matching `cf2245f_orig.cpp`'s precomputed `invs[]`) instead of running $O(\log P)$ modular inverse per inner-loop iteration. Remaining `1.26x` overhead is checked 2D DP indexing and `comb.inv`'s `ensure` check.
