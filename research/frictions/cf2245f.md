# Friction: `cf2245f`

## 64-bit `Mod<P>` storage and checked 2D DP indexing cause 8.6x slowdown in $O(n^3)$ loop

- **Severity:** high
- **Goal it hurts:** performance
- **Measured:** `1782.29 ms` vs `206.16 ms` (`8.65x`) on `gen size=1000` (`research/scoreboard.json`).
- **Cause (layout + codegen):** `Mod<998_244_353>` stores `int64_t` (8 B instead of `uint32_t` 4 B, doubling `dp` cache footprint) and uses 64-bit signed `cpl::modp` division; the innermost $O(n^3)$ loop also runs bounds checks on `dp.ck(i, k)` and `cpl::at(nxt_right, k)`.
- **Fix:** narrow `Mod<P>` to `uint32_t` when $P < 2^{31}$ with branchless add/sub, and hoist/elide range-proven bounds checks in nested DP loops.
