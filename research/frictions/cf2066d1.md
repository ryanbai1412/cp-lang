# cf2066d1 — D1. Club of Young Aircraft Builders (easy version)

The editorial idea: process floors $1, \dots, n - 1$ from bottom to top. Because floor $i$ stops after seeing $c$ launches from floors $\ge i$, it chooses $k \in \{0, \dots, c\}$ of its first $c$ unseen slots in $\binom{c}{k}$ ways, and floor $n$ takes the remaining $c$ slots. The generating function is $(1 + x)^{c(n-1)}$, so the answer is the single binomial coefficient $\binom{c(n-1)}{m-c}$.

## `@!multitest` cannot sit below a shared precomputed table (`Comb`)
- **Where:** `proto/ports/ecnerwala/cf2066d1.cp` lines 6-9:
  ```cp
  let comb = Comb<1_000_000_007>(10_000)

  let t: 1..=10_000 = read()
  for _ in 0..t:
  ```
- **What felt wrong:** Because `@!multitest` wraps the whole file, precomputing `comb` once across $t \le 10^4$ tests forces dropping `@!multitest` and writing the `t` loop by hand.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  let comb = Comb<M>(1e4)

  --- multitest ---
  ```
- **General fix:** Support the `--- multitest ---` divider (bindings above it run once; everything below runs per test case).
- **Dream:** `dream/cf2066d1.cp` lines 7-9.
- **Severity:** medium

## No `skip<T>()` to consume and validate an unused input line without an unused-variable hack
- **Where:** `proto/ports/ecnerwala/cf2066d1.cp` lines 11-12:
  ```cp
  let a: [0..m]Int = read()
  assert(a.len == m)
  ```
- **What felt wrong:** In D1, the input still includes a line of $m$ zeros that must be consumed from stdin. Binding `let a: [0..m]Int = read()` triggers an unused-binding lint unless followed by a dummy `assert(a.len == m)` (or `let _ =`), whereas `skip<[m]0..=0>()` states the intent cleanly without allocating or silencing a warning.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  skip<[m]0..=0>()
  ```
- **General fix:** Add `skip<T>()` (or allow `read::<[0..m]0..=0>()` as a statement without unused-value warning) to consume and range-validate ignored input.
- **Dream:** `dream/cf2066d1.cp` line 11.
- **Severity:** low

## Tuple read types cannot reference earlier tuple elements (`c..=n * c`)
- **Where:** `proto/ports/ecnerwala/cf2066d1.cp` line 10:
  ```cp
  let (n, c, m): (1..=100, 1..=100, 1..=10_000) = read()
  ```
- **What felt wrong:** The statement guarantees $c \le m \le n \cdot c$, which also proves $0 \le m - c \le c(n - 1)$ at the type level, but tuple element types cannot refer to earlier bindings in the same destructuring pattern.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  let (n, c, m): (1..=100, 1..=100, c..=n * c) = read()
  ```
- **General fix:** Allow later component types in a destructuring `let (n, c, m): (...) = read()` to reference earlier bound names, as in `design/EXEMPLARS.md` rule 9.
- **Dream:** `dream/cf2066d1.cp` line 10.
- **Severity:** low
