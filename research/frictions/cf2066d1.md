# cf2066d1 — D1. Club of Young Aircraft Builders (easy version)

The editorial idea: process floors $1, \dots, n - 1$ from bottom to top. Because floor $i$ stops after seeing $c$ launches from floors $\ge i$, it chooses $k \in \{0, \dots, c\}$ of its first $c$ unseen slots in $\binom{c}{k}$ ways, and floor $n$ takes the remaining $c$ slots. The generating function is $(1 + x)^{c(n-1)}$, so the answer is the single binomial coefficient $\binom{c(n-1)}{m-c}$.

## Tuple read types cannot reference earlier tuple elements (`c..=n * c`)
- **Where:** `proto/ports/ecnerwala/cf2066d1.cp` lines 10–12 (`dream/cf2066d1.cp` line 10):
  ```cp
  let n: 1..=100 = read()
  let c: 1..=100 = read()
  let m: c..=n * c = read()
  ```
- **What felt wrong:** The statement guarantees $c \le m \le n \cdot c$, which also proves $0 \le m - c \le c(n - 1)$ at the type level, but tuple element types cannot refer to earlier bindings in the same destructuring pattern, forcing three separate `let` statements instead of one tuple read.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2066d1.cp` line 10):**
  ```cp
  let (n, c, m): (1..=100, 1..=100, c..=n * c) = read()
  ```
- **General fix:** Allow later component types in a destructuring `let (n, c, m): (...) = read()` to reference earlier bound names, as in `design/EXEMPLARS.md` rule 9.
- **Severity:** low
