# cf2053f — Earnest Matrix Complement

The editorial: some optimum gives every blank of a row the same value. Credit
every pair of adjacent blank rows (`b_i · b_{i+1}`) up front; a DP over the
value `v` of the current row's blanks then pays it back only when the value
changes. A row's blanks gain `c · b_i` from every value `v` seen `c` times
in a neighbouring row; values seen in no neighbour do not move, so `stay`
only rises and the best over all values is a running max (the original keeps
a `std::set` for it).

## No `?V` read with a sentinel, so -1 stays an `Int`
- **Where:** `cf2053f.cp`, lines 9, 11 and 15: `let a: [R][0..m]Int`,
  `a[i].count(x => x == -1)`, `if x != -1: ... V(x)`.
- **What felt wrong:** the statement says a cell is a value in `1..=k` or
  `-1` for blank. That is `?V`, but there is no `read(none: -1)`, so the
  matrix is read as plain `Int`, the sentinel `-1` is compared by hand at
  two sites, and each value is converted with `V(x)` after the check. A typo
  in either comparison silently counts blanks as a value.
- **Goal it hurts:** hard to get wrong (sentinels), express (constraints as
  types).
- **Ideal code:** `let a: [R][m]?V = read(none: -1)`, `a[i].count(none)`.
- **General fix (core/io):** a `none:` sentinel argument on `read` for
  optional element types, as already filed for cf2066d2 (`read(none: 0)`).
- **Dream:** `dream/cf2053f.cp` lines 8 and 9.
- **Severity:** medium.
- **Area:** core

## Counting a row needs a hand-written tally into a map
- **Where:** `cf2053f.cp`, lines 12–15:
  ```cp
  var cnt: [R]HashMap<V, Int> = []
  for i in R:
      for x in a[i]:
          if x != -1: cnt[i][V(x)] = (cnt[i].get(V(x)) ?? 0) + 1
  ```
- **What felt wrong:** "the multiset of values in row i" is one idea and a
  four-line loop with the map default spelled at the update. There is no
  `tally`/`counts`; `sorted().runs()` gives `(val, len)` pairs but not a
  lookup, and line 28 needs lookups.
- **Goal it hurts:** express (named standard operations).
- **Ideal code:** `let cnt = [R] i => a[i].present.tally()`.
- **General fix (containers):** `xs.tally()` returning a map with default
  0 (pairs with the map-default friction filed for cf2066c), so reads are
  `cnt[i][v]`. Not added.
- **Dream:** `dream/cf2053f.cp` line 10.
- **Severity:** medium.
- **Area:** containers

## Map dot product spells the default again
- **Where:** `cf2053f.cp`, line 28: `sum(c * (cnt[next].get(v) ?? 0) for (v, c) in cnt[i])`.
- **What felt wrong:** `Σ_v c_i[v] · c_{i+1}[v]` is a dot product of two
  sparse count vectors; without a map default the `.get(v) ?? 0` comes back.
- **Goal it hurts:** express.
- **Ideal code:** `cnt[i].dot(cnt[j])`, or `sum(c * cnt[j][v] for (v, c) in cnt[i])`
  once maps have a declared default.
- **General fix (containers):** the map default from cf2066c; `dot` would
  then be a one-line user function.
- **Dream:** `dream/cf2053f.cp` line 12.
- **Severity:** low.
- **Area:** containers

## Neighbours in a domain go through raw indices
- **Where:** `cf2053f.cp`, lines 21–23 and 26–27:
  ```cp
  for j in [i.to_idx - 1, i.to_idx + 1]:
      if j in R:
          for (v, c) in cnt[R(j)]:
  if i.to_idx + 1 in R:
      let next = R(i.to_idx + 1)
  ```
- **What felt wrong:** "the row above and the row below, when they exist"
  drops out of the domain into `Int` (`to_idx`), tests membership, and
  converts back with `R(j)`; the same dance is spelled twice for "the next
  row". Every conversion is a place to use the wrong index space.
- **Goal it hurts:** hard to get wrong (index spaces), express.
- **Ideal code:** `for j in R.neighbours(i)` and `if let j = R.next(i)`.
- **General fix (core/domains):** `D.next(i)`, `D.prev(i) -> ?D` and a
  neighbour view on 1-D domains, so stepping stays in the index space. Not
  added; a proposal.
- **Dream:** `dream/cf2053f.cp` lines 12, 16 and 19.
- **Severity:** medium.
- **Area:** core
