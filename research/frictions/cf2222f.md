# cf2222f — F. Building Tree

## Rollback `Dsu` cannot roll back companion per-component payloads, and marks are raw `Int`
- **Where:** `proto/ports/ecnerwala/cf2222f.cp` lines 21, 34-41, 47-56:
  ```cp
  var rep_hist = List<V>()
  ...
  fn undo_to(snap: Int, hist_snap: Int):
      conn.undo_to(snap)
      while rep_hist.len > hist_snap:
          rep[rep_hist.pop()!] = none
  ...
  let (snap1, h1) = (conn.mark(), rep_hist.len)
  add_range(mid + 1, hi, lo)
  solve(lo, mid)
  undo_to(snap1, h1)
  ```
- **What felt wrong:** `Dsu` provides `mark()` / `undo_to()`, which is great for rollback connectivity, but maintaining a per-component payload (`rep: [V]?V`) forces a manual parallel undo stack (`rep_hist`), two separate raw `Int` snapshots (`snap1`, `h1`) that are trivially swappable without a type error, and a custom `undo_to` wrapper. Worse, any early `return` between `mark()` and `undo_to()` leaks state into sibling branches of the D&C tree.
- **Goal it hurts:** hard-to-get-wrong, express
- **Ideal code:**
  ```cp
  var conn = Dsu<V, ?V>(init: rep, on_merge: (a, b) => ...)
  ...
  with conn.checkpoint():
      add_range(mid + 1, hi, lo)
      solve(lo, mid)
  ```
- **General fix:** (1) Return a nominal `DsuMark` handle from `Dsu.mark()` instead of raw `Int`; (2) support a payload-carrying `Dsu<V, T>` (or composable rollback log) that snapshots and restores component payloads alongside `up`/`sz`; (3) add a scoped rollback helper or `defer` so early returns cannot skip `undo_to`. Helps every offline dynamic connectivity, bipartite rollback DSU, and D&C-on-time problem.
- **Severity:** high

## Runtime-bounded integer fields in `read()` force either duplicating the max constant or losing arithmetic
- **Where:** `proto/ports/ecnerwala/cf2222f.cp` lines 4, 14-17:
  ```cp
  let edges: [0..m](u: V, v: V, w: 0..=300_000) = read()
  ...
  var by_w: [0..=m]List<(u: V, v: V)> = []
  for e in edges:
      if e.u != e.v:
          by_w[e.w].push((u: e.u, v: e.v))
  ```
- **What felt wrong:** The statement guarantees `0 <= w <= m`, and `m` is already in scope from line 2, yet the read type must repeat the static upper bound `300_000` (so `by_w[e.w]` still needs a runtime bounds check against `m`), unless we wrap `w` in a nominal `domain W = 0..=m` which then loses `Int` arithmetic (`(lo + hi) / 2`, `ans += cost`) and forces conversions at every D&C step.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  let edges: [0..m](u: V, v: V, w: 0..=m) = read()
  ```
- **General fix:** Allow runtime-bounded structural ranges (`0..=m`) in `read()` record/tuple field types (matching `read(0..=m)`), carrying the range fact `0 <= e.w <= m` into the prover so indexing `[0..=m]` is statically proven in-bounds without wrapping `w` in a nominal domain.
- **Severity:** medium
