# Friction report: cf2124d

Dream and port rewritten around the editorial argument: every value below the
(k - 1)-th smallest stays and must be a palindrome, and copies of the
threshold pair up across mirrored gaps. The port differs from the dream in the
two places below.

## No `split(by:)` to cut a sequence at matching elements

- **Severity:** medium
- **Status:** open
- **Goal it hurts:** express
- **Area:** sequences (`plan/STDLIB.md`)
- **Dream lines:** `proto/ports/ecnerwala/dream/cf2124d.cp:24`
- **What happened:** the gaps between the small values are the pieces of `a`
  cut at every `v < thresh`. With no `split`, the port counts them with a
  running `before` index into a `List.filled` buffer, a loop the reader has to
  decode back into "pieces between separators".
- **General fix:** `seq.split(by: pred) -> List<ListView<T>>` (separators
  dropped, `count(pred) + 1` pieces, empty pieces kept), the sequence analogue
  of `Str.split`. `runs(by:)` does not cover it: adjacent separators merge into
  one run and lose the empty gaps between them.

## A two-parameter lambda passed to `.map` over a tuple list fails to compile

- **Severity:** medium
- **Status:** open
- **Goal it hurts:** express, dependable submission
- **Area:** codegen
- **Dream lines:** `proto/ports/ecnerwala/dream/cf2124d.cp:25`
- **What happened:** `zip(gaps, gaps.rev).map((x, y) => min(x, y))` passes
  `cpl check`, but the emitted C++ calls the two-argument lambda with one
  tuple argument, so `g++` rejects it. The port falls back to a comprehension,
  `[min(x, y) for (x, y) in zip(gaps, gaps.rev)].sum()`.
- **General fix:** a lambda with a tuple-pattern parameter list applied to a
  tuple element destructures it (`std::apply` or unpacking in the emitted
  lambda), the same rule `for (x, y) in` already follows. The checker and
  codegen should agree; today only the checker accepts it.

## Measurements

- Emitted C++ grew from 7,068 to 11,638 B: the reversed `ListView` and `zip`
  runtime (`list_rev`, `to_list`, `append_list_view`), the bounded reads and
  the derivation header. Still a quarter of the 48 KB warning.
