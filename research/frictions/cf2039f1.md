# cf2039f1 — Shohag Loves Counting (Easy Version)

The editorial: an array is good iff its values are distinct and, sorted,
have strictly growing suffix gcds; each such set has `2^(n−1)` good orders.
The port adds values from `m` down to 1: an open set (all values above `y`)
with gcd `g` takes `y` iff `gcd(y, g) < g`, doubling its weight. By Möbius
the weight landing on `h | y` is `Σ_{d | y/h} μ(d)·above[h·d]`, where
`above[x]` sums the open sets whose gcd `x` divides, less the sets already
at `h`. The sum of `m` is at most `10^5`, so each test sieves to its own `m`;
the original precomputes every `m <= 10^6` with a two-level harmonic DP.

## No divisor table
- **Where:** `cf2039f1.cp`, lines 10–12:
  ```cp
  var divs: [m + 1]List<Int> = []
  for d in 1..=m:
      for x in (d..=m).step(d): divs[x].push(d)
  ```
- **What felt wrong:** every divisor-lattice DP starts with this harmonic
  sieve. `Sieve` has `mobius_table`, `phi_table` and `div_count_table` but
  not the divisors themselves, and the free `divisors(x)` is O(√x) per call,
  so the obvious `divisors(y)` in the loop is the slow way (about
  `Σ_y d(y)·√y` here).
- **Goal it hurts:** express; performance (the obvious way is the fast way).
- **Ideal code:** `y.divisors` over a divisor domain, or `numbers.divisors(y)`.
- **General fix (math):** `Sieve.divisors(x)` from a precomputed table
  (O(m log m) once, O(d(x)) per call), documented next to `divisors(x)`.
- **Dream:** `dream/cf2039f1.cp` lines 8, 12, 15.
- **Severity:** medium.
- **Area:** math

## The divisor lattice has no index space
- **Where:** `cf2039f1.cp`, lines 10, 14–15, 17: `[m + 1]Z` arrays indexed
  by `Int`, `above[h * d]`, `divs[y / h]`.
- **What felt wrong:** the values are `1..=m`, but a domain `G = 1..=m`
  does not allow `h * d` or `y / h`, so the port falls back to `Int`
  indices and arrays of size `m + 1` with slot 0 unused, giving up the
  index checks a domain would give.
- **Goal it hurts:** hard to get wrong (wrong index space); express.
- **Ideal code:** `domain G = read(1..=1e5).divisors` with `h * d` and
  `y / h` defined when the result stays in `G`.
- **General fix (core/math):** a domain over `1..=m` with checked
  multiplication and exact division, or `D(x)` conversions short enough to
  write inline. Proposal only.
- **Dream:** `dream/cf2039f1.cp` lines 8, 10.
- **Severity:** medium.
- **Area:** core

## Scatter-add to every divisor is a loop
- **Where:** `cf2039f1.cp`, line 20: `for d in divs[h]: above[d] += w`.
- **What felt wrong:** "add `w` at every divisor of `h`" is one statement in
  the editorial. `a[r] += w` works for a range `r`, but an index list is
  rejected (`E0301: a is indexed by 6, but is is a List<Int>`), so the
  same operation has a statement form for contiguous indices only.
- **Goal it hurts:** express (one spelling per idea).
- **Ideal code:** `above[h.divisors] += w`.
- **General fix (core):** let compound assignment through an index take
  any sequence of indices, as it already takes a range. Proposed, not added.
- **Dream:** `dream/cf2039f1.cp` line 15.
- **Severity:** low.
- **Area:** core
