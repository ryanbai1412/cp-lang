# cf2135e2 — E2. Beyond the Palindrome (Hard Version)

## `Mod<P>` and `Comb<P>` use 2.1x memory and 2.3x runtime on $n = 2 \cdot 10^7$
- **Where:** `proto/ports/ecnerwala/cf2135e2.cp` line 9 (`let comb = Comb<998_244_353>(lim)`) and `stdlib/mod.cp` lines 15, 85-98.
- **What felt wrong:** On the max input ($n = 2 \cdot 10^7$, memory limit 1024 MB), the port uses **1,022 MB RSS** (dangerously close to MLE!) and **0.92 s** vs **477 MB** and **0.40 s** for the C++ original. Three concrete causes:
  1. `Mod<P>` stores `v: Int` (64-bit) even when `P = 998_244_353 < 2^31`, doubling the size of every `Mod<P>` array (`fact`, `inv_fact`, `cnt`).
  2. `Comb<P>(limit)` rounds `cap` up to the next power of 2 (`33,554,432` for `20,000,001`) AND allocates a full temporary `tail` list of size `cap - old` before pushing into `g`, briefly holding ~800 MB for factorials alone.
  3. `pfac` has no `I32` type, so `var pfac: [0..=lim]Int = 0` uses 8 bytes per entry (160 MB) instead of 4 bytes (80 MB).
- **Goal it hurts:** performance, dependable-submission
- **Ideal code:**
  ```cp
  let comb = Comb<998_244_353>(lim)
  ```
  (with `Mod<P>` automatically packed to `int32_t` when `P <= 2^31 - 1`, and `Comb<P>(limit)` sizing directly to `limit + 1` in-place without a temporary `tail` buffer).
- **General fix:** (1) Pack `Mod<P>` into `int32_t` whenever `P <= 2_147_483_647` (cutting memory and cache misses in half for all standard moduli `998_244_353` and `1_000_000_007`); (2) in `Comb.new(limit)`, pre-allocate `f` and `g` to exact size `limit + 1` and fill `g` in place without allocating a temporary `tail` list; (3) expose `I32` (or pack bounded ranges `[0..=lim](0..=20_000_001)`) cleanly for large sieve tables.
- **Severity:** high

## `@!multitest` has no way to share precomputed tables across test cases
- **Where:** `proto/ports/ecnerwala/cf2135e2.cp` lines 3-7, 36:
  ```cp
  let t: 1..=10_000 = read()
  let ns: [0..t](1..=20_000_000) = read()
  var lim = 1
  for n in ns: lim max= n + 1
  ```
- **What felt wrong:** Because `@!multitest` wraps the entire file inside the per-test loop, any problem that precomputes a sieve or factorial table once across all test cases must drop `@!multitest`, read `t` and all test inputs up front, and loop manually.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  // Shared precomputation block or lazy `@!once` table alongside `@!multitest`.
  ```
- **General fix:** Support a shared pre-test section (or `@!once` top-level bindings) with `@!multitest` so per-test code stays clean without re-running $O(V)$ precomputation per test case.
- **Severity:** medium

## No multiplicative-function sieve hook in `std.math.Sieve`
- **Where:** `proto/ports/ecnerwala/cf2135e2.cp` lines 13-34:
  ```cp
  fn extend(i: Int, p: Int): ...
  for i in 2..=lim: ...
  ```
- **What felt wrong:** `std.math.Sieve` only computes `spf` and `primes`, so computing a custom multiplicative function (`odd_div_sum(x) = 2^{v_2(x)} * sigma_1(x / 2^{v_2(x)})`) in linear time requires re-implementing the entire linear sieve from scratch (22 lines) instead of supplying the prime-power recurrence.
- **Goal it hurts:** express, accumulate
- **Ideal code:**
  ```cp
  let odd_div_sum = sieve_multiplicative(lim, on_prime_pow: (p, k, prev) => ...)
  ```
- **General fix:** Add a linear multiplicative-function sieve helper to `std.math` (taking the prime-power recurrence) alongside `Sieve`. Helps every Mobius/totient/divisor-sum problem.
- **Severity:** medium
