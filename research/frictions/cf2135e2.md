# cf2135e2 — E2. Beyond the Palindrome (Hard Version)

The editorial idea: count length-`n` arrays in `{-1, 0, 1}` whose adjacent-sum graph has an even spanning-tree weight via inclusion-exclusion on the multiplicative odd-divisor sum `odd_div_sum(x) = 2^{v_2(x)} * sigma_1(x / 2^{v_2(x)})`, precomputing `Comb` and the linear sieve once up to `max(ns) + 1`.

## `Mod<P>` and `Comb<P>` use 64-bit storage and `pfac` lacks `I32`, causing 2.1x RSS and 2.3x runtime (owned by math / codegen area lane)
- **Where:** `proto/ports/ecnerwala/cf2135e2.cp` lines 6, 11, 15-16, 40:
  ```cp
  type M = Mod<P>
  let comb = Comb<P>(lim)
  var pfac: [0..=lim]Int = 0
  var odd_div_sum: [0..=lim]Int = 0
  ```
- **What felt wrong:** `Mod<P>` stores 64-bit `Int` even when `P < 2^31`, `Comb<P>(lim)` rounds capacity up to a power of 2, and `I32` is not available for compact sieve arrays (`lim = 2e7`). On max input (`n = 2e7`), this causes 2.1x RSS (1,022 MB vs 477 MB, near 1024 MB MLE) and 2.3x runtime (0.92 s vs 0.40 s).
- **Goal it hurts:** performance, dependable-submission
- **Ideal code:**
  ```cp
  let comb = Comb<M>(lim)
  let odd_div_sum = Sieve(lim).multiplicative<I32>(...)
  ```
- **General fix:** Store `Mod<P>` in `uint32_t` when `P < 2^31` (math / codegen area lane), avoid power-of-2 over-allocation in `Comb`, and expose `I32` for large sieve tables.
- **Dream:** `dream/cf2135e2.cp` lines 10, 13.
- **Severity:** high

## [Resolved] No multiplicative-function sieve hook in `std.math.Sieve` (owned by math area lane)
- **Resolution:** Added `std.math.sieve_multiplicative<T>(n, prime_pow)` and rewrote `proto/ports/ecnerwala/cf2135e2.cp` onto it (302 tokens vs 285 dream = 1.06x; 1.56–1.62 s on `n = 20_000_000` vs 1.66 s hand-written).
- **Status:** closed
- **Where:** `proto/ports/ecnerwala/cf2135e2.cp` lines 14-37:
  ```cp
  var primes = List<Int>()
  var pfac: [0..=lim]Int = 0
  var odd_div_sum: [0..=lim]Int = 0
  ...
  fn extend(i: Int, p: Int): ...
  ```
- **What felt wrong:** Computing any multiplicative function on `1..=lim` requires hand-rolling a 24-line linear sieve.
- **Goal it hurts:** express, accumulate
- **Ideal code:**
  ```cp
  let odd_div_sum = Sieve(lim).multiplicative<I32>(
      at_prime_pow: (p, e, prev) => if p == 2: prev * 2 else: prev * p + 1,
  )
  ```
- **General fix:** Add a `Sieve.multiplicative` helper to `stdlib/math.cp` (math area lane).
- **Dream:** `dream/cf2135e2.cp` lines 13-15.
- **Severity:** medium

## `2 ** n` on an `Int` literal overflows instead of picking up the `Mod` type

- **Goal it hurts:** hard to get wrong
- **Severity:** medium
- **Area:** check
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2135e2.cp:44` (now `M(2) ** n - bad`)
- **Actual:** the dream as scored wrote `print(2 ** n - bad)` with `bad: M`.
  It type-checks: `2 ** n` is evaluated as `Int` (overflowing for n >= 63,
  caught only by the sanitizer) and then converted. Porting the dream
  verbatim failed the gate on the sample; `M(2) ** n` fixes it.
- **General fix:** in `Int ** Int` mixed with a `Mod` operand, either infer
  the literal base as `Mod` (as `2 * x` already does) or reject the mix with
  a fix-it, so the natural spelling is the correct one.
