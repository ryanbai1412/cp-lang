## `manacher` only accepts `List<T>`, not `Str` or `[Pos]Char`, and `is_palindrome` takes raw `Int`s
- **Status:** closed (`manacher<S: Indexed>(s: S)` accepts `Str`, `StrView`, `[Pos]Char`, `List<T>`, and `ListView<T>` directly; `Palindromes.is_palindrome<R>(self, r: R)` accepts `Range<Int>` and `Range<D>` so `cf1943b` writes `pal.is_palindrome(l..=r)` matching its dream).
- **Area:** `strings` (`plan/STDLIB.md` 4.13)
- **Where:** `proto/ports/ecnerwala/cf1943b.cp` lines 14, 30 vs `dream/cf1943b.cp` lines 12, 26:
  ```cp
  let pal = manacher([c for c in s_str])
  ...
  if pal.is_palindrome(l.ord, r.ord + 1): total - m else: total
  ```
- **What felt wrong:** `std.strings.manacher<T>(s: List<T>)` rejects both `Str` and domain-indexed `[Pos]Char`, forcing an O(n) copy `[c for c in s_str]`. And `Palindromes.is_palindrome(l: Int, r: Int)` takes half-open raw 0-based `Int`s instead of a `Range<Pos>` (`l..=r`), forcing `.ord` and `+ 1` at every query.
- **Goal it hurts:** express, hard-to-get-wrong, coherence.
- **Ideal code (`dream/cf1943b.cp:12,26`):**
  ```cp
  let pal = manacher(s)
  ...
  if pal.is_palindrome(l..=r): total - m else: total
  ```
- **General fix:** Accept `Str` and `[D]T` (preserving domain `D` in `Palindromes<D>`) in `std.strings.manacher`, and accept a `Range<D>` in `Palindromes.is_palindrome(r)`.
- **Severity:** medium.

- **What felt wrong:** Reading a word of length `n` into a domain-indexed character array `[Pos]Char` requires reading a `Str` first and copying it element by element.

- **Severity:** low.

## No optional chaining (`i.prev?.prev`) or `(l..=r).len` on domain ranges
- **Area:** core
- **Where:** `proto/ports/ecnerwala/cf1943b.cp` lines 16–19, 22 vs `dream/cf1943b.cp` lines 14–15, 18:
  ```cp
  for i in Pos:
      if let p1 = i.prev:
          if let p2 = p1.prev:
              if s[i] == s[p2]: alt_run[i] = alt_run[p2] + 1
  ...
  let m = r.ord - l.ord + 1
  ```
- **What felt wrong:** Stepping back two positions requires two nested `if let` blocks instead of `for i in Pos where let prev2 = i.prev?.prev:`, and computing the length of an inclusive domain range requires `r.ord - l.ord + 1` instead of `(l..=r).len`.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code (`dream/cf1943b.cp:14-15,18`):**
  ```cp
  for i in Pos where let prev2 = i.prev?.prev:
      if s[i] == s[prev2]: alt_run[i] = alt_run[prev2] + 1
  ...
  let m = (l..=r).len
  ```
- **General fix:** Support optional chaining `?.` and `where let` filters in `for` loops, and add `.len` on `Range<D>`.
- **Severity:** low.
