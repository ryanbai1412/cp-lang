## Algorithm

Build a spanning tree `T` via `Dsu<V>`, root it with `Rooted(tree, V.first)`, and find its diameter `(len, u, v) = T.diameter()`. Operation 1 (`k = 3`) adds all missing edges between pairs of tree neighbors of each vertex, turning `G` into a superset of `T^2`. Operation 2 (`k = ceil(diam / 2) + 1`) connects every remaining non-adjacent pair `(i, j)` using a simple path of length `path_len = ceil(diam / 2)` in `T^2`: either skipping vertices along `T.path(i, j)` if `dist(i, j) >= path_len`, or detouring toward the further diameter endpoint (`d.u` or `d.v`) and zigzagging out and back along the shared suffix.

## Frictions

### 1. No domain half-range / unordered-pair iteration
- **Where:** `cf2150f.cp`, lines 34–35 and 40 (`dream/cf2150f.cp`, lines 36 and 40):
  ```cp
  for i in V:
      for j in V if j > i and not adj[i, j]: num_ops += 1
  ```
- **What felt wrong:** Iterating unordered pairs `i < j` over `domain V = 1..=n` appears twice (counting `num_ops` and emitting op-2 paths) and scans the full `V x V` grid with `if j > i`, because domains lack `V.after(i)` or `V.pairs`. Counting matching pairs also needs a 3-line accumulator loop instead of `count(...)`.
- **Goal it hurts:** express, performance.
- **Ideal code (`dream/cf2150f.cp`, lines 36 and 40):**
  ```cp
  print(count(for i in V, j in V.after(i) where not adj[i, j]))
  ...
  for j in V.after(i) where not adj[i, j]:
  ```
- **General fix:** Support open-start domain subranges (`V.after(i)`) and `count(for ...)` generator reductions.
- **Severity:** low.

### 2. No open-ended list suffix slicing
- **Status:** closed (O(1) list slice views `pif[split..]` and `pif[..split]` landed in §61; `cf2150f.cp` now uses zero-copy `pif[split..]` / `pif[..split]` without manual comprehension or `truncate`).
- **Where:** `cf2150f.cp`, line 63 (`dream/cf2150f.cp`, line 59):
  ```cp
  let extras = [pif[k] for k in pif.len - keep..pif.len]
  ```
- **What felt wrong:** Copying the last `keep` elements of a list requires an explicit index comprehension `[pif[k] for k in pif.len - keep..pif.len]` instead of a slice `pif[pif.len - keep..]`.
- **Goal it hurts:** express.
- **Ideal code (`dream/cf2150f.cp`, line 59):**
  ```cp
  let extras = pif[pif.len - keep..]
  ```
- **General fix:** Support open-ended list slices `xs[start..]` returning a sub-list/slice.
- **Severity:** low.

### 3. Graph construction and queries are hand-rolled
- **Where:** `cf2150f.cp`, lines 18-27 (`dream/cf2150f.cp`, lines 14, 20-21, 25-26).
- **What felt wrong:** The dream reads `Graph<V>.undirected(edges: ...)`, asks it for `g.spanning_tree()` and tests `g.has(j, k)`. Today the port keeps a `[Sym<V>]Bool` edge matrix beside a `Dsu` loop that pushes tree edges into adjacency lists by hand, and `with io(base: 1)` is not implemented.
- **Goal it hurts:** express, revise.
- **General fix:** A graph value that owns its edge set (membership query `has`, cost documented per representation) and derives standard structures (`spanning_tree() -> Rooted`) instead of every port rebuilding them from a DSU.
- **Severity:** medium.

### 4. No tree median
- **Where:** `cf2150f.cp`, lines 43-44 (`dream/cf2150f.cp`, line 35).
- **What felt wrong:** The meeting point of three paths is spelled as the deepest of three pairwise LCAs, with `argmax` returning an index that must be fed back into the list.
- **Goal it hurts:** express.
- **General fix:** `Rooted.median(a, b, c)` next to `lca`/`dist`/`path`; separately, an `argmax`-style reduction that can return the element (`max(xs, by:)`, see 5).
- **Severity:** low.

### 5. `max(a, b, by:)` does not exist
- **Where:** `cf2150f.cp`, line 42 (`dream/cf2150f.cp`, line 34).
- **What felt wrong:** Choosing the diameter end farther from `i` needs an `if ... else` over two calls to `dist` instead of `max(d.u, d.v, by: f => t.dist(i, f))`.
- **Goal it hurts:** express.
- **General fix:** The variadic `min`/`max` take the same `by:` key option as the list methods.
- **Severity:** low.

### 6. No parity views or drop-first/last on sequences
- **Where:** `cf2150f.cp`, lines 41, 48-52 (`dream/cf2150f.cp`, lines 33, 38-39).
- **What felt wrong:** `p[..2 * skip].even`, `stem.odd + stem.even.rev`, `.drop_last` and `.drop_first` become `[x for (z, x) in xs.items if z % 2 == out]` comprehensions and `xs[..xs.len - 1]` / `xs[1..]` slices. `.step(2)` on a slice does not exist either.
- **Goal it hurts:** express, performance.
- **General fix:** Strided views on slices (`xs.step(2)` or `xs[a..b].step(2)`, O(1) and composable with `.rev`) plus `drop_first`/`drop_last` (or `drop(k)` symmetric with ranges).
- **Severity:** medium.

### 7. `List.pairs` means adjacent windows, `Domain.pairs` means all pairs
- **Where:** `cf2150f.cp`, lines 31-33 (`dream/cf2150f.cp`, line 25).
- **What felt wrong:** The dream's `t.adj[i].pairs` is meant as every unordered pair of neighbours, as `V.pairs` is. On a `List` the same name yields consecutive pairs, so the natural code compiles, runs and silently misses skips (it failed the checker on the sample). The port spells unordered pairs as a double `items` loop with `a < b`.
- **Goal it hurts:** hard to get wrong, coherence.
- **General fix:** One meaning for `pairs` across domains and sequences (all unordered pairs), with adjacent pairs named `windows(2)`.
- **Severity:** high (silent wrongness, goal 2).

- **Area:** core

## `Graph.spanning_tree()` and `Graph.has(u, v)` not in `std.graph` (`E0203`)
- **Where:** `dream/cf2150f.cp`, lines 21–22, 26–27 (`g.spanning_tree()`, `g.has(j, k)`).
- **What felt wrong:** `Graph` lacks both `g.spanning_tree() -> Rooted` and O(1)/O(log deg) edge-membership `g.has(u, v)`, forcing `cf2150f.cp` to build a spanning tree with a hand `Dsu` loop beside a separate `[Sym<V>]Bool` edge matrix.
- **Goal it hurts:** express, revise.
- **Ideal code:** `let t = g.spanning_tree()` and `if not g.has(j, k)`.
- **General fix:** add `Graph.spanning_tree()` and `Graph.has(u, v)` to `std.graph`.
- **Area:** graphs
- **Severity:** medium
