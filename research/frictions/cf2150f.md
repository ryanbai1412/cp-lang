## Algorithm

Build a spanning tree `T` and its diameter `diam`. Operation 1 (`k = 3`) adds all missing edges between pairs of tree neighbors of each vertex, turning `G` into a superset of `T^2`. Operation 2 (`k = ceil(diam / 2) + 1`) connects every remaining non-adjacent pair `(i, j)` using a simple path of length `path_len = ceil(diam / 2)` in `T^2`: either skipping vertices along the tree path `i -> j` if `dist(i, j) >= path_len`, or detouring toward the furthest tree vertex from `i` and zigzagging out and back along the shared suffix.

## Frictions

### 1. `L0414` false positive on `(0..xs.len).rev` and missing `List.enumerate()` (high)

In the zigzag loop, walking `extras` forward by index works cleanly:
```cp
for z in 0..extras.len:
    if z % 2 == f: resp.push(extras[z])
```
Walking the same range in reverse:
```cp
for z in (0..extras.len).rev:
    if z % 2 != f: resp.push(extras[z])
```
triggers `warning[L0414]: extras[z] is bounds-checked on every pass of a nested loop`, which fails `scripts/check.sh --fast` (0-warning gate). Trying to avoid indexing via `for (z, x) in extras.enumerate()` fails with `E0203: a List<V> has no method enumerate`. The port had to work around both by maintaining a manual parity variable `var par = (extras.len - 1) % 2` inside `for x in extras.rev`.

**Ideal code:**
```cp
for (z, x) in extras.enumerate():
    if z % 2 == f: resp.push(x)
for (z, x) in extras.enumerate().rev:
    if z % 2 != f: resp.push(x)
```
**General fix:** Teach bounds-check elision and `L0414` that `.rev` preserves range bounds (`(0..xs.len).rev` is provably in-bounds for `xs`), and provide `.enumerate()` (and `.step(k)`) uniformly on sequences and ranges.

### 2. Repeated `let _ =` discards for shrinking lists and discarding return values (medium)

Trimming the common suffix of `pif` and `pjf` and popping during DFS required five `let _ = ...` statements (`let _ = pif.pop()`, `let _ = pjf.pop()`, `let _ = path.pop()`, `let _ = build_tree(V.first)`, `let _ = dfs(st, none)`). `List` has no `truncate(len)` or `drop(k)` method to shorten a list by `k` elements without a loop of discarded `pop()`s.

**Ideal code:**
```cp
let drop = extra - need
pif.truncate(pif.len - drop)
pjf.truncate(pjf.len - drop)
```
**General fix:** Add `List.truncate(n)` (and `List.extend(iter)`) to `stdlib`.

### 3. No domain half-range / unordered-pair iteration (low)

Iterating unordered pairs `i < j` over `domain V = 1..=n` appears twice (counting `num_ops` and emitting op-2 paths) and requires scanning the full `V x V` grid with `if j <= i: continue`, because domain elements don't support `for j in i.next..=V.last` or `for (i, j) in V.pairs`.

**Ideal code:**
```cp
for i in V:
    for j in V.after(i):
        if not adj[i, j]: ...
```
**General fix:** Support open-start domain subranges (e.g. `V.after(i)` or `(i..).in(V)`), keeping half-matrix loops both concise and free of wasted iterations.
