## Friction 1: 1.42x from string building

- Where: `chain(lo, hi)`, `var e = "{s[lo]}"` and `e += "?{s[i]}:{s[i + 1]}"`, then
  `e + ":{chain(j + 1, n)}"`.
- What felt wrong: the expression is built from interpolated pieces, each a new `Str`
  concatenated into the result, and the top level concatenates several such strings. The
  accepted C++ pushes characters into one `std::string`. The difference is about 3 ms.
- Goal it hurts: R10.
- Ideal code: unchanged source; or a `StrBuilder`-style `out.push(...)` if std has one.
- General fix: codegen could lower `e += "{a}?{b}:{c}"` to appends of each piece into `e`
  without building the temporary. Not profiled beyond timing in this pass.
- Severity: low (9 ms against 1000 ms).
- Owner: Core (codegen), repro: `cpl build corpus/problems/cf2089d/port.cp`, the `--max` input.

## Friction 2: `first_one` is a search written as a loop

- Where: `fn first_one(from: Int) -> ?Int: for k in from..n by 2 if s[k] == '1': return k; None`.
- What felt wrong: `first(k for k in from..n by 2 if s[k] == '1')` is the std spelling used
  in cf2084a and cf2089a.
- Goal it hurts: R8.
- Ideal code: inline `first(...)` at both call sites.
- General fix: port and dream edit.
- Severity: low.
- Owner: idioms.
