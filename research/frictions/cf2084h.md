## `runs()` in `stdlib/seq.cp` only accepts `List<T>`, not `Str`
- **Where:** `proto/ports/ecnerwala/cf2084h.cp` lines 7-15:
  ```cp
  var runs = List<Int>()
  var run = 1
  for i in 1..n:
      if s[i] == s[i - 1]:
          run += 1
      else:
          runs.push(run)
          run = 1
  runs.push(run)
  ```
- **What felt wrong:** `stdlib/seq.cp` provides `runs<T>(a: List<T>) -> List<(val: T, len: Int)>`, but it does not work on `Str` (nor is it in the prelude). Splitting a binary string `s: Str` into run lengths forces either converting `s` into a `List<Char>` first (extra O(n) allocation on $n = 2 \cdot 10^6$) or writing a 9-line manual run-length loop where forgetting the trailing `runs.push(run)` is a classic bug.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  let runs = [r.len for r in s.runs()]
  ```
- **General fix:** Make `runs()` generic over any sequence/slice (`Str`, `[D]T`, `List<T>`) and consider a zero-allocation `runs()` generator so $n = 2 \cdot 10^6$ strings don't pay for an intermediate `List<Char>`.
- **Severity:** medium

## Mixing `Int` expressions with `Mod<P>` requires explicit `M(...)` wrapping on every term
- **Where:** `proto/ports/ecnerwala/cf2084h.cp` lines 18, 34, 36, 41, 43, 46:
  ```cp
  stk_sum[z] -= M(below.len - top.len) * below.val
  ...
  cur_dp += M(top.len + offset[z]) * top.val
  cur_dp += M(base + offset[z] - 1)
  print(prev_dp * M(runs.last!))
  ```
- **What felt wrong:** While integer literals coerce cleanly (`var prev_dp: M = 1`), multiplying or adding a `Mod<P>` by an `Int` count/length forces `M(...)` around every single integer expression (6 wrappers in a 30-line DP).
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  stk_sum[z] -= (below.len - top.len) * below.val
  cur_dp += (top.len + offset[z]) * top.val
  cur_dp += base + offset[z] - 1
  print(prev_dp * runs.last!)
  ```
- **General fix:** Allow `Mod<P> * Int`, `Int * Mod<P>`, and `Mod<P> += Int` (reducing the `Int` mod `P` with Euclidean mod) when one side is already `Mod<P>`.
- **Severity:** medium

## `Str` does not carry `s.len == n` from input, and `String` gives no suggestion for `Str`
- **Where:** `proto/ports/ecnerwala/cf2084h.cp` lines 4-5, 9-10:
  ```cp
  let n: 3..=2_000_000 = read()
  let s: Str = read()
  for i in 1..n:
      if s[i] == s[i - 1]:
  ```
- **What felt wrong:** First, writing `String` (familiar from Rust/C++/Java) errors with `no type or domain named String` without suggesting `Str`. Second, `let s: Str = read()` does not bind `s.len == n` (unlike `[0..n]Char`), so `s[i]` and `s[i - 1]` stay runtime-checked even though `i in 1..n`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  let s: Str<n> = read()
  ```
- **General fix:** Suggest `Str` in the diagnostic for `String`, and support length-constrained string reads (or `Str` with `where s.len == n`) so `s[i]` is statically proven in-bounds.
- **Severity:** low
