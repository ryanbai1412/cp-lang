# cf2096c: friction report

Port: `corpus/problems/cf2096c/port.cp`, dream: `corpus/problems/cf2096c/dream.cp`.

## Measurements

- Tokens: port 401, accepted C++ 624. Emitted C++: 15656 bytes.
- `--max` (n = 1000, median of 15): port 19.3 ms / 3.2 MB, accepted 39.8 ms / 2.5 MB (0.48x).
- Output: identical to the accepted C++.

## Friction 1: the port streams rows where the dream reads the grid

- Where: port `var above: [0..n]Int` and `let h: [0..n]Int = read()` per row; dream
  `let h: [0..n, 0..n]Int = read()`.
- What felt wrong: the port keeps only the previous row to stay at 3 MB; the dream reads
  the grid (8 MB at n = 1000) and is shorter. Both fit 256 MB, so the streaming buys
  nothing the limit asks for and costs a mutable `above` copy per row.
- Goal it hurts: R2, R13.
- Ideal code: the dream's whole-grid read.
- General fix: port edit to the dream's form, then re-measure.
- Severity: low.
- Owner: idioms.

## Friction 2: the difference -1..=1 is an index offset

- Where: `[0..n - 1, 0..3]Bool` with `row_bad[i - 1, d + 1]` and `bad[i - 1, 1 + p - q]`.
- What felt wrong: the second index is the difference `d` in `-1..=1`, stored at `d + 1`.
- Goal it hurts: R6.
- Ideal code: `domain Diff = -1..=1` and `[0..n - 1, Diff]Bool`, indexed `row_bad[i - 1, Diff(d)]`.
- General fix: port and dream edit.
- Severity: low.
- Owner: idioms.

`h` is read as unbounded `Int`; the statement bounds heights (`1..=1e9`), so the read
should say so.
