# cf2178i — Numbers or Fireworks

The editorial idea: expand each city's number `f + 1` as "the city picks
nothing, or picks one of its `f` firework neighbours". Cities `sqrt(k)` apart
form a bipartite graph (lattice parity), so enumerate the set `O` of cities on
the smaller side (at most 15) that are outside `T`; the rest of that side is in
`T`. Sweep the other side: a city outside `T` contributes `1 + |N(b) \ O|`, a
city in `T` can be picked by any of its neighbours in `O`, each of which picks
at most once, so the state is the subset of `O` that has picked. That is
`3^15 * 16 * 15` steps. The port says this almost line for line
(`Subset<A>`, `out.subsets`, `m & out`), but naming the smaller side, building
the adjacency masks and getting the speed of the dense C++ form all cost
workarounds.

## A subset's own subsets cannot be a dense index space, and the sparse form is 1.9x slower
- **Severity:** high
- **Where:** `cf2178i.cp`, lines 25–35:
  ```cp
  var dp: [Subset<A>]Z = 0
  var skip: [Subset<A>]Z = 0
  for out in Subset<A>.full.subsets:
      for s in out.subsets: dp[s] = 1
      ...
          for s in out.without(i).subsets: dp[s.with(i)] += dp[s]
  ```
- **What felt wrong:** the DP lives on the subsets of `out`, but the only
  typed index space is `Subset<A>`, so the table has `2^|A|` cells and every
  pass walks `out.subsets` (a serial `(s - 1) & out` chain that the compiler
  cannot vectorise). The original renumbers `out`'s members `0..l` and runs
  dense `0..2^l` loops. Measured on the max inputs (`g++ -O2`, median of 5):
  port 787 ms vs original 413 ms. A hand-written C++ of the port's sparse
  algorithm runs 652 ms, so most of the gap is the layout the types forced,
  not the code generator. Rewriting the port densely with raw `Int` masks
  (`let o = [i for i in out]`, `for s in 0..1 << o.len if s & bit == 0`) gives
  673 ms, but drops every type: `s` is a bare `Int`, `bit` is a shift by a
  position in a list, and the "which city is bit `j`" fact moves into `o[j]`.
  Patching that dense output by hand to remove `cpl::at` bounds checks, store
  `Mod` in 32 bits, or use unsigned `%` changed nothing measurable
  (681/694/666 ms), so the remaining 1.6x is not explained yet.
- **Goal it hurts:** performance (1.9x, above the 1.5x max), and express and
  revise (the fast form is the untyped one, so tuning is a rewrite).
- **Ideal code:**
  ```cp
  for out in Subset<A>.all:
      var dp: [Subset<out>]Z = 1
  ```
  where `Subset<out>` is the dense `0..2^|out|` space of subsets of a runtime
  subset, `s - {a}` and `s & adj[b]` translate through `out`'s rank (pext), and
  `dp[out]` is the last cell.
- **General fix:** let a subset value act as a domain (its members, ranked),
  so `Subset<s>` is dense and `[Subset<s>]T` is a `2^|s|` array; lower the
  translation of an outer-domain mask into it to `pext`/`pdep`. Then profile
  the dense loops against the original to find the unexplained 1.6x.
- **Dream:** `dream/cf2178i.cp` line 21: `var dp: [Subset<out>]Z = 1` is
  dense; lines 22–24 index it with outer masks.

## The two sides of a bipartition cannot be domains, so `A` is a position list
- **Severity:** medium
- **Where:** `cf2178i.cp`, lines 15–23:
  ```cp
  let left = count(side[v] for v in V) * 2 <= n
  let a = [v for v in V if side[v] == left]
  let b = [v for v in V if side[v] != left]
  domain A = 0..a.len
  fn nbr(v: V) -> Subset<A>:
      var m = Subset<A>.empty
      for i in A if near(a[i.to_idx], v): m = m.with(i)
      return m
  ```
- **What felt wrong:** "the smaller colour class" is one idea, and its
  members are cities. The port spells the minority by counting `true`s, keeps
  two lists, declares `A` as positions into one of them, and converts back
  with `a[i.to_idx]`: the type no longer says an `A` is a city, and nothing
  stops `a` and `A` drifting apart. `b` is a plain `List<V>`, so `adj` is a
  `List` indexed by position, not by city.
- **Goal it hurts:** hard to get wrong (wrong index space: positions vs
  cities), express and revise.
- **Ideal code:**
  ```cp
  let small = side.minority
  domain A = V where side[v] == small
  domain B = V where side[v] != small
  ```
- **General fix:** filtered sub-domains (`domain A = V where pred`), whose
  values convert to `V` for free and from `V` with a check; plus a
  `minority`/`majority` on arrays over `Bool` (or a general `mode`).
- **Dream:** `dream/cf2178i.cp` lines 14–16.

## No set-builder for `Subset`, so a neighbour mask is a four-line function
- **Severity:** medium
- **Where:** `cf2178i.cp`, lines 19–23 (above). `Subset<A>.empty.with_all(...)`
  and every other spelling I tried do not exist; the only way is a `var`
  loop with `m = m.with(i)` in a helper function.
- **What felt wrong:** a set comprehension is the most guessable form; lists
  have one (`[v for v in V if ...]`), subsets do not.
- **Goal it hurts:** express and revise, tokens.
- **Ideal code:**
  ```cp
  let adj: [B]Subset<A> = [b => {a in A if near(a, b)}]
  ```
- **General fix:** set comprehensions `{x in D if p}` producing a `Subset<D>`
  (or `Set`), in the same family as list comprehensions.
- **Dream:** `dream/cf2178i.cp` line 17.

## One DP step needs a scratch array, three loops and an ordering argument
- **Severity:** medium
- **Where:** `cf2178i.cp`, lines 26 and 31–35:
  ```cp
  var skip: [Subset<A>]Z = 0
  ...
      for s in out.subsets: skip[s] = dp[s] * stay
      for i in m & out:
          for s in out.without(i).subsets: dp[s.with(i)] += dp[s]
      for s in out.subsets: dp[s] += skip[s]
  ```
- **What felt wrong:** the recurrence is `dp'[s] = dp[s] * stay + sum over a in
  s & m of dp[s - a]`. The in-place form is correct only because the
  `with(i)` targets never feed later reads in the same pass and `skip` holds
  the old values; that reasoning is the contestant's. `let skip = [s in
  out.subsets => ...]` (an array comprehension over a subset's subsets) is
  rejected, so `skip` is declared once outside both loops and reused.
- **Goal it hurts:** hard to get wrong (in-place update order), express.
- **Ideal code:**
  ```cp
  dp = [s => dp[s] * stay + sum(dp[s - {a}] for a in s & adj[b])]
  ```
  with the compiler double-buffering because the right side reads `dp`.
- **General fix:** whole-array comprehensions over any index space
  (`[s => expr]`, the shape of the destination), with copy-on-read
  double-buffering made visible by `cpl explain`.
- **Dream:** `dream/cf2178i.cp` line 24.

## Geometry and the answer fold are spelled out
- **Severity:** low
- **Where:** `cf2178i.cp`, lines 12–13 and 27–37:
  ```cp
  let p: [V](x: 1..=100, y: 1..=100) = read()
  fn near(u: V, v: V) -> Bool = (p[u].x - p[v].x) ** 2 + (p[u].y - p[v].y) ** 2 == k
  ...
  var ans: Z = 0
  ...
      ans += dp[out]
  print(ans - 1)
  ```
- **What felt wrong:** no lattice-vector type, so a squared distance repeats
  the field names; and the per-`out` result has to leave the loop through an
  accumulator declared before it.
- **Goal it hurts:** express (small), tokens.
- **Ideal code:** `fn near(u: V, v: V) -> Bool = (p[u] - p[v]).norm2 == k`;
  `print(sum(for out in Subset<A>.all: ... dp[out]) - 1)`.
- **General fix:** a stdlib `Vec2<R>` with arithmetic and `norm2` that reads
  as `x y`; loops as expressions that yield their last value into a fold.
- **Dream:** `dream/cf2178i.cp` lines 11–12 and 20–26.
- **Status:** geometry half resolved (`let p: [V]Pt = read()` and `(p[u] - p[v]).norm2 == k` now use prelude `Pt`; loop-as-expression fold remains open).

## `two_color` needs an import other stdlib graph names do not
- **Severity:** low
- **Where:** `cf2178i.cp`, line 6: `use std.graph.{two_color}`.
- **What felt wrong:** `dijkstra`, also in `std.graph`, is in scope without a
  `use` (my cf2178h experiment called it bare); `two_color` is not. The error names the fix, so this costs
  one round trip, but which names are in the prelude is not guessable.
- **Goal it hurts:** express (unguessable).
- **Ideal code:** no `use` line.
- **General fix:** one rule for the prelude (all of `std.graph` or none),
  documented in one table.
- **Dream:** `dream/cf2178i.cp` has no `use` line.
