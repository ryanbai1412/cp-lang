# cf2183h — minimum total cost of k subsequences

Sorted, an optimal partition uses contiguous groups. The first group always
takes the prefix `0..st` (each of those elements lowers its cost), and past
it the segment cost `(P_i - P_j)(i - j)` is Monge, so the optimum `f(k)` is
convex in `k`. Aliens trick: charge each group `1/2 - lam` (all doubled so
it stays integral, which also makes the optimal group count unique), binary
search the least `lam` that reaches `k` groups, and read `f(k)` off the line
through that optimum. Each penalized problem is a Monge 1D/1D DP; the port
solves it with the textbook deque of candidates (each owns the rows from
where it starts to win, found by binary search), O(n log n), where the
original uses ecnerwala's online LARSCH template, O(n).

## No Monge DP or Aliens in the stdlib, and the hand-written one is 4x-16x slower

- **Where:** all of `fn solve` (20 lines: `Deque<(j: Int, from: Int)>`,
  front pops, back pops, `bsearch_first` over rows) and the Aliens
  bookkeeping (`2 * lam - 1`, `(best.cost + (2 * lam - 1) * best.groups) / 2`,
  `f - (lam - 1) * (best.groups - k)`).
- **What felt wrong:** both are standard named algorithms with subtle
  invariants: which candidate wins ties, popping the back candidate when the
  new one already wins at its first row, rows starting at `max(from, i + 1)`,
  the half-integer slope trick and the line interpolation when the count
  jumps past `k`. Each line is a plausible 3am bug and none of it is about
  the problem. It is also slower than the original: on max inputs the port
  takes **3.56 s** vs **0.89 s** (k = n/2, all positive) and **1.11 s** vs
  **0.07 s** (k = 7, mixed signs). The gap is the algorithm (O(n log n)
  deque vs O(n) LARSCH, times ~65 Aliens rounds); writing LARSCH by hand in
  the port would add ~100 lines.
- **Goal it hurts:** express, performance, hard to get wrong.
- **Ideal code:**
  ```
  print(aliens(groups: k, slope: I128) { pen =>
      monge_path(through: [0] ++ (st..=n), cost: (j, i) => cost(j, i) + pen)
  })
  ```
- **General fix:** a `monge_path(through:, cost:)` (min-cost path over an
  increasing node list with a Monge edge cost, online LARSCH, O(n) cost
  calls, documented precondition) and an `aliens(groups:, slope:, solve)`
  that does the exact half-integer search and interpolation, both in the
  stdlib DP module, generic over the cost type. `cpl test` laws can check
  the Monge precondition on small inputs.
- **Severity:** high
- **Dream:** `proto/ports/ecnerwala/dream/cf2183h.cp` lines 13-15.

## `bsearch_first` refuses an `I128` range, with an error that names one type twice

- **Where:**
  ```
  var (lo, lam) = (fewest, I128(0))
  while lo < lam:
      let mid = lo + (lam - lo) / 2
      if solve(mid).groups >= k: lam = mid else: lo = mid + 1
  ```
- **What felt wrong:** the natural
  `bsearch_first(fewest..=I128(0), l => solve(l).groups >= k)!` fails with
  `E0302: expected I128, found I128`. The search over slopes needs 128 bits
  (`f(1) - f(most)` reaches about 8e19), so the contestant hand-writes the
  loop and its midpoint, the exact code `bsearch_first` exists to remove.
- **Goal it hurts:** guessable APIs, doubt to evidence (the message gives
  no way forward).
- **Ideal code:** `bsearch_first(fewest..=0, l => ...)` over any integer
  type; in the dream `aliens` owns the search entirely.
- **General fix:** make `bsearch_first`/`bsearch_last` generic over every
  integer width (they are written for `Range<I>` already), and when two
  types print the same, say what differs (width, domain, or generic
  instance).
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2183h.cp` line 13.

## Wide values need `I128(...)` at every literal and product

- **Where:** `var dp: [0..=n]Best = (cost: I128(0), groups: 0)`,
  `2 * I128(pref[i] - pref[j]) * (i - j)`, `I128(pref[n]) * n`,
  `I128(pref[st]) * st`, `I128(pref[rest]) * rest`, `(fewest, I128(0))`.
- **What felt wrong:** `(cost: 0, groups: 0)` as the fill of a
  `[..]Best` with `cost: I128` fails (`expected [Int](cost: I128, groups: Int),
  found (cost: Int, groups: Int)`), though `Int -> I128` widening is implicit
  per `design/spec/11-types.md`. Every product that can pass 2^63 also needs
  an explicit `I128(...)` on one factor, and forgetting one is a silent
  overflow in release; the ranges (`pref` up to 2e14, lengths up to 2e5)
  already prove which products are wide.
- **Goal it hurts:** hard to get wrong (overflow), express.
- **Ideal code:** `fn cost(j: a.Cut, i: a.Cut) -> I128 = (pref[i] - pref[j]) * (i - j)`
  with the result type widening the product, and tuple fills widening field-wise.
- **General fix:** widen literals field-wise in tuple/struct context (the
  spec's "a struct widens field-wise"), and evaluate an arithmetic
  expression at the width of its declared result when the operand ranges
  prove the narrow form can overflow (or warn there).
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2183h.cp` line 9.

## A nested `fn` that captures is lowered to `std::function`

- **Where:** `fn via(j: Int, i: Int) -> I128 = dp[j].cost + ...` inside
  `fn solve`, called on every probe of the binary search.
- **What felt wrong:** the emitted C++ is
  `std::function<__int128(ll, ll)> via = [&dp_2 = dp, lam_2 = lam](...)`,
  so the hottest call goes through type erasure. Hoisting it to a top-level
  `fn via(dp: [0..=n]Best, lam: I128, j: Int, i: Int)` and passing `dp, lam`
  at all six call sites took the k = n/2 max input from **3.68 s** to
  **3.12 s** and the k = 7 one from **1.39 s** to **0.98 s** (measured on a
  draft with one extra pruning line), at a large cost in readability; the
  port keeps the nested form.
- **Goal it hurts:** performance (abstractions are not free), the obvious
  way is not the fast way.
- **Ideal code:** the nested `fn` as written, compiled to a plain lambda
  (`auto via = [&](ll j, ll i) {...}`).
- **General fix:** lower non-recursive, non-escaping local functions to
  `auto` lambdas; keep `std::function` only for recursion or storage.
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2183h.cp` line 9.

## What worked

- `sort(mut a)`, the `while st < n and ...` prefix, and the closed form for
  `k >= most_groups` read like the editorial.
- `type Best = (cost: I128, groups: Int)` names the Aliens pair, and
  `Deque<(j: Int, from: Int)>` with `cand[1].from`, `cand.last` and
  `while let last = cand.last, ...: cand.pop()` keeps the candidate queue
  readable.
