# cf2237h — H. Slime and Queries

## No interval partition map (ODT / `IntervalMap<D, T>`) in stdlib
- **Where:** `proto/ports/ecnerwala/cf2237h.cp` lines 12-22, 29-33, 42-51:
  ```cp
  var segs = Map<Int, (r: Int, t: Time)>()
  ...
  fn split(mut segs: Map<Int, (r: Int, t: Time)>, x: Int):
      if let (sl, val) = segs.last_le(x):
          if sl < x and val.r > x:
              segs[sl] = (r: x, t: val.t)
              segs[x] = (r: val.r, t: val.t)
  ...
  for (range, _) in tree.chains(cur, c):
      let (l, r) = (range.lo.ord, range.hi.ord)
      split(mut segs, l)
      split(mut segs, r)
      var pos = l
      while pos < r:
          let seg = segs.remove(pos)!
          chunks.push((t: seg.t, w: seg.r - pos))
          pos = seg.r
      segs[l] = (r: r, t: t_now)
  ```
- **What felt wrong:** Hand-rolling an ODT / Chtholly tree with manual `split` at both endpoints, `segs.remove(pos)!`, and a manual initial run-length compression loop. Worse, we had to leave the nominal `tree.Pre` domain via `.ord` and store raw `Int` endpoints because `Map` has no range-partition abstraction. An off-by-one in `sl < x and val.r > x` or forgetting to split `r` silently corrupts the partition.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  var segs = IntervalMap<tree.Pre, Time>(Time(1))
  for v in init_slime:
      segs.assign(tree.pos(v)..=tree.pos(v), Time(2))
  ...
  for (range, _) in tree.chains(cur, c):
      for (r, t) in segs.assign(range, t_now):
          chunks.push((t: t, w: r.len))
  ```
- **General fix:** Add `IntervalMap<D, T>` (or `ColorMap<D, T>`) to stdlib over any domain `D`, supporting `assign(range: Range<D>, val: T) -> yields (range: Range<D>, old: T)`, `at(i: D) -> T`, and automatic adjacent-merge. Eliminates ~25 lines of error-prone split/erase boilerplate across all ODT, color-overwrite, and HLD-paint problems.
- **Severity:** high

## Directional / skip-list DSU merges require manual pre-merge payload save
- **Where:** `proto/ports/ecnerwala/cf2237h.cp` lines 65-74:
  ```cp
  if cnt[u] == 0:
      if let p = prv[u]:
          let b = dsu.find(p)
          let (np, nc) = (prv[b], cnt[b])
          let (kept, _) = dsu.merge(u, b)!
          prv[kept] = np
          cnt[kept] = nc
          it = kept
      else:
          it = none
  ```
- **What felt wrong:** We want a standard "delete empty bucket `u` and redirect all future lookups to the previous non-empty bucket `prv[u]`" skip-list DSU. Because `Dsu.merge(u, b)` picks `kept` by union-by-size, the caller must carefully snapshot `(prv[b], cnt[b])` before merging and copy them onto `kept`. Copying after `merge` or assuming `b` survives is an easy WA trap, and the 9 lines obscure a 1-line idea.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  if cnt[u] == 0:
      it = prv[u].map(p => dsu.redirect(u, to: p))
  ```
- **General fix:** Provide a directional skip-DSU (`SkipDsu<D>` / `ActiveSet<D>` with `erase(i)` and `prev_active(i) -> ?D` / `next_active(i) -> ?D`) or a payload-carrying `Dsu<D, T>` where the caller specifies how payloads combine on merge. Covers the ubiquitous "jump past deleted/saturated elements" pattern in greedy, offline, and sweep problems.
- **Severity:** high
- **Status:** fixed by `std.dsu.DsuOf<Time, (prv: ?Time, cnt: Int)>` with join `(_, b) => b`: the merged set keeps `b`'s value whichever root survives, and the port now uses it.

## No dynamic tree (`LinkCutTree` / `TopTree`) in stdlib forces an extra log factor
- **Where:** `proto/ports/ecnerwala/cf2237h.cp` lines 5, 41-54:
  ```cp
  let tree = Rooted(Graph.undirected(edges), V.first)
  ...
  for (range, _) in tree.chains(cur, c):
      ...
  sort(mut chunks, by: x => desc(x.t))
  ```
- **What felt wrong:** The original uses an $O((n + q) \log n)$ Top Tree that walks the path in order and visits only timestamp-change boundaries. Without a dynamic tree (`LinkCutTree` / `TopTree`) in stdlib, the idiomatic CP Lang solution uses static HLD (`tree.chains`) + `Map` ODT in $O((n + q \log n) \log n)$ and has to re-sort collected `chunks` per query. On $n = q = 10^5$, this is 1.69x slower (0.49s vs 0.29s, above the 1.5x max performance bar) and uses 2.09x peak memory (29.9 MB vs 14.3 MB).
- **Goal it hurts:** performance, express
- **Ideal code:**
  ```cp
  var lct = LinkCutTree<V, (t: Time, sz: Int)>(...)
  for (t, w) in lct.path_runs(cur, c, set: t_now):
      ...
  ```
- **General fix:** Add a generic `LinkCutTree` (and/or arena-backed `TopTree`) to stdlib/local-lib for dynamic trees and $O(\log n)$ amortized path-assign/color-run queries.
- **Severity:** medium
