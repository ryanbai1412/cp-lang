# cf2021d — Boss, Thirsty

- **Status:** ported (`proto/ports/ecnerwala/cf2021d.cp`, dream `proto/ports/ecnerwala/dream/cf2021d.cp`)
- **Gate:** `proto/ports/ecnerwala/gate.sh cf2021d 150`: PASS (1 sample, 150 random cases)
- **Runtime (max input, n * m = 200,000, `g++ -O2`):** 0.01 s vs original 0.01 s on n = 1, 2 and 66,666 rows; outputs identical.
- **Emitted C++:** 11,619 bytes

## `if let` on an optional array or closure copies the payload every iteration
- **Where:** the first draft of `sweep` bound `if let e = end:` inside the cut loop (`end: ?[Cut]Int`, then `?(Cut -> Int)`).
- **Snippet:** `for k in order: ... if let e = end: open max= e[c] - low`
- **Effect:** the emitted C++ copies the whole `std::vector` (or a `std::function` holding it) per iteration: 9.5 s vs 0.01 s at n = 2, m = 100,000.
- **Port today:** `if let` moved out of the loop, into `ends`, which passes a lambda.
- **Goal it hurts:** performance (the obvious code is quadratic).
- **General fix (codegen):** bind `if let`/`while let` payloads by const reference when the binding is not mutated or moved.
- **Severity:** high.

## A domain's `.bounds` can't be iterated or passed as a value
- **Where:** `sweep` walks the cuts both ways (`cf2021d.cp`, `ends(...)` calls).
- **Snippet:** `[k for k in (0..=m).rev]` then `Drink.bounds.nth(k)`; `for c in Drink.bounds.rev` is E0501.
- **Dream:** the scans are over `[Drink.Cut]` arrays; no index list.
- **Goal it hurts:** express (an `Int` list stands in for a range of cuts).
- **General fix (core/codegen):** `D.bounds` as a `Range` value, with `.rev`.
- **Severity:** medium.
- **Fixed:** `for c in Drink.bounds.rev` iterates, and `D.bounds` kept as a value is a `Range` of cuts (`.len`, `.map`, `.rev`, `.first(p)`; `bounds_value.cp`). The checker types `D.bounds` as `Range<D.bounds>` too, so the port passes `Drink.bounds` and `Drink.bounds.rev` to `ends` directly, with no `nth`. A bare domain stays a type; `Drink.all` is its positions.

## No exclusive prefix-extreme scans over cuts
- **Where:** `sweep` keeps `low` and `open` by hand.
- **Dream:** `e - pref.prefix_min(at: .cuts)` and `pref + open.prefix_max(at: .cuts)` (spec 22, Scans).
- **Goal it hurts:** express (the editorial's prefix max of a prefix min is a loop).
- **General fix (seq):** the spec's `prefix_min`/`prefix_max(at: .cuts)` returning `[D.Cut]?T`.
- **Status:** blocked on core `D.Cut` / `D.bounds` (friction #2 above); element-indexed `a.scan(min)` / `a.scan(max)` / `a.suffix_scan(min)` / `a.suffix_scan(max)` already exist, and generic stdlib signatures cannot yet express `[D.Cut]?T` without `D.Cut` in the type system.
- **Severity:** medium.
