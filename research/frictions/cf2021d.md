# cf2021d — Boss, Thirsty

- **Status:** ported (`corpus/problems/cf2021d/port.cp`, dream `corpus/problems/cf2021d/dream.cp`)
- **Gate:** agrees with `orig.cpp` on both tests and 200 `gen.py` inputs plus 10 max inputs (`cpl build --judge codeforces`).
- **Runtime (max input, n * m = 200,000, `g++ -O2`, min of 30):** 13.8 ms vs original 11.2 ms at 66,666 rows of m = 3 (1.23x); 9.8 vs 13.3 ms at n = 1, m = 200,000. The previous port took 25.5 ms on the 66,666-row input (2.3x).

## `if let` on an optional array or closure copies the payload every iteration
- **Where:** the first draft of `sweep` bound `if let e = end:` inside the cut loop (`end: ?[Cut]Int`, then `?(Cut -> Int)`).
- **Snippet:** `for k in order: ... if let e = end: open max= e[c] - low`
- **Effect:** the emitted C++ copies the whole `std::vector` (or a `std::function` holding it) per iteration: 9.5 s vs 0.01 s at n = 2, m = 100,000.
- **Port today:** `if end.is_some: ... end![c]` in the loop; it emits no copy.
- **Still open (2026-11-23):** the payload is read in place unless the loop body also calls a closure parameter: `fn f(e: ?[Cut]Int, g: Cut -> Int) -> Int` with `for c in Drink.cuts: s max= if let x = e: x[c] else: g(c)` emits `std::optional<std::vector<ll>> t = e_2;` per iteration (drop `g(c)` and it is a `const&`), and `s max= e.map(x => x[c])` copies into the closure parameter even without a call. On this port that is 21.4 ms vs 13.8 ms at 66,666 rows.
- **Goal it hurts:** performance (the obvious code is quadratic).
- **General fix (codegen):** bind `if let`/`while let` payloads by const reference when the binding is not mutated or moved.
- **Severity:** high.

## A domain's `.bounds` can't be iterated or passed as a value
- **Where:** `sweep` walks the cuts both ways (`cf2021d.cp`, `ends(...)` calls).
- **Snippet:** `[k for k in (0..=m).rev]` then `Drink.bounds.nth(k)`; `for c in Drink.bounds.rev` is E0501.
- **Dream:** the scans are over `[Drink.Cut]` arrays; no index list.
- **Goal it hurts:** express (an `Int` list stands in for a range of cuts).
- **General fix (core/codegen):** `D.bounds` as a `Range` value, with `.rev`.
- **Severity:** medium.
- **Fixed:** `for c in Drink.bounds.rev` iterates, and `D.bounds` kept as a value is a `Range` of cuts (`.len`, `.map`, `.rev`, `.first(p)`; `bounds_value.cp`). The checker types `D.bounds` as `Range<D.bounds>` too, so the port passes `Drink.bounds` and `Drink.bounds.rev` to `ends` directly, with no `nth`. A bare domain stays a type; `Drink.all` is its positions.

## No exclusive prefix-extreme scans over cuts
- **Where:** `sweep` keeps `low` and `open` by hand.
- **Dream:** `e - pref.prefix_min(at: .cuts)` and `pref + open.prefix_max(at: .cuts)` (spec 22, Scans).
- **Goal it hurts:** express (the editorial's prefix max of a prefix min is a loop).
- **General fix (seq):** the spec's `prefix_min`/`prefix_max(at: .cuts)` returning `[D.Cut]?T`.
- **Status:** not in the design (1-user helper). Inclusive cut-indexed `a.scan(min)` / `a.suffix_scan(max)` over `[V.bounds]T` now work directly (`seq_cut_scan.cp`); exclusive cut-indexed `prefix_min`/`prefix_max(at: .cuts)` returning `[Cut]?T` has only this single user (`cf2021d`).
- **Severity:** medium.

## A reversed cut range passed as a value becomes a list
- **Where:** `sweep(mut next, Drink.cuts.rev, ...)` with `fn sweep<S>(..., order: S, ...)`.
- **Snippet:** `Drink.cuts` reaches `sweep` as a `cpl::Range<int>`; `Drink.cuts.rev` is a `std::vector<int>` filled by `push_back` on every call (two allocations per row here).
- **Goal it hurts:** performance (a range that looks O(1) to pass allocates O(m)).
- **General fix (codegen):** a descending range value (`Range` with a direction, or a `Rev<Range>` view) that a `for` walks in place.
- **Severity:** low.

## Folds over cuts allocate every intermediate
- **Where:** the dream-shaped form, `prefix_fold(max, [Drink] v => open[v.l])` and `suffix_fold(max, [Drink] v => open[v.r])` for the two exclusive maxima, then `[Cut] r => best[r].map(o => pref(r) + o)`.
- **Effect:** 7 vectors per side per row; 25.4 ms vs 11.0 ms for `orig.cpp` at 66,666 rows of m = 3 (2.3x), so the port keeps the hand-written sweep (item 3).
- **General fix (stdlib + codegen):** item 3's `prefix_max(at: .cuts)` as one pass, and comprehensions passed to a fold streamed rather than materialized (compiler worklog, generator-to-`Seq` request).
- **Severity:** medium.
