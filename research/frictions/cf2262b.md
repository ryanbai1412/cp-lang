# cf2262b friction

Reverse the removals into insertions. Only prefix maxima ever become champion, so the
forfeits are the prefix maxima after the first minus those a champion eats; a champion
that eats a prefix maximum more than doubles before it falls, so at most ~30 champions
eat, and the answer walks only those. The port keeps the prefix maxima, the set of eating
champions, and Fenwick sums; the original does the same with a hand-rolled segment tree.

## A position-or-end is a two-arm `if let` every time
- **Where:** `fn next_top(c: I) -> Bounds<I> = if let q = top_at.first_gt(c): q.l else: I.end`
  and again `let reach = if let (_, q) = top_of.first_gt(...): q.l else: I.end`.
- **What felt wrong:** "the cut before the next key, or the end" is one idea, written as
  a four-part conditional twice. There is no way to map over an optional (`?.`), so the
  value (a tuple, for the `Map`) must be destructured just to take `.l`. My first spelling, `I.bounds.last!`,
  checks but `cpl run`/`cpl build` reject it (E0501), and `I.last.r` is flagged by the
  friction lint as stale; `I.end` is the answer but is only in `plan/12`, not the cheat sheet.
- **Goal it hurts:** express, coherence (unguessable).
- **Ideal code:** `top_at.first_gt(c)?.key.l ?? I.end`, or an ordered-map query that
  returns a boundary directly: `top_at.cut_after(c)`.
- **General fix:** optional chaining (`?.`) over fields and methods, lifting like `+`
  already lifts; `D.end`/`D.start` in the cheat sheet next to `v.l`/`v.r`; make
  `D.bounds.last` lower in both backends or reject it in `check`. Helps every port that
  turns a `?(K, V)` from `first_ge`/`last_le` into a boundary or an index.
- **Dream:** `dream/cf2262b.cp` lines 36 and 47 (`.map(q => q.l) ?? I.end`; no `?.`, since postfix `?` is propagation).
- **Severity:** medium.

## The same monotone set lives in three structures, kept in sync by hand
- **Where:** `top_at: Set<I>`, `top_of: Map<Int, I>` and `tops: Fenwick<I, Int>`;
  every removal is
  `top_at.remove(q); top_of.remove(a[q]); eaters.remove(q); tops.add(q, -1)`.
- **What felt wrong:** the prefix maxima increase in both position and value, so one
  ordered set already answers "first maximum whose value exceeds `s`" by binary search
  and "how many maxima in `c..stop`" by rank. CP Lang's `Map` has neither a search by a
  monotone predicate nor a rank, so the fact "this is a prefix maximum" is written into
  three places, and forgetting one of the four lines is a silent wrong answer.
- **Goal it hurts:** hard-to-get-wrong (a fact written three times), express.
- **Ideal code:**
  ```cp
  var tops: Set<I> = Set()
  let reach = tops.first(where: q => a[q] > total.sum(c.l..stop))?.l ?? I.end
  lost -= tops.count(c..stop) - 1
  ```
- **General fix:** ordered `Map`/`Set` gain `rank`/`count(range)` (an order-statistic
  tree, as `SortedBag` already offers) and a `first(where:)` partition-point search for
  predicates monotone in key order, documented O(log n). Helps every "sweep with a
  monotone stack in a map" port (prefix maxima, convex hull trick, staircase).
- **Dream:** `dream/cf2262b.cp` lines 18, 30, 36 and 48 (one `tops` set: `drain(after:, while:)`, a monotone `bsearch_first`, and `range(r).len` as in `SortedSet`, decisions §103).
- **Area:** containers (`plan/STDLIB.md`).
- **Severity:** high.

## The linter steers a domain-keyed ordered map to an array that cannot answer the query
- **Where:** the first version, `var top_at: Map<I, Int> = Map()`, got L0412 "`Map<I, Int>`
  is keyed by the domain `I`; `[I]?Int` uses one slot per `I` and has no lookup cost",
  and the port gate rejects any lint warning.
- **What felt wrong:** the map existed for `first_gt`/`last_lt`; `[I]?Int` has no ordered
  neighbour queries, so the suggested rewrite breaks the program. It only went away
  because the value happened to be `a[q]`, so a `Set<I>` sufficed; a map from positions to
  a computed value (a running sum, a time) has no warning-free spelling.
- **Goal it hurts:** evidence (a lint that is wrong here), coherence.
- **Ideal code:** no warning when the map's ordered queries are used; or an array of
  optionals that offers `next_present(i)`/`prev_present(i)` so the suggestion is valid.
- **General fix:** L0412 fires only when the map is used for lookup and insert alone;
  longer term an ordered presence structure over a domain (`Marks` with `next`/`prev`
  over values) so the lint's advice always works.
- **Dream:** `dream/cf2262b.cp` line 18 (a domain-keyed ordered set, no lint).
- **Severity:** low.

## Set membership toggles are a remove then a conditional add
- **Where:** `eaters.remove(c)` then
  `if let (q, v) = top_at.first_gt(c), total.sum(c..q) >= v: eaters.add(c)`.
- **What felt wrong:** "c is an eater exactly when this holds" is an assignment of a
  `Bool`, spelt as two mutations with a window where the set is stale.
- **Goal it hurts:** express.
- **Ideal code:** `eaters[c] = top_at.first_gt(c) is (q, v) and total.sum(c..q) >= v`.
- **General fix:** `Set<T>` index assignment with a `Bool` (`s[x] = cond`), as `Bitset`
  and `[D]Bool` already allow; and an `is` pattern test usable in expressions.
- **Dream:** `dream/cf2262b.cp` line 22 (`eaters.set(c, on: ...)`, the spelling `Bitset.set(i, on:)` already uses).
- **Severity:** low.

## A fixed-point walk is a hand-written `loop`
- **Where:**
  ```cp
  var stop = next_top(c)
  loop:
      let reach = ...
      if reach == stop: break
      stop = reach
  ```
- **What felt wrong:** "iterate until it stops moving" is a common shape (doubling walks,
  closure computations) that needs a mutable, a loop, a compare and a break.
- **Goal it hurts:** express.
- **Ideal code:** `let stop = fixpoint(next_top(c), s => reach_from(c, s))`.
- **General fix:** a stdlib `fixpoint(start, step)` documented as running `step` until
  the value repeats. Low priority; the loop is clear.
- **Dream:** `dream/cf2262b.cp` lines 39-41: resolved without a `fixpoint` helper (one use); `reach` is a two-line tail recursion that names the quantity.
- **Severity:** low.
