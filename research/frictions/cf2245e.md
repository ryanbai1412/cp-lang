# Friction: `cf2245e`

## `Dsu.groups()` allocates nested `std::vector<std::vector<int>>` buckets (1.8x slowdown)

- **Severity:** medium
- **Status:** fixed: optimized `Dsu.groups()` to allocate only `parts` buckets with no copy (`0.50s -> 0.42s`, `59 MB -> 35 MB` on `10` × `n = 200k`), flipped `DsuOf.unite` to avoid boxing `?(kept, merged)` (`OptTuple`), and added zero-allocation `Dsu.roots()` / `DsuOf.roots()` / `DsuOf.values()` generators. Rewrote `proto/ports/ecnerwala/cf2245e.cp` to use `DsuOf<X, Int>` + `pieces.values()` (matched to `cf2245e_orig.cpp`): `0.50s -> 0.13s` vs original C++ `0.28s` (`0.46x`, 3.85x faster than old port), RSS `59 MB -> 24 MB`, emitted C++ `10,229 B -> 9,867 B`.
- **Goal it hurts:** performance
- **Measured:** `69.92 ms` vs `38.64 ms` (`1.81x`) on `gen size=25000` (`research/scoreboard.json`).
- **Cause (stdlib cost):** `pieces.groups()` builds and returns a `std::vector<std::vector<int>>` with one heap allocation per component, where the original aggregates per-root counts in flat arrays.
- **Fix:** back `Dsu.groups()` with a flat CSR slice view (two allocations total) or provide per-component fold/count helpers.
