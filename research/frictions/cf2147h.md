# cf2147h — Maxflow GCD Coloring

## `Bitset<D>` lacks `.full`, direct `for v in bitset:` iteration, and `Bitset<D>.empty` symmetry with `Subset<D>`
- **Where:** `cf2147h.cp`, lines 31, 35, and 39:
  ```cp
  for u in nbr.each():
  ...
  var alive = Bitset<V>.from([V] _ => true)
  ...
  for v in alive.each():
  ```
- **What felt wrong:** `Subset<D>` provides `.empty`, `.full`, and direct `for v in s:` iteration, while `Bitset<D>` requires `.new()`, allocating a throwaway `[V]Bool` array (`Bitset<V>.from([V] _ => true)`) just to get the full bitset, and calling `.each()` in every `for` loop (`for v in b` fails with `E0302: a for can't walk over a Bitset<V>`). Two bitmask set types with diverging APIs force the contestant to remember which methods exist on which.
- **Goal it hurts:** coherence, express, performance.
- **Ideal code:**
  ```cp
  var alive = Bits<V>.full
  ...
  for v in alive:
  ```
- **General fix:** Unify `Bitset<D>` and `Subset<D>` surfaces (or merge into `Bits<D>` as in the 0.3 spec): provide `Bitset<D>.full` (filling words directly in O(K/64) without a temporary `[D]Bool`) and implement `Seq` on `Bitset<D>` so `for v in b` works directly. Helps every graph/DP problem using `Bitset<D>`.
- **Severity:** medium.

## No `first` / `find` helper to pick the first element matching a predicate
- **Where:** `cf2147h.cp`, lines 38–43:
  ```cp
  var pick: ?V = none
  for v in alive.each():
      if (adj[v] & alive).len % 2 == 1:
          pick = v
          break
  let v = pick ?? break
  ```
- **What felt wrong:** Finding the first alive vertex with odd degree takes 6 lines of boilerplate (`var pick: ?V = none`, loop, assign, `break`, unwrap-or-break), obscuring the single-sentence loop condition "while some alive vertex has odd degree".
- **Goal it hurts:** express.
- **Ideal code:**
  ```cp
  while let v = alive.find(v => (adj[v] & alive).len % 2 == 1):
      alive.remove(v)
      stk.push(v)
      flip_clique(mut adj, adj[v] & alive)
  ```
- **General fix:** Add `.find(pred) -> ?T` (or `first(seq, pred) -> ?T`) on `Seq<T>` in `std.seq` (lazy, stopping at the first match). Helps every greedy/elimination loop that searches for an element satisfying a condition.
- **Severity:** medium.

## `FlowGraph<V>` has no `.reset()` to reuse capacities across repeated max-flow runs (Gomory-Hu)
- **Where:** `cf2147h.cp`, lines 11–13:
  ```cp
  for i in V:
      if i == V.first: continue
      var fg = FlowGraph<V>()
      for e in edges: fg.add_both(e.u, e.v, e.w)
      g = gcd(g, fg.max_flow(i, par[i]))
  ```
- **What felt wrong:** `FlowGraph<V>` already stores `cap0` alongside `left`, so resetting all flows to zero is a single `left = cap0.copy()` loop, yet there is no `.reset()` method. Gomory-Hu (or any algorithm running `n - 1` flows on the same network) must reallocate `FlowGraph<V>()` and re-insert all `m` edges on every iteration.
- **Goal it hurts:** performance, express.
- **Ideal code:**
  ```cp
  var fg = FlowGraph<V>()
  for e in edges: fg.add_both(e.u, e.v, e.w)
  for i in V:
      if i == V.first: continue
      fg.reset()
      g = gcd(g, fg.max_flow(i, par[i]))
  ```
- **General fix:** Add `pub fn reset(mut self)` to `FlowGraph<V>` restoring `left[k] = cap0[k]` in O(E) without reallocation. Helps Gomory-Hu trees and binary-search-on-flow problems.
- **Severity:** low.
