## `JumpTree` has no distance

- **Goal it hurts:** express
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2152f.cp:25, 30-32`
- **Actual:** `proto/ports/ecnerwala/cf2152f.cp:23, 31-32`
- **General fix:** every rooted tree in `std.tree` that has `lca` and `depth` should also have `dist(a, b)`, as `Tree` already does. Without it, the port writes `depth(i) + depth(i.next!) - 2 * depth(c)` and `depth(st) - depth(top) + 1` by hand.

## No way to grow a `JumpTree` from a parent function

- **Goal it hurts:** express, hard to get wrong
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2152f.cp:19-24`
- **Actual:** `proto/ports/ecnerwala/cf2152f.cp:18-22`
- **General fix:** a constructor `JumpTree<V>.grown(order, parent: v => ...)` that adds vertices in the given order. The two trees could then be two declarations, not one loop that interleaves two `add`s with the `taken` update and has to skip the root with `if i != V.last`.

## No top-down accumulation on an incremental tree

- **Goal it hurts:** express
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2152f.cp:25`
- **Actual:** `proto/ports/ecnerwala/cf2152f.cp:19, 23`
- **General fix:** the same `down(init, (above, v) => ...)` fold from the root that the `wtf26a` friction asks for, on every tree shape. The port keeps a `var taken` that it updates inside the build loop.

## First match after a position needs a binary search with an end sentinel

- **Goal it hurts:** express
- **Severity:** low
- **Area:** stdlib
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2152f.cp:21`
- **Actual:** `proto/ports/ecnerwala/cf2152f.cp:20`
- **General fix:** a sorted-view search such as `V.after(i).first(pred)` that the compiler may run as a binary search when `pred` is monotone over a sorted array (or `x.after(i).partition_point(...)`), returning a `V` and not an `Int` plus `!` that `V(...)` has to wrap.
