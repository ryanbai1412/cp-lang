## A needless `use`
- **Where:** the old first line `use std.seq.{argmax}`.
- **Fix:** removed; `argmax(by:)` resolves from the prelude. Done in this commit.
- **Owner:** idioms (done).

The port is ahead of the dream elsewhere: `a.max_k(BITS)` takes the 30 largest values in \(O(n)\), where the dream sorts all n descending and slices `[..min(n, BITS)].to_list()`. Only those values can ever receive coins, because each bit is fixed by at most one of them. Per query the port copies the 30 values into `buf`, walks the bits from the top, and lifts the value with the largest low part when a bit is missing.

## `max_k` cost 4x the original's memory (fixed in std)
- **Where:** `let top = a.max_k(BITS)`. std `max_k` used to push a `(K, Int, T)` tuple for every element before `select`, so it took 24 B per element on top of `a`.
- **Measured before:** 18.0 MB at `gen.py --max` against 4.2 MB for the original.
- **Repro sent:** `let n: 1..=500_000 = read()` / `let a: [0..n]Int = read()` / `print(a.max_k(30).sum())`, run on n = 5e5, reached 18.4 MB RSS while the array itself is 4 MB.
- **Fix:** stdlib landed 333bc31ad: a 2k-element buffer cut back by `select`, \(O(k)\) extra space. Re-measured below at 6.6 MB; what is left over the original is the 4 MB stored `a`, which the original also keeps but in 4-byte ints (values are under 2^30).
- **Severity:** low now.
- **Owner:** stdlib (done).
