# cf2165c friction report

Port: `corpus/problems/cf2165c/port.cp`. Dream: `corpus/problems/cf2165c/dream.cp`.

## A needless `use`
- **Where:** the old first line `use std.seq.{argmax}`.
- **Fix:** removed; `argmax(by:)` resolves from the prelude. Done in this commit.
- **Owner:** idioms (done).

The port is ahead of the dream elsewhere: `a.max_k(BITS)` takes the 30 largest values in \(O(n)\), where the dream sorts all n descending and slices `[..min(n, BITS)].to_list()`. Only those values can ever receive coins, because each bit is fixed by at most one of them. Per query the port copies the 30 values into `buf`, walks the bits from the top, and lifts the value with the largest low part when a bit is missing.

## `max_k` costs 4x the original's memory
- **Where:** `let top = a.max_k(BITS)`. std `max_k` (std/seq.cp) pushes a `(K, Int, T)` tuple for every element before `select`, so it uses 24 B per element on top of `a`.
- **Measured:** 18.0 MB at `gen.py --max` against 4.2 MB for the original. Time is fine (0.02 s against 0.026 s).
- **Repro:** `let n: 1..=500_000 = read()` / `let a: [0..n]Int = read()` / `print(a.max_k(30).sum())`, run on n = 5e5, reaches 18.4 MB RSS while the array itself is 4 MB.
- **General fix:** a bounded k-element heap (or `select` over indices) so `max_k` uses \(O(k)\) extra space, and its `cost:` says so. The port keeps `max_k`, which is the right spelling.
- **Severity:** medium (4x RSS, within the 256 MB limit).
- **Owner:** stdlib, sent to Core with the repro.
