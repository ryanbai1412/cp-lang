## Symmetric 2D matrices require duplicating writes (`nonneg[i, j]` and `nonneg[j, i]`)
- **Where:** `research/frictions/cf2245d1.ideal.cp` lines 10-15:
  ```cp
  var nonneg = Grid<V, V, Bool>(false)
  for _ in 0..m:
      let (o, i, j): (1..=2, V, V) = read()
      let ok = (o == 1)
      nonneg[i, j] = ok
      nonneg[j, i] = ok
  ```
- **What felt wrong:** Forgetting the symmetric write `nonneg[j, i] = ok` is a classic silent WA bug when reading undirected/unordered pairs `(i, j)` with `i <= j` and later querying `(u, v)` in arbitrary order (`u in pos, v in neg`).
- **Goal it hurts:** hard-to-get-wrong, express
- **Ideal code:**
  ```cp
  var nonneg = SymmetricGrid<V, Bool>(false)
  nonneg[i, j] = (o == 1)
  ```
- **General fix:** Either a `SymmetricGrid<V, T>` / `AdjMatrix<V>` helper in stdlib, or a canonicalized unordered-pair key, so symmetric pair data is written once and safely queried in either order.
- **Severity:** medium

- **What felt wrong:** Computing `count(neg, v => nonneg[u, v])` takes a 4-line mutable counter loop twice, and similarly checking `all` pairs in `valid` takes a nested loop with a mutable `valid` flag.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp

  ```
- **General fix:** Add `count(xs, pred)` (or `xs.count(pred)`) alongside `any`/`all` in the sequence utilities.
- **Severity:** low
