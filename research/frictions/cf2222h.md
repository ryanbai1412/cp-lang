## `Map<List<Int>, Int>` / structural hashing for sequence/partition keys
- **Where:** `research/frictions/cf2222h.ideal.cp` lines 25-31:
  ```cp
  fn orbit_size(start: List<Int>) -> Int:
      var seen = Map<List<Int>, Int>()
      var cur = start
      while !seen.contains(cur):
          seen[cur] = seen.len
          cur = step_freq(cur)
      return seen.len
  ```
- **What felt wrong:** Functional-graph and partition-DP problems naturally memoize or detect cycles over small canonical `List<Int>` states (e.g. sorted integer partitions of $n \le 50$). Without `Ord`/`Hash` on `List<T>` (or a `Set<List<Int>>`), contestants must hand-encode sequences into strings or rolling hashes.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  var seen = Set<List<Int>>()
  while seen.insert(cur):
      cur = step_freq(cur)
  return seen.len
  ```
- **General fix:** Derive lexicographic `Ord`/`Eq` (and `Hash`) for `List<T>` and tuples when `T` supports them, and provide `Set<T>.insert(x) -> Bool` returning whether `x` was newly inserted.
- **Severity:** high

## No stdlib `Comb<M>` (factorials, inverse factorials, binomial / multinomial)
- **Where:** `research/frictions/cf2222h.ideal.cp` lines 34-38:
  ```cp
  var fact: [0..=n]M = M(1)
  for i in 1..=n: fact[i] = fact[i - 1] * M(i)
  var inv_fact: [0..=n]M = M(1)
  inv_fact[n] = fact[n].inv()
  for i in (0..n).rev(): inv_fact[i] = inv_fact[i + 1] * M(i + 1)
  ```
- **What felt wrong:** Every modular counting problem rewrites the exact same 5-line factorial/inverse-factorial precomputation and `binom(n, k)` helper, with easy off-by-one traps when `k < 0` or `k > n`.
- **Goal it hurts:** express, accumulate
- **Ideal code:**
  ```cp
  let comb = Comb<M>(n)
  // comb.fact(k), comb.inv_fact(k), comb.choose(n, k)
  ```
- **General fix:** Include a lightweight `Comb<M>` (or `FactTable<M>`) in `stdlib/mod.cp` with `fact`, `inv_fact`, and `choose` (returning `0` out of range).
- **Severity:** medium
