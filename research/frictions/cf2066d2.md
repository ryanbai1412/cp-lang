# cf2066d2 — D2. Club of Young Aircraft Builders (hard version)

The editorial idea: process floors $1, \dots, n - 1$ from bottom to top (floor $n$ takes the remaining $c$ launches). If floors $< f$ have already taken `used` launches, floor $f$ sees only the remaining launches and stops after $c$ of them, so all of floor $f$'s launches must lie in the prefix of length `used + c`. That requires `used + c > last[f]`, leaves `avail = open[used + c] + fixed_below - used` open slots in that prefix, and assigning $k$ launches to floor $f$ multiplies by $\binom{\text{avail}}{k - \text{fixed}[f]}$.

## No `read(none: 0)` for sentinel-encoded optional arrays (`[Time]?Floor`)
- **Where:** `proto/ports/ecnerwala/cf2066d2.cp` lines 16, 22-26:
  ```cp
  let raw: [Time](0..=100) = read()
  ...
  if raw[tm] > 0:
      let f = Floor(raw[tm])
  ```
- **What felt wrong:** The input uses `0` for a missing floor and `1..=n` for a `Floor`. Without `read(none: 0)` on `[Time]?Floor`, we must read raw integers `0..=100` (repeating the static bound `100` instead of `n`) and manually cast `Floor(raw[tm])` after checking `> 0`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:**
  ```cp
  let a: [Time]?Floor = read(none: 0)
  ```
- **General fix:** Support `read(none: sentinel)` for `?T` (and arrays of `?T`) so sentinel-encoded optionals (`0` or `-1` in contest input) become typed `?Floor` at the I/O boundary.
- **Dream:** `dream/cf2066d2.cp` line 15.
- **Severity:** medium

## Inner DP loop is 1.41x slower than C++ (0.31 s vs 0.22 s on $n = 100, c = 100, m = 10^4$)
- **Where:** `proto/ports/ecnerwala/cf2066d2.cp` lines 39-40:
  ```cp
  for k in fixed[f]..=min(c, m - c - used):
      ndp[used + k] += ways * comb.choose(avail, k - fixed[f])
  ```
- **What felt wrong:** On the max input ($O(n m c) \approx 5 \cdot 10^7$ inner iterations), the port takes 0.31 s vs 0.22 s for the C++ original (1.41x). Two causes: (1) `Mod<1_000_000_007>` stores 64-bit `int64_t` and runs 64-bit `%` instead of 32-bit `int32_t` storage, and (2) `comb.choose` calls `ensure(...)` on every inner iteration even when `Comb` was pre-sized to `100` above the loop.
- **Goal it hurts:** performance
- **Ideal code:**
  ```cp
  ndp[used + k] += dp[used] * comb.choose(avail, k - fixed)
  ```
  (with 32-bit `Mod<P>` storage and no `ensure` branch when `Comb` is fixed-size).
- **General fix:** Pack `Mod<P>` into `int32_t` when $P < 2^{31}$, and keep `Comb.choose` branch-minimal (inline fast path `if n < f.len`) so tight $O(10^8)$ binomial loops match hand-written C++.
- **Dream:** `dream/cf2066d2.cp` line 31.
- **Severity:** high

## No `Floor.init` (`1..n`) and no `--- multitest ---` divider below shared `Comb`
- **Where:** `proto/ports/ecnerwala/cf2066d2.cp` lines 10-11, 32-33:
  ```cp
  let t: 1..=10_000 = read()
  for _ in 0..t:
  ...
  for fi in 1..n:
      let f = Floor(fi)
  ```
- **What felt wrong:** Dropping the last element of a domain (`Floor.init`, i.e., all floors except the top floor `n`) requires iterating raw `Int` `1..n` and converting `Floor(fi)` on each iteration; and sharing `comb` across test cases requires dropping `@!multitest`.
- **Goal it hurts:** express
- **Ideal code:**
  ```cp
  --- multitest ---
  ...
  for f in Floor.init:
  ```
- **General fix:** Add `.init` (all elements except `.last`, symmetric with `.rest`) on domains, and support `--- multitest ---` below shared precomputation.
- **Dream:** `dream/cf2066d2.cp` lines 11, 22.
- **Severity:** low
