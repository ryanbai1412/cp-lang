# cf2180f2 — Control Car (Hard Version)

The editorial idea: the F1 sweep gives the answer for every `n <= 50` and
`m <= 600`; for a fixed `n` the answer is a linear recurrence in `m`, so
tabulate 600 columns, find the recurrence with Berlekamp–Massey and evaluate
it at `m` up to `1e15`. The port is the F1 sweep plus three lines, and
`guess_at` (Berlekamp–Massey plus Kitamasa, returning `none` when 600 terms
do not pin the recurrence) is exactly the editorial's "guess it" step. All of
F1's frictions apply unchanged; these are the ones F2 adds.

## The F1 sweep is copied, not reused
- **Where:** `cf2180f2.cp`, lines 17–37, identical to `cf2180f1.cp`, lines
  17–37, apart from the two domain lines.
- **What felt wrong:** F1 and F2 share their whole model; the only difference
  is the table size and the query. There is no way to import a top-level
  computation from another program, and turning it into a library function
  means writing `fn stops(I, J) -> [I, J]Z` with domain parameters, which
  the language has no spelling for, so the 21 lines are pasted. A bug fixed
  in one is not fixed in the other.
- **Goal it hurts:** accumulate, express (one fact in one place).
- **Ideal code:** in the dream the sweep is still written out, but as a unit
  that another program can `use` — `dream/cf2180f2.cp`, lines 13–30, with the
  domains as the only parameters (lines 13–14).
- **General fix:** functions generic over domains (`fn stops<domain I,
  domain J>() -> [I, J]Z`) and importing a sibling file as a library, so a
  personal library can hold a solved subproblem.
- **Severity:** medium.

## `guess_at` lives in `std.spec` and needs a `use`
- **Where:** `cf2180f2.cp`, line 11: `use std.spec.{guess_at}`.
- **What felt wrong:** I looked for `berlekamp_massey` in the prelude and in
  `std.math`; it is in `std.spec` ("specification" helpers), next to
  `dnc_break` and `convexity_break`. The error names the fix, but the module
  name is not guessable, and `guess_at(xs, n)` takes the index positionally,
  so `guess_at(counts, m - 1)` does not say which argument is the index.
- **Goal it hurts:** express (unguessable).
- **Ideal code:** no `use` line, and `guess_at(..., at: m - 1)` —
  `dream/cf2180f2.cp`, line 33.
- **General fix:** recurrence tools in the prelude or in `std.math` with the
  other sequence tools; named index argument.
- **Severity:** low.

## Gluing the F1 table into a sequence crosses domains three times
- **Where:** `cf2180f2.cp`, lines 41–43:
  ```cp
  let i = I(n - 1)
  let counts = [Z(4) ** ((n + 1) * (j.to_idx + 2)) * stopped[i, j] for j in J]
  print(guess_at(counts, m - 1)!)
  ```
- **What felt wrong:** `n - 1` and `j.to_idx + 2` restate that `I` and `J` are
  0-based shifts of `n` and `m`; the column index becomes an `Int` exponent,
  and the query index `m - 1` is an `Int` into a list built over `J`. Each is
  an off-by-one waiting to happen (the original has `n--, m--` and `j + 2`
  and `i + 2` for the same reason). `Z(4)` must stay wrapped: the friction
  lint calls it stale, but `4 ** e` in a `Z` context is computed in `Int` and
  overflows (see `cf2180f1.md`).
- **Goal it hurts:** hard-to-get-wrong (off-by-one, wrong index space).
- **Ideal code:** `inside[..n, ..=j]` indexed by counts, not positions, and
  `4 ** ((n + 1) * (j + 2))` with `Z` inferred — `dream/cf2180f2.cp`, line 33.
- **General fix:** prefix-sum views indexed by ranges (`..n` is "the first n
  rows"), and expected-type propagation into literal arithmetic.
- **Severity:** medium.
