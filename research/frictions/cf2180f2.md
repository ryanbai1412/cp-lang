# cf2180f2 — Control Car (Hard Version)

The editorial idea: the F1 sweep gives the answer for every `n <= 50` and
`m <= 600`; for a fixed `n` the answer is a linear recurrence in `m`, so
tabulate 600 columns, find the recurrence with Berlekamp–Massey and evaluate
it at `m` up to `1e15`. The port is the F1 sweep plus three lines, and
`guess_at` (Berlekamp–Massey plus Kitamasa, returning `none` when 600 terms
do not pin the recurrence) is exactly the editorial's "guess it" step. All of
F1's frictions apply unchanged; these are the ones F2 adds.

## The F1 sweep is copied, not reused
- **Where:** `port.cp`, lines 21-45: `type Ways`, `state` and
  `fn stops<domain I, domain J>() -> [I, J]Z` are F1's sweep (`cf2180f1`
  `port.cp`, lines 18-44) as a domain-generic function.
- **What felt wrong:** F1 and F2 share their whole model; the only
  difference is the table size and the query. Functions generic over domains
  work today (this port's `stops<I, J>()`), but there is no way to import it
  from F1: `use cf2180f1.{stops}` is E0206 "no module `cf2180f1`", whose help
  asks for a `[libs]` entry in `cp.toml`, and a program file (statements, a
  `read`) cannot be a library (R11.1.2). So 20 lines are pasted and a bug
  fixed in one is not fixed in the other.
- **Goal it hurts:** accumulate, express (one fact in one place).
- **Ideal code:** `use cf2180f1.{Z, stops}` — `dream.cp`, line 9.
- **General fix:** a program file's `pub` items importable as a library
  (its statements are not run), so a solved subproblem in one solution is a
  library to the next without moving it out of the file.
- **Severity:** medium.

The F1 sweep's `state` helper and per-field tuple sums are copied too:
`+` on records is E0309 (`type W = (a: Z, b: Z); let x: W = (1, 2); x + x`),
and deriving the corner counts from the rule through a closure costs 1.3x,
see `cf2180f1.md`.

## `guess_at` lives in `std.spec` and needs a `use`
- **Where:** `port.cp`, line 13: `use std.spec.{guess_at}`.
- **What felt wrong:** I looked for `berlekamp_massey` in the prelude and in
  `std.math`; it is in `std.spec` ("specification" helpers), next to
  `dnc_break` and `convexity_break`. Without the `use` it is E0201 "no
  `guess_at` in scope" (the help names the fix), but the module name is not
  guessable, and `guess_at(xs, n)` takes the index positionally.
- **Goal it hurts:** express (unguessable).
- **Ideal code:** no `use` line, and `guess_at(..., at: m)` —
  `dream.cp`, line 17.
- **General fix:** recurrence tools in the prelude or in `std.math` with the
  other sequence tools; named index argument.
- **Severity:** low.

## The query line keeps two literal casts
- **Where:** `port.cp`, lines 30 and 54:
  ```cp
  let weight = [(Z(1) / 4) ** (2 * d + 3) for d in 0..I.len + J.len]
  let count = [Z(4) ** ((n + 1) * (Int(k) + 1)) * inside.prefix(I.cuts(n), k) for k in J.cuts]
  ```
- **What changed:** the glue no longer crosses index spaces by hand. The
  sequence runs over the column cuts (`k in J.cuts`, so `count[m]` is the
  answer for `m` columns and the query is `guess_at(count, m)`, no `m - 1`),
  rows are a count (`I.cuts(n)`, no `n - 1`), and `Prefix` replaces the
  hand-kept `column`/`stopped` running sums. The `k = 0` term (an empty
  grid, 0) adds one to the recurrence order, which `guess_at` absorbs.
- **What still feels wrong:** `Z(1) / 4` and `Z(4)` stay wrapped: in a `Z`
  context `let q: Z = 1 / 4` prints 0 (Int division first) and `4 ** 40`
  is R0202 integer overflow. `Int(k) + 1` turns a cut into an exponent.
- **Goal it hurts:** hard-to-get-wrong (wrong modulus/arithmetic P0).
- **Ideal code:** `4 ** ((n + 1) * (j + 2))` with `Z` inferred —
  `dream.cp`, line 17.
- **General fix:** expected-type propagation into literal arithmetic (or an
  error for `Int / Int` coerced to `Mod`), as in `cf2180f1.md`.
- **Severity:** medium.

## Measurements
- Recurrence order: `berlekamp_massey` over the 601 counts gives 2n + 1 for
  every n (101 at n = 50), so 601 terms pin it with room to spare.
- Max input (`gen.py --max`: `n = 50`, `m = 1e15`), `cpl build --judge
  codeforces`, `g++ -std=c++17 -O2`, mean of 50 runs: port 4.6 ms, original
  13.4 ms; 50 tests of `n = 1` (the port runs Berlekamp-Massey per test):
  port 4.4 ms, original 12.5 ms.
- Emitted C++: 25950 bytes (was 25245; `Prefix` adds about 650 bytes of library
  fns).
- Agreement with `orig.cpp`: `tests/1.in` and 120 `gen.py` seeds, exact.
