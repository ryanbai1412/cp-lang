# cf2183f — Jumping Man

The editorial idea: the sum of squared counts of strings is the number of
ordered pairs of jump chains that spell the same string. Let `f(u, v)` count
pairs whose chains start at `u` and `v`: zero unless the letters match, else
one (both stop) plus every pair starting strictly below `u` and strictly
below `v`. A subtree is a preorder interval, so "strictly below `u` and
strictly below `v`" is a rectangle of the `f` table, a 2D suffix sum gives it
in O(1), and the answer for `i` is the square `sub(i) x sub(i)`. That is one
`n x n` table; the original keeps two and pushes sums to parents. The port is
this idea in eight lines over the cuts of the tree's own positions
(`Bounds<t.Pre>`), with `t.below(u)` for "strictly below".

## Preorder positions cannot index a table of cuts, so the port drops to `Int`
- **Status:** fixed in the tree lane. Cuts already existed (`D.bounds`,
  spelled `Bounds<D>` in a type); the table is now
  `[Bounds<t.Pre>, Bounds<t.Pre>]Z`, subscripts are `x.l` / `x.r` and the
  ranges' `.lo` / `.hi`, and `Rooted.below(v)` is the subtree without `v`.
  Two core gaps remain: `t.Pre.bounds` is not accepted where `V.bounds` is,
  and a `fn` signature cannot name `Range<t.Pre>`, so `rect` is generic
  (`fn rect<R>(a: R, b: R)`); a top-level closure instead lowers to
  `std::function` and costs 5% here.
- **Where:** `cf2183f.cp`, lines 16–18 and 21–28 before this rewrite:
  ```cp
  domain P = 0..=n
  let lo = [V] v => t.pos(v).to_idx
  let hi = [V] v => lo[v] + t.size(v)
  var suf: [P, P]Z = 0
  ...
  suf[P(x), P(y)] = f + suf[P(x + 1), P(y)] + suf[P(x), P(y + 1)] - suf[P(x + 1), P(y + 1)]
  ```
- **What felt wrong:** `Rooted` gives each tree its own position domain
  `t.Pre` and `t.sub(v)` as a `Range<Pre>`, which is exactly the safety I
  want. But a suffix sum needs the cut after the last position (`n`), which
  is not a `Pre`, so the table cannot be `[t.Pre, t.Pre]Z`. I rebuilt the
  interval ends as `Int`s, declared a separate `0..=n` domain and wrapped
  every subscript in `P(...)`: eight conversions where the type system no
  longer knows these are positions of this tree, and `x + 1` past a
  subtree's end is unchecked.
- **Goal it hurts:** hard-to-get-wrong (wrong index space, off-by-one),
  express.
- **Ideal code:** `RectSums<[t.Pre, t.Pre]Z>` summed over `t.below(u)` and
  `t.sub(i)` ranges — `dream/cf2183f.cp`, lines 15–18.
- **General fix:** every domain `D` has a cut domain `D.cuts` (positions plus
  one end), ranges are pairs of cuts, and range-summed structures take
  `Range<D>`; `Rooted` adds `below(v)` (the subtree without `v`). This is
  the positions-vs-cuts P0 the goals name.
- **Severity:** high.

## Inclusion–exclusion on a 2D suffix sum is written by hand, twice
- **Status:** fixed by decision 114 (`Prefix<R, C, T>.filling(order: FillOrder.Reverse)` + `.set(...)` + `.sum(...)` in `stdlib/prefix.cp`, adopted in `cf2183f.cp` and `cf2229e.cp`).
- **Where:** `cf2183f.cp`, lines 22–23 and 28:
  ```cp
  fn rect(x0: Int, x1: Int, y0: Int, y1: Int) -> Z =
      suf[P(x0), P(y0)] - suf[P(x1), P(y0)] - suf[P(x0), P(y1)] + suf[P(x1), P(y1)]
  ```
- **What felt wrong:** the table is "f, queried by rectangle", but I maintain
  its suffix sums myself: once for the query, once for the update, eight
  signed corner terms in all, the classic sign or `+ 1` bug. The same shape
  appears in cf2180f1 (2D prefix sum of stops). The helper has one use, so
  by the design rules the general mechanism is missing.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** `f[t.pos(u), t.pos(v)] = ... f.sum(t.below(u), t.below(v))`
  and `f.sum(t.sub(i), t.sub(i))` — `dream/cf2183f.cp`, lines 17–19.
- **General fix:** a stdlib 2D (and nD) prefix-sum view over an array that is
  filled in an order compatible with the sums (suffix order here), with
  `sum(range, range)`; it costs exactly the four lookups.
- **Severity:** medium.

## Reverse preorder is `t.at.rev`, a struct field
- **Status:** settled by decision 63: `for v in t.at.rev` is the documented
  spelling and `preorder` / `postorder` are gone.
- **Where:** `cf2183f.cp`, lines 21–22: `for u in t.at.rev:`.
- **What felt wrong:** the fill order is "vertices in reverse preorder". I
  found it by reading `stdlib/tree.cp`: `at` is the `[Pre]V` inverse of `pos`,
  and iterating it yields vertices in preorder. Nothing called `preorder`
  exists, and `at` reads like a method taking an argument. The nested loop
  over pairs is also two loops where the idea is one product.
- **Goal it hurts:** express (unguessable).
- **Ideal code:** `for u in t.at.rev, v in t.at.rev:` —
  `dream/cf2183f.cp`, line 16.
- **General fix:** the stdlib has since settled on `t.at` as the one
  preorder iteration and dropped `preorder`/`postorder`; what remains is
  making `t.at` findable (docs and completion say "preorder") and product
  iteration over two iterables.
- **Severity:** low.

## Reading a tree spells its edge count and its graph
- **Status:** partly fixed. `Rooted(Graph.undirected(read<Tree<V>>()), root: V(1))`
  is one line. `Rooted` of a bare `Tree<V>` needs a `Neighbours` impl for an
  edge-list array, which the language cannot declare (no impls on array
  types); logged for the core lane.
- **Where:** `cf2183f.cp`, line 15:
  ```cp
  let t = Rooted(Graph.undirected(read<Tree<V>>()), root: V(1))
  ```
- **What felt wrong:** "read a tree on V rooted at 1" is the most common tree
  input; it fits on one line, but still wraps the edge list in the
  undirected graph that "tree" already means, and `V(1)` restates that `V`
  starts at 1.
- **Goal it hurts:** express.
- **Ideal code:** `let t = Rooted(read<Tree<V>>(), root: V.first)` —
  `dream/cf2183f.cp`, line 13.
- **General fix:** `Rooted` accepts a `Tree<V>` edge list directly.
- **Severity:** low.

## Core gaps left by the typed rewrite
Each is reproduced by `cf2183f.cp` as it stands; owner: core.
- **`t.Pre.bounds` is rejected.** `V.bounds` names the cuts of a declared
  domain, but the same member on a domain held by a value (`t.Pre`) is "not a
  member"; the port spells the type `Bounds<t.Pre>` instead (line 18). Fix:
  domain members resolve the same way for declared and value-held domains.
- **A `fn` signature cannot name `Range<t.Pre>`.** `fn rect(a: Range<t.Pre>,
  b: Range<t.Pre>)` fails with "`t.Pre` is not a type"; `rect` is generic
  over `R` (line 20), and a closure would lower to `std::function` (5%
  slower). Fix: value-held domains are nameable in signatures in scope.
- **No impls on array types.** `Rooted(read<Tree<V>>(), root: V(1))` needs
  `Neighbours` for the edge-list array `Tree<V>`, which no library can
  declare; the port wraps it in `Graph.undirected` (line 15). Fix: allow an
  impl on an array type alias (or make `Tree<V>` a record over the array).
- **No position from an `Int` in a value-held domain.** `human.Pre(i)` is "no
  method `Pre`" although `V(i)` works on a declared domain, so a sweep that
  walks `human.at` by a raw counter copies it into a list first
  (`proto/ports/scout_batch_27/ioi18p3.cp` line 65, `let euler = [v for v in
  human.at]`; the same in `scout_batch_26/ioi18p3.cp` and `ceoi22p3.cp`). Fix:
  the same domain-member rule as `t.Pre.bounds`.
- **Owner:** core.
- **Goal it hurts:** express, coherence.
- **Severity:** medium.

## The interpreter needs 3 GB and 53 s on the max input
- **Where:** `cf2183f.cp`, line 21: `var suf: [P, P]Z = 0` (25M cells).
- **What felt wrong:** the compiled port runs the max input in 0.23 s and
  200 MB; `cpl run` takes 53.2 s and 3148284 KB, so about 125 bytes per
  table cell. Debugging a wrong answer on a large case in the interpreter is
  not practical, and on a 1 GB judge-like limit the interpreter cannot run
  the program at all. The gate only passes with `INTERP_TIMEOUT=900`.
- **Goal it hurts:** evidence (doubt to evidence), submission (interpreter
  and C++ agree on every program).
- **Ideal code:** unchanged — the dream's table is the same size.
- **General fix:** the interpreter stores typed arrays unboxed (a `[P, P]Z`
  is one flat buffer of residues), and runs hot loops without per-value
  allocation.
- **Severity:** medium.
