# cf2129f1 — F1. Top-K Everywhere (Easy Version)

The editorial idea: assign each value `1..=845` a distinct subset of 30 queries with query 0 used `<= 300` times (one type-4 query) and each query `1..30` used `<= 60` times (29 type-2 queries). The 30 query responses give each position a unique signature that directly decodes the permutation.

  ```cp
  let t: 1..=40 = read()
  repeat t:
      ...
      print(kind, held.len, held)
      let resp: [0..held.len]Pos = read()
  ```
- **What felt wrong:** Shared precomputation (`masks`, `value_of`) cannot live above `@!multitest`, forcing a manual `repeat t:` loop, and interactive queries repeat `print(...)` + `read()`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2129f1.cp` lines 38-42):**
  ```cp
  fn query_positions(q: Query, held: List<MaxVal>) -> List<Int>:
      let kind = if q == Query.first: 4 else: 2
      ask<[held.len]Int>(kind, held.len, held)

  @!multitest
  ```
- **General fix:** Support `@!multitest` below top-level shared setup (core) and an `ask<T>(...)` interactive query helper (io area lane).
- **Severity:** medium

## No `.inverse()` for domain-indexed tables of non-domain values (owned by containers / sequences area lane)
- **Where:** `proto/ports/ecnerwala/cf2129f1.cp` lines 46-47 (`dream/cf2129f1.cp` line 36):
  ```cp
  var value_of = Map<Int, MaxVal>()
  for v in MaxVal: value_of[masks[v]] = v
  ```
- **What felt wrong:** `.inverse()` only handles `[D]E` when `E` is another domain; inverting `[MaxVal]Mask` (or `[MaxVal]Int`) into a `Map<Mask, MaxVal>` requires a manual loop. Also `Set<Query>` lacks a `{}` empty-set literal (`dream/cf2129f1.cp` line 45) and `SortedSet<Set<Query>>` (`dream/cf2129f1.cp` line 22) is not available as a hashable/ordered set key.
- **Goal it hurts:** express
- **Ideal code (`dream/cf2129f1.cp` line 36):** `let value_of = masks.inverse()`
- **General fix:** Generalize `.inverse()` on `[D]T` to return `Map<T, D>` for arbitrary hashable/comparable `T`, and support `Set<D>` as a map/set key.
- **Severity:** low

## `Bitset<D>` cannot be used as a `Set`/`Map` key in C++ (`cpl::CpHash` missing `cpl::Row` overload)
- **Where:** `proto/ports/ecnerwala/cf2129f1.cp` lines 19-60 (`dream/cf2129f1.cp` lines 22, 36).
- **What felt wrong:** `Set<Bitset<Query>>` and `Map<Bitset<Query>, MaxVal>` pass `cpl check`, then fail `g++` because `cpl::CpHash` has no overload for `cpl::Row<unsigned long long, 1>` inside `Bitset<D>`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code:** `Set<Bitset<Query>>` and `Map<Bitset<Query>, MaxVal>` instead of raw `1 << q.ord` `Int` masks.
- **General fix:** Add a `cpl::CpHash` specialization for `cpl::Row<T, N>` (codegen / containers area lane).
- **Area:** containers
- **Severity:** medium
