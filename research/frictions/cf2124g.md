# Friction: `cf2124g`

## No `prefix_mins()` / `suffix_sums()` / `suffix_maxs()` sequence helpers
- **Status:** closed (`scan` / `suffix_scan` now support method syntax `a.scan(min)`, `pref_min.suffix_scan(+)`, `ans.suffix_scan(max)`; `prefix_mins`/`suffix_maxs` are replaced by `.scan(min)`/`.suffix_scan(max)`; `with_first` and `suffix_sums(from:)` are not in the design — single-use helpers covered by `[cap] + a[i + 1..j]` and `suffix_scan(+)` / `prefix(a)`).
- **Where:** `cf2124g.cp` lines 13–14, 28–31, 45–46, 51 (`dream/cf2124g.cp` lines 13, 27–28, 42, 47):
  ```cp
  var pref_min: [Pos]Int = a
  for i in Pos if i != Pos.first: pref_min[i] min= pref_min[(i - 1)!]
  ...
  for d in (1..n).rev: ans[d - 1] max= ans[d]
  ```
- **What felt wrong:** Prefix minima, suffix sums (seeded from a right boundary value), and suffix maxima are each written as manual loops over `Pos` / `0..n`.
- **Goal it hurts:** express
- **Ideal code (`dream/cf2124g.cp` lines 13, 27–28, 47):**
  ```cp
  let pref_min = a.prefix_mins()
  lifted[i..j] = a[i..j].with_first(cap).prefix_mins()
  suff_loss[i..j] = lifted[i..j].suffix_sums(from: suff_loss[j])
  print(ans.suffix_maxs())
  ```
- **General fix:** Add `prefix_mins`, `suffix_sums`, and `suffix_maxs` in `std.seq` / `std.prefix`.
- **Severity:** low

## Converting between `Pos` and `Pos.bounds` (`i.ord..j`) drops to `Int`
- **Where:** `cf2124g.cp` lines 28–47 (`dream/cf2124g.cp` lines 27–43):
  ```cp
  for t in i.ord..j:
      lifted[Pos(t)] = ...
  ```
- **What felt wrong:** Iterating a half-open subrange `[i, j)` of `Pos` where `j` starts at the past-the-end cut `n` drops to raw `Int` `i.ord..j` and `Pos(t)` casts.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2124g.cp` lines 30–38):** Iterate `Pos` directly across `[i.l..j]` using `Pos.bounds` cuts (`k.prev!`, `k - i.l`, `pos - i`).
- **General fix:** Allow iterating and slicing `[Pos]T` with `Pos.bounds` cuts and subtracting two `Pos` values directly to get distance.
- **Severity:** low

## `Pos.Cut` as a value is not supported (`E0501`)
- **Where:** `dream/cf2124g.cp` lines 28, 35, 40, 43, 50, 53 (`var end_cut = Pos.Cut.last`, `orig_suff[Pos.Cut.first]`, `a[i.l..end_cut]`).
- **What felt wrong:** Tracking the right boundary of the current prefix-min block as a `Pos.Cut` value fails with `E0501`, forcing raw `Int` `j = n` in `cf2124g.cp`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2124g.cp` lines 28, 35, 40, 53):** `var end_cut = Pos.Cut.last` and `let blk = a[i.l..end_cut]`.
- **General fix:** Lower domain `.Cut` types as first-class values in the backend (same representation as `0..=n`).
- **Severity:** medium
