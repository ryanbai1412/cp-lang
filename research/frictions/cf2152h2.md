# cf2152h2 friction

The port keeps the original's algorithm (Kruskal heaviest first, a slope-trick
function per component as a meldable heap of breakpoints) and derives it in
the header; the raise step is one named fn with a guarded `while let`.
`.divmod`, `partition_point` (a `Cut`, no `?? len`), `repeat` and
`sorted(desc:)` now replace the hand forms. `MeldHeap` exists in `std.heap`,
but the port still keeps its hand skew-heap arena `Breaks`: `MeldHeap` cannot
hold a breakpoint record, and is 2.2-3.4x slower here (below).

## `MeldHeap` is too slow for slope-trick merging

- **Goal it hurts:** performance
- **Severity:** high
- **Area:** stdlib
- **Status:** open
- **Dream:** `corpus/problems/cf2152h2/dream.cp:14,24,29-32,39,43,45,47`
  (`MeldHeap<...>`, `.top`, `.pop()`, `.push_all(...)`, `.meld(...take())`, `.drain()`)
- **Actual:** `corpus/problems/cf2152h2/port.cp:14-33` defines `Breaks`, a
  skew-heap arena (parallel lists, `?Int` roots), and threads roots through
  `single`/`meld`/`rest` by hand.
- **Run:** the dream's form, with a `Break` struct (next section), checks,
  lints clean and matches `orig.cpp` on every max input, but on n = q =
  250,000 it takes 0.38-0.57 s and 117-198 MB against the arena port's
  0.15-0.17 s and 30-43 MB (`absorb(mut ...)` in place of `meld(take())`;
  `meld(take())` is slower still). perf: `MeldHeap.merge` 22%, `take` 9%,
  `malloc` 5%. `meld` copies all of `other`'s node arrays, so it is
  O(|other|), not the documented O(log n), and each vertex's heap owns four
  lists.
- **General fix:** one shared node arena per heap family (as `Breaks`
  does), so `meld` is O(log n) pointer work with no copying, `take` is O(1)
  and a singleton heap allocates nothing. Slope trick on trees and every
  mergeable-priority-queue port need it.

## `MeldHeap<T>` requires `T: Add`

- **Goal it hurts:** express
- **Severity:** medium
- **Area:** stdlib
- **Status:** open
- **Run:** `var h: MeldHeap<(Int, Int)> = MeldHeap(); h.push((2, 1))` is
  E0309 "`+` can't be applied to `(Int, Int)`": the bound sits on the struct,
  though only `add_all` adds. A heap of `(at:, cnt:)` records needs a fake
  `impl Add`.
- **General fix:** put `T: Add` on `add_all` alone (a method-level bound),
  so any ordered `T` is a `MeldHeap` element.

## Small gaps

- **Goal it hurts:** express
- **Severity:** low
- **Area:** stdlib
- **Status:** open

- `MeldHeap.push_all` / `Heap.push_all` take a `List<T>`, so a filtered
  literal needs `List(...)` (`push_all(added)` with `added = [...].filter(...)`
  is E0302). General fix: take any `Seq<T>`.
- `dream:52` `breaks.count_below(l)`: the port writes
  `breaks.partition_point(b => b >= l)`, a `Cut` that feeds `below.prefix`
  directly. Not a gap.

## Measurement

Max case (n = q = 250,000, one test; random, path and near-path trees),
reference `orig.cpp` with its recursive lambda as `std::function` so
g++ 11 -std=c++17 -O2 builds it: orig 0.16-0.19 s / 47 MB, port 0.15-0.17 s
/ 30-43 MB, same output. Emitted C++ 22,178 -> 23,851 bytes
(`partition_point` and `divmod` from std).
