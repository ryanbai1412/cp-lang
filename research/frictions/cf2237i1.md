# cf2237i1 — Tree Labels (easy)

Both run a tree DP over `State(depth, active, resolved)` with `lift` and `merge_edge`, keeping a
`[Bool, Bool]Z` table per depth.

## The port inlines two dream helpers
- **Where:** dream `fn add(mut out: List<Table>, s: State, w: Z)` and `fn states(rows) -> List<(State, Z)>`;
  the port writes `out[nd][na, nr] += w` in place and walks the rows directly.
- **What:** no measured reason: on `--max` the two runs took 0.50 / 0.41 s and then 0.48 / 0.56 s
  (port / dream), same output, so the difference is noise. The dream's helpers name the state
  each write targets; the port's direct index is shorter. Either reads well; no gap.

## Map defaulting
The review's open note: `next[s] = (next.get(s) ?? Z(0)) + ...` is `next[s] += ...` on a map with a
default, and `[w for (_, w) in dp[...].items].sum()` is `.values.sum()`. Owed rewrite; owner idioms.
