# Friction: `cf2268c`

## `SparseTable` uses `std::function` + nested 64-bit vectors and `Ends` allocates per iteration (2.6x slowdown, 6.2x RSS)

- **Severity:** medium
- **Goal it hurts:** performance
- **Measured:** `439.0 ms` vs `207.3 ms` (`2.12x`, RSS `30.7 MB` vs `6.6 MB`, emitted `15,034 B`) on `gen size=25000` (down from `580.16 ms` / `2.62x` / `6.20x` RSS after static `SparseTable.op` lowering `08e78a90`, flat `SparseTable` storage `eb467178`, and scalar `Ends(lo0, lo1, hi0, hi1)` eliminating per-iteration `[0..2]Int` heap allocations).
- **Remaining cause:** `SparseTable<I, Int>` stores `n log n` 64-bit `Int`s (`~28.8 MB`) and `feasible` sorts 24 B tuples (`bounds.sort()`), whereas `cf2268c_orig.cpp` uses a bucketed 32-bit `RangeMaxQuery<int>` (`O(n)` space) and `gp_hash_table`.
- **Fix:** bucketed `SparseTable` / `I32` element width support and stack-allocated small fixed arrays `[0..2]Int`.

## The monotone stack over a class's gaps is written by hand

- **Severity:** medium
- **Goal it hurts:** express
- **Where:** `cf2268c.cp`, lines 34–49: the cuts are sorted into classes, each cut looks one ahead (`cuts.get(t + 1).filter(...)`) to find the gap maximum to the next cut of its class, and a stack pops and merges `Ends` while the gap maximum grows.
- **Dream:** `dream/cf2268c.cp` lines 30–35: `chunk_by` splits the sorted cuts into classes, and `cuts.cartesian(gap:, leaf:, join:)` yields every internal node of the Cartesian tree of gap maxima as `(m, left, right)`, with `left` and `right` the monoid folds of the leaves on each side.
- **General fix:** a sequence fold along the Cartesian tree of the separators between consecutive items, parameterized by a separator key and a leaf monoid, yielding each merge lazily so `any` can stop early. It covers "count/check pairs whose range maximum is X" problems, which today each rewrite the same stack.

## A user monoid on a struct does not lift over `?T`

- **Severity:** low
- **Goal it hurts:** express
- **Where:** `cf2268c.cp`, lines 17–21: `hull` and `wide` exist only to say "`none` is the identity" and "a missing side never reaches".
- **Dream:** `dream/cf2268c.cp` lines 14, 18 and 21: `Span.join` is defined once on `Span`, `even.join(o.even)` applies it to `?Span` with `none` absorbed, and `right.odd.hi - even.lo ?? 0` reads fields through optionals.
- **General fix:** the Tropical Optional Rule already lifts `min`/`max`/`+` over `?T`; extend it to any method declared as a monoid `join(self, o: Self) -> Self`, and let field access on `?T` yield `?Field`.

## No elementwise mask or named `xor` for folds

- **Severity:** low
- **Goal it hurts:** express
- **Where:** `cf2268c.cp`, line 33: `prefix_fold((x, y) => x ^ y, [I] i => a[i] & v)`.
- **Dream:** `dream/cf2268c.cp` line 27: `(a & v).prefix_fold(xor)`.
- **General fix:** operator values (`xor`, like `max`) usable wherever an op is taken, and broadcasting a scalar operator over a `[D]T` as a lazy view so the mask doesn't allocate.

## `[Bool] p => ...` binds `p` as an `Int`, and `type Cut = I.bounds` is not `I.bounds`

- **Severity:** medium
- **Goal it hurts:** coherence
- **Where:** `cf2268c.cp`, line 15: `Span` uses `I.bounds` directly and `Ends` names its two parities as fields. A `[Bool]?Span` built with `[Bool] odd => if odd == b.odd ...` fails with "can't compare a `Int` with a `Bool`", and with `type Cut = I.bounds` a `Cut` from `for c in Cut` is rejected where a field is declared `I.bounds`.
- **Dream:** `dream/cf2268c.cp` line 17 keeps the two fields, which read well here; the bugs block the `[Bool]` form in general.
- **General fix:** a table builder's binder takes the declared index type, and a type alias is the same type as its expansion everywhere.

## `?Span` brings in the niche-optional runtime (+6.9 KB)

- **Severity:** low
- **Goal it hurts:** performance
- **Measured:** emitted C++ grows from 13,717 B to 20,644 B; runtime is unchanged (0.42 s vs 0.41 s on `gen 7 25000`, RSS 21.0 MB vs 20.3 MB). About 6 KB is the shared `Niche`/`OptField`/`OptTuple` support for an optional struct, the rest `prefix_fold`. The optional is the type the review asked for in place of `INF`/`-INF`; rebaselined.
- **General fix:** emit only the niche helpers a program uses, or a compact layout for an optional of a struct of two bounds.
