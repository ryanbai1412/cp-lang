# Friction: `cf2268c`

## `SparseTable` uses `std::function` + nested 64-bit vectors and `Ends` allocates per iteration (2.6x slowdown, 6.2x RSS)

- **Severity:** medium
- **Goal it hurts:** performance
- **Measured:** `439.0 ms` vs `207.3 ms` (`2.12x`, RSS `30.7 MB` vs `6.6 MB`, emitted `15,034 B`) on `gen size=25000` (down from `580.16 ms` / `2.62x` / `6.20x` RSS after static `SparseTable.op` lowering `08e78a90`, flat `SparseTable` storage `eb467178`, and scalar `Ends(lo0, lo1, hi0, hi1)` eliminating per-iteration `[0..2]Int` heap allocations).
- **Remaining cause:** `SparseTable<I, Int>` stores `n log n` 64-bit `Int`s (`~28.8 MB`) and `feasible` sorts 24 B tuples (`bounds.sort()`), whereas `cf2268c_orig.cpp` uses a bucketed 32-bit `RangeMaxQuery<int>` (`O(n)` space) and `gp_hash_table`.
- **Fix:** bucketed `SparseTable` / `I32` element width support and stack-allocated small fixed arrays `[0..2]Int`.
