# cf2159e — Super-Sum

Square-root decomposition over `n`: with `n = i * B + j`, `p^n = p^j * p^(iB)`.
Every power's coefficients come from one recurrence, the identity
`p * f' = n * p' * f` (two terms per coefficient), so the port has a single
`coeffs(n)` used for the small powers whole and for the large ones as prefix
sums, both filled on first use. A query is one dot product of length at most
`2B` against a prefix table, `O(B)` per online (xor-encrypted) query. Same
algorithm as the original (which builds the small powers by repeated
multiplication instead), at a larger block size; see the first friction.

## `Mod<P>` is stored in 64 bits, which forced a different block size
- **Where:** `cf2159e.cp`, lines 1 and 3 (`type Z = Mod<1_000_000_007>`,
  `const B = 1200`) and every `List<Z>`; emitted as
  `struct Mod_1000000007 { ll v; }`.
- **What felt wrong:** with the original's `B = 600` the large-power tables
  hold about 1.5 * 10^8 coefficients. The original stores them as 32-bit
  `modnum`s (595,072 KB); the port's 64-bit `Mod` took 1,245,668 KB, over the
  1024 MB limit, and 9.93 s against 5.17 s. Declaring the table as
  `List<0..Z.MOD>` to narrow it does not help: ranged elements are emitted as
  `std::vector<ll>` too (1,450,464 KB with the conversion copy). The only fix
  in the language was algorithmic: doubling `B` halves the tables. At matched
  `B = 1200` the port takes 3.43 s and 638,956 KB against the original's
  3.21 s and 305,920 KB, so the time is fine and the memory is still 2.1x. A
  storage-width decision turned into a change of the algorithm's parameter.
- **Goal it hurts:** performance and control (values take the fewest bytes
  their types allow; you choose the width); dependable submission (the
  natural port exceeds the memory limit).
- **Ideal code:** `type Z = Mod<1e9+7>` stored in 32 bits because `P < 2^31`,
  and `List<0..P>` stored in 32 bits because its range fits.
- **General fix:** store `Mod<P>` and ranged integers, in scalars and in
  containers, in the narrowest type holding their range (widening only
  inside arithmetic), which majorizes the current layout; show element widths
  in `cpl explain`.
- **Dream:** `dream/cf2159e.cp` line 1 (same text; the fix is in the layout).
- **Severity:** high.

## Tables built on first use need sentinel checks
- **Where:** `cf2159e.cp`, lines 19–20 and 27–28:
  ```cp
  var small: [0..B]List<Z> = []
  ...
  if small[j].len == 0: small[j] = coeffs(j)
  if big[i].len == 0: big[i] = scan(coeffs(i * B), +)
  ```
- **What felt wrong:** "the table of `p^j`" is one value per index. Building
  it eagerly as `let big = [0..=N / B] i => scan(coeffs(i * B), +)` reads
  right but costs the whole table up front, and the interpreter then spends
  most of every small test building rows no query touches (about 6 s per
  sample run before this change, 3 s after). Building on first use needs a
  `var` table, an empty list as the "not built" sentinel, and the check
  repeated at the use site, far from the definition. An array builder also
  takes only an expression (`expected a value after =>` for an indented
  block), which first forced `coeffs` out into a named function.
- **Goal it hurts:** express and revise; hard to get wrong (sentinels).
- **Ideal code:**
  ```cp
  let small = lazy [0..B] j => coeffs(j)
  let big = lazy [0..=N / B] i => prefix(coeffs(i * B))
  ```
- **General fix:** a `lazy` (memoised) array builder whose elements are
  computed on first read, the same mechanism as memoised recursion over a
  domain, plus block bodies for every `=>` lambda.
- **Dream:** `dream/cf2159e.cp` lines 7–14.
- **Severity:** medium.

## Encrypted input needs typed temporaries
- **Where:** `cf2159e.cp`, lines 25–26:
  ```cp
  let (n_enc, k_enc): (Int, Int) = read()
  let (n, k) = (n_enc ^ ans.v, k_enc ^ ans.v)
  ```
- **What felt wrong:** `(read() ^ ans.v, read() ^ ans.v)` fails because
  `read()` takes its type from the binding, and inside an expression there is
  none. Online-decoding problems ("xor with the last answer") are common, and
  each one needs the two-name dance; `ans.v` also leaks the representation of
  `Mod`.
- **Goal it hurts:** express (input as easy as types).
- **Ideal code:** `let (n, k) = read<(0..=N, Int)>(xor: ans)` or at least
  `read<Int>() ^ ans.int`.
- **General fix:** an explicit type argument on `read` so it is usable inside
  expressions, plus a documented `Mod` to `Int` conversion name; a decoding
  option is optional sugar on top.
- **Dream:** `dream/cf2159e.cp` line 18.
- **Severity:** medium.

## Lint pushes a polynomial recurrence into hand-unrolled terms
- **Where:** `cf2159e.cp`, lines 13–14.
- **What felt wrong:** the natural code was the recurrence as written in the
  editorial, `for y in 1..=min(2, z): acc += f[z - y] * p[y] * (n * y - (z -
  y))` with `p = [c, b, a]`, and repeated multiplication by `p` for the small
  powers. `cpl lint` flags `p[y]` and `f[z - y]` as bounds-checked in a
  nested loop (`L0414`) and `check.sh` requires zero warnings, so I unrolled
  the two terms by hand. A change of the polynomial's degree is no longer a
  local edit.
- **Goal it hurts:** express and revise; the obvious way is the fast way.
- **Ideal code:** `let small = [0..B] j => p ^ j` over a `Poly<Z>`.
- **General fix:** a `Poly<Mod<P>>` (or `Series`) type in the stdlib with
  `*`, `^` and `prefix`, generic over the modulus (see `cf2066d1`), and
  bounds-check elision for loops over a small literal list's indices so the
  lint fires only when a check is really paid.
- **Dream:** `dream/cf2159e.cp` lines 5 and 7.
- **Severity:** medium.

## `List` has no `map`, and the error is printed twice
- **Where:** an attempt at narrowing the tables,
  `scan(f, +).map(x => x.v)`.
- **What felt wrong:** `map` is the first guess and is missing
  (`E0203: a List<Mod<1000000007>> has no method map`); the comprehension
  `[x.v for x in scan(f, +)]` works. `cpl check` printed each of the two
  errors twice, so a two-error file read like four.
- **Goal it hurts:** express (guessable APIs); doubt to evidence (one
  diagnostic per root cause).
- **Ideal code:** `scan(f, +).map(x => x.v)`.
- **General fix:** `map`/`filter` on every `Seq` as the method spelling of the
  comprehension, and deduplicate diagnostics by span and code.
- **Dream:** `dream/cf2159e.cp` line 14 (`prefix(f)` needs no conversion).
- **Severity:** low.
