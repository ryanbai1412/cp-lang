# cf2187f1 — Al Fine (maximizing version)

The idea: reverse `b` and relabel it by positions in `a`; the common trees
correspond to the decreasing nodes of the permutation tree of that
permutation, and the deepest common tree follows a decreasing node's chain
while its right child is a leaf. The port builds the binary permutation tree
with one stack pass (neighbours among earlier values via a deletion-ordered
linked list) and folds it recursively.

## No permutation tree in the stdlib

- **Status:** fixed: `std.tree.PermTree.of(p)` (decision 102); the port is `PermTree.of` plus a 4-line `depth`.
- **Where:**
  ```
  type Open = (left: Int, lo: Int, lo_gap: Int, hi: Int, hi_gap: Int, node: Int)
  ...
  while let top = stk.last, x < top.lo_gap or x > top.hi_gap:
      let t = stk.pop()!
      stk.push(join(stk.pop()!, t, Other))
  var t = (left: i, lo: x, lo_gap: prv[x] + 1, hi: x, hi_gap: nxt[x] - 1, node: 2 * i)
  while let u = stk.last, max(u.hi, t.hi) - min(u.lo, t.lo) == i - u.left:
      t = join(stk.pop()!, t, if t.lo < u.lo: Decr else: Other)
  ```
- **What felt wrong:** 30 of the 40 lines rebuild a standard structure (the
  permutation / interval-decomposition tree) whose invariants (gaps, the
  "range length equals span" test, node numbering `2 * t.left - 1`) are the
  whole risk of the solution and have nothing to do with this problem. F2
  copies the same 30 lines unchanged.
- **Goal it hurts:** express, hard to get wrong, accumulate.
- **Ideal code:**
  ```
  let t = PermTree.new(p)                  // binary nodes: leaf | incr | decr
  fn depth(v: t.Node) -> Int = match t.kind(v):
      leaf => 1
      decr if t.kind(t.right(v)) == leaf => 1 + depth(t.left(v))
      _ => max(depth(t.left(v)), depth(t.right(v)))
  print(depth(t.root))
  ```
- **General fix:** a stdlib `PermTree` over any permutation `[I]I`, exposing
  a typed node domain, `kind`, children and the covered range, in the same
  shape as `Rooted` (so `fold`, `children`, `sub` read the same). Needs a
  user-visible way to declare a node domain sized `2n - 1` (see below).
- **Severity:** high
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` lines 9-14.

## Node arena is raw Int ids with a -1 sentinel

- **Status:** partly fixed: `PermTree` nodes are a domain `t.Node`, children are typed and `t.left`/`t.right` trap on a leaf. Payload enums with `match` are still open.
- **Where:**
  ```
  type Node = (kind: Kind, l: Int, r: Int)
  var nodes: [0..2 * n - 1]Node = (kind: Leaf, l: -1, r: -1)
  ...
  let id = 2 * t.left - 1
  ```
- **What felt wrong:** node ids, positions and values are all `Int`; a
  leaf's children are `-1` and nothing stops `nodes[node.r]` on a leaf. An
  enum with payloads (`leaf | join(kind, l, r)`) and a node domain would make
  "children of a leaf" unwritable, but neither exists today.
- **Goal it hurts:** hard to get wrong (sentinels, wrong index space).
- **Ideal code:**
  ```
  domain Node = 0..2 * n - 1
  enum Shape: leaf | join(kind: Kind, l: Node, r: Node)
  var nodes: [Node]Shape = leaf
  ```
- **General fix:** payload enums with exhaustive `match` (`design/spec/11-types.md`), and domains usable as struct/tuple field types so arena ids
  are typed.
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` lines 11-14.

## Inverse permutation and reversal are hand-written on raw Int

- **Status:** fixed: `std.seq.inverse<I, V>(self: [I]V) -> [V]I` supports method syntax `a.inverse()` across distinct domains; `cf2187f1.cp` and `cf2187f2.cp` now use `let pos_a = a.inverse()`.
- **Where:**
  ```
  var pos_a: [V]Int = 0
  for i in 0..n: pos_a[a[i]] = i
  let p: [0..n]Int = [0..n] i => pos_a[b[n - 1 - i]]
  ```
- **What felt wrong:** two idioms the spec names (`p.inverse()`, reversed
  traversal) are loops with a dummy fill `0` and index arithmetic
  `n - 1 - i`. Because the result must be stored as `Int` to be reused as an
  index into `[0..n]`, positions and values lose their domains for the rest of
  the program.
- **Goal it hurts:** express, hard to get wrong (off-by-one, wrong index space).
- **Ideal code:**
  ```
  let p = b.rev.map(a.inverse())          // [Pos]Pos
  ```
- **General fix:** `inverse()` on a bijective `[I]V` returning `[V]I`
  (`design/spec/21-index-spaces.md`), and `.rev` on arrays as a view, as ranges
  already have.
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` lines 8-9.

## Nearest earlier neighbours need the deletion trick

- **Status:** moved into `PermTree.of`; no port writes it now.
- **Where:**
  ```
  var prv: [0..n]Int = [0..n] v => v - 1
  var nxt: [0..n]Int = [0..n] v => v + 1
  for i in (0..n).rev:
      let (l, r) = (prv[p[i]], nxt[p[i]])
      if l >= 0: nxt[l] = r
      if r < n: prv[r] = l
  ```
- **What felt wrong:** "the values seen so far just below and above x" is an
  ordered-set predecessor/successor question; the O(n) offline linked-list
  deletion is a trick that must be written from memory, with `-1`/`n`
  sentinels.
- **Goal it hurts:** express.
- **Ideal code:**
  ```
  let (below, above) = p.earlier_neighbours()     // [Pos]?Pos each
  ```
- **General fix:** a stdlib offline "nearest earlier smaller/larger value"
  family alongside the monotone-stack helpers, returning optionals instead of
  sentinels.
- **Severity:** low
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` line 9.

## Lint forbids peeking below the stack top

- **Status:** moved into `PermTree.of`; no port writes it now.
- **Where:** the first draft
  ```
  let (u, t) = (stk[stk.len - 2], stk[stk.len - 1])
  ```
  gave `L0414 ... bounds-checked on every pass of a nested loop`.
- **What felt wrong:** a stack algorithm naturally compares the top two
  entries; there is no `List` accessor for "second from the top", so the fix
  was to restructure into "hold the new block, compare with `stk.last`". The
  result reads better here, but the warning gives no stack-shaped hint.
- **Goal it hurts:** express.
- **Ideal code:** `while let [.., u, t] = stk, ...` (slice patterns).
- **General fix:** slice/stack patterns on `List`, or have the lint suggest
  `while let u = stk.last` when it sees `stk[stk.len - k]`.
- **Severity:** low
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` line 9 (the stack lives inside `PermTree.of`).

## A recursive fold cannot name `t.Node` (owned by core)

- **Where:** `fn depth<Node>(v: Node) -> Int`
- **What felt wrong:** the node domain belongs to the value `t`, and
  `fn depth(v: t.Node)` (or `type Node = t.Node`) is E0204, so the fold is
  written generic over a parameter nothing constrains.
- **Goal it hurts:** express, hard to get wrong.
- **General fix:** value-held domains nameable in signatures in scope, the
  same gap as `Range<t.Pre>` in `cf2183f.md`.
- **Severity:** low
- **Dream:** `proto/ports/ecnerwala/dream/cf2187f1.cp` line 11.
