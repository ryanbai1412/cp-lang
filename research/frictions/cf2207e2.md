# cf2207e2 — N-MEX (Counting Version)

## No subrange `read()` or sentinel-prepend onto a ranged array
- **Where:** `cf2207e2.cp`, lines 6–7:
  ```cp
  var a: [0..=n]Int = n
  for i in 1..=n: a[i] = read()
  ```
- **What felt wrong:** CP Lang reads a whole array in one line (`let raw: [1..=n]Int = read()`), but adding a single boundary sentinel `a[0] = n` (which unifies both the `a[1] <= n` validity check and the `i = 0` termination step) forces either an explicit element-by-element `read()` loop or allocating a second array (`let a = [0..=n] i => if i == 0: n else: raw[i]`). Trying `[n] + raw` fails with `E0309: '+' can't be applied to 'List<Int>' and '[Int]Int'`, and mutable slices `a[1..=n] = read()` are not yet supported.
- **Goal it hurts:** express, performance.
- **Ideal code:**
  ```cp
  var a: [0..=n]Int = n
  a[1..=n] = read()
  ```
- **General fix:** Support mutable slice views `a[l..=r]` / `a[l..r]` as assignment and `read()` targets (already noted as spec work), so sentinel-padded and 1-based inputs stay single-allocation and one-line. Helps every DP, prefix-sum, and sentinel-padded array problem.
- **Severity:** medium.

## `all` / `any` do not accept a predicate without allocating a `List<Bool>`
- **Status:** fixed: `all(1..=n, i => ...)` is the walk `all(... for i in 1..=n)`, short-circuiting, no list; the port uses it (`decisions.md` 26.9).
- **Where:** `cf2207e2.cp`, lines 9–12:
  ```cp
  for i in 1..=n:
      if a[i] not in (n - i)..=a[i - 1]:
          print(0)
          return
  ```
- **What felt wrong:** Writing the natural universal check `all(1..=n, i => a[i] in (n - i)..=a[i - 1])` fails with `E0303: all takes 1 argument, but 2 were given`. The 1-argument form requires building `[a[i] in (n - i)..=a[i - 1] for i in 1..=n]`, which allocates an O(n) `List<Bool>` and cannot short-circuit, so the contestant drops back to a 4-line imperative loop.
- **Goal it hurts:** express, performance.
- **Ideal code:**
  ```cp
  if not all(1..=n, i => a[i] in (n - i)..=a[i - 1]):
      print(0)
      return
  ```
- **General fix:** Add a 2-argument predicate overload `all(xs, pred)` / `any(xs, pred)` (or non-allocating generator expressions for `all`/`any`/`sum`/`min`/`max`) in the stdlib/core. Helps every problem with validity or monotonicity checks.
- **Severity:** low.
