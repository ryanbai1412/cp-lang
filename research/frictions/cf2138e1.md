# Friction report: cf2138e1 (Determinant Construction, Easy Version)

Ported `proto/ports/ecnerwala/cf2138e1.cp` from `CF/2138/E1/E1.cpp` (dream: `proto/ports/ecnerwala/dream/cf2138e1.cp`).
Instead of a $10^7$ linear prime sieve and hardcoded cutoffs, the port searches outward from $\lfloor x / \phi \rfloor$ using integer arithmetic for a coprime $z$ whose subtractive Euclidean walk has length $\le 80$, and outputs the corresponding tridiagonal $\{-1, 0, 1\}$ matrix.

## No `nearest_first`, `find_map`, or `clamp` on ranges
- **Where:** `cf2138e1.cp`, lines 17–24 (`dream/cf2138e1.cp`, line 23):
  ```cp
  fn find_diag(x: Int, lim: Int) -> List<0..=1>:
      let z0 = max(1, min(x - 1, x * 618_033_989 / 1_000_000_000))
      for d in 0..x:
          if z0 + d < x:
              if let diag = continuant_diag(x, z0 + d, lim): return diag
          if d > 0 and z0 - d >= 1:
              if let diag = continuant_diag(x, z0 - d, lim): return diag
      []
  ```
- **What felt wrong:** Searching outward from a centre `z0` for the first candidate that succeeds requires manual `max(1, min(x - 1, ...))` clamping, a two-branch `for d in 0..x` loop, and an unreachable `[]` fallback at the end of `find_diag` because `Range` has neither `.nearest_first(to:)` nor `.find_map(...)`.
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2138e1.cp`, line 23):**
  ```cp
  let diag = (1..x).nearest_first(to: x / phi).find_map(z => continuant_diag(x, z).filter(d => d.len <= 80))!
  ```
- **General fix:** Add `clamp(val, lo, hi)` to the prelude and `find_map` (and optionally an outward-from-centre range adaptor `nearest_first(to:)`) on ranges/iterables so witness searches return `?T` directly without unreachable sentinel fallbacks.
- **Severity:** low

## No `[N, N]` table with a diagonal `match` on the offset

- **Goal it hurts:** express
- **Severity:** low
- **Area:** syntax
- **Status:** open
- **Dream:** `proto/ports/ecnerwala/dream/cf2138e1.cp:21`
  (`match j - i: 0 => diag[i]; 1 => 1; -1 => -1; _ => 0`)
- **Actual:** `proto/ports/ecnerwala/cf2138e1.cp:37` spells the offsets as an
  `if`/`elif` chain over `to_idx`: positions of one domain have no `j - i`
  offset, and `match` arms must be indented, not `;`-separated on one line.
- **General fix:** an offset between two positions of the same domain
  (`j - i: Int`), and an inline form for short `match` arms.

## `?` cannot leave a fn from inside a lambda or branch

- **Goal it hurts:** express
- **Severity:** low

- **Dream:** `proto/ports/ecnerwala/dream/cf2138e1.cp:11-13,18`
