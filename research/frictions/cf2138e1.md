# Friction report: cf2138e1 (Determinant Construction, Easy Version)

Ported `proto/ports/ecnerwala/cf2138e1.cp` from `CF/2138/E1/E1.cpp` (dream: `proto/ports/ecnerwala/dream/cf2138e1.cp`).
Instead of ecnerwala's $10^7$ linear prime sieve and 120 hardcoded floating-point cutoffs, the port searches outward from $\lfloor x / \phi \rfloor$ using pure integer arithmetic for a coprime $z$ whose subtractive Euclidean chain has length $\le 80$, and directly constructs the corresponding tridiagonal $\{-1, 0, 1\}$ matrix.

## No simultaneous tuple assignment `(a, b) = (b, a - b)`
- **Where:** `cf2138e1.cp` lines 6–13 and 35–44 (dream lines 8, 12):
  ```cp
  if a < b:
      swap(mut a, mut b)
      ops += 1
  a -= b
  swap(mut a, mut b)
  ops += 1
  ```
- **What felt wrong:** Every Euclidean recurrence step has to be broken into `a -= b` followed by `swap(mut a, mut b)` with two `mut` annotations, hiding the single mathematical transition $(a, b) \mapsto (b, a - b)$.
- **Goal it hurts:** express
- **Ideal code:** (dream lines 8, 12)
  ```cp
  (a, b) = (b, a)
  (a, b) = (b, a - b)
  ```
- **General fix:** Support parallel destructuring assignment `(a, b) = (e1, e2)` for existing `var` bindings (evaluating the RHS tuple before assigning). Helps every Euclidean/GCD, Fibonacci, two-pointer, and state-machine recurrence.
- **Severity:** medium

## Duplicating the Euclidean walk to avoid per-candidate heap allocation
- **Where:** `cf2138e1.cp` lines 2–14 and 32–44 (dream lines 2–13):
  ```cp
  fn chain_len(x: Int, z: Int, lim: Int) -> ?Int: ...
  // and later:
  while true:
      if a < b: ...
  ```
- **What felt wrong:** The same subtractive Euclidean loop is written twice—once in `chain_len` to test candidate `z` without allocating, and a second time after `find_start` to record `diag`. Returning `?List<Int>` from one helper would heap-allocate on every rejected candidate.
- **Goal it hurts:** performance
- **Ideal code:** (dream lines 2–13)
  ```cp
  fn euclid_diag(x: Int, z: Int, lim: Int) -> ?SmallVec<Int, 80>:
  ```
- **General fix:** Provide a stack-allocated fixed-capacity `SmallVec<T, N>` (or `ArrayVec<T, N>`) in `std` so bounded-size builders can be returned by value with zero heap allocation, eliminating dry-run/replay duplication across search-and-construct problems.
- **Severity:** medium

## No `clamp` or `find_map` over candidate sequences
- **Where:** `cf2138e1.cp` lines 16–23 (dream lines 22–23):
  ```cp
  let z0 = max(1, min(x - 1, x * 618_033_989 / 1_000_000_000))
  for d in 0..x:
      if z0 + d < x and chain_len(x, z0 + d, lim) != none:
          return z0 + d
      if d > 0 and z0 - d >= 1 and chain_len(x, z0 - d, lim) != none:
          return z0 - d
  1
  ```
- **What felt wrong:** Clamping requires nested `max(1, min(x - 1, ...))`, and finding the first valid candidate requires a manual `for` loop with a dead unreachable fallback `1` at the end.
- **Goal it hurts:** express
- **Ideal code:** (dream lines 22–23)
  ```cp
  let z0 = clamp(x * 618_033_989 / 1_000_000_000, 1, x - 1)
  let diag = spiral(z0, 1..x).find_map(z => euclid_diag(x, z, 80))!
  ```
- **General fix:** Add `clamp(val, lo, hi)` to the prelude and `find_map` on iterables/ranges so search-for-first-witness loops return `?T` directly without unreachable sentinel fallbacks.
- **Severity:** low
