# cf2178h — Create or Duplicate

The editorial idea: build each type's count by Horner's rule. A type's first
create is free (it is the initial present), and a duplicate doubles every
type already started, so the state is the value sum mod `m` and the set of
started types: `8m` states, six move classes (create `a`, `b` or `c`; double
with one, two or three types started), each of a fixed cost. Because every
class has a fixed cost, Dijkstra needs no heap: the settled states, in order,
give each class's candidates in order, so six cursors into the settled list
find the next state in O(1). The port says the moves (`enum Move`, `cost`,
`apply`) the way the editorial does, but the shortest-path engine is written
by hand and costs half the program, and the state space and the distance
table fight the type system.

## The stdlib has no shortest path for fixed-cost move classes, and its `dijkstra` is 10–200x slower
- **Where:** `cf2178h.cp`, lines 24–44:
  ```cp
  fn fixed_cost_paths(moves: List<Move>) -> Int:
      var dist: [R, S]?Int = none
      dist[R(0), S.empty] = 0
      var order = [(R(0), S.empty)]
      var at: [0..moves.len]Int = 0
      while dist[R(0), S.full] == none:
          var best: ?(d: Int, i: Int, r: R, s: S) = none
          for i in 0..moves.len:
              var head = at[i]
              while head < order.len:
                  ...
  ```
- **What felt wrong:** the idea is "shortest path where each move class has
  one cost". The stdlib's `dijkstra(next, from, w)` is the guessable call, but
  it needs a flat vertex domain (so the state is hand-encoded as `r * 8 + s`,
  see the next friction), builds a `List` of arcs per popped vertex, and runs
  a binary heap. Measured with that encoding: 1.53 s on the `m = 500000,
  k = 1` input and 2.39 s on `k = 500000`, against the original's 0.15 s and
  0.012 s. So the port re-implements the monotone-queue Dijkstra: six
  cursors, a settled list, a best-candidate scan. That is 21 of the 37 code
  lines and the part most likely to hide a bug (the cursor must stay on a
  candidate it did not take, and step past it when it is taken). It now sits
  in one `fn fixed_cost_paths(moves)`, so a stdlib call would replace one
  chunk, but the function is not reusable: it closes over `R`, `S`, `step`,
  `cost`, the start and the target, because passing them would cost a
  signature as long as the body (a version taking `from:` and `to:` cost 39
  more tokens and failed the dream-gap ratchet).
- **Goal it hurts:** express and revise (the algorithm is not named),
  performance (the named one is far slower), tokens (2.05x the dream).
- **Ideal code:**
  ```cp
  let dist = shortest_paths(
      from: [((R(0), Subset<T>.empty), 0)],
      moves: Move.all,
      cost: cost,
      step: step,
  )
  print(dist[(R(0), Subset<T>.full)]! - sum(x))
  ```
  documented as "O(states x moves) when every move has a fixed cost: one FIFO
  per move, no heap".
- **General fix:** a stdlib shortest path over an implicit graph whose arcs
  are labelled by a small set of move classes with fixed costs (the
  "k sorted queues" Dijkstra), taking `step` as a closure so no arc list is
  built; and make the existing `dijkstra` accept a closure that yields arcs
  instead of returning a `List`, so the heap version allocates nothing per
  vertex.
- **Dream:** `dream/cf2178h.cp` line 22: `fixed_cost_paths` names the algorithm; the six cursors, the settled list and the best-candidate scan are gone.
- **Area:** graphs (`plan/STDLIB.md`).
- **Severity:** high.

## A product state space is not a domain
- **Where:** `cf2178h.cp`, lines 13–14, 25 and 28:
  ```cp
  domain R = 0..m
  type S = Subset<T>
  var dist: [R, S]?Int = none
  var at: [0..moves.len]Int = 0
  ```
- **What felt wrong:** the state is one thing, `(R, S)`, but only a
  two-dimensional array can be indexed by it. `type State = (R, Subset<T>)`
  with `var dist: [State]?Int` fails (`E0302: State is a type, and a value is
  needed here`), so every access destructures, `dist[r, s]`, and every
  generic algorithm that takes a vertex domain (the stdlib `dijkstra`, `bfs`)
  needs the hand encoding `St(r * 8 + s.bits)` with its decode `u.to_idx / 8`,
  `u.to_idx % 8`. Likewise `enum Move` is not a domain, so the six cursors are
  `[0..moves.len]Int` indexed by a position into a `moves` list built by
  hand (`[Create(t) for t in T] + [Double(j) for j in 1..=3]`): adding a
  variant means also adding it to that list, and the cursor index `i` and
  the move `moves[i]` (lines 31, 35–36, 43) are kept in sync by hand.
- **Update (named records):** fixed. A tuple or record of index types now
  indexes an array whatever its fields are named, as decision 2.16 already
  said: `type P = (a: A, b: B)` with `[P]?Int`, and a generic `[S]?Int` with
  `S` standing for `(a: A, b: B)`, are laid out as `[A, B]` like `(A, B)`,
  and the leaked `` `cpl run` doesn't know the name `S` here `` is gone
  (`tests/programs/named_record_index_domain.cp`,
  `tests/diagnostics/named_record_index_in_a_generic.cp`).
- **Goal it hurts:** express and revise (adding a dimension or a move is not
  local), hard to get wrong (the cursor index and the move are kept in sync
  by hand).
- **Ideal code:**
  ```cp
  domain State = (R, Subset<T>)
  var dist: [State]?Int = none
  var at: [Move]Int = 0
  for mv in Move: ...
  ```
- **General fix:** product domains (`domain S = (A, B)` with `[S]T` laid out
  as `[A, B]T`), and payload-free-or-finite enums usable as domains
  (`Move.all`, `[Move]T`), as the design's `domain` section already sketches.
- **Dream:** `dream/cf2178h.cp` lines 13, 18 and 22: `domain State = (r: R, s: Subset<T>)`, `step` takes and returns a `State`, and `Move.all` enumerates the moves.
- **Area:** core (language / domains).
- **Severity:** high.

## `?Int` is 16 bytes and a ranged element type does not narrow it: 3x memory
- **Where:** `cf2178h.cp`, line 25: `var dist: [R, S]?Int = none`.
- **What felt wrong:** the emitted table is `Grid<std::optional<ll>, 2>`:
  16 bytes per state, 4M states, 82 MB peak against the original's 27 MB
  (`vector<int>` with an `INF` sentinel). Declaring the bound,
  `?(0..=2_000_000_000)`, changes nothing (still `optional<ll>`, still 82 MB),
  and even the sentinel rewrite `[R, S]0..=INF = INF` emits `ll`
  (51 MB, 0.30 s). "Values take the fewest bytes their types allow" does not
  hold for arrays of ranged or optional values, and the only tuning step is
  the sentinel the language exists to remove.
- **Goal it hurts:** performance and control; hard to get wrong (the tuned
  form needs a sentinel).
- **Ideal code:** `var dist: [State]?(0..=2e9) = none`, stored as one 32-bit
  word with a niche for `none`.
- **General fix:** size array elements from their declared range, and store
  `?T` of a ranged `T` in `T`'s width using an out-of-range niche; show the
  chosen layout in `cpl explain`.
- **Dream:** `dream/cf2178h.cp` line 22: `[State]?(0..=2e9)`, one 32-bit word per state.
- **Area:** core (codegen / layout).
- **Severity:** high.

## Arithmetic on a cyclic domain goes through `to_idx` and `%`
- **Where:** `cf2178h.cp`, lines 19–20:
  ```cp
  Create(t) => (R((r.to_idx + x[t]) % m), s.with(t))
  Double(j) => if s.len == j: (R(2 * r.to_idx % m), s) else: none
  ```
- **What felt wrong:** `R` is "residues mod `m`", but adding to one means
  leaving the domain, taking `%`, and re-entering. `r.cyc(x[t])` exists and
  reads better, but it lowers to `(i + d) % len` with a sign fix, a division
  per candidate in the hot loop, where the original uses one conditional
  subtract (`ns >= M ? ns - M : ns`, valid because both operands are below
  `m`). Doubling has no spelling at all short of `r.cyc(r.to_idx)`.
- **Goal it hurts:** express (the residue ring is not a type), performance.
- **Ideal code:** `domain R = Zmod(m)` (or `R.cyclic`) with `r + x[t]` and
  `2 * r`, lowered to a conditional subtract when both operands are proven in
  range.
- **General fix:** a runtime-modulus ring domain whose `+`, `-` and small
  multiples wrap, lowered to compare-and-subtract; `cyc` should use the same
  lowering when `|d| < len` is proven.
- **Dream:** `dream/cf2178h.cp` lines 12 and 19–20: `domain R = Zmod(m)`, `r + x[t]` and `2 * r`.
- **Severity:** medium.

## L0414 only accepts a bare-name cursor, forcing a copy in and out
- **Where:** `cf2178h.cp`, lines 32–39:
  ```cp
  var head = at[i]
  while head < order.len:
      let (r, s) = order[head]
      ...
      head += 1
  at[i] = head
  ```
- **What felt wrong:** the natural loop is `while at[i] < order.len: let
  (r, s) = order[at[i]]`. `cpl lint` flags `order[at[i]]` as "bounds-checked
  on every pass of a nested loop" although the `while` condition is exactly
  the bound; the worklist exemption only recognizes a plain local name. The
  port, and the gate that requires zero lint warnings, force a temporary and a
  write-back, which is a new place to forget the write-back.
- **Goal it hurts:** hard to get wrong (a workaround that adds a bug site),
  doubt to evidence (a false positive).
- **Ideal code:** the natural loop, warning-free.
- **General fix:** treat any place expression (`at[i]`, `self.head`) that
  the guarding condition compares against `xs.len`, and that is not written
  between the check and the index, as proven.
- **Dream:** `dream/cf2178h.cp` line 22: the hand-written worklist, and so the lint, disappears into the library call.
- **Severity:** low.

## Typed lambda parameters are rejected
- **Status:** fixed: optional parameter type annotations on closures (`(x: T) => ...`) are parsed, checked, and tested (`typed_lambda_parameter_annotations_are_checked`).
- **Where:** first draft, `let steps = (s: State) => ...`; now `fn step(...)`.
- **What felt wrong:** the cheat sheet documents one closure spelling,
  `x => ...`, so annotating a parameter (needed when the type cannot be
  inferred from a use yet) is a parse error and the closure must become a
  named `fn`.
- **Goal it hurts:** express and revise (a closure-to-fn rewrite).
- **Ideal code:** `let steps = (s: State) => ...`
- **General fix:** accept optional parameter annotations in closures.
- **Dream:** `dream/cf2178h.cp` line 18: a typed, destructured parameter `(r, s): State`, the same spelling a closure would take.
- **Severity:** low.

## A case that may not apply needs `if ...: ... else: none`
- **Where:** `cf2178h.cp`, line 20:
  `Double(j) => if s.len == j: (R(2 * r.to_idx % m), s) else: none`.
- **What felt wrong:** "doubling with `j` types started applies only when
  `s.len == j`" is a guard on a result that is otherwise absent. The
  `else: none` branch says nothing, and the guard sits in front of the value
  it guards. The guard-last form is rejected: `fn half(x: Int) -> ?Int =
  x / 2 if x % 2 == 0` gives `E0107: expected the end of the statement,
  found if`.
- **Goal it hurts:** express (a small one, on every partial transition).
- **Ideal code:** `Double(j) => (2 * r, s) if s.len == j`.
- **General fix:** a guarded expression `e if c` of type `?T` (absent when
  `c` fails), the expression form of the comprehension filter `for x in D
  if c` the language already has, so it adds no new concept.
- **Dream:** none yet: `dream/cf2178h.cp` line 20 keeps today's
  `if s.len == j: (2 * r, s) else: none`; the guarded form above is what it
  should say once `e if c` exists.
- **Severity:** low.

## The interpreter is too slow to check the max input
- **Where:** the gate's interpreter run.
- **What felt wrong:** the interpreter takes 28 s on a max input that the
  C++ runs in 0.15 s, past the gate's default 20 s `INTERP_TIMEOUT`, so the
  gate needs the timeout raised and "is the interpreter right on the max
  case" is a long wait.
- **Goal it hurts:** doubt to evidence.
- **General fix:** a faster interpreter loop for array-heavy code (shared
  with cf2183e).
- **Dream:** none; the program is unchanged, the fix is in the tool.
- **Severity:** medium.
