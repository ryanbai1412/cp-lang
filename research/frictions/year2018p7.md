## The parent list is read into child lists by hand
- **Where:** lines 15-18: `var kids: [V]List<V> = [V] v => []` and `for v in 2..=n: let parent: V = read(); kids[parent].push(V(v))`.
- **What felt wrong:** the statement gives a parent array, and the port rebuilds child lists with an `Int` loop and a `V(v)` conversion.
- **Goal it hurts:** express.
- **Ideal code:** `Rooted.from_parents` over a read of the parents of vertices 2..=n, then `tree.children(u)`.
- **General fix:** a parents read for a sub-range of a domain feeding `Rooted.from_parents`. This is the same shape as `read<[V]?V>(none: -1)` in yac6p2, but here the root has no entry. Owner: stdlib.
- **Severity:** low.

## Addendum: std documents a parents read that doesn't compile
- **Where:** `std/tree.cp`, the `Rooted.from_parents` doc: "the usual input shape 'parents of 2..n'
  read as `read<[V.drop(1)]V>()`".
- **What felt wrong:** that spelling fails `cpl check` with E0504 "not implemented yet: a fresh type
  made from values, `type Z = Mint(mod: p)`", and the help "give the value as a type argument:
  `Mod<1000000007>`". The message is about a modulus, not a domain slice.
  `let parent: [V.drop(1)]V = read()` fails the same way. The port's `read<[2..=n]V>()` works.
- **Repro:** `let n: 1..=5 = read()` / `domain V = 1..=n` /
  `let t = Rooted.from_parents(read<[V.drop(1)]V>())` / `print(t.depth(V.last!))`.
- **General fix (check, stdlib):** either accept a table keyed by `V.drop(k)`, or make the doc use
  the spelling that compiles. In both cases E0504 should name the construct it rejects. Owner:
  Core (check), repro sent; the doc line is stdlib's.
- **Severity:** medium (writable from the docs).
