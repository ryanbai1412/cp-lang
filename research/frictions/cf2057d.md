## `SegTree` requires `Monoid` with `?Span` sentinel wrapper and lowers through `std::function`

- **Severity:** high
- **Status:** fixed: `Monoid.op` now lowers statically with zero `std::function` (`08e78a90`), and `cf2057d.cp` now uses `Span(0, NEG, NEG, NEG, NEG)` directly without `?Span` or `!` unwraps (`84.7 ms` vs `75.9 ms` C++ = `1.12x`, down from `2.01x`; `11,645 B` emitted; `gate.sh cf2057d 30` passes).
- **Goal it hurts:** performance
- **Area:** ranges (`plan/STDLIB.md`) + codegen
- **Dream lines:** `proto/ports/ecnerwala/dream/cf2057d.cp:13-22`
- **What happened:** `SegTree` requires an identity element (`Monoid(id: none, op: combine)`), forcing `?Span` (a wide `std::optional<Span>`) with `let a = a ?? return b` guards and `tree.all!.best` even though every queried interval is non-empty. Furthermore, `Monoid.op` lowers through `std::function`, producing a `2.01x` runtime slowdown (`109.4 ms` vs `54.3 ms`).
- **General fix:** Support semigroup `SegTree<Pos, Span>` driven by `impl Semigroup` / `+` directly on `Span` (no `id`, no `?Span`, no `!` unwrap), and monomorphize/inline `SegTree` combine operations instead of type-erasing through `std::function`.

## No indexed update `tree[p] = ...`, struct methods, or variadic `max`

- **Severity:** low
- **Goal it hurts:** express
- **Area:** ranges (`plan/STDLIB.md`) + core language
- **Dream lines:** `proto/ports/ecnerwala/dream/cf2057d.cp:10-19, 25`
- **What happened:** `Span.at` and `+` cannot be written as associated methods inside `struct Span`, `max` only accepts 2 arguments (requiring nested `max(max(...), max(...))`), and point updates require `tree.set(p, ...)` instead of `tree[p] = ...`.
- **General fix:** Support associated/operator methods inside `struct`, variadic `max(a, b, c, ...)`, and index-assignment syntax on `SegTree`.
