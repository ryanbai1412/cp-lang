## Interactive I/O lacks a first-class flush/exit protocol and interactor harness
- **Where:** `research/frictions/cf2245g.ideal.cp` lines 9-14:
  ```cp
  fn query(vs: List<V>) -> List<Bool>:
      print("?", vs.len, vs)
      flush()
      let s: String = read()
      if s == "-1": exit(0)
      return [c == '1' for c in s]
  ```
- **What felt wrong:** Every interactive solution repeats the same `print(...)` + `flush()` + `if s == "-1": exit(0)` boilerplate (forgetting `flush()` causes Idleness Limit Exceeded; forgetting `-1` exit causes arbitrary verdict), and there is no built-in interactor mode in `gate.sh` to validate interactive ports against a tree generator.
- **Goal it hurts:** hard-to-get-wrong, doubt-to-evidence
- **Ideal code:**
  ```cp
  @!interactive
  fn query(vs: List<V>) -> List<Bool>:
      let s: String = ask("?", vs.len, vs)
      return [c == '1' for c in s]
  ```
- **General fix:** Add an `ask(...)` helper (prints, flushes, reads response, exits cleanly on `-1`/EOF) and interactor support in `gate.sh` / `cpl stress` (`--interactor`). Helps every interactive problem.
- **Severity:** high

## Binary search over a predicate calling an interactive query needs slice concatenation (`pool[lo..=mid] + [u]`)
- **Where:** `research/frictions/cf2245g.ideal.cp` lines 29-31:
  ```cp
  let probe = pool[lo..] + [u]
  if query(probe).last!:
      break
  let idx = bsearch(lo..pool.len, mid => !query(pool[lo..=mid] + [u]).last!)
  ```
- **What felt wrong:** Building a query prefix plus a single sentinel element `u` allocates a new `List<V>` on every probe unless the user manually builds a scratch list and pops `u`, and `bsearch` over an index range `lo..pool.len` cannot directly take a slice view or return `none` when no element satisfies the predicate.
- **Goal it hurts:** express, performance
- **Ideal code:**
  ```cp
  if let idx = first_true(lo..pool.len, mid => !query_with(pool[lo..=mid], u)):
      res.push(pool[idx])
  ```
- **General fix:** Provide a `first_true(range, pred) -> ?Int` (or `bsearch` returning `?T`) and zero-copy slice concatenation / multi-arg `print` over slices without allocating intermediate lists.
- **Severity:** medium
