## Cannot read a 2D character grid directly into `[Row, Col]Char`
- **Area:** core / `graphs` (`plan/STDLIB.md` 4.15 `std.grid`)
- **Where:** `proto/ports/ecnerwala/cf1404e.cp` lines 11, 20, 24, 27 vs `dream/cf1404e.cp` lines 10, 19, 21–22:
  ```cp
  let rows: [Row]Str = read()
  ...
  for c in Col if rows[r][c.ord] == '#':
  ```
- **What felt wrong:** Reading an `n x m` character grid into `[Row, Col]Char` is not supported directly, so the port reads `[Row]Str` and indexes `rows[r][c.ord]` with `.ord` at every grid access.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code (`dream/cf1404e.cp:10,19`):**
  ```cp
  let grid: [Row, Col]Char = read()
  ...
  for c in Col if grid[r, c] == '#':
  ```
- **General fix:** Allow `read()` into `[R, C]Char` to read `R.count` whitespace-delimited strings of length `C.count` into a 2D character grid.
- **Severity:** low.

## No `if let` with guard (`if let rp = r.prev if ...`) as an expression
- **Area:** core
- **Where:** `proto/ports/ecnerwala/cf1404e.cp` lines 22–27 vs `dream/cf1404e.cp` lines 21–22:
  ```cp
  var up = src
  if let rp = r.prev:
      if rows[rp][c.ord] == '#': up = cell(rp, c)
  var left = snk
  if let cp = c.prev:
      if rows[r][cp.ord] == '#': left = cell(r, cp)
  ```
- **What felt wrong:** Conditional optional binding with a boolean guard requires a mutable `var` plus two nested `if` statements instead of a single expression.
- **Goal it hurts:** express.
- **Ideal code (`dream/cf1404e.cp:21-22`):**
  ```cp
  let up = if let rp = r.prev if grid[rp, c] == '#': cell(rp, c) else: src
  let left = if let cp = c.prev if grid[r, cp] == '#': cell(r, cp) else: snk
  ```
- **General fix:** Allow `if let x = opt and cond: ... else: ...` (or `where`) in conditional expressions.
- **Severity:** low.

## `FlowGraph<V>` requires manual flattening of `(Row, Col) + {src, snk}` into a synthetic `Node` domain
- **Area:** `flows/matching` (`plan/STDLIB.md` 4.12)
- **Where:** `proto/ports/ecnerwala/cf1404e.cp` lines 13–16:
  ```cp
  domain Node = 0..n * m + 2
  let src = Node(n * m)
  let snk = Node(n * m + 1)
  fn cell(r: Row, c: Col) -> Node = Node(r.ord * m + c.ord)
  ```
- **What felt wrong:** Grid-based flow problems must manually flatten `(r, c)` to `r.ord * m + c.ord` and reserve `n * m` and `n * m + 1` for source and sink.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** Product/sum vertex domains (e.g. `FlowGraph<Cell>` with built-in source/sink or `Grid<Row, Col>` vertex indexing).
- **General fix:** Provide source/sink-aware flow builders or domain-product indexing in `std.flow` / core domains.
- **Severity:** low.
