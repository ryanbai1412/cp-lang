# Friction report: cf2138e2 (Determinant Construction, Hard Version)

Ported `proto/ports/ecnerwala/cf2138e2.cp` from `CF/2138/E2/E2.cpp` (dream: `proto/ports/ecnerwala/dream/cf2138e2.cp`).
Uses the same golden-ratio outward Euclidean tridiagonal construction as E1, tightened to `lim = 50` (exhaustively verified over all $x \in [2, 10^7]$ with average offset $d \approx 23.1$, worst $d = 14850$), eliminating ecnerwala's $10^7$ prime sieve, 120 hardcoded cutoffs, and `tensor` template.

## No simultaneous tuple assignment `(a, b) = (b, a - b)`
- **Where:** `cf2138e2.cp` lines 6–13 and 35–44 (dream lines 8, 12):
  ```cp
  if a < b:
      swap(mut a, mut b)
      ops += 1
  a -= b
  swap(mut a, mut b)
  ops += 1
  ```
- **What felt wrong:** Every subtractive Euclidean step splits into `a -= b` and `swap(mut a, mut b)` with two explicit `mut` markers instead of one parallel assignment `(a, b) = (b, a - b)`.
- **Goal it hurts:** express
- **Ideal code:** (dream lines 8, 12)
  ```cp
  (a, b) = (b, a)
  (a, b) = (b, a - b)
  ```
- **General fix:** Support parallel destructuring assignment `(a, b) = (e1, e2)` on existing `var` bindings (evaluating RHS before writing LHS). Helps every Euclidean/GCD, Fibonacci, and two-variable recurrence.
- **Severity:** medium

## Duplicating the Euclidean walk to avoid per-candidate heap allocation
- **Where:** `cf2138e2.cp` lines 2–14 and 32–44 (dream lines 2–13):
  ```cp
  fn chain_len(x: Int, z: Int, lim: Int) -> ?Int: ...
  // repeated after find_start:
  while true:
      if a < b: ...
  ```
- **What felt wrong:** With `t <= 500` and up to ~15,000 candidates tested in the worst case, returning `?List<Int>` from one unified function would allocate on every rejected candidate. Without a stack-allocated fixed-capacity vector, the Euclidean loop is duplicated between the dry-run filter and the witness builder.
- **Goal it hurts:** performance
- **Ideal code:** (dream lines 2–13)
  ```cp
  fn euclid_diag(x: Int, z: Int, lim: Int) -> ?SmallVec<Int, 50>:
  ```
- **General fix:** Add a stack-allocated fixed-capacity `SmallVec<T, N>` (or `ArrayVec<T, N>`) to `std` so bounded-length constructive witnesses can be returned by value with zero heap allocation.
- **Severity:** medium

## No `clamp` or `find_map` over candidate sequences
- **Where:** `cf2138e2.cp` lines 16–23 (dream lines 22–23):
  ```cp
  let z0 = max(1, min(x - 1, x * 618_033_989 / 1_000_000_000))
  for d in 0..x:
      if z0 + d < x and chain_len(x, z0 + d, lim) != none:
          return z0 + d
      if d > 0 and z0 - d >= 1 and chain_len(x, z0 - d, lim) != none:
          return z0 - d
  1
  ```
- **What felt wrong:** Clamping requires nested `max`/`min`, and searching for the first valid witness requires an imperative loop with an unreachable fallback `1`.
- **Goal it hurts:** express
- **Ideal code:** (dream lines 22–23)
  ```cp
  let z0 = clamp(x * 618_033_989 / 1_000_000_000, 1, x - 1)
  let diag = spiral(z0, 1..x).find_map(z => euclid_diag(x, z, 50))!
  ```
- **General fix:** Add `clamp(val, lo, hi)` to the prelude and `find_map` on ranges/iterables so witness searches return `?T` directly without unreachable sentinel values.
- **Severity:** low
