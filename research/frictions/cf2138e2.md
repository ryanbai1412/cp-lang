## No `nearest_first`, `first_some`, or `clamp` on ranges
- **Where:** `cf2138e2.cp`, lines 23–30 (`dream/cf2138e2.cp`, line 21):
  ```cp
  fn find_diag(x: Int, lim: Int) -> List<0..=1>:
      let z0 = max(1, min(x - 1, x * 618_033_989 / 1_000_000_000))
      for d in 0..x:
          if z0 + d < x:
              if let diag = continuant_diag(x, z0 + d, lim): return diag
          if d > 0 and z0 - d >= 1:
              if let diag = continuant_diag(x, z0 - d, lim): return diag
      []
  ```
- **What felt wrong:** Searching outward from a centre `z0` for the first candidate that succeeds requires manual `max(1, min(x - 1, ...))` clamping, a two-branch `for d in 0..x` loop, and an unreachable `[]` fallback at the end of `find_diag` because `Range` has neither `.nearest_first(to:)` nor `.first_some(...)`. Also `print(m)` cannot print a 2D `[N, N]Int` array row-by-row (`dream/cf2138e2.cp`, line 24).
- **Goal it hurts:** express, hard-to-get-wrong
- **Ideal code (`dream/cf2138e2.cp`, line 21):**
  ```cp

      (1..x).nearest_first(to: x / phi).first_some(z => [1] + walk(z, x - z, room: MAX_N - 1)?)!
  ```
- **General fix:** Add `clamp(val, lo, hi)` to the prelude and `first_some` (and optionally an outward-from-centre range adaptor `nearest_first(to:)`) on ranges/iterables so witness searches return `?T` directly without unreachable sentinel fallbacks.
