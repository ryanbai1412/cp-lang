# Friction report — cf2159f

## `MinHeap<T>(by:)` key selector (`E0310`)
- **Where:** `dream/cf2159f.cp`, line 44 (`var heap = MinHeap<Seg>(by: s => s.val)`).
- **What felt wrong:** `MinHeap<T>` does not accept a `by:` key selector, forcing `cf2159f.cp` to store `val` twice inside `MinHeap<(Val, Seg)>` (once as the tuple key and once in `Seg`).
- **Goal it hurts:** express, hard to get wrong (duplicated field).
- **Ideal code:** `var heap = MinHeap<Seg>(by: s => s.val)`.
- **General fix:** support `MinHeap<T>(by:)` / `MaxHeap<T>(by:)` (or `impl Ord` on structs).
- **Area:** stdlib
- **Severity:** medium

## Domain `saturating_add` and `midpoint`
- **Where:** `dream/cf2159f.cp`, lines 51, 55 (`t0.saturating_add(len)`, `lo.midpoint(hi)`).
- **What felt wrong:** Clamped strides and binary-search midpoints on a 1-based domain (`domain Time = 1..=2 * n - 1`) force raw `.ord` round-trips (`Time(min(t0.ord + 1 + len, 2 * n - 1))`, `Time((lo.ord + hi.ord) / 2 + 1)`) in `cf2159f.cp`.
- **Goal it hurts:** hard to get wrong (off-by-one `+ 1` on 1-based `.ord`).
- **Ideal code:** `t0.saturating_add(len)` and `lo.midpoint(hi)`.
- **General fix:** add `saturating_add(d: Int) -> D` and `midpoint(other: D) -> D` on ordered domain elements.
- **Area:** domains
- **Severity:** medium
