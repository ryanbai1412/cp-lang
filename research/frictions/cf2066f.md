## Algorithm

Precompute `max_sub[l, r]` = maximum subarray sum of `b[l..r]` for all `0 <= l < r <= m`. Repeatedly peel the maximum-sum alive subarray `[bl, br)` of `a` (`next_block()`) with sum `best_sum`, shrinking each `valid_end[j]` so `max_sub[j, valid_end[j]] <= best_sum`. After each peel, `try_match(best_sum)` runs a monotone-two-pointer DP matching `a[0..i]` to `b[0..j]` before/after choosing the one special block that holds `[best_sum]` and expands as the final operation.

## Frictions (port vs dream)

### 1. No `PosA.Cut` / `Bounds<D>` indexing or enum-indexed DP dimension, forcing raw `Int` + 40+ `CutA(...)`/`PosA(...)` casts (`dream/cf2066f.cp:12-13,37-61`)
- **Severity:** high
- **Goal it hurts:** express and revise, performance and control
- **Where:** `cf2066f.cp` splits the DP into two parallel grids `dp0, dp1: [CutA, CutB]?Prev` (to avoid a dummy `domain Flag = 0..=1`) and casts raw `Int` indices through `PosA(i)`, `PosB(j)`, `CutA(i)`, `CutB(j)` on every DP access. Each cast emits a `cpl::pos(...)` runtime check inside the `O(n^2 m)` loop.
- **Dream (`dream/cf2066f.cp:12-13,37-61`):**
  ```cp
  enum Phase: Before, After
  struct Prev(i: PosA.Cut, j: PosB.Cut, phase: Phase)
  var dp: [PosA.Cut, PosB.Cut, Phase]?Prev = none
  ```
- **General fix:** Support small enums (`Phase`) and `Bool` directly as array dimensions, provide `D.Cut` with `.next`/`.prev`/`.after` step arithmetic, and elide `cpl::pos` checks when indices are bounded by domain loops.

### 2. `?Prev` lowers to `std::optional<Prev>` instead of niche-packed narrowed fields (`dream/cf2066f.cp:13,37`)
- **Severity:** medium
- **Goal it hurts:** performance and control
- **Where:** `dp0, dp1: [CutA, CutB]?Prev` re-allocate two `501 x 501` grids of `std::optional<Prev>` on every peel iteration, contributing to the 1.50x max-input runtime (`315.6 ms` vs `210.0 ms`).
- **Dream:** `proto/ports/ecnerwala/dream/cf2066f.cp` lines 13, 37.
- **General fix:** Niche-pack `?Struct` whenever any field has an unused bit pattern, and narrow domain/bounded fields inside structs.

### 3. No slice-to-list (`b[prv.j..cur.j].list()`), no `max_subarray_sum()`, and no top-level per-test `return` (`dream/cf2066f.cp:16,69,85-95`)
- **Severity:** low
- **Goal it hurts:** express and revise
- **Where:** `[b[PosB(k)] for k in prv.j..cur.j]`, 10-line Kadane table precomputation, and `fn solve() -> ?List<Op>` wrapper around the peel loop so the test can return early on match.
- **Dream:** `proto/ports/ecnerwala/dream/cf2066f.cp` lines 16, 69, 85-95.
- **General fix:** Add slice `.list()` conversion on `[D]T`, a stdlib `max_subarray_sum()` fold, and top-level per-test `return` inside `@!multitest` files.
