- **Source:** Codeforces 2066F (`proto/ports/ecnerwala/cf2066f_orig.cpp`)
- **Port:** `proto/ports/ecnerwala/cf2066f.cp`
- **Status:** Ported (`gate.sh cf2066f 150` passes; max-size `n = m = 500` diff agrees byte-for-byte)

- **Tokens (contestant-written):** `1249` (CP Lang) vs `1545` (C++ `main()`, `2995` total including `tensor`) — **0.81x**
- **Max-input runtime** (`n = 500, m = 500`, 500 single-element peels, 3-run median): `315.6 ms` (CP Lang) vs `210.0 ms` (C++ `g++ -O2 -std=c++20`) — **1.50x**

## Algorithm

Precompute `b_val[l, r]` = maximum subarray sum of `b[l..r]` for all `0 <= l < r <= m`. Repeatedly peel the maximum-sum alive subarray `[l, r)` of `a` (Kadane over maximal alive runs) with sum `best_sum`, shrinking each `valid_b_end[j]` so `b_val[j, valid_b_end[j]] <= best_sum`. After each peel, run a 3D monotone-two-pointer DP `dp[i, j, used]` matching `a[0..i]` to `b[0..j]`: every non-special peeled segment maps to a `b` slice with max subarray sum `<= best_sum`, while the one special peeled segment (marking `used = 1`) is first replaced with `[best_sum]` and finally replaced with its target `b` slice in the last operation.

## Frictions

### 1. Domain/cut cast noise (`PosA`, `CutA`, `PosB`, `CutB`, `Flag`) inflates tokens to 0.81x and adds runtime `cpl::pos` checks in the DP hot loop (high)

Working with element indices (`0..n`, `0..m`), prefix cuts (`0..=n`, `0..=m`), and a 2-state boolean flag (`0..=1`) required five separate domains and over 40 explicit constructor casts (`CutA(i)`, `CutB(j)`, `PosA(i)`, `PosB(j)`, `Flag(0)`, `Flag(1)`) plus `.to_idx` conversions. Every single DP read/write in the `O(n^2 m)` loop emitted `cpl::pos(...)` runtime checks (e.g. `dp(cpl::pos(ni - CutA_lo, CutA_len), cpl::pos(nxt0 - CutB_lo, CutB_len), cpl::pos(0 - Flag_lo, Flag_len))`).

In particular, there is no `Bool`-indexed array dimension (`[CutA, CutB, Bool]?Prev`), forcing a dummy `domain Flag = 0..=1` and `Flag(0)`/`Flag(1)` casts on every line of the DP.

**Ideal code:**
```cp
var dp: [PosA.bounds, PosB.bounds, Bool]?Prev = none
dp[PosA.start, PosB.start, false] = Prev(PosA.start, PosB.start, false)
```
**General fix:** Support `Bool` (and small enums) directly as array dimensions without a dummy `0..=1` domain, allow `PosA.bounds` / `Bounds<D>` uniformly with `Cut + 1` / `Cut.next` step arithmetic, and elide `cpl::pos` checks when indices come from range/while loops bounded by domain limits.

### 2. `?Prev` lowers to 16-byte `std::optional<Prev>` instead of niche-packed struct (medium)

`struct Prev(i: CutA, j: CutB, f: Flag)` has three bounded domain fields (`0..=500`, `0..=500`, `0..=1`) that could fit in 6 bytes (or 12 bytes as `int32_t`s with `-1` niche on `i`), yet `dp: [CutA, CutB, Flag]?Prev` lowers to `cpl::Grid<std::optional<Prev>, 3>` (16 bytes per cell, re-allocated on every peel iteration). Together with `cpl::pos` checks, this puts max-input runtime at `315.6 ms` vs `210.0 ms` (`1.50x`).

**General fix:** Niche-pack `?Struct` whenever any field is a domain or bounded integer with an unused bit pattern, and narrow domain fields inside structs according to their declared upper bound (`0..=500` -> `int16_t`, `0..=1` -> `uint8_t`).

### 3. No slice-to-list syntax `b[l..r].list()` (low)

Extracting a subsegment of `b: [PosB]Int` into a `List<Int>` required `[b[PosB(k)] for k in prv.j.to_idx..cur.j.to_idx]` instead of `b[prv.j..cur.j].list()`.

**Ideal code:**
```cp
let slice = b[prv.j..cur.j].list()
```
**General fix:** Allow slicing `[D]T` by a `Bounds<D>` range `l..r` with `.list()` conversion.
