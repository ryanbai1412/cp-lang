# cf2066b — White Magic

Every zero-free sequence is magical, so the answer is `n - zeros` unless
keeping exactly one zero (the leftmost, which keeps the most room for the
suffix MEX to stay small) still leaves a magical sequence; then it is one
more. Checking that candidate is a single pass: prefix minima from the left,
suffix MEX from the right, and `min(b[..i]) >= mex(b[i..])` at every cut.

## Suffix MEX is hand-rolled

- **Where:**
  ```
  var seen: [0..=b.len]Bool = false
  var suffix_mex: [0..=b.len]Int = 0
  for i in (0..b.len).rev:
      if b[i] <= b.len: seen[b[i]] = true
      suffix_mex[i] = suffix_mex[i + 1]
      while seen[suffix_mex[i]]: suffix_mex[i] += 1
  ```
- **What felt wrong:** this is half of the solution's text, and it encodes
  three facts by hand: values above the length can be ignored, the MEX of a
  growing set never decreases (so the amortized `while` is linear), and the
  answer array is indexed by cuts (`0..=b.len`, the empty suffix at the
  end). Getting any one of them wrong (forgetting the `<= b.len` guard,
  sizing `seen` as `0..b.len`, recomputing from 0) is a plausible 3am bug,
  and nothing in the language helps. The prefix-min half of the same check
  is one call: `scan(b, min)`.
- **Goal it hurts:** express, hard to get wrong.
- **Ideal code:**
  ```
  let pre = b.prefix_min()
  let mex = b.suffix_mex(at: .cuts)   // [0 ..= b.len]Int
  let magical = all(pre[c.before] >= mex[c] for c in b.cuts.inner)
  ```
- **General fix:** a MEX scan in the stdlib scan family
  (`design/spec/22-sequences.md` already lists `prefix_min`/`suffix_max`;
  `prefix_mex`/`suffix_mex` belong beside them, documented O(n) and
  ignoring values above the length), plus an incremental `Mex` set for the
  cases that are not a scan. `prefix_min` itself is also not yet available
  (`E0203: a [Int]Int has no method prefix_min`), so today's spelling is the
  free `scan(b, min)`.
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2066b.cp` line 10.

## Cut versus element indices are mixed by hand

- **Where:** `prefix_min[i - 1] >= suffix_mex[i]` for `i in 1..b.len`.
  `prefix_min` is indexed by elements (`0..b.len`, inclusive), `suffix_mex`
  by cuts (`0..=b.len`); the `- 1` is what lines them up at cut `i`.
- **What felt wrong:** both arrays are plain `Int` ranges, so writing
  `prefix_min[i]` (an off-by-one) type-checks. The spec's cuts/positions split is exactly the fix,
  but it is not reachable here because `b` is a filtered `List` with no
  declared domain.
- **Goal it hurts:** hard to get wrong.
- **Ideal code:** as above, `pre[c.before]` and `mex[c]` with `c` a cut.
- **General fix:** give comprehension results an index space (a fresh
  domain of positions with cuts), so filtered sequences get the same
  position/cut separation as declared ones (`design/spec/21-index-spaces.md`).
- **Severity:** medium
- **Dream:** `proto/ports/ecnerwala/dream/cf2066b.cp` lines 8-11.

## Fill and read syntax is unguessable from Python/Rust

- **Where:** the first draft wrote `[false; n]`, `[0; n]` (Rust) and
  `read(n)`; all three are errors (`read` takes no arguments, and repeat
  literals do not exist). The working spellings are a typed declaration with
  a scalar fill, `var seen: [0..=b.len]Bool = false`, and a typed read.
- **What felt wrong:** the typed spelling is good once known, but the
  diagnostics did not point at it: the repeat literal gave
  `E0103: expected , or ] in the list, found ;` and the counted read
  `E0303: read takes 0 arguments, but 1 was given`, neither naming
  `var xs: [0..n]Bool = false` or `let a: [0..n]Int = read()`.
- **Goal it hurts:** doubt to evidence (errors name the fix), writable from
  the docs.
- **Ideal code:** unchanged; the fix is the diagnostic.
- **General fix:** recognise `[x; n]` and `read(n)` as common foreign
  spellings and emit an error naming the typed-fill and typed-read forms.
- **Severity:** low
- **Dream:** `proto/ports/ecnerwala/dream/cf2066b.cp` line 5.

## What worked

- `zeros.first` as an optional with `if let` replaced the original's "is
  there a zero?" flag cleanly, and the `else` branch is the trivial answer.
- `all(... for i in ...)` and `Int(magical)` read like the editorial.
- No segment tree: the original keeps a lazy segment tree over all values;
  the editorial's observation reduces it to one linear pass, and the port
  follows the editorial.
