# cf2057e2 — Another Exercise on Graphs (hard version)

The editorial: the answer to `(a, b, k)` is at most `x` iff some path has
fewer than `k` edges heavier than `x`, i.e. iff the 0-1 distance with edges
of weight `<= x` costing 0 is below `k`. Start with every edge at cost 1
(hop distances), lighten edges by increasing weight, and note that only an
edge joining two zero-cost components (a Kruskal edge, `d[u, v] > 0`) changes
any distance, by one O(n²) relaxation through it. A query is answered by the
weight that first drops its distance below `k`.

## All-pairs hop distances go through a hand-built `?Int` matrix
- **Where:** `cf2057e2.cp`, lines 13–17:
  ```cp
  var hop: [V, V]?Int = none
  for e in edges:
      for (x, y) in [(e.u, e.v), (e.v, e.u)]: hop[x, y] = 1
  let hops = floyd_warshall(hop)!
  var d = [V, V] (i, j) => hops[i, j]!
  ```
- **What felt wrong:** "hop distances in this graph" is one fact and five
  lines. `floyd_warshall` takes a weight matrix, not a `Graph`, so the
  undirected edge list is written into a matrix by hand (the first draft set
  both orders on two lines and lint `L0503` flagged it); the result is
  `?[V, V]?Int`, so a connected unweighted graph pays two unwraps (`!` for
  "no negative cycle", `!` per entry for "reachable") and a copy into an
  `Int` matrix. The alternative, `[V] s => bfs(g, [s]).dist`, reads better
  but is slower (below).
- **Goal it hurts:** express; performance (the copy).
- **Ideal code:** `var d = Graph<V>.undirected(edges).hops()`.
- **General fix (graphs):** all-pairs distances on a `Graph` (`g.hops()` /
  `g.all_pairs()`), returning `[V, V]Int` when the graph is known connected
  or `[V, V]?Int` otherwise, picking BFS or Floyd–Warshall by the documented
  cost. Not added; a proposal.
- **Dream:** `dream/cf2057e2.cp` line 11.
- **Severity:** medium.
- **Area:** graphs

## 400 stdlib `bfs` calls are 2x slower than Floyd–Warshall here
- **Where:** the variant `let hops = [V] s => bfs(g, [s]).dist` (draft).
- **What felt wrong:** on the max input (n = 400, complete graph) the BFS
  variant took 0.60 s against 0.29 s for the Floyd variant, same algorithm
  afterwards. Each `bfs` builds a full `Paths` (distance, back pointer and
  order arrays) even when only `dist` is read, and walks a dense adjacency
  through the generic neighbour interface. The natural code is the slow one.
- **Goal it hurts:** performance (the obvious way is the fast way).
- **Ideal code:** `g.hops()`, or `bfs(g, [s]).dist` costing one array.
- **General fix (graphs/codegen):** let `bfs` skip what is never read
  (back pointers, order), or offer the distance-only form through the same
  function with a named option.
- **Dream:** `dream/cf2057e2.cp` line 11.
- **Severity:** medium.
- **Area:** graphs

## Grouping queries by pair is a hand-written bucket fill
- **Where:** `cf2057e2.cp`, lines 19–20:
  ```cp
  var pending: [V, V]List<Q> = []
  for i in Q.sort(by: i => queries[i].k): pending[queries[i].a, queries[i].b].push(i)
  ```
- **What felt wrong:** "the queries of each pair, by k" is a group-by; the
  port spells the bucket table's type, then fills it in a loop, naming
  `queries[i]` three times.
- **Goal it hurts:** express.
- **Ideal code:** `var pending = Q.sorted(by: .k).group(by: i => (queries[i].a, queries[i].b))`.
- **General fix (seq):** `xs.group(by: key)` into a dense table when the
  key is a domain (a `Map` otherwise), stable so a prior sort survives.
  Not added; a proposal.
- **Dream:** `dream/cf2057e2.cp` line 12.
- **Severity:** low.
- **Area:** seq

## Pop-while on a stack is a hand-written loop
- **Where:** `cf2057e2.cp`, lines 30–32:
  ```cp
  while let x = pending[i, j].last, queries[x].k > via:
      ans[x] = e.w
      pending[i, j].pop()
  ```
- **What felt wrong:** "answer every pending query this distance now
  satisfies" peeks, tests, acts and pops; the list is named three times and
  the `pop` result is discarded because the peek already produced it.
- **Goal it hurts:** express.
- **Ideal code:** `for x in pending[i, j].pop_while(x => queries[x].k > via): ans[x] = e.w`.
- **General fix (seq):** `xs.pop_while(p)` yielding the popped elements
  (the mirror of `take_while`); it also covers monotonic stacks. Not added;
  a proposal.
- **Dream:** `dream/cf2057e2.cp` line 19.
- **Severity:** low.
- **Area:** seq

## No filtered `for` and no product loop
- **Where:** `cf2057e2.cp`, lines 23–26: `for e in edges:` / `if d[e.u, e.v] > 0:` /
  `for i in V:` / `for j in V:`.
- **What felt wrong:** "every Kruskal edge" and "every pair" cost two
  nesting levels, so the relaxation sits five indents deep. Comprehensions
  accept `if`, the `for` statement does not.
- **Goal it hurts:** express.
- **Ideal code:** `for e in edges if d[e.u, e.v] > 0:` and `for (i, j) in V * V:`.
- **General fix (core):** a guard on `for` with the comprehension's
  meaning, and a product domain `V * V` (already the index space of
  `[V, V]`). Syntax; proposed, not added.
- **Dream:** `dream/cf2057e2.cp` lines 14 and 15.
- **Severity:** low.
- **Area:** core

## Ranged fields are stored as 64-bit
- **Where:** `cf2057e2.cp`, lines 10–11; emitted C++ declares
  `std::vector<std::tuple<int, int, ll>> edges, queries`.
- **What felt wrong:** `w: 1..=1e9` fits 32 bits but is emitted as `ll`, and
  `k: Int` has no bound because the statement's (`k <= dist(a, b) < n`)
  is not a type. The port's peak memory is 32 MB against the original's
  15 MB; the query table (300,000 tuples), the answer list and the per-pair
  `List<Q>` table are most of it.
- **Goal it hurts:** performance (fewest bytes the types allow).
- **Ideal code:** unchanged; `1..=1e9` should store as `int32`.
- **General fix (codegen):** width from the declared range for tuple
  fields, as already filed for cf2152g.
- **Dream:** `dream/cf2057e2.cp` lines 8 and 9.
- **Severity:** low.
- **Area:** codegen

## `floyd_warshall` needs an import, `Graph` does not
- **Where:** `cf2057e2.cp`, line 6: `use std.graph.{floyd_warshall}`.
- **What felt wrong:** `Graph`, `Rooted` and `bfs`-style methods are in
  scope by default, but the free algorithm next to them is not; the error
  names the fix, so it costs one round-trip, not a search.
- **Goal it hurts:** express (guessable).
- **Ideal code:** no import (see `g.hops()` above).
- **General fix (graphs):** methods on `Graph` for the all-pairs algorithms.
- **Dream:** `dream/cf2057e2.cp` line 11.
- **Severity:** low.
- **Area:** graphs
