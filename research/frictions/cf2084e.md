## No `.next()` / successor step on domain positions
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` line 40 vs `dream/cf2084e.cp` line 36:
  ```cp
  add_rect(Pos(p.to_idx + 1)..=lo, hi..=Pos.last, -1)
  ```
- **What felt wrong:** Stepping one position right of `p` inside `Pos` required dropping out of the domain into raw `Int` via `p.to_idx + 1` and re-wrapping with `Pos(...)`, because `p.next()` fails with `E0203: a Pos has no method next`. That breaks domain abstraction right where an off-by-one bug is easiest to write.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code (`dream/cf2084e.cp:36`):**
  ```cp
  add_rect(p.next()!..=lo, hi..=Pos.last, -1)
  ```
- **General fix:** Add `.next() -> ?D` and `.prev() -> ?D` (or exclusive-lower range syntax `(p..=lo)` / `p.after`) on ordered domain positions, returning `none` at the domain ends. Helps every sweeping-interval and two-pointer port.
- **Severity:** medium.

## `Comb<P>` repeats the modulus instead of deriving from `Z`
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` lines 5, 18 vs `dream/cf2084e.cp` lines 1, 15:
  ```cp
  type Z = Mod<1_000_000_007>
  let comb = Comb<1_000_000_007>(n)
  ```
- **What felt wrong:** The prime modulus `1_000_000_007` is written twice. Switching to `998_244_353` requires editing two places.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code (`dream/cf2084e.cp:15`):**
  ```cp
  let comb = Z.comb(n)
  ```
- **General fix:** Provide `Z.comb(n)` (or `Comb<Z>(n)`) so the modulus lives in one declaration. Also helps `cf2150g` and every combinatorics port.
- **Severity:** medium.

## No `Int(bool)` conversion or `.prefix_sums(at: .cuts)` method on arrays
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` line 16 vs `dream/cf2084e.cp` line 13:
  ```cp
  let missing = prefix1([Pos] i => if a[i] == -1: 1 else: 0)
  ```
- **What felt wrong:** Building a 0/1 indicator array requires `if a[i] == -1: 1 else: 0` instead of `Int(x == -1)`, and prefix sums are a free function `prefix1(...)` taking a fresh `[Pos]Int` array rather than a `.prefix_sums(at: .cuts)` fold on `a.map(...)`. Also `read` cannot bind `domain Pos = read(1..=5000)` with a range-typed element `[Pos]-1..n`.
- **Goal it hurts:** express, coherence.
- **Ideal code (`dream/cf2084e.cp:5-7,13`):**
  ```cp
  domain Pos = read(1..=5000)
  let a: [Pos]-1..n = read()
  let missing = a.map(x => Int(x == -1)).prefix_sums(at: .cuts)
  ```
- **General fix:** Add explicit `Int(b)` indicator conversion, `prefix_sums` on arrays/views (per `design/EXEMPLARS.md` rule 10), and `domain D = read(lo..=hi)` binding form.
- **Severity:** low.

## `Mod<P>` 64-bit storage and uninlined `Comb.arrange` overhead
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` line 52 (`ans += Z(freq[f]) * comb.arrange(f, need) * ways_rest`).
- **What felt wrong:** On `n = 5000`, the CP Lang binary takes `36.6 ms` vs `29.5 ms` for the C++ original (`1.24x`), primarily because `Mod<P>` stores 64-bit `Int` and `comb.arrange(f, need)` runs an `ensure(n)` check on every inner-loop call.
- **Goal it hurts:** performance.
- **Ideal code:** Same `cf2084e.cp` source, with `Mod<P>` narrowed to `int32_t` for `P < 2^31` and `Comb` bounds-checked once when pre-sized.
- **General fix:** Narrow `Mod<P>` storage to the narrowest integer holding `0..P`, and mark `Comb.ensure` cold / hoistable in codegen.
- **Severity:** low.
