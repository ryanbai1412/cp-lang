## `Comb<P>` requires a separate `const P` instead of `Z.comb(n)`
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` lines 9–10, 22 vs `dream/cf2084e.cp` lines 7, 18:
  ```cp
  const P = 1_000_000_007
  type Z = Mod<P>
  ...
  let comb = Comb<P>(n)
  ```
- **What felt wrong:** `Comb<P>` cannot be derived from the modular type `Z`, forcing a separate `const P` declaration alongside `type Z = Mod<P>`.
- **Goal it hurts:** express, coherence.
- **Ideal code (`dream/cf2084e.cp:18`):**
  ```cp
  let comb = Z.comb(Pos.count)
  ```
- **General fix:** Provide `Z.comb(n)` (or `Comb<Z>(n)`) so the modulus lives only in `type Z = Mod<...>`.
- **Severity:** low.

## No `.prefix_sums(at: .cuts)` method on arrays or `domain Pos = read(1..=5000)`
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` lines 12–13, 20 vs `dream/cf2084e.cp` lines 9, 16:
  ```cp
  let n: 1..=5000 = read()
  domain Pos = 0..n
  ...
  let missing = prefix1([Pos] i => Int(a[i] == -1))
  ```
- **What felt wrong:** Prefix sums are a free function `prefix1(...)` taking a fresh `[Pos]Int` array rather than `.prefix_sums(at: .cuts)` on `a.map(...)`, and reading a domain size still requires `let n = read(); domain Pos = 0..n`. (Note: `.next` on `Pos` works as a getter; calling `.next()` with parentheses fails without suggesting `.next`.)
- **Goal it hurts:** express, coherence.
- **Ideal code (`dream/cf2084e.cp:9,16`):**
  ```cp
  domain Pos = read(1..=5000)
  let missing = a.map(x => Int(x == -1)).prefix_sums(at: .cuts)
  ```
- **General fix:** Add `prefix_sums` on arrays/views (per `design/EXEMPLARS.md` rule 10) and `domain D = read(lo..=hi)` binding form; suggest `.next` when `.next()` is called on a domain value.
- **Severity:** low.

## `Mod<P>` 64-bit storage and uninlined `Comb.arrange` overhead
- **Where:** `proto/ports/ecnerwala/cf2084e.cp` line 57 (`ans += sum(Z(freq[f]) * comb.arrange(f, need) * ways_rest for f in need..=m)`).
- **What felt wrong:** On `n = 5000`, the CP Lang binary takes `36.6 ms` vs `29.5 ms` for the C++ original (`1.24x`), primarily because `Mod<P>` stores 64-bit `Int` and `comb.arrange(f, need)` runs an `ensure(n)` check on every inner-loop call.
- **Goal it hurts:** performance.
- **Ideal code:** Same `cf2084e.cp` source, with `Mod<P>` narrowed to `int32_t` for `P < 2^31` and `Comb` bounds-checked once when pre-sized.
- **General fix:** Narrow `Mod<P>` storage to the narrowest integer holding `0..P`, and mark `Comb.ensure` cold / hoistable in codegen.
- **Severity:** low.
