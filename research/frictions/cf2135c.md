# Friction: `cf2135c`

The port hand-rolled a low-link DFS to find 2-edge-connected components and,
in the same pass, the parity of each back edge. It now says the editorial:
values agree across a 2-edge-connected component (`two_edge_components`), and
an odd cycle inside one forces 0. A component is entered through one bridge,
so the depth parity of a single `bfs` from vertex 1 is consistent inside it;
an edge whose ends share a component and a parity closes an odd cycle.

## A local fn cannot name a domain bound by `let (domain C, ...)`

- **Where:** `let (domain C, comp) = two_edge_components(g)` followed by
  `fn force(c: C, val: Int)`; `cpl check` rejects it with "`C` is not a type
  `cpl run` knows". The port collects `(component, value)` pairs into a list
  and folds them in a loop instead.
- **Resolved:** a destructured fresh domain is now a type name for the rest
  of its scope, nested fns included; the port declares `fn force(c: C, x: Int)`
  next to `var want: [C]?Int` and calls it from both loops.
- **What felt wrong:** the domain is in scope for `[C]?Int` and `for c in C`
  but not for a parameter type, so the natural helper has to become a list.
- **Goal it hurts:** express, coherence.
- **Ideal code:** `fn force(c: C, val: Int)` next to `var want: [C]?Int`.
- **General fix:** core: a domain bound by a destructuring `let` is a type
  name for the rest of its scope, fns included. Helps every port that groups
  by `components`, `scc`, `two_edge_components` or `biconnected`.
- **Severity:** low (resolved).
