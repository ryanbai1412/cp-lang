# cf2053i1 — Affectionate Arrays (Easy Version)

The editorial's greedy: the boredom can't go below `s = Σ a`, and it equals
`s` exactly when every prefix sum of `b` stays in `[0, s]`. So scan `a` with
the interval of prefix sums still reachable; when it empties, one inserted
element before `a_i` makes all of `[0, s]` reachable again. `b` must end at
`s`, which costs one more insertion when `s` is not reachable at the end.

## An interval of integers has no shift or intersection
- **Where:** `cf2053i1.cp`, lines 13 and 16:
  ```cp
  reach = max(reach.lo + x, 0)..=min(reach.last + x, s)
  reach = max(x, 0)..=min(s + x, s)
  ```
- **What felt wrong:** the invariant is "the reachable set is an interval
  inside `bounds = 0..=s`", and the step is "shift it by `x`, intersect with
  `bounds`". `Range<Int>` has `lo`, `last`, `is_empty` and `in`, but
  `reach + x` and `reach & bounds` are `E0309` and there is no
  `intersect`/`clamp` method, so each step re-spells the bounds as a
  `max`/`min` pair. The bound `0..=s` is written three times (lines 13, 16,
  17 by implication) instead of once, and the reset on line 16 is the same
  shift-and-clamp as line 13 but cannot say so.
- **Goal it hurts:** express and revise (a fact in one place: changing the
  allowed band, e.g. to `[-c, s]`, edits two `max`/`min` pairs).
- **Ideal code:** `reach = (reach + x) & bounds` and
  `reach = (bounds + x) & bounds`.
- **General fix (core/ranges):** translation `Range<T> + T` (and `-`) and
  intersection `Range<T> & Range<T>` (empty when disjoint) for ordered
  ranges, both O(1). The same pair covers sliding windows, interval DPs and
  feasibility intervals. This is a library addition; proposed, not added.
- **Dream:** `dream/cf2053i1.cp` lines 8, 13 and 16: `bounds` is declared
  once and each step is one shift and one intersection.
- **Severity:** medium.
- **Area:** ranges

## `(a..=b).hi` is `b + 1`
- **Where:** `cf2053i1.cp`, line 13 uses `reach.last`; the first draft used
  `reach.hi` and gave wrong answers on the sample.
- **What felt wrong:** for `r = 2..=5`, `r.lo` is `2` but `r.hi` is `6`
  (the half-open end), while `r.last` is `5`. After writing an inclusive
  range, `hi` reads as its upper bound; the off-by-one is silent (no trap,
  no lint). `last` is also partial: it has no value on an empty range, so the
  port relies on `reach` being nonempty at the top of every step.
- **Goal it hurts:** hard to get wrong (off-by-one, unguessable API).
- **Ideal code:** no endpoint access at all (see above); when needed,
  `r.lo`/`r.hi` should mean the bounds as written, or `hi` should not exist
  on a `..=` range.
- **General fix (core/ranges):** name the half-open end so it can't be
  mistaken for the written bound (`r.end`), or lint `.hi` on a value built
  with `..=`. Not added.
- **Dream:** `dream/cf2053i1.cp` lines 13 and 16 never touch an endpoint.
- **Severity:** medium.
- **Area:** ranges

## Bool to count is `Int(b)`
- **Where:** `cf2053i1.cp`, line 17: `print(n + inserted + Int(s not in reach))`.
- **What felt wrong:** the first guesses were `(if hi < s: 1 else: 0)` and
  `(s !in reach)` (`!` is unwrap, so `E0302`). `Int(b)` works but is not in
  the cheat sheet; the dream's `.int` suffix reads left to right.
- **Goal it hurts:** express (guessable APIs).
- **Ideal code:** `(s not in reach).int`.
- **General fix (core):** document `Int(b)` next to `not in`, or make the
  conversion a method so it composes left to right.
- **Dream:** `dream/cf2053i1.cp` line 17.
- **Severity:** low.
- **Area:** core
