## Algorithm summary

Every beautiful subsequence over $\{1, 2, 3\}$ has the form `1, 2, ..., 2, 3` with at least one `2`. Stream the $n$ values with refined type `1..=3`, maintaining three `Mod<998_244_353>` counts: `ones` (count of `1`s), `one_twos` (count of `1, 2+` subsequences), and `ans` (count of `1, 2+, 3` subsequences).

---

## Frictions

This problem is a near-ideal fit for CP Lang (`@!multitest`, `Mod<998_244_353>`, `1..=3` refinement enabling exhaustive `match`). The only minor frictions observed are:

### 1. Streaming `read()` cannot be typed inline at a `match` scrutinee

**What happened:**
`read()` infers its target type from an enclosing binding annotation, so matching directly on a streamed input value requires a single-use binding `let x: 1..=3 = read()` on the line above `match x:`. Writing `match read() as Int:` is a parse error (`E0103`).

**Current code:**
```cp
for _ in 0..n:
    let x: 1..=3 = read()
    match x:
        1 => ones += 1
        2 => one_twos = one_twos * 2 + ones
        3 => ans += one_twos
```

**Ideal code:**
```cp
for _ in 0..n:
    match read::<1..=3>():
        1 => ones += 1
        2 => one_twos = one_twos * 2 + ones
        3 => ans += one_twos
```

**General fix:**
Allow type-argument syntax `read::<T>()` (including range types like `1..=3`) wherever a generic function call is valid, so single-use reads don't require a throwaway `let` binding.

---

### 2. Repeating type and initializer for multiple same-type accumulators

**What happened:**
Initializing three zeroed `Z` counters requires either three separate `var` lines or repeating both `Z` and `0` three times in `var (ones, one_twos, ans): (Z, Z, Z) = (0, 0, 0)`.

**Current code:**
```cp
var ones: Z = 0
var one_twos: Z = 0
var ans: Z = 0
```

**Ideal code:**
This is already readable at 3 lines; if tuple/multi-binding declarations ever allow a shared type or broadcast zero, it would compress naturally, though keeping one declaration per variable is acceptable.

---

## What worked well

- `let x: 1..=3 = read()` both encodes the statement's input constraint (`1 <= a_i <= 3`) and lets the compiler prove `match x:` over `1`, `2`, `3` is exhaustive without a dead `_ => ()` arm.
- `Mod<998_244_353>` mixed arithmetic (`one_twos = one_twos * 2 + ones`, `ones += 1`) needed no `Z(...)` wrappers.
- The emitted C++ is nearly 2x faster than `std::cin` C++ on $n = 200\,000$ at 0.54x the contestant tokens.
