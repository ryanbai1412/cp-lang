# cf2183d1 — Tree Coloring (easy)

The dream groups vertices by depth with `V.group(by: t.depth)` and checks `all` parents of a
layer equal; the port walks `t.order` (breadth-first, so a layer is one run) and keeps
`size`/`shared` by hand across runs.

## `group(by:)` is twice as slow as the hand run scan
- **Where:** dream
  `for (_, layer) in V.group(by: t.depth): ... ans max= layer.len + Int(same_parent)`;
  port lines `var size` / `var shared` / `for (k, v) in order.items:` with
  `let prev = if k > 0: Some(order[k - 1]) else: None`.
- **What:** the dream checks and gives the same answers, but on the `--max` input it takes
  101 ms against the port's 46 ms: `group(by:)` materialises a `List` per depth. The port's
  run scan is a C++-style state machine (two flags reset on a boundary) and reads worse.
- **Goal it hurts:** performance (dream form), express (port form).
- **General fix:** `group(by:)` over a domain should be a lazy view of runs over a sorted
  order without per-group lists, or `t.layers` should give the breadth-first runs directly.
- **Severity:** medium.
- **Owner:** stdlib (Seq grouping), tree lane (`Rooted.layers`).
