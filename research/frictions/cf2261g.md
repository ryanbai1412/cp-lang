# Friction: `cf2261g`

## Un-niched `Row<std::optional<ll>, 2>` and per-node temporary `std::vector` in `Trie` (3.5x slowdown)

- **Status:** closed (`?Int` in `cpl::Row<cpl::OptInt, 2>` is niched to 8 B, and `emit_row_init` in `crates/cpl-codegen/src/expr.rs` now constructs fixed-size `cpl::Row<T, K>` fields directly on the stack for array comprehensions/literals/fills without a per-node temporary `std::vector`; matched `bench/strings/trie` dropped from `43.8 ms` / `1.33x` to `35.4 ms` vs `33.8 ms` C++17 / `1.05x`).
- **Severity:** high
- **Goal it hurts:** performance
- **Measured:** `357.41 ms` vs `100.79 ms` (`3.55x`) on `gen size=25000` (`research/scoreboard.json`).
- **Cause (layout + codegen):** `struct Trie(cnt: Int, kid: [0..2]?Int)` emits `cpl::Row<std::optional<ll>, 2>` (32 B for two children instead of two niched 4-byte `int32_t` indices), and `[0..2] b => ...` inside `chain()` allocates a temporary `std::vector<std::optional<ll>>` on every trie node (`25 * n` heap allocations).
- **Fix:** niche `?Int` / `?Pos` inside fixed-size `Row` fields and emit fixed-size array comprehensions directly on the stack without a heap `std::vector`.

## No binary trie with counts and destructive merge

- **Goal it hurts:** express, hard to get wrong
- **Severity:** medium
- **Area:** stdlib
- **Status:** open
- **Dream:** `corpus/problems/cf2261g/dream.cp:8, 12, 16, 19`
- **Actual:** `corpus/problems/cf2261g/port.cp:18-51`
- **General fix:** a fixed-width `BitTrie<W>` in the stdlib (counts per node, `of(x)`, `absorb` that merges another trie in amortized O(total nodes), and `walk(x)` yielding `(bit, subtree)` along a path). `std.strings.Trie` is alphabet-indexed with `-1` children and no merge, so the port keeps its own arena of `Node(cnt, kid: [Bool]?Int)`, a bottom-up `chain` builder and a recursive `merge`.

## Merging equal neighbours of a list: the stdlib form costs 1.36x the hand loop

- **Goal it hurts:** express, performance
- **Severity:** low
- **Area:** codegen
- **Status:** open
- **Dream:** `corpus/problems/cf2261g/dream.cp:16`
- **Actual:** `corpus/problems/cf2261g/port.cp:56-63` (a `kept.last` loop calling the named `absorb`)
- **Today's spelling:** `[run.reduce(absorb)! for run in groups.map(g => Group(g.mask & x, g.root)).runs(by: g => g.mask)]` says it with no `merge_runs`, so none is owed in the stdlib.
- **Measured:** on a max input (n = 4e5, `a_i = FULL ^ 2^(i % 25)`, so 25 groups live), best of 5: port with the hand loop 0.53 s, the same port with the `runs` + `reduce` spelling 0.72 s, `orig.cpp` 0.44 s (g++ -std=c++17 -O2, deducing-`this` lambda swapped for `std::function`). The `runs` form is 1.64x the original, over the 1.5x bar, so the port keeps the loop. Spelling the run fold as `Group(run.first!.mask, run.map(g => g.root).reduce(merge)!)` was 1.41 s.
- **Cause:** the emitted `shrink` copies its `List` parameter, materialises the `map` result, materialises `runs` as a `std::vector<cpl::ListView<Group>>`, and passes an empty `std::optional<std::function<..>>` for `link`; `perf` puts 25% of the run in `shrink`.
- **General fix:** `runs` consumed by a comprehension or `for` streams its slices instead of building a vector, `map` fuses into a following `runs`, and a by-value `List` parameter that is only read is passed by reference.

## A `[Bool]T` struct field is a heap `std::vector`, not a `cpl::Row<T, 2>` (3.3x slower, 5x RSS)

- **Goal it hurts:** performance
- **Severity:** high
- **Area:** codegen
- **Status:** open
- **Repro:** `struct Node(kid: [Bool]?Int)` emits `std::vector<cpl::OptInt> kid;`, while `kid: [0..2]?Int` emits `cpl::Row<cpl::OptInt, 2> kid;`.
- **Measured:** the port with `kid: [Bool]?Int` and `kid[x.bit(z)]` ran 1.87 s / 655 MB against 0.56 s / 127 MB for `orig.cpp` on the max input above; with `[0..2]?Int` it is 0.53 s / 249 MB.
- **Actual:** the port keeps `kid: [0..2]?Int` indexed by `(x >> z) & 1` (`port.cp:20, 41, 48`), where `[Bool]` and `x.bit(z)` say it.
- **General fix:** a table over any finite domain with a compile-time size (`Bool`, enums, `0..k`) lowers to `cpl::Row<T, |D|>`.

## A bounded `?(0..=10_400_000)` takes 8 bytes

- **Goal it hurts:** performance
- **Severity:** low
- **Area:** codegen
- **Status:** open
- **Repro:** `kid: [0..2]?(0..=10_400_000)` still emits `cpl::Row<cpl::OptInt, 2>`; a node is 24 B against 12 B in `orig.cpp` (`int cnt; std::array<int, 2> c;`), so the port's RSS is 249 MB against 127 MB.
- **General fix:** an optional over a range that fits 32 bits takes a niched 32-bit slot (as `int32_t` with a spare value).

## A `[Bool]` table's comprehension index is an `Int`

- **Goal it hurts:** coherence
- **Severity:** low
- **Area:** types
- **Status:** open
- **Dream:** `corpus/problems/cf2261g/dream.cp:8`
- **Actual:** `corpus/problems/cf2261g/port.cp:37, 40`
- **General fix:** `[Bool] b => ...` should bind `b: Bool`, as `kid[x.bit(z)]` already indexes by `Bool`. Today `[Bool] b => if b == x.bit(z): ...` fails with E0302 (`Int` vs `Bool`), so the port fills with `None` and assigns the one child (rechecked: still E0302).
