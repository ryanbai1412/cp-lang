## Friction 1: the visit index is a hand counter

- Where: `var cur = 0` incremented inside `for i in 0..k: for v in (n - 1 - i) % k..n by k`.
- What felt wrong: `cur` is the position of `v` in the visit order, which the loop nest
  defines; the port counts it by hand so it can write `a[v] = cur / (m + 1)`.
- Goal it hurts: R13 (a counter whose meaning is the loop's order).
- Ideal code: `for (cur, v) in enumerate(v for i in 0..k for v in (n - 1 - i) % k..n by k): a[v] = cur / (m + 1)`.
- General fix: port edit, if `enumerate` over a nested comprehension stays lazy; not probed.
- Severity: low.
- Owner: idioms.

Memory is 4.5 MB against 3.1 MB: the `[0..n]Int` answer table is 8 bytes per value where
the values are below n / (m + 1); bounding it as `[0..n]0..=n` would narrow it.
