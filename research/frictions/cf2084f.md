## `MinHeap.pop()` heap-allocates a `std::vector` on every sift-down step, and `SegTree` uses `std::function` (2.36x slowdown)
- **Where:** `proto/ports/ecnerwala/cf2084f.cp` lines 18, 25, 42 (`SegTree<Val, Pos>(Monoid(...))` and `pq.pop()`).
- **What felt wrong:** On `n = 500_000`, the port takes `325.5 ms` vs `137.8 ms` for C++ (`2.36x`) and `53.8 MB` vs `35.5 MB` RSS (`1.51x`). Inspecting the emitted C++ shows two stdlib/codegen causes:
  1. `stdlib/heap.cp:44` writes `for c in [2 * i + 1, 2 * i + 2]:`, which emits `std::vector<ll> t0 = std::vector<ll>{2 * i + 1, 2 * i + 2};` inside the `while (true)` sift-down loop — roughly `n log n` (~8M) heap allocations per `n = 500_000` test.
  2. `SegTree<Val, Pos>` stores `Monoid.op` as `std::function<int(int, int)>`, causing an indirect call on every tree node in `set` and `fold`.
- **Goal it hurts:** performance.
- **Ideal code:** Same `MinHeap` and `SegTree` calls, with zero heap allocations in `MinHeap.pop()` and monomorphized/inlined `Monoid.op`.
- **General fix:** (1) Lower small literal list iterations (`for x in [a, b]:`) to stack `std::array` / unrolled checks in codegen (and avoid allocating in `stdlib/heap.cp`), and (2) monomorphize `Monoid` / `Action` operations instead of erasing to `std::function`. Helps every heap and segment-tree port (`cf2147f`, `cf2084f`, etc.).
- **Severity:** high.

## No top-level `return` inside `@!multitest` to short-circuit impossible cases
- **Where:** `proto/ports/ecnerwala/cf2084f.cp` lines 38-52 vs `dream/cf2084f.cp` lines 31-37:
  ```cp
  fn solve() -> Bool:
      for i in Pos:
          ...
          let (deadline, v) = pq.pop() ?? return false
          ...
      true

  if solve():
      print(b)
  else:
      print(-1)
  ```
- **What felt wrong:** To exit early on an impossible case without a boolean flag variable, we had to wrap the greedy loop in a `fn solve() -> Bool` helper and dispatch on its return value at the bottom. In `design/EXEMPLARS.md` / `exemplars-16-25.md`, `return` below `--- with multitest() ---` returns from the per-test body directly.
- **Goal it hurts:** express.
- **Ideal code (`dream/cf2084f.cp:31-37`):**
  ```cp
  for i in Pos:
      for v in by_lo[i]: pq.push((hi[v], v))
      let (deadline, v) = pq.pop() ?? return print(-1)
      if deadline < i or (c[i] != none and c[i] != v):
          return print(-1)
      b[i] = v
  print(b)
  ```
- **General fix:** Allow `return` (and `return expr`) at top level inside `@!multitest` / `--- with multitest() ---` to finish the current test case. Helps every multitest constructive/decision problem.
- **Severity:** medium.

## No `.invert()`, `.group(by:)`, or direct `for v in a` / `a.rev` over domain arrays
- **Where:** `proto/ports/ecnerwala/cf2084f.cp` lines 12-15, 19-20, 26-27, 31-33 vs `dream/cf2084f.cp` lines 10, 15, 22, 26:
  ```cp
  var fixed: [Val]?Pos = none
  for i in Pos:
      if let v = c[i]:
          fixed[v] = i
  ...
  var by_lo: [Pos]List<Val> = []
  for v in Val:
      by_lo[lo[v]].push(v)
  ```
- **What felt wrong:** Inverting `c: [Pos]?Val`, bucketing `Val` by `lo[v]`, and sweeping `a` forward/backward each take a multi-line imperative loop instead of one declarative expression (`c.invert()`, `Val.group(by: v => lo[v])`, `for v in a.rev:`). Also `SegTree<Val, Pos>` could not use bare `max`/`min` directly (required `Monoid(Pos.first, max)` / `Monoid(Pos.last, min)` because `Pos` has no built-in `Max<Pos>`/`Min<Pos>` monoid over `?Pos`).
- **Goal it hurts:** express, coherence.
- **Ideal code (`dream/cf2084f.cp:10,14-26`):**
  ```cp
  let fixed: [Val]?Pos = c.invert()
  var pref_max = SegTree<Val, Max<Pos>>(init: none)
  for v in a: ...
  let by_lo = Val.group(by: v => lo[v])
  ```
- **General fix:** Add `.invert()` on partial-permutation arrays, `D.group(by:)` returning `[K]List<D>`, `a.rev` on arrays, and `Max<T>`/`Min<T>` monoids over `?T` for any `Ord` type `T` (including domains).
- **Severity:** low.
