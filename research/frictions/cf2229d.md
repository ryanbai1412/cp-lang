# cf2229d — Median Columns

Both binary-search the largest `v` with `(1..=2 * n).last_true(is_good)`, where a column's
sign is `[x >= v] + [y >= v] - 1` and `is_good` compares `+1` columns against runs of `-1`.

## The dream's lists are 1.5x slower than the port's loop
- **Where:** dream: `let signs = [...]`, `let nz = [s for s in signs if s != 0]`,
  `count(s == -1 and (i == 0 or nz[i - 1] != -1) for (i, s) in nz.items)`; port: one loop
  with `ones`, `neg_runs`, `last`.
- **What:** same output, 10 ms vs 15 ms on `--max`, because each of `log(2n)` probes builds two
  lists. The dream reads as the editorial; the port threads three counters, one with a
  "previous nonzero" comment.
- **Goal it hurts:** the obvious way is the fast way.
- **General fix:** a run-count helper (`nz.runs().count(r => r.key == -1)`) over a lazy
  filter, so no list is built.
- **Severity:** low.
- **Owner:** stdlib (Seq runs), perf.
