# Friction report: cf2268e

The port and the dream share the per-bit reduction: base `C_n (n - 1)`, minus `sum_d C_d C_(n-d) corr(d)` when the bit's total parity is even. They differ only in how the autocorrelation is paid for.

## The autocorrelation is a hand frequency-domain dot product
- **Where:** `port.cp` lines 25-38: `let size = bit_ceil(2 * n + 1)`, `var w = List.filled(size, Z(0))`, `ntt(mut w)` once, then per bit `ntt(mut a)` and `scale * sum(a[f] * a[(size - f) % size] * w[f] for f in 0..size)`.
- **What felt wrong:** the dream says what is computed, `convolve(a, [a[n - i] for i in 0..=n])` then `sum weight[d] * corr[n - d]`. The port writes the transform length, the padding, the `-f` index and the `1 / size` scale by hand, so one sum is spread over five lines that have to agree.
- **Goal it hurts:** express, hard-to-get-wrong.
- **Ideal code:** the dream's lines 66-71: `var a: [0..=n]Z = 1`, `let corr = convolve(a, a.rev)`, `for d in 1..n: cur -= weight[d] * corr[n - d]`.
- **General fix:** a std `Ntt` plan that keeps a transformed operand (`let wt = ntt.transform(weight)`) and offers `ntt.dot(a, a.rev, wt)` or `autocorrelation(a)`. The port would then cost one transform per bit with no hand indexing. The same applies to any port that convolves many sequences against one fixed kernel. Owner: stdlib.
- **Severity:** low.

## Dream

`dream.cp` is the ideal as written. It already checks, so the only gap is the one above.
