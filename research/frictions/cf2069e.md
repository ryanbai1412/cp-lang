## Algorithm summary

Every `"AB"` or `"BA"` pair consumes one `'A'` and one `'B'`, so we need at least `need = max(0, cnt_a - a, cnt_b - b)` pairs; if `need > ab + ba`, the answer is `"NO"`. Partition `s` into maximal alternating runs (`s[i] != s[i - 1]`): an odd run of length $2k+1$ yields $k$ flexible pairs (`wild`), while an even run of length $2k$ yields either $k$ pairs of its own type (`AB` or `BA`) or $k-1$ pairs of any mix. After subtracting `wild` from `need`, if neither side's total alone covers `need` via `min(sum_ab, ab) + min(sum_ba, ba) >= need`, exactly one side overflows its capacity; sort that side's even runs ascending and convert the largest runs one by one (sacrificing 1 pair per converted run) until the capacity check passes or runs are exhausted.

## Frictions

### 1. `std.seq.runs` only splits on equality and only accepts `List<T>`, not `Str`

- **Severity:** medium
- **Goal it hurts:** express
- **Area:** seq

**What happened:**
Partitioning `s` into maximal alternating runs (`s[i] != s[i - 1]`) could not use `std.seq.runs` for two reasons:
1. `runs` only groups equal adjacent elements (`a[j] == a[i]`), with no adjacency-predicate variant (like Rust's `chunk_by` / `split_when`).
2. `std.seq` combinators (`runs`, `pairs`, `windows`) are typed for `List<T>` rather than any indexed sequence including `Str`.

We had to write a manual `start`-tracking loop with an end-of-string boundary check (`if i + 1 == s.len or s[i + 1] == s[i]:`).

**Current code:**
```cp
var start = 0
for i in 0..s.len:
    if i + 1 == s.len or s[i + 1] == s[i]:
        let len = i - start + 1
        if len % 2 == 1:
            wild += len / 2
        elif s[start] == 'A':
            ab_runs.push(len / 2)
        else:
            ba_runs.push(len / 2)
        start = i + 1
```

**Ideal code:**
```cp
for run in s.chunk_by((x, y) => x != y):
    if run.len % 2 == 1:
        wild += run.len / 2
    elif run[0] == 'A':
        ab_runs.push(run.len / 2)
    else:
        ba_runs.push(run.len / 2)
```

**General fix:**
Add a generator `chunk_by(self, same: (T, T) -> Bool) -> yields [T]` (yielding slices/views without copying) in `std.seq`, and make sequence combinators work uniformly over `Str`, `[D]T`, and `List<T>` via the sequence/indexable trait.

### 2. No 3+ argument `max` / `min` without allocating a list literal

- **Severity:** low
- **Goal it hurts:** express, performance
- **Area:** seq

**What happened:**
Taking the maximum of three values (`0`, `cnt_a - a`, `cnt_b - b`) required either nested calls `max(0, max(cnt_a - a, cnt_b - b))` or allocating a temporary `List<Int>` via `max([0, cnt_a - a, cnt_b - b])`.

**Current code:**
```cp
var need = max([0, cnt_a - a, cnt_b - b])
```

**Ideal code:**
```cp
var need = max(0, cnt_a - a, cnt_b - b)
```

**General fix:**
Support variadic `min(a, b, ...)` / `max(a, b, ...)` (or optimize `max([a, b, c])` on literal arrays with zero heap allocation in codegen, alongside variadic syntax).

### 3. `count(s, pred)` predicate overload missing (same gap as `all`/`any`)

- **Severity:** low
- **Goal it hurts:** express
- **Area:** seq

**Status:** fixed: `count(s, c => c == 'A')` and `s.count(c => c == 'A')` now count on any sequence (`decisions.md` 26.9); the port keeps `s.count('A')`, the shorter form for one value.

**What happened:**
`s.count('A')` worked cleanly here because we matched a single character, and `count(c == 'A' for c in s)` also works. However, `count(s, c => c == 'A')` fails with `E0303: count takes 1 argument, but 2 were given`, matching the same predicate-overload asymmetry seen on `all`/`any` in `cf2207e2`.

**Ideal code:**
```cp
let cnt_a = count(s, c => c == 'A')
```

**General fix:**
Unify `all`, `any`, and `count` to accept an optional predicate argument `(xs, pred)` in addition to a boolean generator.

## What worked well

- `s.count('A')` worked out of the box on `Str`.
- Conditional tuple binding `var (over, cap, rem, other) = if sum_ab > ab: ... else: ...` plus `for l in over.rev:` eliminated the 3-way `std::swap` and `while (!lenAB.empty())` pop loop from the C++ original, cutting contestant tokens nearly in half (0.51x).
- Runtime on $|s| = 500\,000$ matched C++ closely (5.1 ms vs 4.7 ms, 1.09x).
