## Algorithm

Track the online LNDS state `(cx, cy, lnds)` along `a`, branching at every `'0'` (placing `'1'` in `b` so `b > a`). Before `a`'s prefix reaches `lnds == k`, accumulate the number of ways each branch first hits `lnds == k` at `(px, py)` into a 2D diagonal difference table `pref[0..=k, 0..=k]` using the binomial reflection formula in `e0 = k - cx`, `e1 = k - lnds`. If `a`'s prefix itself reaches `lnds == k` at `(ox, oy)`, branch along the remaining suffix of `a` directly using the closed-form completion count. Finish with a diagonal prefix sum on `pref` and sum `pref[px, py] * C(n - px - py, max(x - px, y - py, k))`.

## Frictions

### 1. `Mod<P>` stores `Int` (64-bit) instead of narrowing to `0..P` (`int32_t`), causing 2.0x memory and 2.1x runtime (critical)

`stdlib/mod.cp` declares `pub struct Mod<P>(v: Int)` rather than `v: 0..P`. For `P = 998_244_353`, the emitted struct `Mod_998244353_4` holds an 8-byte `ll v` instead of a 4-byte `int32_t`. On `pref: [Cnt, Cnt]Z` (`5001 x 5001 = 25M` entries), this doubles memory (`198784 KB` vs `101120 KB`), doubles memory bandwidth on the `O(k^2)` diagonal sweep, and pushes max-input runtime from `366.3 ms` to `761.0 ms` (2.08x, above the 1.5x performance ceiling).

Additionally, `Comb<P>.choose(n, k)` emits a non-inlined function that calls `ensure(n)`, checks `n >= P` for Lucas's theorem, and performs three bounds-checked `List` lookups on every call in the `O(k^2)` loop.

**Ideal code:**
```cp
// In stdlib/mod.cp:
pub struct Mod<P>(v: 0..P)
// Compiler narrows 0..998_244_353 to uint32_t / int32_t (4 bytes)
```
**General fix:** Narrow `Mod<P>`'s field type to `0..P` (4 bytes when `P <= 2^31`), and mark small hot stdlib helpers (`Comb.choose`, `Mod` ops) `inline` (with a fast path when `n < f.len`).

### 2. `Comb<998_244_353>` repeats the modulus instead of accepting `Z` or `Z.MOD` (low)

After declaring `type Z = Mod<998_244_353>`, constructing the combinatorics helper requires repeating the literal modulus `let comb = Comb<998_244_353>(n)` rather than `Comb<Z>(n)` or `Z.comb(n)`.

**Ideal code:**
```cp
type Z = Mod<998_244_353>
let comb = Z.comb(n)
```
**General fix:** Allow `Comb<Z>` (or a `Mod<P>.comb(limit)` constructor) so the modulus lives in one place.

### 3. Binary-only `max` and missing typo suggestion for `String` -> `Str` (low)

- `max(x - px.to_idx, y - py.to_idx, k)` had to be nested as `max(x - px.to_idx, max(y - py.to_idx, k))` (or `max([a, b, c])`, which allocates a `List` in the hot loop).
- Writing `let a: String = read()` produced `E0204: no type or domain named String` with no "did you mean `Str`?" suggestion.

**Ideal code:**
```cp
max(x - px.to_idx, y - py.to_idx, k)
```
**General fix:** Support variadic `min`/`max` for 2+ arguments without allocating a `List`, and add common-name suggestions (`String` -> `Str`, `Vec` -> `List`) to `E0204`.
