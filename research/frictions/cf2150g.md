## Algorithm

Track the online LNDS state `(z, o, lnds)` along `a`, branching at every `'0'` (placing `'1'` in `b` so `b > a`). Before `a`'s prefix reaches `lnds == k`, accumulate the number of ways each branch first hits `lnds == k` at `(px, py)` into a 2D diagonal difference table `pref[0..=k, 0..=k]` using the binomial reflection formula in `e0 = k - z`, `e1 = k - lnds`. Once `a`'s prefix reaches `lnds == k` at `base = (ox, oy)`, reset `cur` and count each suffix directly. Finish with a diagonal prefix sum on `pref` and sum `pref[px, py] * C(n - px - py, max(x - px, y - py, k))`.

## Frictions (port vs dream)

### 1. `Mod<P>` stores 64-bit `Int` instead of narrowing to `0..P` (`int32_t`), causing 2.0x memory and 2.1x runtime (`dream/cf2150g.cp:7,18`)
- **Severity:** high
- **Goal it hurts:** performance and control
- **Where:** `var pref: [Cnt, Cnt]Z = Z.zero` emits `Mod_998244353` holding an 8-byte `ll v` instead of a 4-byte `int32_t`. On `5001 x 5001 = 25M` entries, this doubles memory (`198784 KB` vs `101120 KB`) and bandwidth on the `O(k^2)` diagonal sweep (`761.0 ms` vs `366.3 ms`, 2.08x). `Comb<P>.choose(n, k)` also emits a non-inlined function with `ensure(n)` and Lucas checks inside the `O(k^2)` loop.
- **Dream:** `proto/ports/ecnerwala/dream/cf2150g.cp` lines 7, 18.
- **General fix:** Narrow `Mod<P>`'s field type to `0..P` (4 bytes when `P <= 2^31`) and inline hot `Comb.choose` / `Mod` ops.

### 2. No `Z.comb(n)` constructor or implicit `Int -> Z` literal coercion (`dream/cf2150g.cp:11,18-24,29,56-59`)
- **Severity:** low
- **Goal it hurts:** express and revise
- **Where:** `const MOD = 998_244_353`, `type Z = Mod<MOD>`, `let comb = Comb<MOD>(n)`, `Z.zero`, `Z.one`, `Z(2)`.
- **Dream (`dream/cf2150g.cp:7,11,18-24,29`):**
  ```cp
  type Z = Mod<998_244_353>
  let comb = Z.comb(x + y)
  var pref: [Cnt, Cnt]Z = 0
  pref[s.z, s.o] += 1
  ```
- **General fix:** Provide `Z.comb(limit)` (or `Comb<Z>`) and allow integer literals `0`/`1`/`2` to coerce to `Mod<P>` where `Mod<P>` is expected.

### 3. No struct methods (`s.push0()`) or multi-clause `for` / `sum` comprehension over 2D domains, plus binary-only `max` (`dream/cf2150g.cp:13-15,53-59`)
- **Severity:** low
- **Goal it hurts:** express and revise
- **Where:** `fn push0(s: Prefix) -> Prefix` top-level helpers, nested `for px in Cnt: for py in Cnt:`, `Cnt(...)` casts on `pref`, and `max(x - px.to_idx, max(y - py.to_idx, k))`.
- **Dream (`dream/cf2150g.cp:13-15,53-59`):**
  ```cp
  struct Prefix(z: Int, o: Int, lnds: Int):
      fn push0() -> Prefix = Prefix(z + 1, o, max(lnds, z + 1))
      fn push1() -> Prefix = Prefix(z, o + 1, lnds + 1)
  ...
  ans += sum(
      pref[px, py] * comb.choose(x + y - px - py, max(x - px, y - py, k))
      for px in Cnt, py in Cnt if pref[px, py] != 0
  )
  ```
- **General fix:** Support inline methods on structs, multi-generator `for`/`sum` clauses, and variadic `min`/`max` for 2+ arguments without allocating a `List`.

### 4. Enum variant payload labels can't be named at construction (`dream/cf2150g.cp:74`)
- **Severity:** low
- **Goal it hurts:** express and revise
- **Where:** `enum Phase: … Split(base: Walk)` declares the label, and `match` binds it (`Split(base) =>`), but `Split(base: walk)` fails with `E0310: Split has no argument named base`. Struct constructors accept the same named form (`W(z: 1, o: 2)`).
- **Actual:** `proto/ports/ecnerwala/cf2150g.cp:79` writes `Phase.Split(walk)` positionally.
- **General fix:** Variant construction should accept payload labels as named arguments, exactly like struct construction.
