# research/

Evidence and history: non-normative. `spec/` and `std/` are the rules; this is
how we got there and what we measured. Current folders first.

| Path | Holds | Current? |
|---|---|---|
| `PORTS.md` | Every port with token ratio and taste score (generated by `scripts/ports-page.py`). | yes |
| `MIGRATION.md` | The 0.2 to 0.3 migration guide. | yes |
| `writable-from-docs.md`, `writable-from-docs*.json` | The docs-only eval and its ratchet. | yes |
| `scoreboard.json` | Conformance and diff ratchet baseline. | yes |
| `perf/` | Corpus runtime results (`corpus-p95-*`, written by `bench/corpus_p95_bench.py` and `cpl bench`), tail profiles, max-n audits, build timings. | yes |
| `reviews/` | Taste reviews and their baseline. | yes |
| `frictions/` | One friction report per port. | yes |
| `dryrun/` | The contest dry run. | yes |
| `ports/`, `conformance-generators/`, `skill-eval/`, `bench/` | Port notes, conformance generator work, blind skill tests, bench C++ helpers. | yes |
| `design-history/`, `retros/`, `blind-critic/` | Design debates, retros, blind critiques. | history |
| `archive/` | Superseded, kept: `frictions/` (the v0.2 friction batches and hunter waves), `ecnerwala/` (corpus waves), `blind-evals/` (blind contests and cold-writer benches), `architecture/` (language-architecture drafts, syntax bake-off, 0.3.0 spec review), `audits/`, `scripts/` (one-off miners), `spec-status.md`, `restructure.md`, the v0.2 CLI programs and local lib. | no |

New evidence goes in a topic folder, not at the top; a write-up that a later
one replaces moves to `archive/`.
