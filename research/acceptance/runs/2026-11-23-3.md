## 1. understand (pass)
I read /, /learn/intro, /llms.txt, getting-started and the cheatsheet. Three sentences:
CPL is a Python-indented contest language that compiles to one readable C++17 file you submit as GNU C++17. It writes statement constraints as types (1..=2e5, [V]Int over a named 1-based domain) so input is validated, widths chosen and off-by-ones / index mixups become compile errors or named traps; ?T replaces -1/INF sentinels. Its library (segtree, DSU, dijkstra, Mod) and tooling (cpl stress with @alt brute + shrink, time-travel Trace) aim to cut boilerplate and debugging vs C++.
The release notes still say parts of the stdlib are "check-only". The getting-started page and /setup also disagree about the installer (`release-notes-say-unimplemented`, `install-docs-disagree`).

## 5. test (pass)
Every problem has its sample plus a custom case (40 random small inputs checked against my Python brute force) in `cfX.tests/`, run with `cpl test`.
- **2285A:** exact comparison failed with ``first difference at line 2, token 2: expected `3`, got `2` ... if any valid answer is accepted, add a `@check fn` ``, so I wrote a `@check` validator. It works and also catches a broken copy (`checker: assertion failed: composite((i + 1) * p[i])`).
- **Yes/No:** comparison is now case-insensitive (`test-exact-case-yes-no` is fixed).
- **`count(pred for ...)`:** the team claim it is fixed is confirmed: `count(x > 2 for x in [5,3,8,1])` gives 3 (`count-of-bools-counts-all` is fixed).
- **Other probes:** `a.rev.items` still yields the original indices (`rev-view-index-not-reversed`). `(0..4).sorted(by:)` and `V.sorted(by:)` are non-empty (`range-sorted-empty` not reproduced). `argmax` works (`argmax-on-range-confusing-error` not reproduced).

Bug hunt: in `cf2289C_offbyone.cp` I changed the final loop to `for i in 0..n - 1:` and added an `@alt(program)` brute force. `cpl stress --size 8` printed `FAIL on case 1 (seed 1): WA ... that is: n = 1  pv = [1] expected: 1 got: 0` and saved `bugC.tests/stress-1.in`. `cpl run --trace` then wrote `bugC.trace.html`.

Stress caveats:
- With the natural `p: [0..n]1..=2e5` type, stress generated `p = [1, 1]` and reported a false WA after the fix.
- `Perm<1..=n>` fails with an error blaming `V` inside std.seq. Only `domain V = 1..=n; let pv: Perm<V>` worked.
- The brute force may not reuse the solution's `p` (`` `p` is the solution's own work: a brute or a checker shares only the input ``).
