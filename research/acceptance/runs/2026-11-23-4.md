## 1. understand (10:37–10:37 UTC, ~1 min, pass)
Read the homepage and the intro guide (https://cp-lang.org/learn/intro/). My three sentences: CPL is a small statically typed language for competitive programming that compiles to one readable C++17 file you can submit to any judge. It turns the statement's constraints into types (`let n: 1..=2e5 = read()`), so out-of-range input, off-by-one index spaces (`domain V = 1..=n`) and "-1 means none" sentinels become checked errors or optionals instead of silent wrong answers. Compared with C++ it removes the boilerplate (no main, includes, fast-IO, `#define int long long`), ships a CP standard library (Prefix, DSU, segment trees, graphs) and has built-in stress testing and trace debugging. Small doubt: three spellings of the install command across pages (`install-cmd-three-spellings`).

## 8. design (11:21–11:24 UTC, ~3 min, pass: 5/5 predictions, both chapters give reasons)
I read the ownership chapter in two places, https://cp-lang.org/docs/guides/borrowing and the normative https://cp-lang.org/docs/ref/core/05-ownership. The second in-depth chapter was https://cp-lang.org/docs/ref/core/04-indices, with the guide /docs/guides/indices. I wrote `design/predictions.md` at 11:22, before running anything. All five predictions were right. p1 `var b = a` then using `a` gives `error[E0608]: \`a\` was already moved`. p2 assigning a non-`mut` parameter gives `error[E0401]: \`a\` is a parameter without \`mut\`, so it can't be assigned`. p3 calling without caller-side `mut` gives `error[E0402]: \`bump\` changes \`a\`, so the argument must be passed as \`mut a\``. p4 writing `a[1]` while `s = a[1..3]` is live gives `error[E0602]: \`a[1]\` can't be changed here: \`a\` is lent to \`s\` until its last use`. p5 pushing inside `for x in xs` gives `error[E0602]: ... the \`for\` loop is going over \`xs\``. Both chapters give reasons and alternatives. 05-ownership §13a "Why, compared with Rust" lists the four bug classes that mutation-XOR-access removes and compares the design with `&T`/lifetimes/`split_at_mut`; the guide has "Why there are no lifetime annotations". 04-indices has inline `Rejected:` entries (`r.mid: ?V`, `.start/.end/.before/.after`, a position-only range reading). Both spec chapters also cite unpublished `decision 137` / `plan/*.md` files. Extra probes found three more problems. Move checking is skipped inside `@check`: design/p9.cp compiles `var b = a` in a loop, while p8.cp gets `error[E0608]: \`a\` moves here in one round of the loop`. `.copy()` (guide) and `.clone()` (spec, diagnostics) both work.
