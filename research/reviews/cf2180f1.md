# cf2180f1 — Control Car (Easy Version)

Score: 3/5
Dream: 5/5

The header is a careful statement of the editorial's lazy-corner
argument. The body then encodes it in constants: `(9, 3, 3, 1)`,
`(6 * falls, 3 * falls, 2 * falls, falls)` and `(3 * slides, slides,
3 * shut, shut)` are counts of corner choices per shut/open state, and
nothing in the code says which. A contestant cannot check line 34
against the header without rederiving it.

## Checklist failures

- Unexplained constants carrying the recurrence (lines 21, 34, 36).
- Two prefix sums fused into the sweep with a boundary branch and
  `(i - 1)!` (lines 28, 32, 37). Reported.
- `Z(1) / 4`, `Z(4)` casts (lines 23, 39). Reported, with the silent
  `1 / 4 == 0` trap.
- `max(x.n for x in q)!` to size domains (lines 14-15). Reported.

## Owed rewrites

- Name the counts as the dream does, with today's tuple:
  `fn odds(shut: Bool, open: Int) -> Int = if shut: 1 else: open` and
  build `Ways` from it, e.g. `ways[j] = (falls * 3 * 2, falls * 3 * 1, ...)`
  written as `falls * odds(wall, 2) * odds(floor, 3)` per field. The
  numbers then come from the header's rule instead of from the reader.

## Language gaps

Reported: 3.2x for the `[Shut]Z` layout, 64-bit `Mod` storage, `1 / 4`
and `4 ** e` disagreement, fused prefix sums, input-sized domains. Missing:
`max(q.n)` over a field of a record list (dream line 13) is not in the
report as a separate ask.

## Dream notes

At the bar: `record Shut` with `odds` makes every coefficient a rule,
`stops.prefix_sums()` and `inside[..n, ..m]` say the answer is a 2D
prefix. This is the shape the port should approach.
