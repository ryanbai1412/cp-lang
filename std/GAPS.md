# Library bodies the compiler can't express yet

One line per fn left `todo`, or written below its documented cost, because
of a compiler gap: module, fn, and what the compiler is missing. Remove a
line when the gap closes and the body lands.

- subset: every `Subset` method: `Subset` is built into the compiler, so `cpl run` ignores these bodies, lacks `shifted`, `complement`, `supersets` and `for` over `items`, and a program's `Subset<D>` doesn't unify with the stub's (E0302 "expected `Subset<D>`, found `Subset<D>`"). The bodies check but can't be exercised by conformance cases yet.
- mod: `Barrett.reduce`, `Barrett.mul`: no 128-bit multiply-high on `U64`, so they reduce with `%` (same O(1) cost, not division-free).
- graph: `Functional.new` via `Functional(nx)`: on a generic struct, a call with fewer args than fields is read as a struct literal (E0303) instead of `new`, and `Functional.new(nx)` doesn't infer `V` from `[V]V` (E0302); programs must write `Functional<V>.new(nx)`.
- graph: `Graph.directed`, `Graph.undirected`, `Graph.of`, `bfs`, `bfs01`, `dijkstra`, `bellman_ford`, `topo`, `scc`, `components` and every fn taking `g: Next<V>` or `from: Seq<_>`: `cpl run` resolves `Graph`, `bfs` and `dijkstra` to compiler built-ins typed over `Int` (E0302 "expected `Int`, found `V`"), and rejects `Seq` as a parameter type (E0204 "`Seq` is not a type `cpl run` knows"); the stub also needs trait aliases (`trait WeightedNext<V, W> = ...`), open record bounds (`R: (u: V, v: V, ..)`), a `Domain` trait, `lends` returns and `where` (all parse errors today).
- graph: `floyd_warshall` (body landed, not callable): `cpl run` and `cpl build` stop on every call with E0501 "can't handle explicit type arguments here yet", likely from the defaulted generic `over: R = Semiring(min, +)`; the `dijkstra` and `bellman_ford` tests compare against a hand-written relaxation instead.
- tree: `Rooted` and `Lift` (all methods): `cpl run` resolves them to compiler built-ins typed over `Int` (E0302 "expected `?Int`, found `?V`" on `Lift.of(v => par[v])`), so spec bodies would never run; `Rooted.new` also needs `std.graph.Neighbours` (E0201).
- strings: `z_function`, `prefix_function`: `cpl run` can't build a `[K]T` keyed by a generic `K` (E0201 on `var z: [K]Int`, E0302 "expected `[Int]Int`, found `List<Int>`"); `find_all`, `period` and `borders` use a private positional `failure_lengths` instead.
- tree: `Rooted` (every constructor, so every method): a return type with an inferred fresh domain parameter (`-> Rooted<V, _>`) is rejected with E0005 "expected a compile-time constant integer", and a struct built over a local `domain P = 0..n` is typed `[Int]T`, not `[P]T` (E0302); `Centroids`, `LcaTable`, `PermTree`, `PreferredPaths` take or build a `Rooted`.
- tree: `Lift.of` (body landed, not runnable): the unit value `()` is not accepted where the unit type `()` is expected (E0302 "expected `()`, found `()`"), so `[V]?(V, ())` can't be filled.
- graph: every free fn over `g: Next<V>` (`two_color`, `topo`, `components`, ...): with a body, `two_color(g)` for `g: [V]List<V>` type-checks but `V` is bound to `Int`, so the result is `?[Int]Bool` and indexing it by `V` is E0301; the trait parameter is not inferred from a `[V]List<V>` argument.
- strings: `SuffixArray.rank_range`, `find_all`, `count`: the pattern must be compared with the original elements, but `SuffixArray` is not generic over its element type, so it cannot store `s`; needs `SuffixArray<T>` (a signature change) or an element-erased `Ord` box.
- poly: `Poly<T>` `mul`, `div`, `inv`, `log`, `exp`, `pow`, `sqrt`, `shift`, `transposed_mul`: their documented O(n log n) cost needs an NTT, which exists only for `Mod<P>`, and a generic `T` method has no way to specialize on `T = Mod<P>`; the free `List<Mod<P>>` functions carry the bodies.
- pair: `symmetric`: `[Pair<V>]T` is rejected as an array key (E0204 "an array is indexed by a domain or a length"), and `Pair<0..4>` in the doc examples is rejected ("`Pair` takes a domain by name"); blocks egoi23p4.
- window, `Tracked.push`/`pop`, `Undoing.push`/`pop`/`state`, `undoing`: calling a `(mut S, T) -> ()` fn value drops the `mut` (`add(mut state, x)` is E0401 "this parameter is not `mut`: the fn takes a copy"); btoi20p3 also needs tuple patterns in closure parameters (`(mut d, (u, v)) =>`, E0302 "a `Int` can't be taken apart into 2 names").
- io: `read_all`: CP Lang has no end-of-input test (the interpreter has one internally, `Input::at_eof`), so reading to the end can't be written; blocks ioi05p2 and the site's `read_all<Cmd>(until:)` snippets.
- algebra: `each`: a variadic tuple of operation values (`..ms: Ms`) returned as one fused operation needs per-component dispatch the type system can't express yet; `fold(each(+, max), ...)` has no body to call.
- matrix: `Mat.new`/`Mat.filled` with `over:` other than the default: `Mat<T>` has no slot for a semiring and `Semiring(min, +)` carries no identity, so `*` and `pow` stay `(+, *)`; the bodies trap on a non-default `over`.
- dsu: the site's `content/landing/lib/dsu.cp` reaching `todo`: plain `Dsu<V>` (`new`/`unite`/`same`/`size`/`find`/`components`) runs in this tree (`spec/conformance/std-dsu`); the remaining `todo`s are `PersistentDsu` and `@cache`-blocked bodies, so the snippet likely calls one of those.
- seq, `filter` / `map`: `Filtered<S>` and `Mapped<S, U>` have no fields and no `T` parameter to hold the closure, and a struct cannot implement `Seq` yet; the compiler's built-in views serve these calls.
- seq, `min` / `max` (example with `by: .0`): tuple-field shorthand `.0` as a closure is not parsed.
- segtree, `SegTree.new` (and so `all`, `monoid`, `try_fold`, `clear`, `walk`, which need a tree to test): `apply`'s tag type `F` is not a declared parameter (`F is not a type cpl run knows`), the struct's header parameter `m: Monoid<T>` captures the `op` argument, and `at`'s `-> lends mut T` does not parse.
- hashmap, `Counter.reserve`: the builtin `HashMap` has no `reserve` in `cpl run` (waits on the `Map` stub).
- search, real-valued examples using `close(...)`: `close` is not in scope for a bare doc example; verified with `abs(...) < eps` in `spec/conformance/std-search`.
- io, `read_all`: no end-of-input test (`read` traps past the end), so "read to end" is not expressible.
- pair, `symmetric`: `[Pair<V>]T` is not an indexable domain array in `cpl run` (`a Int can't be indexed`).
- timetree, `TimeTree.add_range` doc example: `TimeTree<Str>(3); add_range(1..3, "e")` gives 7 steps under `add_interval` (nodes [1,2) and [2,3)), not the documented 5; the example needs correcting by the doc owner.
- mo, examples on `Int` ranges (`mo_order([0..3, ...])`): `cpl run` cannot bind `D` for `Range<Int>`, and `Int` ends have no `.ord`; bodies verified over a declared `domain` against brute force (`spec/conformance/std-mo`).
- mo, `mo_rollback` doc: an in-block query answered with only `mark`/`undo` sees the previous block's right part unless the structure is reset first; the body resets on entering a block that the previous one left dirty (still at most one `reset` per block).
- bag, `SortedBag.range`/`drain_range`, `SortedSet.range`/`sum(keys:)`, `SortedRange.*`: no way to read an open bound of a generic `Range<K>` (`..b`, `a..`, `..`), and `..` alone is rejected by `cpl run`.
- bag, `SortedBag.split_at`/`join`, `SortedSet.split_at`/`join`: each bag owns its node pool, so O(log n) split/join between two bags needs a shared pool (or node moves) the struct layout does not have.
- bag, `SortedBag.reserve`/`SortedSet.reserve`/`SortedMap.reserve`, hashmap `Counter.reserve`: the bodies are no-op capacity hints, because stdlib bodies have no `List.reserve`/`HashMap.reserve` yet (waits on the `List`/`Map` stubs).
- fenwick, test `xor_matches_a_plain_array`: `Fenwick<D, T>` sums with `+`/`-` on `T` and a struct cannot define `+`/`-`, so there is no xor Fenwick to test; needs operator overloading or an `op:` parameter.
- pair, `symmetric`: `cpl run` rejects `[Pair<V>]T` as an array type (E0204 "an array is indexed by a domain or a length"), so no program can build the argument.
- seq, `subsequences` / `SubseqStep.prune`: the yielded step is a copy, so `prune()` in the consumer cannot reach the generator; item-steered generators (decision 126) need compiler support.
- io, `read_all`: no stdlib-visible end-of-input test (the interpreter's `at_eof` is only reachable from `@!multitest(until_eof)`), so there is no way to stop reading.
- seq, `span`: the body is written, but `span(lo, hi)` still lowers to the compiler's builtin `span` (cpl-ir lower/call.rs `lower_span`), which skips the `lo <= hi` trap; the builtin should go so the stdlib body runs.
- dp, `Step.prune` (`backtrack`): same as seq `SubseqStep.prune`; the yielded step is a copy, so pruning needs item-steered generators (decision 126). `backtrack` itself walks without pruning.
- deque, `LinkedList.splice_back`/`splice_front`: each list owns its `nx`/`pv`/`val` pools, so an O(1) splice needs a shared pool the struct layout does not have.
- beats, `BeatsSegTree`/`HistoricBeatsSegTree` query doc examples (`BeatsSegTree([5, 1, 4]).sum(1..3)`): `sum`/`min_val`/`get` take `mut self` (they push tags down), so calling them on a temporary is E0401; the examples need a `var` or the queries a non-pushing signature.
- segtree, `DynamicOrderTree.kth`: a Fenwick of order trees answers `count_lt` in O(log^2 |D|), but the k-th value over arbitrary online `T` needs a binary search over values on top of it (O(log^3 |D|)); O(log^2) needs the values known ahead (offline compression), which the signature doesn't take.
- lazy, `LazyTreap.split_at`/`append`: each treap owns its `nodes` list, so returning or absorbing another treap copies its nodes (O(n), not O(log n)); needs a shared node pool.
- lazy, `LazyTreap.reverse`: `apply(v, k, f)` and `split(f, k)` see the left-subtree size `k`, so a pending tag is position-dependent and can't be carried through a reversal flag without a way to reverse a tag.
- seq, `compress`/`pieces`/`rebase`: a fn can now bind `domain C = 0..k` (as `with_domain` does), but a struct over it (`Compressed<C, T>`) keeps the callee's domain instead of unifying with the caller's `C` (E0302), and `(C:, Compressed(...))` misparses as a record field (E0103).
- seq, `compress`/`pieces`/`rebase`: each returns or keys by a fresh `domain` (`(domain C, ...)`, `t.Idx`), which a library fn cannot mint (same gap as `with_domain`).
- seq, `covering`: maps a range of cuts back to piece keys of `pieces`, which is itself blocked on fresh domains; nothing can build its `[P]Range<D>` input today.
- seq, `rev`, `Filtered.src`/`Mapped.src`/`Rev.src`/`Items.src`: the view structs are declared with no fields (`struct Rev<S>()`), so a body cannot hold or hand back its source; needs the views to carry `src`.
- seq, `drop`/`drop_last`/`take`/`take_last`/`split`/`maximal`/`minimal`/`Ring.maximal`/`Ring.minimal`: return `Slice<S>` views of a generic `S`, which cannot be built (`Slice<S>()` has no fields and `self[i..j]` on generic `S` indexes one element).
- segtree, `SegTree.apply_all`: same as `apply`; its tag type `F` is not a declared parameter.
- persistent, `PMultiset.*`: an immutable value holding only `root: Int` needs one node pool shared by every multiset (and a hash per node for O(1) `==`); a struct cannot own shared storage.
- graph, `Graph.weighted` (`Reweighted`): a lambda stored in a struct's generic field is typed `Int` (`Rw(g, a => 5)` is `Rw<Graph<..>, Int>`, then E0203 "no method `f`").
- tree, `KruskalTree.top<E>`: a method type parameter mentioned only by a fn-typed parameter is bound to `Int` (compiler worklog), so `ok(E.nth(i))` cannot be typed; the body is one line over an `[N]Int` merging-edge field.
- segtree, `SegTree.new(over:)`: `SegTree<Int, Int>` is E0201 "doesn't know the name `D`" in `cpl run`, and the layout is one `bit_ceil(D.K)` array with no slot for nodes made on first touch.
- strings, `parse<T: Read>`: works as a compiler built-in; `Read` only reads standard input, so a std body needs `Read` over a token source (Q3).
- seq, `filter`/`map`/`items`, `Slice.keys`/`len`/`is_empty`/`iter`: lowered as compiler built-in views (`crates/cpl-ir/src/lower/call.rs`, `"map" | "filter"`, `"items"`); a std body needs the view structs to carry their source (as `rev` above) and a `Seq` impl per view that lowers as fast (Q3).
- derive: `Hash`, `hash_fields`, `Gen`, `gen`, `gen_fields` (README 4.17, not yet in `derive.cp`): `crates/cpl-check/src/prelude.rs` `TRAIT_NAMES` already names `Hash` and `Gen`, and `Gen` is also the compiler's generator type (`crates/cpl-check/src/ty.rs`), so a std trait of either name overlaps a compiler table (`debt-ratchet` `prelude_privilege` 27 -> 28). Held on Q3; the old `stdlib/derive.cp` bodies (before `954d6842f`) check and run as user code.
