There are n tasks (1 ≤ n ≤ 2·10⁵) and m rules (0 ≤ m ≤ 2·10⁵); rule `u v` means task u must come before task v. The rules have no cycle. Print the largest number of rules in a chain u₁ → u₂ → … where each step is a rule.

**Input:** n and m, then m lines `u v`. **Output:** one integer.

| Input | Output |
|---|---|
| `5 5`<br/>`1 2`<br/>`2 3`<br/>`1 3`<br/>`3 4`<br/>`5 4` | `3` |

<Judge id="longest-chain">

- `len[v]` is the longest chain ending at v. In a topological order every rule `u → v` has u first, so by the time you reach u its value is final, and `len[v] max= len[u] + 1` pushes it on.
- `topo(Graph.directed(es))` returns the order as `?List<V>`, `None` on a cycle; the statement promises none, so `!` says so. See [Graphs](/learn/read/graphs) and [Dynamic programming](/learn/read/dynamic-programming).
- Compare [Course order](/learn/practice/course-order), which needs the smallest order rather than any order.

</Judge>
