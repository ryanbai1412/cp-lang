You can try CP Lang immediately with zero setup in the [browser playground](/play), or install the local `cpl` CLI to run programs natively, emit standalone C++17 for online judges, and enable editor support (`cpl lsp`).

## Install

One line installs a prebuilt `cpl` for Linux, macOS or Windows. Until the first stable release, both channels install edge, the newest build of main that passed every check.

```sh
curl -fsSL https://cp-lang.org/install.sh | sh -s -- --edge   # Linux and macOS
```

```powershell
& ([scriptblock]::Create((irm https://cp-lang.org/install.ps1))) -Channel edge   # Windows PowerShell
```

`cpl self update` updates it later. To build from source instead (any Rust toolchain):

```sh
cargo install --locked --git https://github.com/ryanbai1412/cp-lang cpl-cli
```

Verify the installation:

```sh
cpl --version
cpl --help
```

## Write, run, and compile your first program

Save this example as `sum.cp`:

```cp
let n: 1..=2e5 = read()
domain V = 1..=n
let a: [V]Int = read()
print(a.sum())
```

Check types, run directly with the local interpreter, or compile to a standalone C++17 submission:

```sh
cpl check sum.cp
printf '5\n3 1 4 1 5\n' | cpl run sum.cp
cpl build sum.cp -o sum.cpp
g++ -std=c++17 -O2 sum.cpp -o sum
printf '5\n3 1 4 1 5\n' | ./sum
```

The output is `14`.

`cpl build` writes a single self-contained `.cpp` file with your original `.cp` source preserved as a comment header at the top, unused library code tree-shaken away, and `@alt` / `@check` / `@interactor` blocks stripped so the file is clean and ready to upload to any judge.

## A contest, start to finish

1. **Import the problem.** Install the [Competitive Companion](https://github.com/jmerle/competitive-companion) browser extension, run `cpl new --listen` in your contest folder, and click the extension's green plus on the problem page. You get `a.cp` (title, URL, limits and the input skeleton) and `a.tests/` with every sample. Clicked on a contest page, it creates every problem in a folder named after the contest.
2. **Write it**, then `cpl run a` runs every sample and judges each one. `cpl run a 2` runs only sample 2; `cpl run a < in.txt` runs once on your own input.
3. **Add a case** you worry about: `cpl test a --add mine.in --expect mine.out` saves it as the next numbered case and runs it. `cpl t a` reruns them all.
4. **Stress it** against a brute force kept in the same file:

   ```cp
   let (a, b): (1..=9, 1..=9) = read()
   print(a + b)

   @alt(program)
   fn brute():
       let (a, b): (1..=9, 1..=9) = read()
       var s = a
       for _ in 0..b: s += 1
       print(s)
   ```

   `cpl stress a` generates inputs from the declared types and stops at the smallest one where the two disagree. When any valid answer is accepted, a `@check fn` judges the output instead (see [Testing](/docs/guides/testing)).
5. **Submit.** `cpl b a -c` writes `a.cpp`, one C++17 file without the `@alt`, `@check` and `@interactor` blocks, and copies it to the clipboard. Paste it into the judge.

## Editor support

One command sets up your editor: diagnostics, completion, hover, formatting, go to definition and run lenses, all from `cpl lsp`.

```sh
cpl setup neovim      # or vim, vscode, jetbrains
```

Neovim needs 0.10 or later. JetBrains needs a commercial IDE (IDEA Ultimate, CLion, PyCharm Professional, ...); restart it after setup. Any other editor with an LSP client can run `cpl lsp` on `.cp` files.

## What works today

CP Lang is in beta. `cpl new`, `cpl check`, `cpl run`, `cpl test`, `cpl build`, `cpl stress`, `cpl lsp` and the trace viewer all work, in the CLI and in the browser. Parts of the standard library are still being implemented: an example on this site marked **check-only** passes the type checker but does not run yet.
