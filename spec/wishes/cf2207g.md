## Library

    pub fn cycle_through<V, N>(next: N, s: V) -> ?List<V>
        // a simple cycle of the undirected graph `next` that passes through s, in walking order, or none; O(n + m)
    pub fn dfs_order<V, N>(next: N, within: [V]Bool) -> List<V>
        // the vertices with within[v], in depth-first preorder, one tree after another (roots in V order); O(n + m), no recursion
    pub fn max<T, K>(self: Iterable<T>, by: T -> K) -> T
        // the first item with the largest key; O(len) key calls (the decided `by:` option)
    pub fn find<T>(self: List<T>, f: T -> Bool) -> ?T
        // the first item satisfying f, or none; O(len)

`dfs_order` is the general form of "a legal growth order": in a forest every
vertex has exactly one earlier neighbour (its parent) in preorder, which is
the move rule here. `cycle_through` complements the existing `find_cycle`
(directed, any cycle) with the undirected, anchored question; `find_cycle`
would need a `through:` option to cover it, which is the alternative spelling
if the spec prefers one name.
