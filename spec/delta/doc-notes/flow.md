# flow: doc-standard notes

- Examples pass optional capacities and limits as `Some(k)`, the one spelling certain to type-check for a `?Int` parameter.
- `FlowGraph.add`, `add_both`, `set_cap`, `CostFlow.add`, `set_cap`: chose to trap on a negative capacity (unspecified; a negative capacity has no meaning).
- `FlowGraph.max_flow`, `push_relabel`, `paths`, `min_cost_flow`: chose to trap when `s == t` (unspecified; no finite answer).
- `FlowGraph.max_flow` ties: pinned "the flow Dinic finds scanning arcs in `add` order"; flow values on individual arcs are observable through `flow`.
- `FlowGraph.cap`: the old doc said "the capacity `a` was added with", but `set_cap` changes it and `residual` is `cap(a) - flow(a)`. Documented the current capacity (0 for an `add` reverse arc, `cap` for both arcs of `add_both`). Same for `CostFlow.cap`.
- `FlowGraph.min_cut` / `cut_arcs`: chose to require that the completed flow came from the same `s`; also stale after `set_cap` (added to "since the last `add` or `reset`").
- `FlowGraph.out`: chose forward arcs only (handles `add`/`add_both` returned whose source is `u`), matching `arcs`' "never a reverse arc".
- `FlowGraph.paths`: pinned the decomposition order (from `s`, the first arc in `add` order still carrying unclaimed flow); does not mutate the graph.
- `CostFlow.min_cost_flow`: chose to trap when the residual network has a negative-cost cycle (the stated precondition of `add`); ties pinned to Dijkstra breaking ties by least vertex.
- `CostFlow.slope`: chose that it sends the flow like `min_cost_flow` (it takes `mut self`) and reports amounts relative to the flow already there.
- `max_closure` ties: the smallest optimal closure, which is what the min-cut source side gives.
- `max_matching`, `general_matching`, `max_weight_general_matching`, `max_weight_matching`, `min_weight_matching`: which optimal matching comes back was open; pinned to the named algorithm's scan order (increasing vertices, list order), since the spec names the algorithm.
- `min_vertex_cover`, `Matching.cover`: pinned the standard König construction from alternating reachability.
- `circulation`, `max_bounded_flow`, `min_bounded_flow`, `min_cost_circulation`: chose to trap on `lo > hi` (and `s == t` for the s-t forms).
- `gomory_hu`: pinned Gusfield's parent order (every vertex starts under `V.first`, output one edge `(u, parent, w)` per non-first vertex by increasing `u`); traps on negative weights.
- `global_min_cut`: pinned `side` to the side without `V.first` and Stoer-Wagner ties to the least vertex and the first minimum phase.
- `Matching.remove` (unclear): "unmatch `l` (and its mate), then try to rematch both" has no visible effect on a maximum matching unless edges change, and no edge removal exists. Pinned the literal reading (`augment(l)`, then one path ending at `r` if still free) and left the API unchanged.
- `Matching.augment`: pinned Kuhn's DFS trying edges in `add` order.
- `best_matching`: without `size`, stops at the first non-improving path, so equal totals prefer fewer pairs; traps on negative `size`. `min: true` without `size` therefore returns the empty matching when all weights are positive.
- `stable_matching`: chose mutual acceptability (a pair matches only when each lists the other) and to trap on a repeated entry in a preference list.
- `edge_coloring`: pinned the alternating-path colouring order (edges in `E` order, least free colours).
- `matroid_intersection`: pinned BFS from sources in increasing element order so ties take the least element. The old doc's "O(E^2 V) is not reached" was dropped as noise.
- `max_weight_matching` / `min_weight_matching` (contradiction): the old doc said `L.K <= R.K`; `K` is not a domain member elsewhere. Documented `L.count <= R.count`. `gomory_hu`'s `V.K` likewise read as `V.count`.
- `ColorMatroid.new`: chose to trap on a negative limit.
