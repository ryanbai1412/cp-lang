# spec/: the target language, checked against the dreams

The spec is the deliverable of this phase: the language and library we
intend, written so the real checker can hold every dream to it. A dream
"works under the spec" when `scripts/spec-check.sh` reports no error for it.
Implementation follows later and is measured against the same files.

- `std/` holds stdlib modules as the spec wants them. A file here shadows
  `stdlib/` module by module (`CPL_STD` is searched first), so it may be a
  copy of the real module with new signatures added, or a new module.
  A signature not yet implemented has `todo` as its body:

      /// Shortest arcs from `from`; O((n + m) log n).
      pub fn dijkstra<V, E>(g: Graph<V, E>, from: V, w: E => Int) -> [V]?Int = todo

  `todo` type-checks as any type and traps if it runs.
- `POWERS.md` lists what user libraries can define, each power with the
  smallest example and the stdlib signatures that need it.
- `SYNTAX.md` lists core syntax the dreams use that the parser does not
  accept yet, each with its decision number. These dreams are checked by
  review until the parser catches up.
- `STATUS.md` is the dream pass rate and the open failures, regenerated by
  `scripts/spec-check.sh --json`.

The loop: edit a stub or a dream, run `scripts/spec-check.sh`, fix the top
gaps, repeat. A failing dream is either a spec gap (add the signature, or
the power it needs) or a dream that does not follow a decision (fix the
dream). Never weaken a dream to make it pass.
