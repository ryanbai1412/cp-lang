C++ `%` takes the sign of the dividend, so C++ code writes `(a - b + m) % m` or `(a % m + m) % m` to get a value in `0..m`. CP Lang's integer `%` is Euclidean: `a % m` is already in `0..abs(m)` for every sign of `a` and `m`, so the `+ m` only adds a term that can overflow and makes the reader wonder what it guards. The fix drops it (and the outer `% m` when the inside is already `x % m`); it applies when the divisor is a literal or a name or field of a signed integer type, where the two forms agree for every input. When the whole computation is modular arithmetic, `Mod<P>` removes the remainders altogether.
