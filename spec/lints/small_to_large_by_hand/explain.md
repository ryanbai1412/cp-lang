Merging two sets by first swapping so the smaller one is walked, then adding its elements to the larger, is small-to-large merging: each element moves \(O(\log n)\) times over any sequence of merges. Written by hand it is a length test, a swap of two names, a loop, and the bookkeeping of which name now holds the union. `a.absorb(mut b)` does the same: it swaps the contents when `a` is the smaller, adds the rest, and leaves `b` empty, so `a` always ends up with the union. It exists on `SortedSet`, `SortedBag`, `SortedMap` (with a `join:` for equal keys), `FlatMap`, `Counter` and `MeldHeap`. There is no automatic fix, since code after the loop may still read the swapped names. A swap by length followed by something other than adding each element (adding two lists position by position) is not reported.
