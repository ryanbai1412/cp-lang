A statement numbers its positions from 1, so a query reads `l` and `r` as `1..=n`, and code written for 0-based arrays then subtracts 1 at every use: `a[l - 1]`, `p[r] - p[l - 1]`. Each use is a place to forget the shift, and the declared type `1..=n` and the array's `0..n` disagree about what a position is. Declaring the array over the positions as read, `domain I = 1..=n` and `let a: [I]Int = read()`, makes `l: I` index it directly, and `a.scan(+).fold(l..=r)` sums the query without a hand-built prefix. The rule fires when a name read as `1..` is used as `[l - 1]` later in the same block, unless it also bounds a range or a size (`0..n`, `[n]`), where `a[n - 1]` is the last element; there is no automatic fix, since every array over those positions changes together.
