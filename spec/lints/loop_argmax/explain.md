C++ finds the index of the largest value by keeping a best index `j` and replacing it whenever `a[i] > a[j]`. `(lo..hi).max(by: i => a[i])` says the same thing in one call and keeps the first largest on ties, exactly as the strict `>` loop does; over the whole table, `a.argmax()` is the index directly (`argmin` and `min(by:)` for `<`). The loop with `>=` keeps the last largest instead, so it is not reported. There is no automatic fix, since `j`'s start value and later uses have to change with it.
