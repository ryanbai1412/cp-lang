Geometry input often gives all x coordinates and then all y coordinates, and the natural first program keeps them that way: `xs[i] * ys[j] - xs[j] * ys[i]` for a cross product, `xs[i] - xs[j]` and `ys[i] - ys[j]` for a vector. Every formula then repeats itself once per axis, and swapping an `x` for a `y` is a typo the checker cannot see. Building the points once, `let p = [D] i => Pt(xs[i], ys[i])`, gives `p[i] - p[j]`, `p[i].cross(p[j])`, `p[i].dot(p[j])` and the rest of `std.geometry` on whole points. When the input gives one point per line, `let p: [D]Pt = read()` reads them directly. The rule fires on two adjacent `read()`s of the same array type named `xs`/`ys` (or `x`/`y`, `px`/`py`) that are later combined across two points (`xs[i] * ys[j]`, `xs[i] - xs[j]`); data columns combined at one index (`x[i] * y[i]`) are not reported; there is no automatic fix.
