Python's `s[:len(p)] == p` and C++'s `s.substr(0, p.size()) == p` test a prefix by cutting a slice and comparing it. CP Lang names the test: `s.starts_with(p)`, `s.ends_with(p)`, and `s.starts_with(p, at: i)` for a match at position `i`. They work on `Str` and `List` alike, cost \(O(|p|)\) with no copy, and are `false` when the pattern runs past the end, where the slice traps, so the `p.len <= s.len` guard goes away too. The fix rewrites the comparison, guard included; with `at: i` it keeps an `i + p.len <= s.len` guard, since `at` outside `0..=s.len` traps. It fires only on `Str` and `List`: a `[D]T` slice takes keys while `starts_with` counts positions.
