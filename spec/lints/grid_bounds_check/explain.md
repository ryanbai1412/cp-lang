C++ BFS steps with `dx`/`dy` arrays and tests `0 <= nx && nx < h && 0 <= ny && ny < w` before each read. Get one bound wrong and the program reads outside the grid. In CP Lang a grid over two domains (`[Row, Col]T`, `domain Row = 0..h`) knows its own edges: `for (nx, ny) in (x, y).adj4` from `std.grid` yields just the up to four neighbours inside it (`adj8` with diagonals), and `(x, y).step(d)` is `None` off the grid. There are no bounds to write, and the indices are proven.

The lint fires on an `and` of comparisons that tests two names against `0` below and a bound above. It has no fix, since the grid's declaration and the loop change together.
