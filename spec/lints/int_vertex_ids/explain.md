Graph and tree statements number vertices from 1, so a program reads `u` and `v` as `1..=n` and sizes every table one larger, `[0..=n]Int` or `[i for i in 0..=n]`, to index it with the ids as read. Slot 0 is then never an id: it holds a default every fold over the table sees, `print(deg)` prints it, and the ids stay plain `Int`s, so nothing stops a 0-based index or a vertex of another graph from reaching the table. Declaring the ids as a domain, `domain V = 1..=n`, reading them as `V` and making the tables `[V]T` gives one slot per vertex, and an id outside `1..=n` traps where it is read. The rule fires on a top-level table spanning `0..=n` when some name is read as `1..=n` and every index of the table is a plain name that no loop from 0 binds; a table indexed by `0`, by arithmetic (`t[i - 1]`) or by a loop from 0 is over positions or cuts, where slot 0 is used. There is no automatic fix, since the domain, the reads and every table over the ids change together.
