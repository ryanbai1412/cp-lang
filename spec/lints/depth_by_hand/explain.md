Filling `depth[v]` from the parent's depth plus one, in a loop over the parent list or inside a DFS, is the first step of almost every tree algorithm written by hand, and the next steps (the parent table, a climb to the LCA) follow it. `Rooted.from_parents(par)` builds the rooted tree from parents keyed by vertex (`None` at the root), and `Rooted.new(adj, root)` from an adjacency list; either knows `t.depth(v)`, `t.parent(v)` and `t.lca(u, v)`, so none of these tables is written. There is no automatic fix, since the tree has to be typed over a vertex domain first. It reports a table that the program also compares or subtracts at two vertices (`depth[u] > depth[v]`, `depth[u] - depth[a]`), the start of a walk up the tree or a distance; depths read only as values (a sum, a maximum) are one pass by hand, cheaper than building the tree, and are not reported. The rule reads tables whose name says depth (`depth`, `dep`, `level`, `lvl`); a breadth-first `dist` on a general graph is not a tree depth and is not reported.
