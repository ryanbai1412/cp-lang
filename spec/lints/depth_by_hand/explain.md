Filling `depth[v]` from the parent's depth plus one, in a loop over the parent list or inside a DFS, is the first step of almost every tree algorithm written by hand, and the next steps (the parent table, a climb to the LCA) follow it. `Rooted.from_parents(par)` builds the rooted tree from parents keyed by vertex (`None` at the root), and `Rooted.new(adj, root)` from an adjacency list; either knows `t.depth(v)`, `t.parent(v)` and `t.lca(u, v)`, so none of these tables is written. There is no automatic fix, since the tree has to be typed over a vertex domain first. `std.tree` states it as `@lint`s on `Rooted.from_parents`: a list started `[0, 0]` and pushed `d.push(d[par[v - 2]] + 1)` in a `for v in 2..=n` loop, or a table started at `0` and set `d[x] = d[k] + 1` from the loop's own vertex `k`. A count bumped at the parent (`size[par[v]] = size[par[v]] + 1`) is not a depth and is not reported.
