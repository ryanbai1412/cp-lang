C++ marks "not computed yet" or "unreached" with a value the answer can't take: `-1` in a memo table or a BFS distance grid, `1e18` in Dijkstra. The type still says `Int`, so nothing stops that value being read as a real one: printed, added to (`INF + c` overflows), or compared with the wrong sentinel. `?Int` says "maybe absent" in the type: start the table at `none` (`var memo: [0..=90]?Int = none`), test it with `if let v = memo[i]:` or `memo[i].is_none`, and read it with `memo[i]!` or `memo[i] ?? -1` where the output wants `-1`. An unset entry then can't be used by mistake.

The lint fires on a `var` table or list filled with `-1` or a value of at least `10**9` in size, when the file compares an entry with that value (or, for a large one, with `<` or `>`, as a relaxation does). It has no fix: each read needs its own choice of `!`, `??` or `if let`.
