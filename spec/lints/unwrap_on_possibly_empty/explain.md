`a.max()`, `a.min()`, `a.first` and `a.last` are `?T`: `None` when `a` is empty. `a.max()!` says you know it isn't. When the declared bounds let the list be empty, as `let n: 0..=10` then `let a: [0..n]Int` does when `n` is 0, that input makes the unwrap trap. Handle the empty case with `if let v = a.max():` or `a.max() ?? fallback`, or, if the statement guarantees at least one element, declare it: `n: 1..=10`. The lint fires only when the array's index range comes from declared inputs and literals, the ranges allow it to be empty, and the file never tests the length. The same holds for a slice `a[l..r]` whose declared ends allow `l >= r`: declare `r: l + 1..=n`, or test `if l < r:` first.
