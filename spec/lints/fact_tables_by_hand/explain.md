A loop that fills `fact[i] = fact[i - 1] * i % P` builds the factorial table every counting solution needs, and usually its inverse table and a `choose` next to it, each with its own `% P` to forget. `Comb<Mod<P>>(n)` (`std.mod`) holds both tables, built in \(O(n)\): `comb.fact(i)` is \(i!\), `comb.inv_fact(i)` is \(1 / i!\), and `comb.choose(a, b)` is \(\binom{a}{b}\) in \(O(1)\), 0 when `b` is outside `0..=a`. The tables grow on demand, so `Comb<Z>()` with no size also works. A recurrence over the previous entry that is not a factorial (powers, `(i + 1)` products) is not reported. There is no automatic fix, because each reader of the table becomes a different `Comb` call.
