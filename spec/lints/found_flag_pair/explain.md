C++ keeps "have I found one yet?" in a `bool` beside the value: `bool found = false; int first = 0;`, because an `int` always holds some number. In CP Lang the value's own type can say it: `var first: ?Int = None` holds nothing until the first match, and `first == None` (or `if let x = first`) asks what `not found` asked. With a flag the two can disagree: an edit that sets one and forgets the other leaves `first` at a stale or made-up `0` that the program then trusts.

The lint fires on a `var f = false` that is only ever set to `true`, each time in the same block as an assignment to one other `var`, which is set nowhere else, and is read somewhere. It stays quiet when the flag is ever set to `false` or to a computed value, or when the value is also set without the flag: there the flag says more than whether the value exists.
