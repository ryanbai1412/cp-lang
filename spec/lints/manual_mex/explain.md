Walking a counter up while a table marks it (`while seen[m]: m += 1`) is a search for the first unmarked value: the mex, when the table marks the values present. `(lo..=hi).find(m => not seen[m])` names the search and the range it runs over, so the end of the table is visible instead of implied. There is no automatic fix, because the range has to be read from the table's declaration.
