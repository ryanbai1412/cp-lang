C++ drains a queue with `while (!q.empty()) { auto x = q.top(); q.pop(); ... }`, because `pop` returns nothing. In CP Lang `pop()` returns the element it takes, or `None` when the collection is empty, so the emptiness test and the `!` that unwraps the pop say the same fact twice: `while not q.is_empty:` then `let x = q.pop()!`. `while let x = q.pop():` says it once. It stops on the same `None` the test guarded against, and an edit can no longer move the test away from the pop. It works for every collection whose `pop` (or `pop_front`, `pop_min`, ...) returns an optional: `List`, `Deque` and the heaps, and for a tuple pattern such as `while let (d, u) = pq.pop():`.

The lint fires only when the `let` is the loop's first statement and pops the same name or field path the condition tests (`not q.is_empty`, `q.len > 0` or `q.len != 0`). The fix rewrites the condition and deletes the `let` line.
