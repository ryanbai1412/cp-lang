Filling `dp[l, r]` for lengths 2, 3, ... with the end computed as `l + len - 1` is the usual order for an interval DP, since every smaller interval is done before it is read. Written by hand it is three index variables, a loop bound (`n - len + 1`) that is easy to get off by one, and a square table half of which is never used. `var dp: [I.ranges]T` keys the table by the ranges of a domain, and `for r in I.ranges` visits them shortest first, so the order is the type's and not a convention. `r.first!` and `r.last!` are the ends, `r.drop(1)` and `r.drop_last(1)` the ranges one shorter, and `lead[I.range]` the whole. There is no automatic fix, since the base case and the recurrence move into the range form together. Loops with the start outside and the length inside (prefix sums from each start) are not reported.
