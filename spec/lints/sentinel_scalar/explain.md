C++ starts "the index found so far" at `-1` and "the best so far" at `-1e18`, because an `int` has no value for "nothing yet". Both are real numbers: `-1` indexes from the end in Python habits and passes any `>= -1` test, and `-10**18` is only a guess at a bound the data may pass. CP Lang has the value C++ lacks: `var found: ?Int = None` starts with nothing, `found = i` sets it, and the reader must say what nothing means (`found ?? -1`, `if let`, `!`). For a running best, `a.max()` or `.min()` from `std.seq` returns `?T` and needs no start at all.

The lint fires where `std.seq` declares it, beside the call that needs no start: `var found = -1` (or `: Int`) followed by a `for i in xs` whose body is only `if cond: found = i` is `xs.rfind(i => cond)`, and `var best = -10**18` (any start of `-10**9` or less) followed by a `for x in xs` whose body is only `best = max(best, x)` or `if x > best: best = x` is `xs.max()`, with `min` and a start of `10**9` or more mirrored. A `while` loop's bound (`var hi = 10**18` in a binary search) is not a sentinel and is left alone. It has no fix, since each read of the variable changes.
