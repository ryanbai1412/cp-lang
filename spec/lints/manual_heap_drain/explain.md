`for _ in 0..k:` with `h.pop()!` in the body takes the top `k` elements of a heap one by one, and traps when the heap holds fewer than `k`. `for x in h.drain().take(k)` (`std.heap`) yields the same elements in the same order, names each one, and stops early when the heap runs out; `for x in h.drain()` takes them all. Each pop is \(O(\log n)\) either way. A loop that pushes into the heap it pops (merging, simulation) is not reported. There is no automatic fix, because the popped value has to be named where the body uses it.
