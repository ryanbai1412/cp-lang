# 10. Input, output and program shape

Status: draft for 0.3.0. Sources: archived `design/spec/25-io.md`,
`31-interaction.md`, `32-graders-bundling.md`; decisions 20, 136, 139.
Nothing here is compiler-special except return-type dispatch: I/O is
byte intrinsics, two traits, and the `io` context.

## 10.1 Program shape

A program is a flat sequence of top-level statements run top to bottom;
there is no required `main` or `solve`.

```
let sv = Sieve(1e6)                   // runs once

@!multitest
let n: 1..=2e5 = read()               // runs once per test case
let a = read<[n]Int>()
print(a.sum())
```

- `@!multitest` reads the test count and runs everything below it per
  case; `@!multitest(until_eof)` runs until input ends. State declared
  below the divider is per-test, and a fresh type declared below it can
  not leak into the next case (chapter 2).
- Top-level `return` ends the program, or the current case under
  `@!multitest`.
- IOI-style tasks mark entry points with `@grader`,
  `@grader(interactive)` or `@grader(two_phase)` on a `fn` or `mod`, and
  declare judge-provided functions with `extern fn`. The judge profile
  supplies the harness; local runs use a generated stub (decision 136).

## 10.2 Reading

```
trait Read: fn read() -> Self uses io
fn read<T: Read>() -> T
```

- `read<T>()` dispatches on the expected type, so `let n: 1..=2e5 =
  read()` and `read<[n]Int>()` are the same mechanism.
- Range types read with their contract. A domain written with explicit
  ends (`1..=n`, `0..n`, `lo..=hi`) reads and prints its positions as
  their integers, never shifted. `io.base` applies only to *counted*
  domains, declared by a count alone (`[n]T`, `domain E = [m]`): `with
  io(base: 1)` makes 1-based input for them 0-based positions, and back
  on output. So the two never stack. Sizes, cuts and plain integers never
  convert.
- Arrays `[D]T` read `D.count` values; `[R, C]Char` reads rows of
  characters with no separators; `[V]List<V>` reads count-prefixed rows;
  records, tuples and structs read their fields in order; an enum reads
  one token, picks the variant whose tag (or name) it equals, then reads
  that variant's fields, so a command stream is `read<Cmd>()` in a loop; `Range<T>`
  reads two ends and checks order; `Str` reads one token; `read_line()`
  reads the rest of the line; `Char` skips whitespace then reads one
  character. `Mod<P>` reads one signed integer token of any length and
  reduces it modulo `P`, so a 10^4-digit coefficient is `read<Mod<P>>()`.
- `s.parse<T>()` reads a `T` from a string by these same rules, `none` on
  a bad or leftover token: one token read under two moduli is
  `let s = read<Str>()` then `s.parse<Mod<P>>()!` and `s.parse<Mod<Q>>()!`.
- Graphs read edge lists with `Graph.read(...)` (`lib/graphs-trees.md`).
- A bad token traps with the input position and the expected type.

- `read_all<T>()` reads every remaining `T` until the input ends, for
  statements that give no count; reading after it is an error. O(tokens).

## 10.3 Printing

- `print(x, y, ...)` joins by `io.sep` and ends the line; `print(xs)`
  prints a sequence on one line; `print(xs, sep: "\n")` overrides.
- Interpolated strings format each piece through `Print`; positions
  print in the file's base; `"{x:.9}"` sets float precision.
- `Bool` is not `Print`: `print(b)` is an error naming `print(yes(b))`.
  `yes(b)` is the word from `io.answers`, a `Str`, so it also works in
  interpolation (`yes(b, answers: ("Possible", "Impossible"))`).
- `F64` uses `io.precision` or `print(x, precision: k)`.
- `#derive`-free: records, tuples and structs print their fields joined
  by `io.sep`; enums print their variant name unless the type implements
  `Print`.

## 10.4 Interaction

`Wire` switches to interactive mode: every read and every exit flushes
first. A program that never constructs one never flushes early. A trap
in any mode flushes buffered output before writing to stderr. The local
interactor harness (`cpl interact`, `tools/stress.md`) runs the program
against an `@interactor` fn or an external binary.

## 10.5 Cost

Input is one bulk read and a hand-rolled parser; output is one buffer
written at exit (or per flush in interactive mode). `io` is a
compile-time context, so `- io.base` folds away.
