# 10. Input, output and program shape

Status: draft for 0.3.0. Sources: archived `design/spec/25-io.md`,
`31-interaction.md`, `32-graders-bundling.md`; decisions 20, 136, 139.
Nothing here is compiler-special except return-type dispatch: I/O is
byte intrinsics, two traits, and the `io` context.

## The model in one paragraph

A program is a flat sequence of top-level statements run top to bottom,
with no required `main`; `@!multitest` marks where each test case
starts, so single-test and multitest code are identical. `read<T>()`
reads any type from its declaration (records, arrays over a domain,
ranges that validate the statement's bounds), and `print` writes values
separated by the `io` context's separator. Nothing is compiler-special
except return-type dispatch: I/O is byte intrinsics, two traits and the
`io` context.

## 10.1 Program shape

A program is a flat sequence of top-level statements run top to bottom;
there is no required `main` or `solve`.

```cp
let sv = Sieve(1e6)  // runs once

@!multitest
let n: 1..=2e5 = read()  // runs once per test case
let a = read<[n]Int>()
print(a.sum())
```

- `@!multitest` reads the test count and runs everything below it per
  case; `@!multitest(until_eof)` runs until input ends. State declared
  below the divider is per-test, and a fresh type declared below it can
  not leak into the next case (chapter 2). The divider does not start a
  block, so a bare `with` above it (`with io(answers: ("Alice", "Bob"))`)
  covers every case (R09.1.1). A `fn` declared below the divider is
  nested in the per-test body and captures that case's names (chapter 6). A
  runtime modulus `type Z = Mod(m)` read there is a fresh type per case
  (R03.5.1). A domain declared there may size itself from another's
  `.count`: `domain N = 0..n + C.count`. (R10.1.1)
- Top-level `return` ends the program, or the current case under
  `@!multitest`. (R10.1.2)
- IOI-style tasks mark entry points with `@grader`,
  `@grader(interactive)` or `@grader(two_phase)` on a `fn` or `mod`, and
  declare judge-provided functions with `extern fn`. The judge profile
  supplies the harness; local runs link the judge's grader, `cpl test`
  and `cpl run` with `--grader grader.cpp` or a `grader.cpp` beside the
  tests, and `cpl run` or `cpl test` of a program whose fns cross to a
  grader, with no grader, is an error naming `--grader` (decision 136).
  (R10.1.3)
- A value crossing to the judge's grader takes its C++ type from the
  type the `@grader` fn declares: an `Int` is `int`, and a range is the
  narrowest of `int` and `long long` that holds it, so `1..=1e15` is
  `long long` and `0..n` is `int` unless `n`'s own declared range is past
  `int`; a range with an open end (`0..`) is an error naming it. `F64` is
  `double`, `Bool` `bool`, `Char` `char`, `Str` `std::string`, `List<T>`
  `std::vector`, a pair `std::pair` and a wider tuple `std::tuple`. So
  souvenirs' `std::pair<std::vector<int>, long long> transaction(long long M)`
  is `@grader fn transaction(m: 1..=1e15) -> (List<0..100>, 0..=1e15)`.
  A fn over its own domain crosses over lists: `p: [C]1..=1e9` is a
  `std::vector<int>` that binds `C` to its length, and a `C` it gives
  is an `int`, as festival's `max_coupons(a, p: [C]1..=1e9, t: [C]1..=4)
  -> List<C>` is `std::vector<int> max_coupons(int, std::vector<int>,
  std::vector<int>)`. An array sized by a value crosses the same way:
  `a: [m]1..=n` is a `std::vector<int>` whose own length sizes it, and a
  grid `[r, c]T` is a `std::vector<std::vector<T>>` of `r` rows, so
  worldmap's `std::vector<std::vector<int>> create_map(int, int,
  std::vector<int>, std::vector<int>)` is `@grader fn create_map(n:
  1..=40, m: Int, a: [m]1..=n, b: [m]1..=n) -> [2 * n, 2 * n]1..=n`; a
  grid the grader gives with rows of different lengths is an error.
  Every `@grader fn` is built, or the build fails.
  A local build forces these declarations into the grader's C++ too, so a
  grader that declares a crossing fn in another type does not compile.
  (R10.1.4)

## 10.2 Reading

```cp
let n: 1..=2e5 = read()  // read<T: Read>() -> T, by the expected type
let m = read<Int>()
```

- `read<T>()` dispatches on the expected type, so `let n: 1..=2e5 =
  read()` and `read<[n]Int>()` are the same mechanism. The count in `[n]T`
  is any `Int` expression: `read<[n - 1](u: V, v: V)>()`. A record reads its fields in order, one
  token each, `Str` fields too: `read<[n](name: Str, w: Int)>()`. An array of counted arrays
  `[k][n]T` reads `k` rows of `n`, row-major, indexed `x[i][j]`. A type reads by its
  `Read` impl, `fn read(mut input: Input) -> Self`, which reads its parts from the `Input` it
  is given (`let r: 1..=n = input.read()`), so the same impl reads standard input and a string;
  `read<T>()` is `T.read` of `Input.stdin()`, and an impl body's plain `read()` reads standard
  input, never the string. (R10.2.1)
- Range types read with their contract. A domain written with explicit
  ends (`1..=n`, `0..n`, `lo..=hi`) reads and prints its positions as
  their integers, never shifted. `io.base` applies only to *counted*
  domains, declared by a count alone (`[n]T`, or `domain E = [m]`, where `[m]` in a domain declaration is
  shorthand for `0..m`; `D.from_count` says which): `with
  io(base: 1)` makes 1-based input for them 0-based positions, and back
  on output. So the two never stack. Sizes, cuts and plain integers never
  convert. A counted array takes plain `Int` keys (`a[i - m]`, R04.4.30). (R10.2.2)
- Arrays `[D]T` read `D.count` values; `[R, C]T` reads `R.count * C.count` tokens row-major,
  wherever the line breaks fall; `[R, C]Char` reads one line per `R`
  position (the first factor is the row, R04.2.9), characters with no
  separators; `[V]List<V>` reads count-prefixed rows;
  `[Pair<V>]T` reads a lower triangle without its diagonal (row `i` gives
  the values for every earlier `j`), since it walks in that order;
  records, tuples and structs read their fields in order (a struct with a
  `Read` impl of its own reads through it; one with a single field reads the
  one parameter of its `new` when that has no default; a struct from another
  module reads field by field only when every field is `pub`, R11.1.4); an enum reads
  one token (one `Char` when every tag is one letter, so a `[D]` column of
  them reads packed, `WLW`, or spaced), picks the variant whose tag (or name) it equals (an integer
  `@tag(1)` compares as a number, so `01` matches), then reads
  that variant's fields, so a command stream is `read<Cmd>()` in a loop; `Range<T>`
  reads two ends `l r` as the inclusive `l..=r`, the statements'
  convention, and checks `l <= r`; `Bool` is not a token type (`read<Bool>()` is E0315), and `yes(b)`
  prints `io.answers`, `("YES", "NO")` in the default profile; `Str` reads one token; `read_line()`
  reads the rest of the line; `Char` skips whitespace then reads one
  character. `Mod<P>` reads one signed integer token of any length and
  reduces it modulo `P`, so a 10^4-digit coefficient is `read<Mod<P>>()`.
`read<[q]Cmd>()` reads `q` tagged commands, each tag then its payload, and
`[D]List<T>` reads `D`-many count-prefixed rows for any element type `T`,
a range type included. A tuple read's later part may be bounded by an
earlier one, `let (n, k): (1..=2e5, 1..=n) = read()`, and the generator
honours that order. (R10.2.3)
- `read<T>(from: s)` reads a `T` with the string `s` as the whole input, by
  these same rules and the same `Read` impls, and is `Some` of it, or `None`
  on a bad, out-of-range, missing or leftover token; standard input is
  untouched: it is `T.read` of `Input.of(s)`, then a check that every read held and no
  token is left. `s.parse<T>()` is std's body over it: one token read under two
  moduli is `let s = read<Str>()` then `s.parse<Mod<P>>()!` and
  `s.parse<Mod<Q>>()!`. (R10.2.4, permits)
- Graphs are built from an edge list read as records,
  `read<[E](u: V, v: V)>()`, then `Graph.undirected(edges)` or
  `.directed` (`lib/graphs-trees.md`); there is no `Graph.read`. (R10.2.5)
- An `F64` token is a sign, then digits with at most one `.` among
  them, then optionally `e` or `E`, a sign and digits: `-0.5`, `.5`,
  `5.`, `+3e-2`. It reads as the `F64` nearest its value, ties to even,
  on every back end; `inf`, `nan` and hex are bad tokens. (R10.2.6)
- A bad token traps with the input position and the expected type. (R10.2.6)

- `read_all<T>()` reads every remaining `T` until the input ends, for
  statements that give no count; reading after it is an error. \(O(\mathit{tokens})\).
  `read_all<T>(until: f)` stops at the first value with `f` true, a
  sentinel, which it consumes and leaves out; reading may continue after
  it (decision 161). (R10.2.7)
- Input lines may end in `\n` or `\r\n` on every platform: `\r` is
  whitespace to a token read, and `read_line()` drops a trailing `\r`.
  A token read skips any run of whitespace (space, `\t`, `\n`, `\v`,
  `\f`, `\r`), so blank lines between tests are invisible to it.
  Output lines end in `\n`. (R10.2.8)
- Input the program doesn't need is still read and checked:
  `let _ = read<[n - 1]1..=n>()` consumes the n - 1 tokens and keeps none
  (decision 379). (R10.2.9)
- `read<?T>()` is `None` when only whitespace is left in the input and a
  `T` otherwise, so `while let x = read<?Int>(): xs.push(x)` reads to the
  end and a trailing optional field reads `(n, k): (Int, ?Int)`. Checking
  for the end is a read: one that must wait for more input flushes first
  (§10.4). With `none: k` the
  number `k` is the `None` instead, and the end of input traps as for any
  other read (decision 568). (R10.2.10)

## 10.3 Printing

- `print(x, y, ...)` joins by `io.sep` and ends the line; `print(xs)`
  prints a sequence on one line (an empty one prints an empty line), and a
  `Str` is one word, not a sequence of `Char`s, and any sequence of
  `Char` prints with no separator, like a grid row (`eoe`); `print(xs, sep: "\n")` overrides;
  `print(xs, none: -1)` prints each absent element of a `?T` sequence as `-1`.
  A range is a sequence wherever it appears: `print(1..=3)` prints `1 2 3`, and
  a sequence of sequences, ranges included, prints one inner sequence per line,
  so `print([4..6, 7..9])` prints `4 5` and `7 8` like `print([[4, 5], [7, 8]])`. (R10.3.1)
- Interpolated strings format each piece through `Show`; a position of a
  counted domain prints in the file's base (R10.2.2), any other as
  `Int(v)` (`1..=n` prints 1..n); `"{x:.9}"` sets float precision, `"{x:6}"`
  pads on the left with spaces to width 6 and `"{x:04}"` with zeros after
  the sign (`-005`); a wider value prints in full. (R10.3.2)
- `Bool` is not `Show`: `print(b)` is an error naming `print(yes(b))`.
  `yes(b)` is the word from `io.answers`, a `Str`, so it also works in
  interpolation (`yes(b, answers: ("Possible", "Impossible"))`). (R10.3.3)
- `F64` uses `io.precision` or `print(x, precision: k)`; with neither it
  prints 10 decimals, `2.5` as `2.5000000000`, in both backends (decision 377). A value
  that is not finite prints as C's `printf` does: `nan`, `-nan`, `inf` or `-inf`, padded
  with spaces to a width even under `0`. (R10.3.4, permits)
- Derived structurally (see R08.1.6), with nothing to write: records, tuples and structs print their fields joined
  by `io.sep`; enums print their variant name unless the type implements
  `Show` (`impl Show for T: fn show(self) -> Str`). A sequence of tuples,
  records or structs prints one element per line, as such input is laid
  out (decision 437): `print([(1, 2), (3, 4)])` prints `1 2` and `3 4`.
  `print(ps, sep: " ")` puts them on one line: `sep:` joins the elements,
  and each element's fields still use `io.sep`. (R10.3.5)
- Output mirrors input, shape for shape, except that counts are never
  written for you. `[R, C]Char` prints one row per line with no
  separators. Any other `[R, C]T`, a `[V]List<T>` and a `List<List<T>>`
  print one inner row per line, joined by `io.sep`. `[Pair<V>]T` prints
  its lower triangle row by row. To print a count-prefixed row, print the
  count: `print(xs.len, xs)` prints the length and the elements on one line. (R10.3.6, permits)
- `?T` is not `Show`, like `Bool`: `print(x)` on a `?Int` is a compile error
  (E0606); write `x ?? d`, `x!`, or `print(xs, none: d)` for a sequence. (R10.3.7)
- `HashMap` and `HashSet` are not `Show`, like `?T`: walking one has no
  defined order (lib/containers.md §2.8), and the two engines would print
  different orders. `print(h)` is E0606 naming `print(h.keys.sorted())`
  (`print(s.sorted())` for a set); an `Interner` prints in id order (decision 460). (R10.3.8)

## 10.4 Interaction

`Wire` is the handle for an interactive judge. A query is
`wire.ask("? {x} {y}")`: print a line, flush, and read the answer as the
type the call site expects (`fn ask(x: Int, y: Int) -> Int =
wire.ask("? {x} {y}")`). In every mode, a read that must wait for more
input hands the judge the output written so far first, so a program
waiting for an answer never holds back the query; a read the input already
holds waits for nothing and flushes nothing. `flush()` hands what has been
written so far to the judge at once, and every exit does too. A flush
moves only when the judge gets the output: its bytes are the same with or
without one (R10.4.1). A trap
in any mode flushes buffered output before writing to stderr. The local
interactor harness (`cpl run` on a file with an `@interactor`, `tools/stress.md`) runs the program
against an `@interactor` fn or an external binary.

Under `@!multitest` the harness passes the test count to the program and
runs the `@interactor` once per test, so the interactor sees one test.
`wire.ask` doesn't change `wire`, so `let wire = Wire()` is enough. A
reply that is a marker or a number is read as `Str` and parsed:
`let r: Str = sol.recv()`, then `r == "!"` or `r.parse<Int>()!`
(decision 382).

## 10.5 Signatures

`read` and `print` are core, so they have no stub in `std`. Their
exact forms:

```cp
let n: Int = read(base: 1)    // read<T: Read>(base: Int = io.base, none: ?Int = None) -> T
let k = read<Int>(from: "4")  // read<T: Read>(from: Str, base: Int = io.base, none: ?Int = None) -> ?T
let l: Str = read_line()      // read_line() -> Str
// print(xs: Show..., sep: Str = io.sep, end: Str = "\n", none: ?Show = None, precision: ?Int = io.precision)
print(n, l, [Some(1), None], sep: ",", end: "\n", none: "-", precision: 3)
```

<!-- signatures: std/io.cp -->
```cp
fn read_all<T: Read>(until: ?(T -> Bool) = None) -> List<T>
fn yes(ok: Bool, answers: ?(Str, Str) = None) -> Str
```

`print` takes any number of positional values. A sequence argument (any
`Seq`: a list, array, range, view such as `xs.rev`, or generator) prints
its elements joined by `sep`. `none:` replaces each absent element of a
`?T` sequence. `?T` is not `Show`, like `Bool`, so printing one without
`none:` is a compile error that names it. `end: ""` leaves the line open.

## 10.6 Cost

Input is read in large pieces as the program asks for it, with a
hand-rolled parser; output is one buffer, handed over at exit, at a
`flush()` and before a read that must wait for more input (R10.4). `io` is a
compile-time context, so `- io.base` folds away.
