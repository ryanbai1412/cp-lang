# 25. I/O

**Layer:** library. Status: [proposed].

Nothing in this chapter is compiler-special. It is four things:
1. byte intrinsics (`20`): `bytes_in.next() -> ?Byte`, `bytes_out.write(Byte)`, `flush()`;
2. return-type dispatch (core, chapter 14), which is all `read<T>()` is;
3. two traits, `Read` and `Print`, with ordinary impls;
4. one library-declared context, `io` (chapter 17).

A user library could replace any of it.

## 25.1 The traits

```cp
trait Read:
    fn read() -> Self                         // consumes tokens from stdin; traps with a position on bad input

trait Print:
    fn print(self, out: &mut Out)             // appends to the output buffer

context io:
    base: 0 | 1 = 0                           // positions of counted domains, on input and output
    sep: Str = " "
    answers: (Str, Str) = profile.answers     // what `yes(b)` prints
    precision: ?Int = profile.precision

fn read<T: Read>() -> T = T.read()
fn print<Ts: Print...>(xs: Ts) uses io       // joins by io.sep, ends the line
```

**Why traits.** One mechanism for every type, including user structs and enums (`#derive(Read, Print)`
reads/prints fields in order), and the interactive `Wire` reuses the same impls (chapter 31).

**Rejected.** `scanf`-style format strings (untyped); a special `input` statement (would need compiler
support for every new type).

## 25.2 Impls that matter

```cp
impl Read for Int:   fn read() = parse_int(next_token())            // rejects Int's niche [r12 R5]
impl<lo, hi> Read for lo..=hi:
    fn read() = check(read<Int>(), lo..=hi)                         // a range type reads with its contract

impl<D: Counted> Read for D uses io:
    fn read() = D.at(read<Int>() - io.base)                         // the whole of 1-based input
impl<D: Counted> Print for D uses io:
    fn print(self, out) = (self.ord + io.base).print(out)

impl<D: Index, T: Read> Read for [D]T:    fn read() = D.map(_ => read())
impl<T: Read> Read for (len: Range<Int>) -> List<T>:                 // `[len: 1..=n]T`
    fn read() = repeat(read<Range>(), read)
impl<T: Read> Read for Range<T>:
    fn read() = read<T>() ..= read<T>()                              // traps unless first ≤ last
```

- Under `with io(base: 1)`, counted positions and ranges of them convert. Sizes, cuts, labeled domains and
  integer ranges don't, because their `Read` impls don't `uses io` [r9 16].
- `read<[Cell]Byte>()` reads r rows of c characters with no separators [r13 P22]. `Perm` checks
  bijectivity; `Graph<V>` and `[k]Edge<V>` read edge lists (chapter 28).
- `read_line() -> Str` reads the rest of the current line [r11 N29].

**Sugar.** `domain V = read(1..=n)` is `domain V = read<1..=n>()` (chapter 12).

**More impls [p3]:**
- `Bool` reads `0`/`1` (its labels).
- `read<Byte>()` skips whitespace, then reads one byte.
- `[D]T` with a byte-labeled `T` (`Letter`, `Byte`) reads one contiguous token of exactly `D.count` bytes.
- `[V]List<V>` reads count-prefixed rows.
- The integer-range read lint is named `lint(read_range_index: allow)`.

## 25.3 Printing

- `print(x, y)` separates by `io.sep` and ends the line. `print(xs)` prints an array on one line;
  `print(xs, sep: "\n")` overrides locally.
- **`Bool` doesn't implement `Print`.** `print(b)` fails with the trait's library-authored diagnostic naming
  `yes(b)` [you]. `yes(b)` returns a `Str` from `io.answers`; `yes(b, answers: ("Possible", "Impossible"))`
  overrides locally.
- `F64` uses `io.precision`, or `print(x, precision: k)` [r7 31].

**Sugar.** `"? {v}"` desugars to `Print` calls on each piece into the output buffer. Positions interpolate
in the file's base; arrays use `io.sep` [r11 N32].

## 25.4 Cost

Input is one `fread` into a buffer and a hand-rolled integer parser; output is one buffer and one `fwrite`
at exit. The range check in `Read for lo..=hi` is one compare pair per value (kept in submissions; that
check validates input for free). `io` is a compile-time context, so `- io.base` folds to a constant.

## 25.5 Interactive mode

Constructing a `Wire` switches stdout to interactive mode at runtime; in that mode every read and every exit
flushes first. Programs that never construct a `Wire` never flush early. See chapter 31 [p4].

A trap, in any mode, flushes buffered stdout before writing its message to stderr, so partial output
is what the program had printed [2impl Q74].

## 25.6 Tooling

The tracer records every token read with the value it became and the source line that consumed it; a
bad-input trap shows the input position and the expected type.
