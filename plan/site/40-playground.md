# Playground, share links, `/s`, embeds

Status: proposed.

## The editor component

One React component used by the playground, course problems, the
landing hero, quickstarts and every runnable docs fence. Modes:
`compact` (docs fence, hero), `problem` (course), `full` (playground).

- CodeMirror 6 with the CP Lang grammar (Shiki/TextMate from
  `editors/vscode/syntaxes/cp.tmLanguage.json`, *verified*, or a
  Lezer port if CodeMirror needs it).
- Diagnostics as you type, hover types, completion, from the WASM build
  of the compiler (`crates/cpl-wasm`, which already exposes diagnostics
  and type inspection, *verified* in `site/README.md`).
- Format (`cpl fmt` in WASM) on Ctrl+S; Ctrl+Enter runs.
- The compiler runs in a Web Worker with a step budget and a stop
  button; the main thread never blocks. The WASM file (about 1.3 MB
  today, *verified*) loads on first Run, then is cached by a service
  worker so the playground works offline.

## `/play`: the playground page

- **Panes**: source; test cases (several, each with input and optional
  expected output, pass/fail per case); output; C++17; explain;
  trace. Panes are resizable tabs on narrow screens.
- **Actions**: Run, Run all cases, Stop, Format, Lint, Build C++
  (download `.cpp`), Trace (opens the trace pane on the selected case),
  Share.
- **Toolbar**: an examples menu (generated from the cookbook and the
  landing/quickstart snippets), the judge profile selector (sets the
  build flags shown in the C++ header), the compiler version.
- **Persistence**: the last program and cases in `localStorage`;
  several named scratch files.
- **Header link**: a quiet "Run locally" that opens Setup.

## Share links

- **Fragment links**: `/play#c=<deflate+base64url of {src, cases,
  version}>`. Nothing leaves the browser; private by default.
- **Short links**: *Share -> Create short link* POSTs to the Worker,
  which stores the snapshot in R2 under its content hash and returns
  `/p/<hash>` (10-char base62). Snapshots are immutable, capped at 64 KB,
  and carry the compiler version they were made with.
- **Opening an old link** on a newer compiler: the page says "made with
  0.x; running on 0.y" and, if it fails to compile, offers the version
  notes.
- **Chat previews**: fragment links can't unfurl with code (chat apps
  never send the fragment to the server), so *Share for chat* makes a
  `/p/` link and the Worker serves an OpenGraph image of the first lines.
- **Problem challenge links**: on a solved course problem, *Share*
  offers "my solution" (a `/p/` link) or "challenge a friend"
  (`/learn/course/<id>?from=<name>`, no code).
- Abuse: size cap, per-IP rate limit in the Worker, optional Turnstile.

## `/s`: arriving from a submission

The header `cpl build` writes already quotes the whole source
*(verified)*. A new header line, `// Written in CP Lang: <site>/s`
(a codegen change; off with a flag or a judge-profile setting), brings
readers of submissions here.

1. One line: "That C++ was generated by CP Lang, a competitive-
   programming language that compiles to one readable C++17 file." Beta
   note.
2. A paste box: paste the whole submission. The page extracts the
   quoted source from the header and shows it beside the C++, with line
   counts. *Run* (your own input) and *Open in playground*. Entirely in
   the browser.
3. The "bugs you can't write" pairs from the landing page.
4. The C++ quickstart, with links to the other three.

## Embeds

`/embed?c=...` or `/embed/p/<hash>`: a compact editor for blog posts
and editorials, with Run and "Open in playground". An "Embed" item in
the Share menu copies the `<iframe>` snippet.

## Trace viewer (`/trace`)

The existing trace viewer moves into the editor component's trace pane
and also stays as a page that opens a trace file (`cpl run --trace`
output) dropped onto it. Same features as today (`site/test_trace.*`
cover them, *verified*).
