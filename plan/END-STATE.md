edit the first, and the gate measures the second. The migration to the new architecture
(`handbook/design/architecture.md`) is done when every suite here is `done`.

**0 of 25 suites done; 2 measured and not there; 23 with no number yet.**

- `done`: every number is at its target.
- `measured`: the gate counts it, and the count only moves toward the target.
- `unmeasured`: nothing counts it yet. Building its number comes before building toward it.

Rules for every suite: expected results come from the spec, never from what a compiler
prints; a case passes, is wrong, or is refused (not implemented), and a refusal is never
a correct rejection; a committed list is always what the suite finds; each suite is itself
measured, by a mutation score or a matrix with no empty cell.

## What each suite must be

### 1. Spec conformance

- Decides: Every spec rule is implemented.
- Minimum size: Every rule has at least one accepting and, where it forbids something, one rejecting case; at least 6,000 cases.
- At the end state: 100% pass on every engine and the C++; 0 wrong; 0 refused; error cases match code and line.
- Mechanism level (`handbook/process/quality.md`): 3.

### 2. Feature-by-context matrix

- Decides: Features work in every place they can appear.
- Minimum size: Every syntax form (239 counted) in every context it is legal in; at least 20,000 generated cases.
- At the end state: No empty cell; each cell agrees across engines.
- Mechanism level (`handbook/process/quality.md`): 2.

### 3. Corpus

- Decides: Real contest solutions work.
- Minimum size: All 1,108 problems; at least 1,500 programs.
- At the end state: Accepted on generated tests within the judge's limits, on every engine.
- Mechanism level (`handbook/process/quality.md`): 3.

### 4. Std as a program

- Decides: Std is ordinary CP Lang.
- Minimum size: All 43 modules, every `pub` item.
- At the end state: Compiles with 0 compiler-known names; every doc example runs; std's own tests pass on every engine.
- Mechanism level (`handbook/process/quality.md`): 1 + 3.
- Last changed: 2026-11-27: next_std_unchecked counts the std modules cpl-next does not compile with every fn checked (tests/std_modules.rs), so the suite has a number.

### 5. Checker totality

- Decides: The checker is the one source of types.
- Minimum size: Every expression in suites 1, 3 and 4.
- At the end state: 0 expressions without a type or a diagnostic; 0 type inference outside the checker; never panics on any input.
- Mechanism level (`handbook/process/quality.md`): 1 + 4.
- Last changed: 2026-11-27: next_lowered counts the programs cases whose error only lowering finds (tests/lowered.txt), so the suite has a number.

### 6. Ownership soundness

- Decides: Moves, borrows and lends are right in both directions.
- Minimum size: At least 1,000 written cases (half must-accept, half must-reject) plus generated programs.

- Mechanism level (`handbook/process/quality.md`): 2 + 3.

### 8. Sanitized C++
