## Input

`read()` is typed by the expected type, so the type you declare is the
format you read. No format strings, no loops for arrays:

```
let (n, m): (1..=2e5, 1..=2e5) = read()
domain V = 1..=n
domain E = 1..=m
let a: [V]0..=1e9 = read()               // n numbers
let es: [E](u: V, v: V, w: Int) = read() // m lines of three; u and v checked in V
let g: [Row, Col]Char = read()           // a grid, one row per line
let s: Str = read()                      // one token
let line: Str = read_line()
let q: List<Query> = read_until_eof()    // enums read by their declared Read
```

- Reading a domain position checks it is in range in debug runs, so a
  0-indexed input read into `1..=n` fails at the exact input position, with
  the line and column.
- Any type can define its own format by implementing `Read`, so the
  language is expressive enough to write custom input logic in user code
  (the user asked for this); the built-in formats are just stdlib impls.
- Debug runs validate every declared range and trap with the input position
  of a violation.
- Input is read with a whole-buffer fast reader.
- Proposed (plan/18-key-features.md): input types like `Perm<V>`, `Tree<V>` and `where`
  refinements also generate and shrink stress inputs.

## Output

`print(x)` prints any value: lists space-separated, grids by row, records
field by field, `?T` as the value or `none` (a lint suggests `?? -1`).

```
print(ans)
print("Case #{t}: {ans}")             // every string literal interpolates
print(dist)                           // 0 3 7 5
print_sep(path, "\n")
print("YES" if ok else "NO")
print(x, digits: 9)                   // floats: fixed precision
print(k); print(colour, sep: "\n")    // sep: goes between arguments and between list items
print(best, none: "IMPOSSIBLE")       // none: is what a `none` is written as
print(" ".join(path))                 // the same text as a Str
```

### Format specifiers (0.2.2)

A `:` after an interpolated value says how a number is written. There is
one small grammar, `[0][width][.digits[f] | x | b]`, and nothing else: no
alignment flags, no nested `{}` inside a specifier.

```
let (n, x) = (42, 3.14159)
print("{n:5}")        // "   42"      at least 5 wide, padded with spaces
print("{n:05}")       // "00042"      padded with zeros; the sign stays in front: "{-42:05}" is "-0042"
print("{x:.3}")       // "3.142"      3 digits after the point; "{x:.3f}" is the same
print("{x:8.2f}")     // "    3.14"   width and digits together
print("{n:x} {n:b}")  // "2a 101010"  hex and binary of an Int
print("{-0.0004:.2}") // "0.00"       a value that rounds to zero has no sign
```

`.digits` works on an `Int` too (`"{n:.2}"` is `42.00`). A width alone on
an `F64`, or `x` / `b` on an `F64`, is a compile error. When the number is
an exact ratio of integers, `fixed(num, den, k)` from `std.math` (in the
prelude) gives the same text without going through a float:

```
print(fixed(num, den, 5))   // round half away from zero, never "-0.00000"
print(fixed(t, 2, 1))       // a half-integer
```

Types implement `Show` to customize; `@derive(Show)` is the default.
- Output is buffered and flushed at exit, or before every read in interactive
  mode.

## I/O and parts

There is no purity keyword. Tools record each part's input bytes and printed
bytes, so any fn can be replayed. `@memo` rejects fns that read or print.

## Interaction

Goal: one definition of the interactor serves as the local judge, the
stress-test opponent and the query-limit check, for both interaction
styles, without adding anything to the core.

### The two styles

**Grader functions** (IOI-style, e.g. ioi17p4's `ask(i)`): on the judge,
the grader's real functions are linked in; locally, the `@interactor`'s
methods are called directly.

**stdin/stdout** (Codeforces-style `? x` and `! y`): on the judge, the
program prints a query, flushes and reads the reply; locally, the
`@interactor` reads the solution's output and writes replies through a
pipe.

Both use the same `protocol`, so the solution code is identical in both
builds.

### Defining an interactor

```
protocol BigPrize:                          // what the solution may call
    fn ask(i: Box) -> (Int, Int)
    limit queries: 10000

@interactor(BigPrize)
@derive(Gen)                                // hidden state is generated
struct PrizeJudge:
    boxes: PrizeBoxes                       // a type with its own Gen
    fn ask(mut self, i: Box) -> (Int, Int) = self.boxes.count_better(i)
    fn answer_ok(self, b: Box) -> Bool = self.boxes.is_best(b)
```

- `protocol` lists the calls and their limits. The tooling counts calls
  and fails the run when a limit is exceeded, showing the call log.
- The hidden state uses `Gen`, so edge-biased generation applies: one
  candidate left, all equal, maximum size.
- `answer_ok` is the interactor's checker.

### The solution side

```
@graded fn find_best(n: Int, judge: BigPrize) -> Box:
    ... judge.ask(b) ...
```

On the judge, `judge.ask` is the grader's `ask`, or prints `? b`, flushes
and reads the reply; a text protocol derives its wire format from the types,
like `Read`. Locally, `judge` is a `PrizeJudge`.

### Tooling

- `cp run sol --judge PrizeJudge` runs once against a generated hidden
  state.
- `cp stress sol` tries many hidden states and fails on a wrong answer, a
  crash or an exceeded limit, shrinking to the smallest failing state.
- `cp stress --trace` adds the call log of the smallest failure to the HTML
  trace.
- `cp stress --adaptive` picks the hidden state adversarially from the
  solution's queries.

### Adaptive interactors

Some judges commit to a hidden state as late as possible. An adaptive
interactor keeps the set of states still consistent with its answers and
replies so as to keep that set large:

```
@interactor(Guess, adaptive)
struct WordJudge:
    alive: List<Word>                       // states still possible
    fn guess(mut self, w: Word) -> Pattern:
        let p = max_by(groups(self.alive, by: s => pattern(w, s)), by: g => g.len).key
        self.alive.retain(s => pattern(w, s) == p)
        p
```

That finds worst cases a random hidden state would miss, such as
noiwc22p3's crash when the candidate set became empty.

### Before and after

Before (noiwc22p3): global `dict` and `cand`, state reset by hand in the
grader callback, and no local judge, so the empty-candidate RTE first
appeared on submit:

```cpp
vector<str> dict, cand;
...
if (remaining_guesses == 1) {               // RTE when cand was empty
```

After: state lives in the solution, the interactor is a 30-line
`@interactor`, and `cp stress --adaptive` finds the empty case locally.
