# tree: doc-standard notes

- `Rooted.new`: pinned the heavy child as the first largest child in child order, and `t.Pre` as heavy child first, then the other children in child order (the module says only "heavy-first preorder").
- `Rooted.new`, `forest`: chose to trap when a vertex is unreachable (the old doc said "stops"), and for `forest` when `from` is empty or a vertex is reached from two roots.
- `Rooted.from_parents`: chose children in increasing key order.
- `Rooted.try_from_parents` example compares the option with `None`, which needs `Rooted` equality or an `is_none`; neither is declared. Left as is; flag for the stub tests.
- `Rooted.tour` (contradiction): the old doc says `Enter(v, parent)` / `Exit(v, parent)`, but `std.graph.Visit` is `Enter(v)` / `Exit(v)`. Documented the one-field form. (resolved: follows the new `Visit<V, V>`: `Enter(v, via: parent)` / `Exit(v, via: parent)`, as in the old doc; `Events.at` too)
- `Rooted.w` (contradiction): says "1 unless built with `w:`", but `new` takes lengths from `Weighted` arcs and has no `w:`. Documented the arc rule. `dist` said "a tree built with `weighted`"; same fix. (resolved: stub kept (lengths from `Weighted` arcs); the doc already says so)
- `Rooted.centroid`, `centroids`, `diameter`, `euler_tour`: chose that they look only at the tree holding `t.root` in a forest.
- `Rooted.diameter`: pinned two sweeps, root then farthest, ties to the first in `t.Pre`.
- `Rooted.shapes`: "numbered by first appearance from the leaves up" pinned to reverse `t.Pre` order.
- `Rooted.lower`, `lca`, `dist`, `path`, `jump`, `chains`, `fold_path`, `apply_path`, `virtual`, `sub_at`, `meet`, `farthest`: chose to trap across trees of a forest (the old doc says these exist only within one tree, without saying what happens).
- `Rooted.ancestor`, `jump` and the `JumpTree`, `Lift`, `LinkCut`, `LazyLinkCut` counterparts: chose to trap on negative `k`.
- `Rooted.chains`: the empty case (`edges` with `a == b`) yields nothing.
- `Rooted.virtual`: repeated keys count once; empty keys give an empty domain.
- `Rooted.farthest`: pinned the candidate order for ties: `x`, `y`, then the four cross pairs.
- `Rooted.sub_at`: empty ranges are skipped; ranges in increasing position order.
- `Rooted.long_paths`: the tallest child is the first in child order on ties.
- `Centroids.new`: pinned the first centroid as `Rooted(next, root: V.first).centroid()` and each piece rooted at its neighbour of the removed centroid; `piece` is breadth-first in `next` order.
- `JumpTree.add`: traps when `v` already has a parent or `v == p`. Hanging a vertex that already has children breaks the stored depths and is not detected in O(1); logged rather than changing the cost.
- `Lift.climb_while`: `ok` must hold for `identity` (it returns `v` itself).
- `Lift.of` example writes `Lift<I, ()>.of(...)` so the lambda's parameter type is known.
- `LinkCut.link`, `LazyLinkCut.link`: pinned that `u` becomes its tree's root and hangs below `v`, so `root_of` after a link is `v`'s root. Trap when already connected (the old doc said "must be", costing one `root_of`). `cut` traps when the edge is missing.
- `LinkCut.new`, `LazyLinkCut.new` (contradiction): the old doc says `V.K` trees; read as `V.count`. The `LazyLinkCut` struct doc shows `LazyLinkCut.new(+, add, a)`, but the signature takes one `Action`; examples use the signature. (resolved: signature kept; struct doc now says `LazyLinkCut.new(act, a)`)
- `LazyLinkCut`: the struct doc comment sits above `PreferredPaths` (a misplaced block); left for the parent to move, since it is not a function entry.
- `PreferredPaths.access`: accessing a vertex already on the root's preferred path yields nothing.
- `PermTree.new`: pinned left-deep joins for runs, and traps on an empty `I`, unequal sizes or a non-bijection.
- `Layers.below`: chose depth counted from the root, as `level` does, and `v` itself at `d == depth(v)`.
- `Events.path`: pinned the classic ranges (`enter(a)..=enter(b)` when `a` is an ancestor, else `exit(a)..=enter(b)` plus the lowest common ancestor).
- `EulerTourTree`, `LazyEulerTourTree`: `link` traps when already connected, `cut` and `fold_sub`/`apply_sub` trap when the edge is missing.
- `kruskal_tree`: pinned `N` as leaves in vertex order, then merge nodes in merge order; equal weights merge in edge key order; `KruskalTree.tree` roots in increasing node order.
- `KruskalTree.reach`: `leaf[v]` itself when no merge is within the limit.
- `prufer` / `from_prufer`: pinned least-leaf removal, and `from_prufer`'s edge order `(u: leaf, v: neighbour)` with the last edge smaller end first; both trap below two vertices.
