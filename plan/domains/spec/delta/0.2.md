# Delta: cp-lang 0.2.x to the 0.3.0 spec

What the compiler on this branch does against this tree. The build-out
phase starts from this list. Regenerate the numbers with
`scripts/spec-blocks.py` (code blocks) and `scripts/spec-check.sh`
(dreams against the stubs).

## Measured (2026-11-22, `73d7cb76`)

- **Gold dreams:** all 16 check against the `std` stubs
  (`scripts/spec-check.sh`).
- **All dreams:** 95 of 115 check; the other 20 name library gaps
  (`rect_counts`, `suffix_mex`, `Rope`, `subsets`, ...) or still use
  spellings that are not in the stubs yet.
- **Stubs:** every `std` function body is `todo`
  (`scripts/spec-stub.py --check`).
- **Spec code blocks:** 25 of 178 check today. This is a floor: most
  blocks are fragments that use names defined in the prose. The new core
  chapters (`01`, `02`, `06`, `08` to `13`) put their examples in `text`
  blocks, so they are not counted yet.

First errors over those 178 blocks:

- `E0201` (70) and `E0204` (22): a name or domain the block does not
  define (`n`, `V`, `s`). Fragments, not gaps.
- `E0103` (33): signature-only declarations (`struct Bitset<D>` with no
  body, `fn f(...) -> T` with no `=`). The spec writes API summaries this
  way; the parser wants a body. Gap: accept bodiless declarations in
  `.md` summaries, or write them as `= todo`.
- `E0107`, `E0102`, `E0108` (11): syntax in `delta/parser-gaps.md`.
- `E0603`, `E0402`, `E0302` and others (8): mostly ownership exercises
  that are meant to fail. They need `// expect:` markers so the
  conformance runner counts them as passes.

## By area

The syntax gaps are listed form by form in `delta/parser-gaps.md`. The
compiler gaps by area (fresh domains, existential returns, associated
types, decorators, `?T` lifting through traits, and so on) are in
`design/DELTA.md`, a first cut from 2026-11-21 written against the older
`design/spec/` chapters; it is still the best list per area and gets
folded in here as each area is rechecked.

Variant case (decision 157): the parser reads `Some(x)` and `None` as the
`?T` variants and still accepts `some`/`none`, which the 0.2 ports and
stdlib use. Left: a codemod over `proto/` and `stdlib/`, then a lint (and
later an error) for lowercase `some`/`none`.

Not built anywhere yet, by design for this phase:

- the conformance runner for `spec/conformance/` and `// expect:` markers;
- the `spec/tools/` contracts beyond what `cpl` 0.2 already has (`explain`
  layout reports, judge-profile `release_checks` and `isa`, LSP size hints);
- the library bodies: every 0.3 API is a documented stub.
