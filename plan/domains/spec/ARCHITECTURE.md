# spec architecture

The code as it is on 2026-11-22 (`4b8f504f`), from reading it. Updated in the same commit as any structural change; reviewed by architecture & tech-debt.

## Modules

| Path | What it is for |
|---|---|
| `spec/README.md`, `spec/STATUS.md`, `spec/GLOSSARY.md` | Index and reading order; where 0.3 stands; one term per concept (normative). Shared entry points, edited by spec. |
| `spec/core/00-13*.md` (16 files) | The language. A rule is defined where `(Rnn.n.n)` ends its sentence; a reference is `(see Rnn.n.n)`. 527 rules; none in 00. Code blocks are fenced `python` (83), bare (25) or `ebnf`/`text`. |
| `spec/lib/*.md` (10 chapters + `rationale/`) | Library design per family; model and examples behind `spec/std` signatures. No rule ids. Fences: `cp` (59), `python` (43), bare (2). `rationale/` is superseded background. |
| `spec/tools/*.md` (8 files, 16-41 lines each) | One contract per tool (cli, judge profiles, stress, explain, trace, fmt-lint, lsp, bundle). No rule ids. |
| `spec/conformance/<group>/*.cp` (55 groups, 1711 cases) | One program per case. Line 1 `// expect: ok[, output "..."] \| E/L/R/W#### at N [(checked)] \| exit N`; optional `// rule:`, `// input:`, `// tool:`, `// has:`/`// lacks:` lines. Groups: `core-01`..`core-13`, `lib-ops-ranges`, `std-<module>`, `diagnostics`, `lints`. Format: `spec/conformance/README.md`. |
| `spec/conformance/COVERAGE.md` | Generated by `scripts/conformance-coverage.py`: per-rule accept/reject counts, happy-path-only rules, codes and std items named by a case. Pass status comes from `research/scoreboard.json`. |
| `spec/delta/` | Measurements against the tree: `0.2.md`, `parser-gaps.md`, rebuild rounds (`rebuild-1/`, `rebuild-2/HOLES.md`), dream comparisons. Not normative. |

| Path | Role |
|---|---|

| `crates/cpl-conform/src/spec_blocks.rs` | Extracts ```` ```cp ```` and ```` ```python ```` fences from `spec/core` and `spec/lib`; checks each as a whole program. Bare fences are skipped. |

| `scripts/conformance-coverage.py` | Writes `COVERAGE.md` and `rule-gaps.txt`; `--check` (in the fast gate) fails when stale or when a rule gap is new. |
| `scripts/conformance-matrix.py`, `spec/conformance/matrix.toml` | Generates `spec/conformance/matrix/` (feature x consumer cells); `--check` (in the fast gate) fails on a stale case or a cell with neither a case nor an n/a reason. |
| `scripts/spec-check.sh`, `spec-vocab.py`, `spec-stub.py` | Dreams vs stubs, banned spellings, std doc shape. |

## Interfaces other domains use

| Interface | Consumers | Held by |
|---|---|---|
| Rule ids `Rnn.n.n` in `spec/core` | compiler, diagnostics (`spec/diagnostics.md` cites them), site docs, idioms skill | `cpl-conform --rules`; `conformance-coverage.py` |
| Conformance case format (header lines above) | compiler (fix target), tools (tool cases), diagnostics (code cases), stdlib (`std-*` groups) | `crates/cpl-conform` tests (`tests/ratchet.rs`) |
| The conformance pass count in `research/scoreboard.json` | compiler (its headline metric), infra (gate step "cpl-conform ratchet" in `scripts/check.sh`) | `cpl-conform all --check` |
| Normative text (`spec/` wins over every other doc) | every domain | AGENTS.md; `spec-vocab.py` |
| `GLOSSARY.md` terms | diagnostics, site, idioms | `spec-vocab.py` |

## Invariants

- A case is never deleted or weakened; a wrong case is fixed with the reason in the commit.
- Cases test the language through `cpl`, never through crate internals, so the suite stays independent of the compiler.
- Each rule id is defined once; `// rule:` ids are written without the `R`, whitespace-separated.
- `at N` counts from the first line after the header lines.
- A new case that fails today is recorded as known-failing by the ratchet; a passing case that starts failing blocks the land.
- Normative rules live only in `spec/`; `plan/domains/spec/` never restates them.

## Known debt

- `cpl-conform --rules` reports 78 unknown cites: 39 are std ids (`// rule: std.graph.Next`) the rule check does not understand (`conformance.rs` `check_rules`), the rest malformed rule lines.
- `research/scoreboard.json` holds 1222 conformance entries (995 passing) while 1711 cases exist and 1617 pass, so `COVERAGE.md`'s pass column is stale.
- `spec_blocks.rs` treats every fence as a whole program, so 84 of 166 failures are fragments naming undefined values (`cpl-conform spec-blocks --causes`); no `spec-only` marker exists.
- `spec/core` fences CP Lang code as `python` (83 blocks); the language tag says nothing.
- `spec/lib` and `spec/tools` have no rule ids; tool behaviour is cited by prose.
- Contradictions between chapters and `spec/std` signatures are found only by rebuild rounds (e.g. ch. 7 line 315 "descending is a key, not a flag" vs `spec/std/seq.cp` `sort(..., desc: Bool = false)`, which `std-seq/sort-sorted-last.cp` exercises).
