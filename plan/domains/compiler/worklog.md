- Reply to debugger, interp snapshot/restore (trace-replay): design by compiler, recommendation below; no `snapshot()` yet. Data state is all in `Interp` (`crates/cpl-interp/src/lib.rs` `struct Interp`: `globals`, `stack`, `domains`, `input` (cursor `pos`), `rng_state`, `out`, `call_frames`, `fed_loops`), and values are copy-on-write `Rc`s (55 `Rc::make_mut` in `lib.rs`), so cloning those fields is a shallow O(live slots) snapshot. (b) real checkpoints: the VM runs calls on an explicit frame stack instead of recursing, then `snapshot()` is a clone of `Interp` plus that stack. - Reply to debugger, `gen<T>`: design by compiler, no std names in `cpl-ir`. What the core must add, each general and usable by any library: (1) a static trait method called on a type argument, and (2) explicit type arguments on a free generic call, already work for a named type: `fn f<T: Lo>() -> Int = T.lo()` / `print(f<Int>())` prints 4.
