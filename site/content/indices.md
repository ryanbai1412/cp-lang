An integer tells you a number. An index also tells you what that number belongs to. Vertex `3` and edge `3` may print alike, but they should not be interchangeable when indexing arrays.

> **Approved design, implementation in progress.** This chapter uses unified `Index`, `.l`/`.r` boundaries, and parent-indexed slices. Older prototype code may still use `.before`/`.after` or different index helpers.

## A domain is a fresh type

```cp CP Lang · design
let n: 1..=2e5 = read()
let m: 1..=2e5 = read()
domain V = 1..=n
domain E = 1..=m
let weights: [E]Int = read()
var degree: [V]Int = 0
```

`V` and `E` are different types even if `n == m`. You can index `degree` with a `V`, not an `E` or an arbitrary `Int`. Check or refine a number when it enters the domain; do not repeat that check at every array access.

```cp CP Lang · design fragment
let v = V(x)             // checked conversion; rejects an invalid label
if x in V:              // x is rebound to a V in this branch
    degree[x] += 1
```

Domain labels are for input and output. Internally, an index maps densely to an ordinal. Avoid assuming every domain starts at zero or one: a character domain can use labels such as `'a'..='z'`.

## The mechanism is Index

`domain V = 1..=n` expands to a nominal struct with a sealed constructor and an `Index` implementation. The sealed constructor prevents arbitrary invalid indices. The trait supplies a size `K`, conversion to `0..K`, and conversion back from a valid ordinal.

The associated size uses a runtime-frozen `let`, not compile-time-only `const`:

```cp Index implementation · explanatory fragment
impl Index for V:
    let K = n
    fn to_idx(self) -> 0..K = self.ord
    fn from_idx(i: 0..K) -> V = V(i)
```

Here `V` is the sealed wrapper generated by the domain declaration; its private constructor and `ord` field are part of that expansion. `n` may come from input, but it is immutable and fixed when the index type is declared. A changing `var` cannot size the same index type differently later.

`[V]T` means `Array<V, T>`. Tuples of index types are indices too, so `[Row, Col]T` is an array indexed by `(Row, Col)`. Grids need no separate indexing rules. `Seq` adds order and neighbor operations on top of `Index`; not every bounded index needs to be a sequence.

## Elements and boundaries

For three elements, there are four gaps: before everything, between each pair, and after everything. `V.bounds` names the type of those gaps. An element `v` has `.l` immediately to its left and `.r` immediately to its right.

```text
elements           a       b       c
boundaries      |       |       |       |
                a.l     a.r
                        b.l     b.r
                                c.l     c.r
```

`a.r` and `b.l` above are the same boundary. `v.l(k)` and `v.r(k)` are the parameterized left/right boundary shorthands; the no-argument `.l` and `.r` mean the immediately adjacent gaps. Use these instead of inventing numeric `+1` shifts. A requested offset still has to satisfy the boundary range.

## Prefix sums without shifts

```cp CP Lang · design
var pre: [V.bounds]Int = 0
for v in V:
    pre[v.r] = pre[v.l] + a[v]

fn range_sum(l: V, r: V) -> Int:
    pre[r.r] - pre[l.l]
```

This fragment assumes `a: [V]Int` and an ordered nonempty query `l..=r`. The zero at the initial boundary represents the empty prefix. `pre[v]` is a type error: `v` is an element, not a gap. `a[v.r]` is wrong for the opposite reason. The two arrays express different jobs in their types.

## A range is a value; a slice is a lend

A `Range<V>` stores two boundaries. An inclusive expression `l..=r` describes the window from `l.l` through `r.r`. You can return that range from a function or store it for later: it holds no reference to an array.

Applying it to an array, `a[window]`, temporarily lends the storage in that window. A slice keeps the parent's index type, not a fresh `Sub<V>` type.

```cp CP Lang · design fragment
let part = a[window]
for v in part.positions:
    print(part[v])
```

An arbitrary `v: V` is valid for `a`, but might not belong to `part`. `part[v]` therefore checks membership unless the checker already knows it, as it does when iterating `part.positions`. It must not become unchecked merely because another slice uses the same parent index type.

## When an integer is the right tool

Keep large coordinates as `Int`; use a fresh compressed index space when you actually need an array over them. Use `.raw` when numeric indexing really is clearer: `a.raw[i]` explicitly opts out of nominal domain matching, but it is still checked for bounds unless proven safe. `unchecked` is not the default way to make code compile.
