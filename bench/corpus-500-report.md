## Headline

- **959 `.cp` files** under `proto/ports/` are ports of **573 unique problems**, out of 747 problems with an accepted submission in the corpus (836 attempted).
- **477 of those 573 problems** have a port that a harness differentially checked against the original in a recorded run at `02f6137`.
- Canonical ports are **66.1% shorter than the raw originals** and **47.9% shorter than the library-stripped originals** (23059 CP Lang lines against 67938 raw and 44262 stripped).
- **62 hard problems** with an accepted source are still unported.

## Files against problems

The 959 files are not 959 solved problems. 91 are regression ports that `proto/run_all.sh` stresses on every change. 525 are runnable scout ports, the form a batch harness builds. 298 are spec-form files: the same solutions written against the locked spec, which no implementation accepts yet, so each has a runnable twin in `today/`. 38 are blind-critic first drafts or superseded `before/` versions, and 7 are shared modules and a bug repro rather than ports.

After grouping by problem code, 345 problems have more than one file and 50 were ported independently in more than one directory (parallel scout batches landing the same pick, or a scout sketch that later graduated to a regression port). The registry keeps one canonical port per problem: a port with a passing harness run beats one without, then regression beats runnable beats spec, then the newer spec generation, then the shorter file. Every other file is listed under that problem's `duplicates`.

The most re-ported problems: `dpz` (blind_critic_2, scout_batch_17, top-level).

## Line counts

Blank and comment-only lines never count. "Stripped" removes from the original what a perfect C++ contest library would have supplied: the template, the I/O driver and standard data structures.

Over the 573 canonical ports that have a measured original, the median original is 100 lines raw and 65 stripped, and the median port is 32 lines (means: 118.6, 77.2 and 40.2). Per port, the median reduction is 69.0% raw and 47.4% stripped (means 66.1% and 44.3%). 27 ports are no shorter than their stripped original.

Restricted to the 477 canonical ports with a passing harness run, the numbers are 66.4% raw and 48.4% stripped (18546 lines against 55155 and 35936). This is the number to quote: every line in it compiled and agreed with the original.

The 298 spec-form files are shorter still: 73.3% raw and 60.0% stripped (9683 lines). The runnable ports of 290 of those problems take 13673 lines (41.9% stripped), so the gap between the spec and what builds today is the difference between those two figures. Spec-form numbers are a design target, not a measurement of working code.

How the stripping was done: 91 canonical ports have hand-written `.strip` ranges, and those are used as they are. For the rest, `auto_strip` removes the template, the driver, generic (`template`) types and top-level code whose name is a library name (`DSU`, `binpow`, `SparseTable` and so on). On the 91 regression ports that have hand-written ranges, the heuristic leaves 4113 lines where the hand ranges leave 3542 (+16.1%), matching exactly on 45 and within five lines on 62. It misses library code with a problem-specific name, so auto-stripped reductions lean high.

**`noip21p3`** ([`proto/ports/scout_batch_28/noip21p3.cp`](../proto/ports/scout_batch_28/noip21p3.cp)): 14 lines against 118 raw and 76 stripped in [`5445678.cpp`](../corpus/submissions/5445678.cpp).

```
// NOIP 2021 Variance: a non-decreasing sequence a. Any number of times,
// replace an inner a[i] by a[i-1] + a[i+1] - a[i]; that swaps the two gaps
// next to it, so the gaps can be put in any order. Print n^2 times the
// least variance, which is n * (sum of squares) - (sum)^2.
// The best order is a valley: gaps taken from small to large go to either
// end. With the left value at 0, a gap put on the right adds one value, as
// tall as all the gaps so far; put on the left it lifts every earlier value.
// original: corpus/submissions/5445678.cpp
use std.seq.{scan}

let n: 1..=10000 = read()
let a: [n]1..=600 = read()
let gaps = sorted([a[i + 1] - a[i] for i in 0..n - 1])
let height = scan(gaps, +)                  // height[i]: gaps 0..=i together
let top = n * (a[n - 1] - a[0])

// gaps i.. are still to place around i + 1 values that sum to s: n times
// the squares they add, less the square of the final sum
@memo
fn rest(i: 0..n, s: 0..=top) -> Int:
    if i == n - 1: return -s * s
    let d = gaps[i]
    let tall = height[i]
    let lift = (i + 1) * d
    min(rest(i + 1, s + tall) + n * tall * tall, rest(i + 1, s + lift) + n * (2 * d * s + lift * d))

print(rest(0, 0))
```

**`noi14p1`** ([`proto/ports/scout_batch_22/noi14p1.cp`](../proto/ports/scout_batch_22/noi14p1.cp)): 16 lines against 96 raw and 81 stripped in [`3595714.cpp`](../corpus/submissions/3595714.cpp).

```
// NOI 2014 Getting-Up Syndrome: n gates in a row (n <= 100000), each `AND t`,
// `OR t` or `XOR t` with 0 <= t <= 1e9. Pick a starting number from 0 to m
// (m <= 1e9), pass it through every gate in order, and print the largest
// result.
//
// The gates work on every bit alone, so send all-zeros and all-ones through
// once. Then choose the start from the top bit down: a 0 that already comes
// out as 1 is free; otherwise a 1 is worth it if it comes out as 1 and still
// fits under m.
// original: corpus/submissions/3595714.cpp
let (n, m): (Int, Int) = read()
let bits = 30
var (from_zeros, from_ones) = (0, (1 << bits) - 1)
for _ in 0..n:
    let (gate, t): (Str, Int) = read()
    if gate == "AND": (from_zeros, from_ones) = (from_zeros & t, from_ones & t)
    elif gate == "OR": (from_zeros, from_ones) = (from_zeros | t, from_ones | t)
    else: (from_zeros, from_ones) = (from_zeros ^ t, from_ones ^ t)

var (start, best) = (0, 0)
for b in (0..bits).rev:
    let bit = 1 << b
    if from_zeros & bit != 0: best |= bit
    elif from_ones & bit != 0 and start + bit <= m:
        start += bit
        best |= bit
print(best)
```

```
// IMO 2022 P6 (checker): a Nordic square holds 1..n^2 once each. An uphill
// path starts at a valley (a cell with no smaller neighbour) and climbs
// through side-adjacent cells. Count the uphill paths, mod 998244353.
// Runnable on proto/cpc today.
// original: corpus/submissions/4955728.cpp
let n: 1..=1500 = read()
domain Row = 0..n
domain Col = 0..n
type Cell = (Row, Col)
type M = Mod<998244353>
let a: [Row, Col]Int = read()

fn adj4(p: Cell) -> List<Cell>:               // v2: p.adj4
    var out: List<Cell> = []
    if let r = p.0 - 1: out.push((r, p.1))
    if let r = p.0 + 1: out.push((r, p.1))
    if let c = p.1 - 1: out.push((p.0, c))
    if let c = p.1 + 1: out.push((p.0, c))
    out

var at: [1..=n * n]Cell = (Row.first, Col.first)
for r in Row:
    for c in Col: at[a[r, c]] = (r, c)

// Paths ending at a cell, taken in increasing order of value.
var ways: [Row, Col]M = 0
var total: M = 0
for v in 1..=n * n:
    let p = at[v]
    var valley = true
    for q in adj4(p):
        if a[q] < v:
            valley = false
            ways[p] += ways[q]
    if valley: ways[p] = 1
    total += ways[p]
print(total)
```
