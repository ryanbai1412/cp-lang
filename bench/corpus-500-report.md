## Files against problems

The 1247 files are not 1247 solved problems. 91 are regression ports that `proto/run_all.sh` stresses on every change. 576 are runnable scout ports, the form a batch harness builds. 313 are spec-form files: the same solutions written against the locked spec, which no implementation accepts yet, so each has a runnable twin in `today/`. 44 are blind-critic first drafts or superseded `before/` versions, and 223 are shared modules and a bug repro rather than ports.

After grouping by problem code, 381 problems have more than one file and 68 were ported independently in more than one directory (parallel scout batches landing the same pick, or a scout sketch that later graduated to a regression port). The registry keeps one canonical port per problem: a port with a passing harness run beats one without, then regression beats runnable beats spec, then the newer spec generation, then the shorter file. Every other file is listed under that problem's `duplicates`.

The most re-ported problems: `dpz` (blind_critic_2, scout_batch_17, top-level); `dpy` (scout_batch_8, top-level, wave2); `dpx` (scout_batch_4, top-level, wave2); `dpv` (hillclimb_dp_graph, scout_batch_2, wave2); `dpu` (hillclimb_dp_graph, scout_batch_4, wave2).

## Line counts

Blank and comment-only lines never count. "Stripped" removes from the original what a perfect C++ contest library would have supplied: the template, the I/O driver and standard data structures.

Over the 594 canonical ports that have a measured original, the median original is 101 lines raw and 66 stripped, and the median port is 32 lines (means: 120.5, 78.8 and 41.3). Per port, the median reduction is 68.8% raw and 48.0% stripped (means 66.0% and 44.7%). 32 ports are no shorter than their stripped original.

Restricted to the 566 canonical ports with a passing harness run, the numbers are 66.4% raw and 48.4% stripped (22721 lines against 67692 and 44048). This is the number to quote: every line in it compiled and agreed with the original.

The 313 spec-form files are shorter still: 72.7% raw and 59.2% stripped (10597 lines). The runnable ports of 305 of those problems take 14553 lines (42.5% stripped), so the gap between the spec and what builds today is the difference between those two figures. Spec-form numbers are a design target, not a measurement of working code.

How the stripping was done: 91 canonical ports have hand-written `.strip` ranges, and those are used as they are. For the rest, `auto_strip` removes the template, the driver, generic (`template`) types and top-level code whose name is a library name (`DSU`, `binpow`, `SparseTable` and so on). On the 91 regression ports that have hand-written ranges, the heuristic leaves 4113 lines where the hand ranges leave 3542 (+16.1%), matching exactly on 45 and within five lines on 62. It misses library code with a problem-specific name, so auto-stripped reductions lean high.

```
// CTSC 2006 Singing Kingdom: letters 1..m are drawn uniformly at random until
// a given name appears as a block of consecutive draws. Print the expected
// number of draws modulo 10^4, as four digits, for each of t names.
//
// The original solves a recurrence over the failure function. The closed
// form is shorter: the expected wait is the sum of m^b over every border b
// of the name, the whole name included (a border is a prefix that is also a
// suffix).
// original: corpus/submissions/4528855.cpp
use std.strings.{prefix_function}

let (m, t): (Int, Int) = read()
type Z = Mod<10000>

fn digit(x: Int) -> Str = "0123456789"[x % 10..x % 10 + 1]

for _ in 0..t:
    let n: Int = read()
    domain I = 0..n
    let name: [I]Int = read()
    let border = prefix_function([name[i] for i in I])
    var (wait, b) = (Z.zero, n)
    while b > 0:
        wait += Z(m).pow(b)
        b = border[b - 1]
    let w = wait.v
    print(digit(w / 1000) + digit(w / 100) + digit(w / 10) + digit(w))
```

**`noip21p3`** ([`proto/ports/scout_batch_28/noip21p3.cp`](../proto/ports/scout_batch_28/noip21p3.cp)): 13 lines against 118 raw and 76 stripped in [`5445678.cpp`](../corpus/submissions/5445678.cpp).

```
// NOIP 2021 Variance: a non-decreasing sequence a. Any number of times,
// replace an inner a[i] by a[i-1] + a[i+1] - a[i]; that swaps the two gaps
// next to it, so the gaps can be put in any order. Print n^2 times the
// least variance, which is n * (sum of squares) - (sum)^2.
// The best order is a valley: gaps taken from small to large go to either
// end. With the left value at 0, a gap put on the right adds one value, as
// tall as all the gaps so far; put on the left it lifts every earlier value.
// original: corpus/submissions/5445678.cpp

let n: 1..=10000 = read()
let a: [n]1..=600 = read()
let gaps = sorted([a[i + 1] - a[i] for i in 0..n - 1])
let height = scan(gaps, +)  // height[i]: gaps 0..=i together
let top = n * (a[n - 1] - a[0])

// gaps i.. are still to place around i + 1 values that sum to s: n times
// the squares they add, less the square of the final sum
@memo
fn rest(i: 0..n, s: 0..=top) -> Int:
    if i == n - 1: return -s * s
    let d = gaps[i]
    let tall = height[i]
    let lift = (i + 1) * d
    min(rest(i + 1, s + tall) + n * tall * tall, rest(i + 1, s + lift) + n * (2 * d * s + lift * d))

print(rest(0, 0))
```

```
// so that it stays connected when any one link fails. Print the number of
// new links and the links (any optimal answer).
// Every leaf needs a new link, so ceil(leaves / 2) is a lower bound. List the
// leaves in preorder from an inner root and join leaf i to leaf i + k/2:
// the two ends of each new link lie on different sides of every tree edge
// that has leaves on both halves, which covers every edge.
// original: corpus/submissions/5640865.cpp

let n: 3..=5e5 = read()
domain V = 1..=n
domain E = 0..(n - 1)
let edges: [E](u: V, v: V) = read()
let g = Graph<V, E>.undirected(edges)

var root = V.first
for v in V:
    if g.deg(v) > 1: root = v
let t = Rooted(u => g.adj(u), root)

var leaves: List<V> = []
for v in t.preorder:
    if g.deg(v) == 1: leaves.push(v)

let k = leaves.len
print((k + 1) / 2)
for i in 0..(k + 1) / 2: print(leaves[i], leaves[i + k / 2])
```
